# issue 502：画谱进度条改「一行到底」+ 预处理四段补齐动态进度

- 关联：issue 497（进度块两行形态）、issue 469（prep 折算总进度）、issue 470（图片描述批进度）、
  issue 455（双卷口径 → 其人 / 相交 / 纪事）
- 域：people（脸谱）

## 反馈

用户三轮递进：

1. 「把副行的详细语义合并到主行当中，去掉副行」——状态与细节分两行看，细节容易被忽略。
2. 「固定建议，如果有动态信息显示都保留下来」——静态机制说明（每批参数、抽样规则、缩略图留档、
   chat.json 只读、冷加载按分钟计）一律砍，随进度变化的数字一律留。
3. 「导出媒体不能只显示 4 个字呀，那后面的导出媒体的数量进度不跟在后面吗？……
   让用户不用等待，而是能看到整个过程的流动」——段级 step 短语不能替代流动的计数。

## 根因

1. **主行与副行信息同源、互为包含**：`render.ts` 的副行就是引擎 `job.message` 原文，
   而主行的阶段行（`媒体导出 312/1631`）也是从同一份 prep 状态算出——两行说的是同一件事，
   副行只在 prep/describe 段被 `msg !== main` 挡掉，切批与成文段又照念一遍。
2. **预处理四段里两段没有分母、一段静止**：`newPrepProgress` 只给 media / transcribe / map
   预存总数，derive 段没有分母只能退成 `派生图片档 40%`；map 段工具侧只在开段打 `None`、
   收尾打 `100`，中间无打点 → 整段死在 `图片关联表 0/1631` 直到结束才跳。
3. **段级 `[bz-step]` 是「讲机制」而非「讲动作」**：`媒体导出：语音 wav、图片（wxgf 就地转
   jpg/gif）、视频、文件、缩略图（仅留档…）` 这类句子占了副行，说的却是段名本身已承担的语义，
   且把「缩略图绝不当 AI 输入」这种免责补充写进了用户视野。

## 改动

### 1. 主行合并（`src/people/render.ts`）

- 新增 `jobsMainLine(s)`：`状态词 · 进度锚点 · 引擎细节` 三段合一行，返回 `{ head, detail }`；
  `progressBlock` 把 head 拼粗体主行、detail 挂同行内 `.bz-people-jobs-detail`（400 字重灰字），
  **不另起第二行**。
- 合并口径：锚点与细节互为包含时只留更详尽的那条（`正在生成《纪事》…` +
  `《纪事》完成，正在提炼人物档案…` → 只留后者）；细节开头的重复状态词先剥掉
  （`已暂停（12/60 批）` → `12/60 批`）。
- **error 面不挂细节**（原因由底部 `.bz-people-jobs-err` 承担）；done 只有一句，该态整块不上屏。
- 删副行渲染与 `.bz-people-jobs-sub`；删无调用点的死代码 `jobsQueueLabel` / `jobsFallbackMessage`。
- 阶段标签与折页名逐字对齐：`《我们》`→`《相交》`、`关系时间线`→`《纪事》`。

### 2. 引擎文案（`src/people/jobs.ts`）

- 切批 / 抽样说明砍参数与机制：`消息 20773 条 → 35 批 · 共 38 次 AI 调用`、
  `消息 91234 条 → 均匀抽样 60 批`。
- 素材统计前缀 `素材采集完成：` → `素材：`；阶段推进句成对：`《其人》完成，正在生成《相交》…`
  → `《相交》完成，正在生成《纪事》…` → `《纪事》完成，正在提炼人物档案…`。
- 失败 / 暂停句精简：`第 30/47 批失败（<原因>），重试 1/2…`、`已暂停（2/3 批）` → `2/3 批`、
  `预处理完成，3 条失败待补齐，开始组装素材…`。
- **error 面不再写 message**（不上屏，只留 `error` 字段给底部红字）；
  终局（done）不再写 message。

### 3. 预处理四段动态进度（`src/people/prep.ts` + `tools/obsidian-face/python/bz_prep.py`）

- `prepMediaTotals` 增加 derive 分母（取图片数，与关联表同源）；
  `newPrepProgress` 为 derive 段预存总数 → 四段统一 `标签 N/M`：
  `媒体导出 312/1631` / `派生图片档 12/1289` / `图片关联表 810/1289` / `语音转写 40/1289`。
- `bz_prep.py` 的 map 段循环内按 1% 限频补 `progress("map", pct)`，不再整段静止。
- 删四个段级 `step`（媒体导出 / 派生图片档 / 图片关联表 / 语音转写）——段名与计数已由主行承担；
  `bz-face.js` 的「预检通过…启动预处理」只活一帧也删。
- **保留**无数量可跟的等待 / 状态 / 异常句（否则进度条不动会被当成卡死）：
  `加载转写引擎 funasr…`（省略号即流动信号）、`转写引擎加载失败，本轮跳过转写`、
  `收到停止，已完成产物保留`、`媒体目录改用账号目录`、`清除暂停指令，继续预处理`。

### 4. 样式（`src/people/styles.css`）

`.bz-people-jobs-sub` / `.bz-people-jobs-queue` / `.bz-people-jobs-note` 三件套 →
`.bz-people-jobs-detail`（同行内 `--ink-mut`、400 字重），保住「粗标题 + 灰细节」的层次。

## 验证

- `tests/people` 6 个文件断言同步到新口径（主行一行到底、细节挂尾、无副行、旧名改新名、
  删掉的死函数断言不存在）。
- people 域 35 文件 / 538 例全绿；`tsc --noEmit` 0 错；全量测试通过。

## 遗留

- **「图片名流转」不在现状里**：prep 段目前无逐条动态信息——`[bz-p]` 协议只带 `{phase, pct}`，
  没有「当前项 / 文件名」通道。要做需扩展协议（`bz_sync.py:progress()` 加 note 字段、
  `external-tool.ts` 的 `onProgress` 加参数），属核心协议改动，未纳入本批。
- 进行中的计数是 `pct × 预存总数` **推算**值（比如 1631 项时 pct 每跳 1% 就是 16 项），
  要变成逐条真值同样需要 `[bz-p]` 带 `{done,total}` 的协议扩展。
- prompt 内部仍自称「卷二《我们》」（`digest.ts`），AI 正文可能与折页名「相交」不一致，
  属产出结构变更，单独一批。
