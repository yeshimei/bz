# issue 503：影院名称索引翻新——两表合并 14.3 万条，剧集侧类型细分修正

- 关联：issue 498（索引首版，ADR-0210）
- 域：cinema（影院）· 数据资产

## 反馈

1. 「核实里面的类型是否都正确，然后把它改成 Json 的形式替换掉在线资源当中的」——
   瘦表（自抓 2026 影视表 98,231 条）要替换在线资源 `downloads/cinema-douban-index.json`。
2. 「两表合并吧」——瘦表单表只有 Kaggle 67k 的 33.6% 覆盖，直接替换会丢 4.5 万条冷门老片；
   按既有合并口径（2026 表优先 + Kaggle 补老片）出全量。
3. 「《绿色星球》是电视剧这样的分类，它应该是纪录片的」——证实为系统性缺口：
   `merge2` 只对「标成电影」的行做 is_tv 翻转，剧集侧从不按豆瓣 types 细分，
   绿色星球（33387356）的富化数据里 `types=['纪录片']` 一直在盘上却没被用上。

## 核实结论（类型远谈不上全对）

| 缺口 | 规模 | 处置 |
|---|---|---|
| 剧集侧未细分（绿色星球类） | 改类 1,707 行（电视剧→综艺 673 / →纪录片 546 / →动画 423 等） | 已修：`merge2` 两侧统一按 types 定类，重出表 |
| movie-search 未核验 is_tv | 48,340 行，在线抽验 40 条误标 14 条（**35%**），全表暗藏约 1.7 万假电影 | `enrich_pool.py` 6 分片后台补核（约 3–4 小时），跑完后重跑 merge → 索引 → 出版即刷新 |

## 出版

- `cinema_name_index.json`：2026 表 98,231 + Kaggle 新增 44,410 = **142,641 条**（有评分 85.5%）。
- `downloads/cinema-douban-index.json` 7.10MB（行定长数组，ADR-0210 决策 2），清单 sha256 随 `pnpm manifest` 重出。
- 类别分布：电影 129,172 / 电视剧 7,774 / 动画 2,034 / 纪录片 1,843 / 综艺 1,818。
- 类型细分只动 scratch 管线（merge2.py），插件零代码改动；`douban-name-index.ts` 注释条数随手更新。
