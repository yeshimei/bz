# 531 · 重任务严格单跑：画谱与录音任何时刻只允许一个在跑

## 用户原话（2026-10-01）

> 11 不冲突，不管任何时候只能做一事情，就是说，如果在画谱，就不能跑录音，反之亦然，因为你没有实现这个，所以才会有冲突。你把这个实现了就可以了。

## 诉求

不要「自动排队」那套编排。规则就一条：**任何时刻只能做一件事**——

- 画脸谱在跑 → 录音不能跑；
- 录音在跑 → 画脸谱不能跑；
- 反之亦然，无例外、无抢占、无并行。

当前实现互斥没做严（heavy-gate 有「待命 prep 进程可被抢占、30 秒宽限硬杀」的口子；sync 与画谱是另一套零散互斥；UI 各处「等它跑完再…」各写各的），用户因此撞到过冲突。把「严格单跑」实现完整即可。

## 验收口径

1. 任一时刻至多一个重任务持有执行权（画谱全链或录音全链，含其子进程）。
2. 后来的重任务不许启动：按钮禁用 + 一句话说明「现在在跑 X」，不允许「排队中/等它跑完再手动试」这类让用户自己掐时间的状态。
3. 不做抢占：在跑的任务不许被另一类任务打断。
4. 各处互斥判断同源（单一判定入口），不再散落多套各自为政的锁。
