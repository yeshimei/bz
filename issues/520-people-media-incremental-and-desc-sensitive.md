# 520 · 画脸谱两个实测病：媒体导出非增量 + 敏感图卡死整批描述

来源：用户实测（2026-09-30）——①「每次补画谱都是全量导出媒体、全量派生，特别慢」；②进度块报
`生成失败 · 图片描述 4/17 批`，原因 `AI 请求失败: 系统检测到输入或生成内容可能包含不安全或敏感内容…（fallback: Request failed, status 400）`，整批 20 张全废。用户建议：敏感批改为逐张走，确定有问题的图标注、下次不再描述。

用户拍板（2026-09-30）：敏感标注落**聊天仓消息字段（保库内）**；降级范围**只对敏感拒绝**；两个问题**一起修**；媒体增量做到 **档 A + 档 B 一起**（存在判定先行 + 索引驱动增量）。

## 根因

### 病因一：媒体导出不是增量，是「全量白读」

`tools/obsidian-face/python/bz_prep.py` 段 1 的四类媒体里，**错的两类正好是体量最大的两类**：

| 处理函数 | 现状 | 判定 |
|---|---|---|
| `do_image` / `do_video` | `p.read_bytes()` → `decode_dat()`（AES 多密钥轮试）→ **才** `target.exists()` | ❌ 顺序错 |
| `do_file` | `target.exists()` 在前 | ✅ |
| 语音段 | `target.exists()` 在前（且走 flow，本就近增量） | ✅ |
| derive 段 | `target.exists()` 在前 | ✅（但遍历是全量） |

1631 张图（936MB）+ 全部视频，每轮 prep 都要完整读盘 + 轮流试 AES 密钥，算出来一个字都不用直接丢。

叠加**三次全量目录遍历**：`attach_dir.rglob('*')`（段 1）、`img_root.rglob('*')` 两遍（段 2 derive 建 sources、段 3 map 建 disk 表）。

### 病因二：敏感拒绝走的是普通重试路径，整批陪葬

`runDescribeStage` 现状：批 20 张 → 失败 → 退避重试 `maxRetries` 次 → 耗尽 → 整段 `status: 'error'`。敏感拒绝（400）与网络抖动、5xx、额度错**共用同一条路径**，既无批内降级，也无 poison 标注，更没有"这张已经确定不行了"的终态。

### 病因三（耦合点）：描述失败的图让欠账永久化

`pendingMediaCounts` 判欠账的口径是「媒体消息且 `text` 为空」。敏感图被拒后 `text` 恒空 → **插件侧永远判有欠账 → 每次补画都重起 prep 进程**，把病因一整套浪费重走一遍。所以 4/17 批卡住的实际代价不是那一批，是此后每次补画都全库重扫。

## 改动

### A. 媒体导出：存在判定先行（档 A）

`do_image` / `do_video` 改为**先探测产物再读字节**：

- `do_image`：目标名 = `<源 stem 首段>.<ext>`，`ext` 解密后才知道 → 按 `jpg / gif / png / bin` 四种候选探测，命中即 `skip`（`.bin` 命中仍走 `try_wxgf` 补解码分支，语义不回退）。
- `do_video`：目标名与 ext 无关（直接 `<stem>.mp4`）→ 一次 `exists` 即可。

效果：已导出文件的代价从「读全字节 + AES 轮试」降为一次 `stat`。

### B. 媒体导出：索引驱动增量（档 B）

段 1 不再每轮全量 `rglob` attach 目录，改为增量索引：

- 新产物 `<数据根>/<联系人>/.bz-face/media-index.json`（落点与断点状态同处，**跟数据走不跟人走**）：存每个月份子目录的 mtime + `hex → 月/文件名` 映射。
- 构建：比对月份目录 mtime 集合——**没变的月份直接用缓存**，变了的月份只重扫那一个目录并并入索引；首次运行仍全量建一次（一次性代价）。
- 导出队列 = 索引里**产物缺失**的条目（判定走档 A 的探测）。索引命中的已导出文件根本不进队列。
- 段 2 derive 与段 3 map 复用同一份产物清单，不再各自 `rglob` 一遍 `image/`。

保留了「索引里全部源文件都过一遍」的结构（而非纯消息流驱动）：`thumb/`（微信自带缩略图）与未挂消息的附件不进消息流，纯消息驱动会漏；索引把"遍历"变成内存操作，"读盘解密"由档 A 消掉，两条一起才是完整的增量。

### C. 敏感拒绝：批内降级（只对敏感）

- 新增错误分流：`400 + 敏感/不安全关键词` → `sensitive` 类；网络超时 / 5xx / 额度错仍是原有重试路径。
- 命中 `sensitive` 的批**立即降级为逐张调用**（不退避重试整批——整批必然再次被拒，白付费）：

  - 逐张成功的照常 upsert 进仓；
  - 被拒的那张标 `sensitive` + `text` 留空；
  - 逐张跑完 → 本批 `doneBatches` 推进 → **整段继续走画像生成**，不阻断整链。

- 记录落账：`describe` 段进度账本加 `sensitive: N`（被拒张数），完成通知由 UI 层拼出「其中 N 张被判敏感已跳过描述——图片页签里可以解除标注并重试」。

### C2. 先标注、后并仓（实现期暴露的既有缺陷）

同一笔 `safe.write` 里，**标注必须先于 `applyImageDescToMsgs` 执行**。否则被拒的图会被
「同月 ct 最近邻兜底」借到邻居的描述——一张毒图反而顶着别人的描述进时间线。

配套收窄该兜底：`items` 里**明示了 `file` 但描述为空**的图不再借用邻居的描述（那是「本轮确实没
拿到」，不是「调用方没提这张」）；最近邻只服务「旁路表只给 `ct` 不给 `file`」的老场景。

### D. 敏感标注：聊天仓消息字段 + 排除出欠账

- 聊天仓消息新增派生字段 `descSkip?: 'sensitive'`（与 `text`、`img` 同级，加密在保库记录内）。**与 ADR-0197 一致：插件是唯一写者**，工具侧永不产出该字段。
- `pendingMediaCounts`、describe 段的 `refs`、`applyImageDescToMsgs` 与图片页签的 `undescribed`
  四处口径**都排除 `descSkip === 'sensitive'` 的图**——标注即终态，等价 done，永不重跑；也因此不再
  让病因三的永久欠账成立。
- **不动结构版本**（落笔前核实）：`descSkip` 是消息上的可选派生字段，旧记录缺它按「未标注」读入
  （`normalizeRecord` 的 spread 原样保留 msgs）。类型加可选字段即天然兼容，无需迁移脚本。
- 撤回入口：图片页签里已标注的格子给「敏感 · 解除」入口，一点 = 解除标注 + 走 `runDescribeOnly`
  重试描述（这一次点击即计费授权）。否则误判无法挽回。

## 验收

1. `pnpm test`：新增/更新以下用例——
   - 档 A：产物已存在时 `do_image` / `do_video` **不读源字节**（注入假 fs 断言 read 次数为 0）。
   - 档 B：月份目录 mtime 未变 → 不重扫该月；变了的月只重扫该月；导出队列只含产物缺失项；首次全量后第二次 prep 的遍历次数下降。
   - 敏感分流：`400 + 敏感文案` → `sensitive`；`429 / 5xx / 超时` → 仍走重试（矩阵断言，不误伤）。
   - 批降级：假 `askLLM` 对整批抛敏感错、对单张抛敏感错 → 断言调用序列退化为逐张、成功项落仓、被拒项 `descSkip = 'sensitive'`、`doneBatches` 推进、整段返回 `ok`。
   - 欠账口径：标了 `sensitive` 的图不计入 `pendingMediaCounts`；未标注的仍计入。
   - 结构版本：旧记录（无 `descSkip`）读入不炸、缺省未标注。
2. `tsc --noEmit` + 自审 + diff 审查全绿。
3. 人工：拿大琳级别（1631 图 / 1289 语音）跑一次完整 prep 并记录耗时，再跑第二次——第二次的媒体导出与派生段应近乎瞬时；构造一张必然被拒的图，验批降级、标注落仓、整链走到画像生成、再次补画不重试那张。

## 边界与不做

- **不做**：把微信原始 attach 目录当缓存删掉（不可逆）。
- **不做**：给敏感图做本地模糊 / 打码后重试（需要新的图像处理管线，且用户未要求）。
- **不动**：语音转写的既有增量口径（本就按 `voice.json` 水位跳过）与 derive 的存在判定（本就正确）。
- **不迁**：`desc/` 派生档的生成策略（长边 1280 / q80）不变。

## 风险

- 索引的失效判据是**月份目录 mtime**：微信若把补下载的历史文件写进旧月份目录，该月 mtime 会变 → 重扫该月，正确性安全。若某个文件系统 / 同步盘不回写 mtime，则可能漏——首次全量建索引 + 产物存在判定（档 A）构成第二道兜底：产物在就不动作，产物不在则即便索引说"没有"也会在当轮 rglob 里被捞到（索引只影响"要不要重扫"，不影响"扫到之后怎么判"）。
- 敏感关键词匹配是启发式：宁可漏判（退回原有重试 + 报错）也不误判（把一次网络抖动当成敏感，白白拆成逐张慢调用）。
