# Ticket 110：第二大脑切块剥离 frontmatter（YAML 头进向量）

- 状态：待开发
- 域：secondbrain
- 来源：知识库双链设计交流（2026-08）中实测发现，用户拍板立项
- 关联：第二大脑「双链管线」设计（其候选生成直接复用本向量库，受本缺陷影响最大）

## 问题

`src/secondbrain/vector-store.ts` 切块时把整篇原始内容（含 YAML frontmatter）作为 chunk 文本送 embedding。frontmatter 样板字段（复习卡的 `reviewStart/reviewStage/reviewHistory`、剪藏的 `url/author/site` 等）参与向量计算，对短笔记构成支配性噪声：卡片长得像不是因为说得像，而是因为格式像。

## 实测证据（2026-08，bge-m3 / dim=1024 / 3572 篇 / 12591 chunks）

以 `卡片盒/次卡片盒/幽灵之战：记忆依据图式构建.md` 为探针做全库近邻检索：

- Top8 分数全部挤在 0.946–0.949 的异常窄带（正常语义近邻分布应更离散）；
- 命中块的文本即裸 frontmatter 样板；《山水田园诗派》（唐诗卡，语义无关）以 0.946 混入；
- 对照的长文卡（《图式》《自我效能理论》）近邻质量正常——问题随「正文越短、样板占比越高」恶化，恰是卡片盒的主体形态。

## 方案要点

1. 切块前剥离 frontmatter，YAML 头不进 embedding 文本；标题建议并入首块文本保留主题信号；
2. meta version bump，走现有版本升级路径自动触发全量重建（vector-store.ts 已有 version 不符 → 重建逻辑）；
3. 全量重建约 12.6k chunks，建议桌面端执行（见设计交流结论：手机仅承担增量更新）。

## 影响

- 正向：短卡近邻检索精度修复；第二大脑 QA 检索与后续双链管线同源受益；
- 一次性成本：全库 re-embedding 一轮（桌面执行）；
- 兼容性：`secondbrain_meta.json` / `.vec` 属插件内部缓存而非冻结数据格式，version 升级自动重建即可，无外部消费者受影响。

## 验收

- [ ] 切块产物不含 YAML 头文本
- [ ] 复测探针《幽灵之战》：Top8 无样板驱动的假邻居（山水田园诗派类消失），分数带恢复离散
- [ ] 版本升级后旧库自动重建成功，QA 检索表现正常
