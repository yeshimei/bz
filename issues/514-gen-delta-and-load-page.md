# 514 · 开工单增量只报增量 + 解密页重排

来源：用户实测（2026-09-29）——①开工单「增量 · 只提炼新增」却列全量数字（素材 17277 / 图片 1616 / 语音 1289），自相矛盾误导用户；②解密过渡页难看：左页大片空白只有一枚小方块，页眉「14/25位」挤压换行。用户拍板：增量就只显示增量的数据描述；解密页调整好看。

## 改动

**开工单增量口径（datasource / types / ui / render）**
- 新纯函数 `pendingMediaCounts(msgs)`：type 3 / 34 且 text 空 = 待描述 / 待转写（描述与转写升级进 text，空即未做——与 refreshSuppStoreInfo 的未描述判定同源）。
- `GenTarget` 带 `pending`（两处构造点从保库 store.msgs 现算）与 `planCount`（planTargets 把提炼集条数带出，此前丢弃）。
- `GenerationConfirmItem.images / voices` 改**待办口径**：full 模式待办 = 全量（首画本来就没做过）；newer 模式 materials 显示 planCount（新增条数），明细措辞「新增素材 N 条 · 增量提炼」；older 维持全量 + 「补录合并重画」（语义如实：older 确实全量过一遍与旧画像合并）。
- 总览行待办为 0 自动省行（全部描述过 / 转写完就不再出现这两行）；画像调用估算 newer 模式按提炼集条数（`estimatePortraitCallsOfCount`，24 字符哑行近似）。

**解密页（render / styles / ui）**
- 左页改居中进度卡：大号当前数 + 「/ N 位联系人」+ 细进度条（红章色）+ 一句人话；页眉不再塞「14/25位」小字（换行挤压的根源），右侧改一句「解密完就摊开」。
- 右页照片墙骨架保留（「先不急着看」的洗照片隐喻成立）。
- 原位更新钩子随新结构调整（数字与进度条 width），轮询不再改旧节点。

## 验收

1. 大琳增量开工单：逐人行只出现「新增素材 N 条 · 增量提炼」；图片 / 语音无待办则两行整体消失。
2. 解密页：左页大数字 + 进度条居中，无换行小字；右页骨架保留。
3. 门禁全绿。
