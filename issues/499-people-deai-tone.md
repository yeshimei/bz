# issue 499：脸谱成文去 AI 味（第一人称散笔 + 卷名对齐）

- 关联：issue 455 / ADR-0192（双卷画像）、ADR-0191（提炼管线）
- 域：people（脸谱）

## 背景

脸谱三处成文（卷一《其人》/ 卷二《相交》/《纪事》）的提示词把叙述主体写成「用户」，
模型照抄，正文通篇「用户如何」，读起来是报告不是笔记。

同时查出**改名只改了一半**：折的书脊与标题早已换成《相交》/《纪事》，
但送模型的 prompt、用户可见的阶段文案（jobs / render）、以及测试里假 LLM 的分流判据仍是旧名。
后者最阴——prompt 文案一改，`p.includes('关系时间线')` 这类判据会静默走错分支，测试测了个空。

## 改动

1. **旧名对齐（P0）**：`digest.ts` / `incremental.ts` / `jobs.ts` / `render.ts` / `types.ts` /
   `ui.ts` / `styles.css` 与各测试里的「卷二《我们》」「关系时间线」全部换为「卷二《相交》」「《纪事》」；
   假 LLM 分流判据 `p.includes('关系时间线')` → `p.includes('《纪事》')`（9 处）。
2. **第一人称（P1–P7）**：三处开场与正文人称改「我」；批提炼 / 档案提炼里的
   「[我] = 用户发出」一并换掉（该词会进模型上下文）。
3. **文体块 TONE_RULES（P8，新增）**：与 HARD_RULES 并列注入三处。含第一人称硬禁「用户」、
   从具体的事开口、句长节奏量化（连续两句超 18 字拆开 / 连续两句不到 10 字并起）、
   口语额度（每百字 ≤ 3）、全篇至少一次犹豫或自我修正、抽象结论后必须垫一件看得见的事、
   每节不许升华 / 收尾金句 / 排比三段、禁用套话表、一组改前改后对照。
4. **HARD_RULES 修订（P9）**：「当 X 时，TA Y」句式改为「用事写，模式让读的人自己看出来」
   （该句式本身是公式感的主要来源）；补「全篇 3~6 处引用块」；字数上限 1200 → 1500。
5. **逐节写法（P10）**：只改节内写作要求（画像速写不许「TA 是一个……的人」开头、
   关系定性不许「我们是一段……的关系」开头、兴趣 / 情感倾向去掉形容词兜底），
   **小节标题一字未动**。

## 守住的三条边界

- **小节标题不动**：`render.ts` 的 `MD_SEALS` 按标题取印章字，改标题会让印章字退化成「一二三」。
- **不搬社区的内容层规则**：社区去 AI 味方案普遍带一句「没有细节时可根据上下文合理虚构」，
  本条不适用——脸谱素材是聊天记录里真实发生过的事，属事实层；为凑人味编细节等于往一个人的
  关系档案里塞假记忆，比 AI 味严重得多。本次只搬句法 / 语气层。
- **存储键与兼容读不动**：`person` / `bond` / `chronicle` 字段名保持。

## 验证

- 真实数据（`export_full/莫莫`，152 条）按新 prompt 逐字试跑，三卷产出见
  `.scratch/face-tone/momo-脸谱-新提示词试跑.md`（方向已认可）。
- `pnpm exec vitest run tests/people` + 全量 `pnpm test`、`tsc --noEmit`。
- 测试新增反向断言：卷一 / 卷二 prompt 必须含「## 文体：日记散笔」，且不得再出现「你在帮用户」。

## 遗留

- 已生成的脸谱需**重新画谱**才生效（prompt 只在生成时消费，旧产物不会自动改写）。
- 样本不足（< 200 条）时「（素材不足）」会大面积出现——是否改为「无证据的整节省略」待定。
