# 249：剪藏本已读原位保留（会话冻结序 + 桌面打开即读 + 已读/已收双折叠段）

日期：2026-09-08 ｜ 分支：feat/clipbook-frozen-order-249 ｜ worktree：clipbook-frozen-order-249

## 背景

用户实测反馈（果壳科学人）：打开一篇文章状态立即变已读、目录标题变色；在目录内打开另一篇时，
上一篇已读的文章**保持原位**；再次打开该源目录，已读才排到未读下面。而现状两端均「即时让位」：
桌面端无自动落读（ui.ts:760「无自动落读」拍板），已读条目在重渲时直接从列表消失（store.ts
`queryBySource` 源头过滤 read）；移动端打开即已读，返回目录瞬间沉入默认收起的「已收」折叠段
（ADR-0107）。两端目录每次都实时现算（sortedView unread 置前），←→/jk 用实时序非快照。

## 决策（ADR-0108）

**会话冻结序**：打开面板（装载）拍目录快照；会话内打开即已读、右键/批量标读、收藏均**原位**
只变视觉与计数、不重排；**唯一重排点 = 重开面板**。重排来源入双折叠段。

- **桌面端也「打开即已读」**：废除 ui.ts「无自动落读」拍板，与移动同动线（含 ←→/jk 步进）。
- **双折叠段**：重开后已读 →「已读 N 篇」段（30 天保留）；已收藏/剪藏承接 →「已收 N 篇」段。
  移动端原单「已收」段拆分；桌面端新增双段（现状无折叠、已读直接消失）。
- **桌面端兜底展开**：源目录无未读时默认展开「已收」（已收空则已读），保证不空场；
  移动端多章平铺不套此例外（维持默认折叠）。
- **计数**：rail 徽标 / 章头计数即时更新（status 变），仅排列不动。
- **适用范围**：仅 news 订阅源（果壳/知乎/B站 UP）；剪藏本源 .md 无未读/已读生命周期不套。

## 改动（实现时落 worktree）

- **store/data**：桌面源视图 query 不再源头剔除已读（保留原位渲染所需）；排序改「进站快照序」
  （sortedView 改消费快照），站切换/重进站/重开面板时才重算。
- **ui.ts**：桌面 renderList 未读区后挂「已读 N 篇」「已收 N 篇」两个折叠段（默认收起，无未读
  时按规则默认展开）；打开详情/←→/jk 触发 markReadOnOpen（桌面新增，移动到既有静默链路）；
  折叠展开态模块级记忆；rail 徽标与章头计数即时更新。
- **render.ts / styles.css**：双折叠段 markup（桌面 + 移动复用同一折叠行排版；移动拆
  arch=saved 与 read 两批）+ 已读灰字原态样式已存在（未读色/已读灰）。
- **tests**：数据层（保留已读/快照序）+ UI 层（双折叠段/默认展开/计数即时）用例；行为单源域
  （ADR-0106）需同步重出 clipbook 行为包并在评审壳 selftest 增加断言。
- **cli governance**：保留天数已统一（issue 224），此处不另设键。
