# 435 · 脸谱域（people）：微信聊天导入 + AI 生成脸谱

- 状态：开发中（2026-09-25）
- 用户原话①：「人脉本 可不可以导入微信聊天数据来处理这个东西？」
- 用户原话②：「我想做的是"脸谱"的东西。比如，我可以导入微信的聊天记录，然后输入关于这个人的各种信息，比如他的社交账号、我和他发生的一些事情等等」
- 用户原话③（MVP 拍板）：「先做两类，一个是微信聊天记录导入，根据这些聊天记录来生成脸谱，就这样就可以了，你可以去使用社区的插件，我这里已经有一份微信的聊天导出的记录了」
- 用户原话④（外部力量模式）：「不需要自己写，直接用社区的插件和开源库，就像B站下载一样，可以使用外部脚本、外部的力量」
- 关联：ADR-0191（本域立项）/ issue 367（微信账单导出调研，已取消的域外先例）/ ADR-0071+0072（bili-downloader 外部工具模式，本票照办）/ ADR-0004（命令裸注册通道）

## 范围（MVP，用户拍板「先做两类，就这样就可以了」）

1. **微信聊天记录导入**：消费「留痕 MemoTrace」（LC044/WeChatMsg）导出的 CSV / JSON 文件。解密导出全部由社区工具完成（用户在其 GUI 操作），插件只做产物消费——解密层不自研、不自动同步。
2. **AI 生成脸谱**：统一消息流 → 分批 LLM 提炼（交往事件 + 特质线索）→ 汇总生成人物画像（markdown）。

## 非目标（后续票）

- 手动档案区（社交账号 / 生日 / 纪念日）、随手记事件流、跨人向量检索（「谁懂装修」）、Jev 亲疏打分与联系提醒、虚拟人聊天（角色扮演）。

## 技术要点

- 解析器按留痕 CSV / JSON 字段**嗅探式**实现（`is_sender` / `CreateTime` / `msg|StrContent` / `type_name`，数字 Type 1=文本），待用户真实导出样例校准。
- **聊天原文不落盘**（ADR-0191 §2）：解析与提炼全程内存，`people.json` 只存人物卡 + 事件 + 画像 + 导入元数据。
- LLM 走 `core/ai.ts` 生成通道（`createAI`），提炼批走 `.json()`、画像走 `.chat()`；`AskLLM` 注入式设计，管线可整管单测。
- 数据 `CONFIG/STORAGE/people.json`（`jsonFileStore` + `enqueueFileTask` 串行写）；命令 `bz-people-open` / `bz-people-import`；域图标 `drama`。
