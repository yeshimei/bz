# 402 影院网格重排动效（移动的 FLIP、消失的淡出、出现的接力）

## 背景

影院网格是 `renderAll` 整写 innerHTML（`renderMidnightDesk/Mob`），排序 / 筛选 / 搜索 /
状态流转之后卡片**直接跳位**——这是走查里最大的一块动效空白。而 FLIP 的量与演两件工具
（`measureFlip` / `playFlip`）已经写好并在线（共享元素飞行在用，`ui.ts` extractSrc / reinsertSrc），
只是没接给网格重排。

三类件分别对应三种语义，本批一次补齐：

- **留下来的卡**：知道它从哪来 → FLIP 补位（移动）；
- **消失的卡**：渲染后就没了 → 按旧矩形留一枚幽灵淡出（离场）；
- **新出现的卡**：没有来处 → 前若干张接力淡入（进场）。

## 决策（2026-09-21 用户拍板「按照你的来」）

1. **跨渲染的 FLIP 按稳定键配对**：`data-cinema-key`（单条目 = 笔记名，合并卡 = `series:<组>:<base>`，
   `shared.ts` 里已是卡片稳定键，季圆点换脸也用它）。渲染前量「键 → 矩形」，渲染后按同键配对补位；
   新老都看不见的件不演（沿用 `playFlip` 的视口过滤，省下几百个合成层）。
2. **离场不留旧 DOM，留幽灵**：`.cn-exit` 只是一块底色 + 海报图的绝对定位盒子（位于网格容器内，
   随滚动一起走），旧矩形处淡出后自清。两道闸：**视口外的旧件不演**（沿用 `playFlip` 的 `near()`
   口径——一屏 50 张卡只给看得见的几张留残影）＋ **超过 40 张整体不演**（那种规模本就是一屏换新，
   逐张淡出只会拖慢感知）。用幽灵而不是「延迟重排」：不吃渲染时序、不与软渲染 / 防抖渲染抢管道。
3. **进场接力只在「内容身份变了」时上演**：视图 / 分组 / 状态 / 排序 / 关键词变化才排接力
   （前 12 张、步进 .02s、从下 4px 淡入）；标星 / 队列回填 / 保存这类原地刷新只演 FLIP，
   免得每次后台刷新整屏都在闪。身份令牌由状态层给出（`touchViewEpoch()`）。
4. 三件套全部走台账常量（`MOTION.move` / `MOTION.base`），不新增时长。

## 落地

| 文件 | 改动 |
|---|---|
| `src/cinema/ui.ts` | `measureGridCards(root)` / `playGridMotion(root, before, opts)`；`renderAll` 在渲染前量、滚位恢复后演；`M.state` 加视图纪元令牌 |
| `src/cinema/styles.css` | `.cn-exit`（离场幽灵）、`.cn-enter`（进场接力，含 `--i` 序号延迟） |
| `src/cinema/state.ts` | `viewEpoch` 字段 + 复位 |
| `tests/cinema/ui.test.ts` | ①留下的卡按键补位（量到的位移与期望一致）；②消失的卡留幽灵、幽灵自清；③身份没变时不排接力、变了才排 |

## 验证

- 单测（真几何替身 + WAAPI 替身，否则位移差恒 0 会空转）：①切排序后有 `.pcard` 补位动画，
  时长 = 台账 move 档（200）且首帧带位移、终帧 `none`；②筛选后消失的卡各留一枚幽灵、数量对得上，
  收尾清空。
- 原型自检（真浏览器）：先钉「切排序后顺序确实变了」作为非空转前提，再断言存在补位动画；
  幽灵数量 > 0 且 ≤ 消失数（视口外的卡本来就不演）、随后自清。
- 打坏验证：幽灵上限临时改 0 → 「离场幽灵数量对得上（50→31 幽灵=0）」当场红。
- 全量 `pnpm test` + `tsc --noEmit` 绿；原型自检 95/95。

## 遗留

- 移动端网格（`m-grid`）同源渲染，三件套一并生效；移动端的滚动惯性下 FLIP 是否够跟手，待真机观感再看。
