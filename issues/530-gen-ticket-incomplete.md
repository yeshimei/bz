# 530 · 补画脸谱的开工单报账不全（用户实测）

## 用户报的

截图（大琳，2026-09-30 22:12）：「开始生成脸谱」只写

```
为 1 位联系人生成脸谱
聊天记录   1 条
图片       2 张
「大琳」· 新增聊天记录 1 条 · 图片 2 张 · 增量提炼
```

用户原话：

> 补画脸谱，给的用户消息不准确。不是说有 1000 多条语音要走 LLM？这边也没有给用户完整的显示出来。
> 如果补画流程当中的任何数据的变动，数据源都要在这里显示清楚的。

诉求 = **开工单要当一张「这一趟会动什么」的账单**，不是「有几个素材」的计数。

## 二、开工单现在错在哪（三条根因）

### 1. 「录音」这个词指错了实体 —— 用户困惑的直接来源

- `render.ts:1721` 出「录音」行，`render.ts:1731` 逐人写「录音 N 条」；喂给它的 `info.voices` 来自
  `ui.ts:1573 ← GenTarget.pending ← ui.ts:1342 pendingMediaCounts(store.msgs)`。
- `datasource.ts:665`：`else if (m.type === 34) voices++` —— **type 34 是微信语音消息（语音条）**。
- 真正的「录音」（见面/通话，`rec:` 轮次、`recordings/` 目录、声纹分离+逐轮转写）是**另一条线**：
  `recording.ts` + `ui.ts:4529` 的补充素材页，**根本不在这趟补画流程里**（`jobs.ts` / `prep.ts` 全无 `recordings` 字样）。

→ 所以「录音 0 条」既可能表示"没有待转写语音条"，也可能被读成"没有录音待处理"。大琳两样都是 0，屏幕上直接整行消失，用户只能自己猜。

### 2. 只报「没做过的」，把「做了没校对」整类吞掉

- `datasource.ts:662`：`if (m.text !== '') continue;` —— 待办只认 `text === ''`。
- 校对的口径在 `prep.ts:371`：`text !== '' && proofread !== true`。

两个集合**不相交**：转写完成会立刻把 `text` 填上，于是「转写完成、校对未跑」的条目**既不属于待转写、也不存在于任何计数里**。大琳 1,289 条全部落在这个盲区。

### 3. 只报条数，不报「这一趟会改什么」

开工单现在只有三条数字，没有一行说明落库动作。用户要的是后者。

## 四、顺带查实的两件事

### 4.1 一个会真的漏跑的边界缺陷

`jobs.ts` 的 prep 段有两条**在 LLM 校对之前**的提前返回：

- `jobs.ts:1194`：零媒体 → `return 'skipped'`
- `jobs.ts:1199`：`if (!pending.images && !pending.voices) return 'skipped'`

而 LLM 校对在 `jobs.ts:1215`（`runJob` 侧是 `1696`），只在 `prepState === 'ok'` 时执行。

→ **某位联系人「0 张待描述图 + 0 条待转写语音」但 voice.json 压着一批没打校对标记时，prep 段判 skipped，校对整段不跑，开工单也不提。** 用户永远不会知道自己在欠账。

大琳这次不受影响（还有 2 张待描述图把 prep 段拽起来了），所以**点「开始生成」会真的跑那 1,289 条校对**——这正是问题所在：真跑了，开工单却没预告。

### 4.2 图片这条线的账对不上

开工单报「图片 2 张 待描述」，但盘上按 `image_desc.json` 算是 31 张没描述（1,616 − 1,564 − 21 张源图缺失）。

差额 29 张有两种可能，**需要解锁保险库后核实**：

1. 那 29 张被标了敏感终态（`descSkip`，ADR-0224 标注即终态，合法不出现在待办里）；
2. 描述跑了一半没并仓 —— 盘上已有描述、仓内 `text` 还是空。

若是第 2 种，那「待描述 2 张」就是**少报**，用户点开始后会比说的多做 29 张。

## 五、需要用户拍板

1. 「录音」是拆成两条线各报一行，还是合并成「音频素材（语音条 / 录音）」一行？
2. 校对这一行要不要报「约 81 批」？（issue 523 用户原话是不要讲 AI 通道与调用次数——但校对是唯一批量烧 token 的段，建议破例只在这一行报）
3. 校对开关关着时，那一行显示「已关，按原文并仓」还是直接不显示？
4. 数据源行要不要加「待办」徽标（P1-7）？

## 六、明确不动的

- issue 523 的「只报素材、不报 AI 通道 / 调用次数」总原则不回退；只在「待校对」这一行破例报批数。
- 不把「录音」线搬进补画流程（那是独立一条线，`recording.ts` + 补充素材页）。本条只做**说清楚它不在这里**。
