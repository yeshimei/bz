# 485 bz-face sync 只出统计——chat.json 挪到导入/画谱按需导出

## 背景（2026-09-27 用户拍板）

实测全量同步 5 分 21 秒（57 联系人 / 72,436 条），大头是导出段：每轮对全部有消息联系人
重读全量消息并重新序列化（字节比对在序列化之后，省不掉 CPU）。用户拍板：**同步不需要
chat.json，只需要统计数字**——全量消息在导入/画谱时对选中的人按需导出。

## 方案

### 工具侧（tools/obsidian-face/python/bz_sync.py）

1. **sync 变轻**：解密（已是秒级增量）后只做逐联系人统计——消息数 / 语音数 / 图片数 /
   语音时长 / 最新消息时间（SQL 聚合，无人读消息正文），写 `<联系人>/stats.json`
   （原子写、字节比对幂等）。**不再产出 chat.json**。
2. **新增按需导出**：`bz-face export --data-root … --contact <名>`（可多值）——对指定联系人
   走现有 export_flow 全量导出 chat.json + 头像。供插件在「导入所选 / 画脸谱」时调用。
3. `[bz-result]` 口径适配：stats 轮上报统计数；export 轮沿用 written/unchanged/failed。

### 插件侧（src/people）

4. **datasource 扫描**：优先读 `stats.json`（旧数据根回落读 chat.json，兼容存量）；
   水位/预览数口径不变。
5. **导入所选**：勾选后先对选中者逐个调 `bz-face export --contact`（进度行显示当前联系人），
   完成后按现有 normalizeChatJson → mergeStore 落保库记录。
6. **画脸谱**：数据源路径在导入段已带出 chat.json，不重复导出；详情页单人补画同 5。

## 验收

- 无新消息的日常同步进入 **十秒级**（解密秒过 + 3835 人统计聚合秒级）。
- 导入所选只对勾选者出全量导出，单人（大琳 2 万条量级）不超 5 秒。
- 既有 sync 测试口径更新 + 新增 stats/export 测试；四行协议不变。
