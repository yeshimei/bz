# 512 · 脸谱录音 sidecar 命名口径错位：插件永远读不到账本（并仓通道失灵）

来源：issue 511 部署后用户实测复测（2026-09-29）——录音仍显示「待处理」、点处理仍「启动模型一会儿消失」。截图取证：done/508 轮的账本在盘，UI 却是「待处理」。

## 根因（实锤）

- 脚本落账：`bz_rec.py:390` `out_json = os.path.splitext(src)[0] + ".turns.json"` —— **剥扩展名**，磁盘真实文件 `大琳 周六 10点14分✔️.turns.json`。
- 插件找账本：`recordingSidecarPath` 拼 `<file>.turns.json` —— **不剥**，找的是 `…✔️.aac.turns.json`（Node 实测 existsSync=false）。
- 命名口径错位从 509 收编起就存在，此前 sidecar 从未成功落过 done 账（funasr 缺失等环境问题挡在前面），今天第一次有完整账本才显形。

## 失灵面（全部同根）

1. 条目状态机读不到账本 → 恒「待处理」（pending），处理按钮永远在。
2. 起跑预检读到 null → 恒放行 → 对已完整账本反复 spawn → 脚本幂等秒退 → 「启动模型一会儿消失」。
3. 进度轮询读到 null → 阶段/百分比/文案全不显（511 的进度增强也全部落空）。
4. **并仓通道失灵**：`suppMergeRecording` 读 null 静默返回——508 轮从未进聊天仓，且无任何提示。

## 修复

- `recordingSidecarPath` 剥最后一段扩展名再拼 `.turns.json`（对齐 `os.path.splitext` 口径）；无扩展名原样保留，多点文件名只剥最后一段。
- control 文件（`<file>.control.json`）与质心 npz（`<联系人>.npz`）核对过口径一致，不动。
- `bz-face status` 按目录列 `.turns.json` 后缀（不拼路径），天然兼容实际文件，不动。
- 存量账本即脚本口径，插件对齐后即刻可读，无迁移。
- 测试：路径断言改剥扩展名口径 + 补空格/emoji 导出名、多点文件名、无扩展名三档边界。

## 验收

1. 对大琳那条录音：UI 显示「待并仓」（不再是「待处理」），点「并仓」成功并入 508 轮。
2. 对已并仓录音点「处理」：弹「已转写完成（508 轮）」提示，不起进程。
3. 门禁全绿。
