## 一、用户评审四改（UI）

1. **关闭钮收小**：38px → **28px**（图标 20 → 16，圆角 10 → 9），与头行品牌块
   28×28 同尺寸、头行两端等重。命中区由 `.bz-touch-target--lg`（`-8px`）保住 44px。
2. **平铺场景也风格化**：`.bz-mobstrip-chip` 此前吃组件库基线（1px 淡边 + 品牌橙底圆胶囊），
   与两套皮肤语汇都不搭。现按皮肤换装：
   - 纸感：白底 + 1.5px 墨框 + 深墨字；选中 = 品牌橙底 + 墨框 + `2px 2px 0` 硬阴影 + 奶白字；
   - 编辑部：白底 + 1px 墨框 + 方角 3px + 字距；选中 = 黑底白字。
   - **顺序陷阱**：虚线「添加场景」规则必须排在通用 chip 段**之后**——两者同特异性
     `(0,2,0)`，靠「后写者赢」，写在前面会被实框白底规则吃掉虚线。已加断言锁顺序。
3. **选中场景后点「添加」→ 弹窗预选该场景**：`openEditor` 新增 `opts.presetScene`
   （合法才认；伪场景回落 `memoDefaultScene` → 第一个），与桌面 composer 的
   `composerScene()` 同口径；剪藏/代码/公开课的场景联动一并生效。
4. **顶区 44px 避让带也要有头行斜纹**：核心层 `.bz-panel-mtop` 把
   `padding-top: max(44px, 安全区)` 挂在**面板根**上，头行斜纹只盖自己那 44px，
   顶上露出纸面点阵 → 斜纹看着「被截断」。改为垫顶挪进**头行自身**，
   头行 `height: auto` + `min-height: calc(44px + max(44px, env(safe-area-inset-top)))`
   （全局 `*{box-sizing:border-box}`，故内容行仍 44px，顶区总高 44+44 = 88px 与改动前一致）。
   - **特异性约束**：核心层反制规则是 `.bz-panel-mtop > div:first-child{padding-top:0}`
     ——`:first-child` 算**类级** → `(0,2,1)`。本域只写 `(0,2,0)` 会被它压掉、垫顶归零、
     内容顶到状态栏底下（实测症状）。故选择器必须写成
     **`.bz-memo-panel.bz-panel-mtop .bz-panel-head`（0,3,0）**，并在守卫里写死这条约束。

## 二、切换类缺陷三修（本票的真正价值）

用户反馈「点击皮肤切换，移动端没有切换」。排查出**三层独立缺陷**，逐层修复：

### A. 皮肤钮标签与判定方向写反 → 点按永远不动

旧实现（`prototypes/memo/prototype.html`）：

```js
const next = skinBtn.textContent.includes('编辑部') ? 'paper' : 'editorial';
```

而标签初始就是「皮肤→**编辑部**」，判定串与标签同形 → `next` 恒为 `paper`；
初始已是 `paper`，于是**点多少下都不变**。

修复：判定改读**当前皮肤真值**（`skinState()`），标签改回显**当前**值
（「皮肤：纸感手账 / 编辑部」），并把切换收敛到行为层 `toggleSkin()`。

### B. 只驱动桌面实例 → 双 iframe 下移动端不跟随

评审壳是**双 iframe**（桌面 920 / 移动 412×915），**每个 iframe 各加载一份行为包**
= 两个互不相识的模块实例，`demoSettings` 是各自的**内存副本**。壳上按钮只调
桌面那一份，移动那份停留初值 → 「桌面变了，移动没变」。

修复两层：

1. **壳侧**：外观类按钮（皮肤/布局）改为**对两个 iframe 同时下发**，且按**绝对值**
   下发（先算 next，再把同一个 next 调两侧 setter）——不做「两侧各自 toggle」，
   那两个实例一旦状态不一致就会各转各的、越切越偏。
   （注：数据类钩子只驱动桌面实例即可——数据落 localStorage，移动侧重开面板即读到同一份；
   外观是**内存态**，必须逐实例下发。）
2. **行为层侧**：皮肤/布局这类外观选择**落 localStorage**（键 `bz-sim:demo-settings`，
   `fake-sim.ts` 的 `loadSharedSettings`/`saveSharedSettings`），两个实例 boot 时读同一份
   → 谁改都一致，刷新（SSE 热重载＝整页 reload）也不丢。`applySkin` 改为返回归一后的值，
   供壳按返回值回显（曾因返回 `void` 而回显切换前的值）。

壳上「重置演示数据」一并清该键（否则重置后仍停在上一轮皮肤，与按钮语义不符）。

### C. `file-sync` 删除分支只清一半引用（**生产代码缺陷**）

`syncDelete` 此前只清 `linkedNote`，**但当前域从不写非空 `linkedNote`**
（`addFromComposer` / `openEditor` 一律置 `null`，见 `src/memo/ui.ts`），
真正在用的是 `notePath`（编辑器「定位到笔记」写入）。后果：删掉被引用的笔记后，
条目仍留着指向**不存在文件**的 `notePath` → 卡片 meta 继续渲染「位置」tag
（`render.ts` 的 `data-memo-pos`），点它 = `jumpToNote` 跳一个已删文件。

而 **`syncRename` 本就同步改写 `notePath`** ——同一文件两个分支口径不对称，
属实现遗漏（非设计取舍）。修复：`syncDelete` 同时清 `notePath` / `notePosition`，
并补 2 条单测（清空效果 + 无引用命中时 `changed` 恒 false 不写盘）。

守卫：`tests/memo/file-sync.test.ts` 5 → 7 用例。

## 三、评审壳徽牌调整

按用户要求撤下三枚**手动演示钮**（被动捕获 / 笔记改名 / 笔记删除）——
三面的真链路（`reminder.ts` / `file-sync.ts`）**未删**，触发口收敛到 `?selftest=1` 自检，
覆盖率不减。徽牌新增**布局钮**：可切布局清单**读域设置 schema 的「面板布局」行**
（`memoSettingsSchema`，单源）——`layouts/<x>/` 落地后只需给那行加一张卡，按钮自动可切，
壳内不写死任何布局名。现状该行只有 `default`「清单」（唯一实现），故标注「仅一套」、
点按不变（`memoLayout` 目前尚无消费方）。

自检补守卫：三枚演示钮已撤、布局钮在场、皮肤钮**两端**分别可切 + 标签回显切换后的值 +
再点能切回。

## 四、已知遗留（本票不修，另开）

原型壳自检有 4 项长期红：`改名演示派发成功` / `改名改写 3 条引用` /
`删除演示派发成功` / `打开笔记提醒定位`。根因是**评审脚手架**的种子缺口——
演示数据引用的笔记（`笔记/项目规划.md`、`课程/数据分析实战.md`）未写入假 vault，
且路径不在 `file-sync` 监听目录（`SYNC_WATCHED_FOLDERS = 卡片盒,归档/网页剪藏`）内，
「打开笔记提醒」那条的关联条目也缺 due/importance。属演示数据配置问题，
**不是产品缺陷**，既往版本同在；本票只记录，不改演示数据（避免混入无关改动）。
