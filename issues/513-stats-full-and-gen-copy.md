# 513 · 互动统计卡统计全量 + 开工单说明口径修正与排版

来源：用户实测（2026-09-29，issue 512 并仓恢复后）——①统计页「消息形态」没有「录音」项；②开工单写「约 81 次调用」但实际幂等跳过已完成部分，说明与事实不符且一大段文字堆在一起。用户拍板：统计页应统计全部；说明写正确、排版简洁明了。

## 根因

1. **统计卡数据源是导入快照**：`buildInsightsCard` 用 `p.imports` 最近一次导入记录的冻结 `stats.kindCounts`——录音轮次走并仓通道（不产生导入记录），永远进不了那张卡。数据层的 store.kindCounts 是实时的（并仓时增量维护），只是没接到卡上。
2. **开工单数字是满额口径**：`describeCalls`（图片/每批）与 `voices` 按全量估算；引擎的 prep / describe / 转写各段幂等（产物在即跳过），实际调用量通常远小于满额。文案未表达幂等语义，读起来像「全部重烧」。排版上总览是一整段 `join('；')` 长句。

## 改动

**统计卡（ui.ts）**
- 打开「互动统计」时异步读保库 `store.kindCounts` 存模块缓存（读不到 / 上锁回落快照，不劣化）；`buildInsightsCard(p, liveKinds?)` 形态行与卡头总条数优先用实时全量。
- 其余行（谁主动 / 回复时延 / 活跃时段 / 月度图）保留导入快照口径——导入历史语义不变。

**开工单（types.ts / ui.ts / render.ts / styles.css）**
- `GenTarget` / `GenerationConfirmItem` 带出提炼模式（full / newer / older——planTargets 里 plan.mode 已算好，此前丢弃）：older 逐人行追加「补录合并重画」标识，让「素材 17277 条」不再像无解释的全量重烧。
- 总览从长句改行式清单：联系人 / 图片描述（已完成的自动跳过 · 至多 N 次调用，每批 N 张）/ 语音转写（本地离线 · 已转写的自动跳过）/ 画像生成（通道 · 约 N 次调用）四行，零图片 / 零语音自动省行。
- 尾注保留（自动完成全部步骤 · 中途不再询问 · 可暂停）。

**测试**
- describe-ui.test.ts 文案契约随排版更新（行式断言 + 幂等措辞 + 补录标识）。
- 统计卡实时形态回落语义补用例。

## 验收

1. 大琳统计页「消息形态」出现「录音 486」，卡头总量含录音（2.1 万级）。
2. 开工单不再出现「约 81 次调用」的全量误导措辞；补录时逐人可见「补录合并重画」。
3. 门禁全绿。
