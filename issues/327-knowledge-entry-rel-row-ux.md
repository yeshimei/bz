# 327 · 知识盒录入关联行：确认写入不回退 + 分析不锁按钮 + 中断/后台两条分支

- 状态：已交付（2026-09-15，门禁全绿后合并部署；主构建产物已提交）
- 关联：issue 309（关联行与预演）、issue 326（同面板关闭确认与生成后开笔记）、ADR-0141（关联引擎与范围）

## 用户原话拆解

1. 「点击确认写入，不要动关联，不回退」——326 之前确认写入会把关联行设回 loading（写入阶段复用
   「分析中」视觉），看起来像在重新分析，实际只是本地写 frontmatter。改为：确认写入**全程不动关联行**。
2. 「关联分析中不锁定重新生成，总结和确认写入」——拆除 setEntryRelBusy 整套按钮闸门。
3. 「点了总结和重新生成，就中断 ai 调用，等新的内容返回，再进行分析」——在途预演要**真中断**
   （AbortSignal 从 UI 一路穿到 AI.ask），点下按钮即断；新内容回来后再起新一轮预演。
4. 「点了确认写入，那就在后台进行分析，挂一个动态通知」——分析中确认写入：面板照常关、笔记照常开，
   在途的这次作废（省 token），后台重起一轮 预演→apply，用同键动态通知（progress→结果原地更新）。

## 设计

- **signal 穿透**：`LinkBridge.preview(content, title?, opts?: { signal })` → `previewLinks(opts)` →
  `AI.ask(prompt, { signal })`（core/ai 本就支持取消）。面板侧 `entryRelAbort` 控制器：
  - 新一轮预演起跑前先 abort 上一轮（重生成 / 总结都会再起预演）；
  - `resetEntryRel`（关面板 / 换图 / 改输入作废草稿）也 abort；
  - 重新生成 / 总结 / 图版重读的入口处先 `resetEntryRel()`——点下即断，行归「—」。
- **确认写入分支**（行全程不动）：
  - 预演 done 有 picks → `apply` 落库（本来就地显示过的结果原样写进 related）；
  - 预演 done 无 picks（「无关联」结论）→ 无可写，直接过；
  - 预演仍在分析 → 作废面板绑定的一次，后台重起 预演→apply，挂动态通知；
  - 预演 failed → 兜底 now 也转后台（同款通知）；
  - 通道未接线 / off → 无可写，直接过。
- **动态通知**：`notify` 同键（`bz-kb-entry-rel`）原地更新——起跑「知识盒关联：后台分析中…」（progress）→
  落地换「已写入 N 条关联 / 未发现实质关联 / 向量服务不可达已入队 / 失败原因」。
- **拆除按钮闸门**：`setEntryRelBusy` 方法与全部调用点退役（生成 / 总结各自的 termGenerating /
  termSummarizing 锁保留——那是操作自身的忙态，不是关联的）。

## 测试面

- 改写两处锁断言：分析中三按钮可用；分析落地仍可用；换图作废在途后按钮态不再有「闸门」概念。
- 新增：重新生成/总结在分析中点下 → preview 收到 aborted signal；确认写入在分析中 → 面板立关 +
  后台通知 + 预演落地后 apply 被调；确认写入（预演 done）→ apply 调用且关联行文本不被改写。
