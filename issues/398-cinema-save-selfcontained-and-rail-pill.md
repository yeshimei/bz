## 一、保存即齐：海报落库 + 不入队 + 无通知

395 之后「解析」已把豆瓣字段写进笔记属性，但**海报只拿到远程 URL**（不下载）→ 建档后仍入队后台抓取补海报，于是卡片转 loading、抓完再弹通知。

现在保存时直接下载海报落库（vault 相对路径 + 正文 embed 与抓取路径**同款**），建档即「齐」→ 不入队、无 loading、无通知。**只有真没落成**（没解析 / 没网 / 写盘失败）才回退老路径交队列补齐（兜底通知保留：那时它是唯一能让用户知道海报还没来的渠道）。

## 二、滑动高亮：侧栏（跨类型 / 状态 / 底部工具）+ 排序钮

底面一片 `.slide-pill`（绝对定位），位置与尺寸按目标项矩形驱动：

- **悬停跟随**：鼠标落到哪一项，底片滑到哪一项——侧栏三段通吃（类型组 → 状态组 → 底部 AI 荐片 / 观影分析）；
- **离开回落**：鼠标离开容器 → 滑回当前选中项（ai/stat 页无选中态则隐去）；
- **点击固定**：选中项由渲染结果决定，渲染后**按键重新解析**（悬停中的项重渲染后仍按同一键锁定）；
- 排序钮（最近观看 / 加入先后 / 按评分）同款：底片就是原来那枚选中的白片。

关键口径：

- 底片与监听挂**容器**（`.d-rail` / `.j-sort`）上，不进会被 `innerHTML` 冲掉的子树——侧栏三段与排序钮每渲染都重写，挂项里会被一起冲掉；
- 项的底色改由底片承载（`.rail-item.is-on` 与 `:hover` 不再自绘背景），项本体 `position:relative` 压在底片之上；
- 绑定必须**先于**落位早退执行：首帧没有几何（测试环境 / 尚未布局）就早退的话监听永远绑不上（单测第一版就踩了，见下）；
- 悬停只在有悬浮能力的设备上接（呈报#9 F4 范式）；滚动（侧栏 `.rail-sec` 可滚）即时落位不演滑行；滚出可视区的项不画底片（底片挂 `.d-rail`，不受 `.rail-sec` 裁剪）；
- 零改动偏好：两套皮的既有观感保留（午夜场 `--chip`、booth `--room` + 左侧琥珀条；排序钮 `--panel` / `--chalk`）。

## 遗留

- 评审壳的海报是 **240px 缩图存 data URL**（localStorage 配额所限）：真机没有这步，原型里海报会比真机糊一点。重置演示数据会清掉。
- 合集/详情等其它入口的海报仍走老路径（只覆盖「添加影视」保存这一条，按用户口径）。
- 排序钮底片在「切换视图（list → ai → stat）」时不重定位（排序钮随视图一起消失），回到列表页时按选中项落位。
