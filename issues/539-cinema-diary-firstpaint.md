# 539 · 影院与日记本打开卡顿：首屏改「先绘壳 + 窗口化渲染 + 后台分片让出」

## 症状

两个域都是「笔记最多」的域，打开面板时全量加载，有明显的卡顿：

- **影院**：打开后有一段肉眼可感的停顿，期间面板是死的（点不动、打不了字）。
  筛选 / 搜索 / 排序同样要整刷一遍。
- **日记本**：打开后要等较久才出书；期间书桌是空壳，出书那一瞬间还会再顿一次。

## 根因（实测，非推测）

**影院是「同步链」问题，不是数据量问题。**
`createOverlay` 挂上空壳后，**同一个 tick 内**同步跑完：

| 步骤 | 位置 | 成本 |
|---|---|---|
| `rebuildItems` | `src/cinema/ui.ts:2625` | `getMarkdownFiles()` 前缀过滤 + **820 次** `metadataCache.getFileCache` 同步解析 |
| `renderAll` | `src/cinema/ui.ts:2626` | **820 张卡** HTML 拼串 + 整写 `.grid` 的 `innerHTML` |

全链路零 `await` ⇒ 浏览器**从未得到绘制空壳的机会**，首帧 = 全部工作做完。

**日记本是「读盘 + 全量测量」问题。**

| 步骤 | 位置 | 成本 |
|---|---|---|
| 日记正文读盘 | `src/diary/data.ts:237` `vault.read` | **1243 篇**（磁盘读，非缓存） |
| 读盘并发 | `src/diary/data.ts:94` `READ_BATCH_SIZE = 10` | **125 个串行批次** |
| 信正文读盘 | `src/diary/parser.ts:191` `vault.read` | 15 篇 |
| 全量离线测高 + 切页 | `src/diary/ui.ts:589-595` | 全部条目的块流一次 reflow 测量 + 二分切段 |
| 建书 | `src/diary/ui.ts:689` `buildBook` | StPageFlip 全量页注入 |

真实 vault（`E:\Obsidian\叫我包仔`）规模：

| 目录 | .md 数 |
|---|---|
| `我的/影视` | 820（带 `影评` 进墙 156） |
| `我的/日记` | 1243（23 年 190 / 24 年 285 / 25 年 301 / 26 年 467） |
| `我的/信` | 15 |
| `书库` | 72（带 `bookReview` 进墙 29） |

## 方案（ADR-0231）

1. **扫描保持同步、只把渲染收进窗口**：量过账——820 次 `getFileCache` 是纯内存查表（`parseMovieFile`
   只吃 frontmatter，不读正文），几十毫秒量级；病根是 `renderAll` 一次拼 820 张卡 HTML 再整写 DOM。
   所以 `createOverlay` 里 `rebuildItems + renderAll` 仍**同步**（同步语义是既有契约），改动落在
   **渲染窗口**：首屏只渲 `FIRST_PAINT_CARDS` 张卡，其余交空闲追加。
2. **首屏数量按各域版式定**（不与批粒度共用）：
   - 影院 `FIRST_PAINT_CARDS = 20`——桌面 5 列 / 移动 3 列，卡片 `aspect-ratio: 2/3` 随面板
     等比缩放 ⇒ 可视区恒约 2 行；20 张 = 5 列 × 4 行 ≈ 两屏。
   - 日记本 `FIRST_PAINT_ENTRIES = 30`——书页 520×700、正文可用高 546 px，一个跨页约 6 则；
     30 则 ≈ 5 个跨页 ≈ 最近半个月。
   - 后台批粒度统一 50（`src/core/paging.ts` `LIST_BATCH_SIZE`）。
3. **计数一律按全量**，窗口只决定渲染/排版多少。
4. **后台不阻塞**：影院空闲时每批 50 张追加到 `.grid` 尾部（不走 `renderAll`）；日记本后台把正文
   读进内存时**不重排**（进度回调不碰书页），读盘结束后由 `widenFull()` 在后台自动续排到
   `min(全量, WIDEN_CAP = 120)`（封顶口径见回修记录「2026-10-03 封顶回修」）。
5. **交互即让路**：批间 `await yieldToMainThread()`；打字（400ms）/ 滚动（220ms）期间暂停推进，
   静默后自续。影院作废靠 `appendSeq` 编号（`renderAll` / `closeOverlay` 各递增一次）。
6. **日记本窗口化 + 页索引锁定**：`relayout` 只吃窗口（`shown`），计数类按全量。窗口的推宽有两条：
   **主路**——读盘结束后 `widenFull()` 在后台自动续排（目标 `min(全量, WIDEN_CAP)`；2026-10-03 回修，见下）；
   **兜底**——`extendIfAtTail` 翻到书尾推宽一批 / `revealEntry` 点窗口外目标按需推宽，
   两条都走 `relayout(false, true)` 的 `keepPage` 钉住页索引。
   **「书尾」不是 `pages.length - 1`**：StPageFlip 跨页模式的 `flip` 给的是**当前跨页左页号**，
   偶数页数时最后一跨是 `[n-2, n-1]` ⇒ 止于 `n-2`。判据抽为纯函数 `lastReachableCursor()`
   （`src/diary/ui.ts`）；奇数页数为 `n-1`，单页模式恒 `n-1`。
   **续叠是整窗重排**（不是「只测新增」）——成本以窗口为界；窗口已全量后该判据恒假 ⇒ 一次不触发。
7. **日记本读盘换 `cachedRead`**（官方口径：只展示用 `cachedRead`），并发 10 → 50；批间让出。
   **写后回刷路径仍用 `read` + `invalidateWallCache` 回源**（`cachedRead` 在外部改动→通知之间有
   陈旧窗口）。
8. **冷启动守卫**：首次渲染**之前**判定（`items` 空 + 目录有 .md ⇒ metadataCache 未就绪），
   落骨架页；等 `onLayoutReady` / 一次性 `resolved`（配 1500ms 超时）后重扫。
9. **`content-visibility: auto` + `contain-intrinsic-size: auto`** 跳过屏外卡片的 layout/paint
   （只做影院；日记本靠离屏测高切页，加了会量错）。
10. **首开出骨架页**，不再误闪「影片空空如也」。

## 验收口径（可单测）

1. 影院首屏 DOM 卡片数 = `FIRST_PAINT_CARDS`（20），且 `M.items` 已是全量；
2. 影院空闲追加后卡片数 = 全量；侧栏「全部」计数不受窗口影响；
3. 影院视图身份一变（筛选/搜索/排序）→ 窗口收回首屏值；
4. 日记本首屏**排成纸页**的条目数 = `FIRST_PAINT_ENTRIES`（30），而 `entries` 已读全量；
   后台读盘**进度回调不触发** `relayout` / `buildBook`（读盘结束后那一次后台续排不算进度回调）；
5. 日记本读盘结束后**后台自动续排到 `min(全量, WIDEN_CAP = 120)`**（不必等用户去点）；
   封顶以内点窗口外的月份 / 台历跳日 / 检索命中都只是一次 `turnToPage`，**不重建整本书**；
   超过封顶的目标走按需推宽（只顿那一下）；后台续排落地前就翻到书尾时，兜底续叠照旧生效；
   重开册子窗口复位回首屏值（再在后台续排）；**偶数页数的书尾是 `n-2`**（跨页左页号），停在那里也必须续叠；
6. 冷启动（metadataCache 未就绪）出骨架页而非空态页，就绪后重扫出卡；真空库仍出空态页。

## 回修记录

- **2026-10-02 · 日记本「翻到 50 之后就没内容了」**（验收 5 的失效）：书尾判据原写成
  `cursor < pages.length - 1`，偶数页数下跨页左页号止于 `n-2`，条件恒成立、续叠不触发。
  30 则窗口的测试夹具实际排出 **59 页（奇数）**，旧判据在里面碰巧成立 ⇒ 夹具测不出这条。
  修法 + 成套测试见 ADR-0231「回修」段。

- **2026-10-03 · 索引 / 检索 / 台历吃「已加载全量」**（用户报「会导致索引和搜索失真」）：
  三处都在读**排版窗口**而不是**已加载全量**——① 册页索引拿书页汇月份 ⇒ 窗口外的月整行消失，
  表头「凡 N 则」是全量、「M 个月」是窗口；② 检索遍历 `this.pages` ⇒ 搜老词假称「整本册子都翻了，
  没有这个词」；③ 台历跳日扫 `this.pages` ⇒ 标着「那天有 N 则」却说「那天没落笔」。
  另修同族一处：台历「当天几则」读未过滤的 `this.entries`，筛选态下角标与跳日互相打脸。
  改法 = 口径全部抬到 `visibleEntries()`（已加载全量），窗口外的目标用共用原语
  `revealEntry(eid)`「按需推宽再跳」；索引行分「第 N 页」/「未展开」两种（页码只有排过版才知道）。
  **影院不动**：`getDisplayItems()` 本就吃全量 `M.items`，计数与搜索命中集不受渲染窗口影响。
  详见 ADR-0231 决策 12 与其「回修」段。
- **同日 · 评审跟进（三条 P2）**：① `nextHit` 跨窗跳转后把检索态续回（`relayout` 会把
  `this.search` 换成空态，不续回则将来接「下一处」入口会从第 2 条起就断）；② 检索命中若真落不到
  页上，改为与索引行同口径地说一句「这一则翻不到页上」，不再静默；③ 修正用例夹具注释里
  「窗口恰是整个 3 月」的差一天（`seedManyEntries(90)` 的窗口实为 3/31…3/2）。

- **2026-10-03 · 点日期转跳卡顿很久**（用户报「难道会把之前所有页面都渲染了？」——判断正确）：
  点窗口外任一日期走 `widenToCover(idx)` → `shown = idx+1` → `relayout(false, true)`，这是**同步
  整窗重排**（建块流 → reflow 量高 → `paginateFlow` → 重建 StPageFlip）。首屏窗口只排 30 则、
  本子上千则 ⇒ 窗外的老日期几乎都在窗口远处，**一次跳转的成本 ≈ 排全量**，且每次点都付。
  修法（用户拍板「首批加载渲染后，不阻塞把后续的都渲染出来」）：读盘结束后 `widenFull()` 在后台
  自动续排（建块流分片让出主线程；量高 + 切页 + 建书原子，因为 StPageFlip 没有
  `addPage`），`keepPage` 钉住读者当前页；`sceneQuiet()` 不静就过一拍再来。此后所有跳转只剩一次
  `turnToPage`。
  顺带修掉一个真缺陷：拆封动效那 620ms 里若后台续排落地，会重建书、把信封元素换掉 ⇒ 拆信中断、
  全文放不出来（`sceneQuiet()` 因此增加「有 `.bz-diary-opening` 在飞即不静」）。
  顺带消掉一处浪费：窗口全量后 `extendIfAtTail` 恒假 ⇒ 翻到书尾不再每批重建整本书。**影院不动。**
  详见 ADR-0231「回修」段（2026-10-03）。

- **2026-10-03 · 翻页卡顿回修：后台续排封顶 `WIDEN_CAP = 120` + 可缩媒体块（图一）**：
  上一条「排到全量」在真机上被判为**堵塞**（用户原话「我说了不阻塞，然后实际情况是堵塞的，用户
  打开界面翻页会卡顿很久」）。两笔账漏了：① 尾段（量高 + 切页 + 建书）是原子的 O(窗口)，推到全量
  就是一次长冻结；② **书页数 = 每一次翻页的成本**——vendored StPageFlip 的 `drawFrame()` 每帧
  遍历全部页元素写 `display:none`，几百页 × 每次约 23 帧 ⇒ 每次翻页都钝（这条才是主因）。
  修法：`WIDEN_CAP = 120`（删 `WIDEN_FULL_MAX`），目标改 `min(all.length, WIDEN_CAP)`；
  `setScope` 仍喂全量 ⇒ 索引/检索/灯箱口径不受影响；封顶外退回 `widenToCover` 按需推宽。
  **真正的解法（已挂号，未做）**：把书做成视窗——只渲染当前跨页附近的纸页，总页数由「块高缓存 +
  预估高度 + 占位」撑出来（社区不定高虚拟列表口径 / Obsidian 编辑器「视窗」同思路）。
  同一提交还修了**图一**（照片放不下就整块跳下页 ⇒ 页尾大片留白）：用户拍板「按比例缩到塞得下
  （有下限）」——`paginateFlow` 新增规则 3a 与 `shrink` 形参，`layoutBook` 传 `fitMedia`
  （缩块宽 `--bz-diary-ph-w`，下限 `MEDIA_FIT_MIN_RATIO = 0.6`）。详见 ADR-0231 末条回修。

## 验收口径（可单测）补充

- **索引/检索/台历按已加载全量认账**：书只排了首屏那 30 则时，册页索引仍列出全部月份
  （窗口内的月印「第 N 页」，窗口外的月印「未展开」）；检索能命中窗口外那一则；
  台历能跳到窗口外那天。点中窗口外的目标 → 排版窗口按需推宽到盖住它（正常轮不到这一步：
  读盘结束后后台已续排到 `min(全量, WIDEN_CAP)`，封顶以内即全量）。
- **后台续排不换血**：把读者停在非首页，等后台续排落地——`shown` 涨到 `min(全量, WIDEN_CAP)`、页数变多，
  但读者的页索引不动；且此后点窗口外的月份 `flipRecords` 不增（没重建书）。

## 已知代价

1. 日记光箱「下一张 / 上一张」只在**已加载**条目内轮转（窗口外未上屏时不在轮转序列里）；
2. 读盘结束后有一次**后台整窗重排**（建块流分片让出主线程；量高 + 切页 + 重建 StPageFlip
   因为库无 `addPage` 而必须原子）——这是把「点一下卡一下」换成「开册后台排一次」的代价。
   书尾续叠（兜底）同样是整窗重排，但成本 O(窗口) 且只在用户主动翻到书尾时发生；
3. 影院的后台刷新（vault 事件 / 豆瓣逐部落盘）仍走同步扫描——纯内存、几十毫秒量级；
   若条目量涨到扫描进秒级，再考虑分片让出。

## 本次不做

- 虚拟滚动（`Clusterize.js` / `@tanstack/react-virtual`）——820/1443 规模属过度工程；
- 「轻元数据全量索引」（日历标记 / `getYearRange` 改由文件名 + frontmatter 全量推算）——
  **索引/检索的数据源已抬到「已加载全量」（见回修记录第二条）**，但没做「不读正文就算出月份」
  这一层：所以它们仍随后台读盘逐步变准，过渡窗口 = 后台读盘期；要消掉这个过渡窗口另立 issue。
- 「下一处命中」入口——检索命中集按 eid 存、`nextHit` 也留着轮转计数，但界面上没有推进它的动作
  （改动前就只跳第一条命中）。本次只收掉「跨窗跳转会把检索态冲掉」这处耦合，**新增交互入口属产品决定**。
- 「按条目 id 缓存块高」（只测新增块、不重跑 `paginateFlow`）——能把书尾续叠与超过
  `WIDEN_CAP` 时的按需推宽也压成常数级；两处都已是低频兜底，收益不足以现在动排版尾段。
  （**视窗化的书**是另一件事，已挂号：只渲染当前跨页附近的纸页，总页数靠块高缓存 + 预估 + 占位撑出来。）
