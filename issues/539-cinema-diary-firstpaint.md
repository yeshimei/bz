# 539 · 影院与日记本打开卡顿：首屏改「先绘壳 + 窗口化渲染 + 后台分片让出」

## 症状

两个域都是「笔记最多」的域，打开面板时全量加载，有明显的卡顿：

- **影院**：打开后有一段肉眼可感的停顿，期间面板是死的（点不动、打不了字）。
  筛选 / 搜索 / 排序同样要整刷一遍。
- **日记本**：打开后要等较久才出书；期间书桌是空壳，出书那一瞬间还会再顿一次。

## 根因（实测，非推测）

**影院是「同步链」问题，不是数据量问题。**
`createOverlay` 挂上空壳后，**同一个 tick 内**同步跑完：

| 步骤 | 位置 | 成本 |
|---|---|---|
| `rebuildItems` | `src/cinema/ui.ts:2625` | `getMarkdownFiles()` 前缀过滤 + **820 次** `metadataCache.getFileCache` 同步解析 |
| `renderAll` | `src/cinema/ui.ts:2626` | **820 张卡** HTML 拼串 + 整写 `.grid` 的 `innerHTML` |

全链路零 `await` ⇒ 浏览器**从未得到绘制空壳的机会**，首帧 = 全部工作做完。

**日记本是「读盘 + 全量测量」问题。**

| 步骤 | 位置 | 成本 |
|---|---|---|
| 日记正文读盘 | `src/diary/data.ts:237` `vault.read` | **1243 篇**（磁盘读，非缓存） |
| 读盘并发 | `src/diary/data.ts:94` `READ_BATCH_SIZE = 10` | **125 个串行批次** |
| 信正文读盘 | `src/diary/parser.ts:191` `vault.read` | 15 篇 |
| 全量离线测高 + 切页 | `src/diary/ui.ts:589-595` | 全部条目的块流一次 reflow 测量 + 二分切段 |
| 建书 | `src/diary/ui.ts:689` `buildBook` | StPageFlip 全量页注入 |

真实 vault（`E:\Obsidian\叫我包仔`）规模：

| 目录 | .md 数 |
|---|---|
| `我的/影视` | 820（带 `影评` 进墙 156） |
| `我的/日记` | 1243（23 年 190 / 24 年 285 / 25 年 301 / 26 年 467） |
| `我的/信` | 15 |
| `书库` | 72（带 `bookReview` 进墙 29） |

## 方案（ADR-0231）

1. **扫描保持同步、只把渲染收进窗口**：量过账——820 次 `getFileCache` 是纯内存查表（`parseMovieFile`
   只吃 frontmatter，不读正文），几十毫秒量级；病根是 `renderAll` 一次拼 820 张卡 HTML 再整写 DOM。
   所以 `createOverlay` 里 `rebuildItems + renderAll` 仍**同步**（同步语义是既有契约），改动落在
   **渲染窗口**：首屏只渲 `FIRST_PAINT_CARDS` 张卡，其余交空闲追加。
2. **首屏数量按各域版式定**（不与批粒度共用）：
   - 影院 `FIRST_PAINT_CARDS = 20`——桌面 5 列 / 移动 3 列，卡片 `aspect-ratio: 2/3` 随面板
     等比缩放 ⇒ 可视区恒约 2 行；20 张 = 5 列 × 4 行 ≈ 两屏。
   - 日记本 `FIRST_PAINT_ENTRIES = 30`——书页 520×700、正文可用高 546 px，一个跨页约 6 则；
     30 则 ≈ 5 个跨页 ≈ 最近半个月。
   - 后台批粒度统一 50（`src/core/paging.ts` `LIST_BATCH_SIZE`）。
3. **计数一律按全量**，窗口只决定渲染/排版多少。
4. **后台不阻塞**：影院空闲时每批 50 张追加到 `.grid` 尾部（不走 `renderAll`）；日记本后台把正文
   读进内存后**不重排**——直到用户翻到书尾才整窗续叠一批。
5. **交互即让路**：批间 `await yieldToMainThread()`；打字（400ms）/ 滚动（220ms）期间暂停推进，
   静默后自续。影院作废靠 `appendSeq` 编号（`renderAll` / `closeOverlay` 各递增一次）。
6. **日记本窗口化 + 页索引锁定**：`relayout` 只吃窗口（`shown`），计数类按全量；翻到书尾
   才推宽一批，`relayout(false, true)` 的 `keepPage` 钉住页索引。
   **「书尾」不是 `pages.length - 1`**：StPageFlip 跨页模式的 `flip` 给的是**当前跨页左页号**，
   偶数页数时最后一跨是 `[n-2, n-1]` ⇒ 止于 `n-2`。判据抽为纯函数 `lastReachableCursor()`
   （`src/diary/ui.ts`）；奇数页数为 `n-1`，单页模式恒 `n-1`。
   **续叠是整窗重排**（不是「只测新增」）——成本以窗口为界，且只在主动翻到书尾时发生。
7. **日记本读盘换 `cachedRead`**（官方口径：只展示用 `cachedRead`），并发 10 → 50；批间让出。
   **写后回刷路径仍用 `read` + `invalidateWallCache` 回源**（`cachedRead` 在外部改动→通知之间有
   陈旧窗口）。
8. **冷启动守卫**：首次渲染**之前**判定（`items` 空 + 目录有 .md ⇒ metadataCache 未就绪），
   落骨架页；等 `onLayoutReady` / 一次性 `resolved`（配 1500ms 超时）后重扫。
9. **`content-visibility: auto` + `contain-intrinsic-size: auto`** 跳过屏外卡片的 layout/paint
   （只做影院；日记本靠离屏测高切页，加了会量错）。
10. **首开出骨架页**，不再误闪「影片空空如也」。

## 验收口径（可单测）

1. 影院首屏 DOM 卡片数 = `FIRST_PAINT_CARDS`（20），且 `M.items` 已是全量；
2. 影院空闲追加后卡片数 = 全量；侧栏「全部」计数不受窗口影响；
3. 影院视图身份一变（筛选/搜索/排序）→ 窗口收回首屏值；
4. 日记本首屏**排成纸页**的条目数 = `FIRST_PAINT_ENTRIES`（30），而 `entries` 已读全量；
   后台读到新增条目**不触发** `relayout` / `buildBook`；
5. 日记本翻到书尾 → 窗口推宽一批；已覆盖全量后再翻不动；重开册子窗口复位回首屏值；
   **偶数页数的书尾是 `n-2`**（跨页左页号），停在那里也必须续叠；
6. 冷启动（metadataCache 未就绪）出骨架页而非空态页，就绪后重扫出卡；真空库仍出空态页。

## 回修记录

- **2026-10-02 · 日记本「翻到 50 之后就没内容了」**（验收 5 的失效）：书尾判据原写成
  `cursor < pages.length - 1`，偶数页数下跨页左页号止于 `n-2`，条件恒成立、续叠不触发。
  30 则窗口的测试夹具实际排出 **59 页（奇数）**，旧判据在里面碰巧成立 ⇒ 夹具测不出这条。
  修法 + 成套测试见 ADR-0231「回修」段。

## 已知代价

1. 日记光箱「下一张 / 上一张」只在**已加载**条目内轮转（窗口外未上屏时不在轮转序列里）；
2. 书尾续叠是一次**整窗重排** + StPageFlip 整实例重建（库无 `addPage`）——成本 O(窗口)，
   只发生在用户主动翻到书尾那一刻；
3. 影院的后台刷新（vault 事件 / 豆瓣逐部落盘）仍走同步扫描——纯内存、几十毫秒量级；
   若条目量涨到扫描进秒级，再考虑分片让出。

## 本次不做

- 虚拟滚动（`Clusterize.js` / `@tanstack/react-virtual`）——820/1443 规模属过度工程；
- 「轻元数据全量索引」（日历标记 / `getYearRange` 改由文件名 + frontmatter 全量推算）——
  现状是随后台加载逐步变准，过渡窗口 = 后台读盘期；要保真另立 issue。
