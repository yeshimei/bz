# Ticket 141 — 小橘「对话即操作」助手（待实现计划）

> 需求：打开小橘对话，说一句话（例：「添加关于黑洞的文献笔记」），小橘直接调用**对应域的函数**生成对应产物，无需手动打开域面板。
> 状态：**计划中**（未实施，仅记录需求 + 设计概要 + 待拍板项）。

## 需求

- 入口：小橘聊天（smartcat 域，`sendChatMessage` 流程）。
- 输入：自然语言一句话。
- 行为：识别「域操作意图」→ 解析参数 → 调用对应域既有函数 → 产物直接落盘 → 小橘自然回复确认 + 自动打开产物。
- 未命中操作意图时：照常聊天（小橘仍然是陪伴猫，不打断普通对话）。
- 通用性：不只做单个域，采用「技能注册表」模式，后续任何域只要注册一条技能即可被一句话调用。

## 设计概要（三层）

### 第 1 层：技能注册表（Action Registry）

集中注册「可被一句话调用的域动作」，每条技能 = 一个条目：

| 字段 | 作用 |
|---|---|
| `id` | 技能标识，如 `literature:term-note` |
| `detect(message)` | 识别该句话是否为该动作 + 提取参数（词法优先） |
| `execute(params)` | 调对应域**既有导出函数**（如 literature 的 `generateTermNote`）落盘 |
| `confirm?` | 是否需要用户确认（默认直执；破坏性/参数不全才弹确认） |
| `summary(result)` | 把执行结果转成一句话，注入 AI 回复上下文 |

新域接入 = 注册表加一条，chat 主流程零改动。

### 第 2 层：意图识别（分层，控制成本）

- **快路径（词法）**：动作词（添加/生成/创建/记/整理/收录…）× 产物词（文献笔记/术语/待办…）× 参数提取（`关于X` / `术语X`）。确定性、可单测、零 AI 成本。
- **慢路径（AI 兜底）**：只有同时出现「动作词 + 产物词」但词法没抓到参数时，才用 `callChatJson` 做一次结构化分类确认动作 + 补参数——不是每条聊天都多花一次调用。
- **兜底**：都不命中 → 正常聊天。

设计取舍：不依赖服务商 function-calling API（core/ai 只有 chat/json 两条通道），插件侧识别 + 插件侧调用，任何已配置 provider（DeepSeek/Ollama 等）通用。

### 第 3 层：执行与反馈

- 执行发生在「小橘正在思考…」打字机阶段（等待期被现有 UI 覆盖）。
- **成功**：产物路径/摘要注入 user 消息尾部（括号标注小橘已执行）→ 正常 AI 调用 → 小橘自然确认；同时自动打开产物 + toast。不额外消耗 AI 调用。
- **AI 不可用但动作已成功**：回退固定确认文案，不把成功说成失败。
- **执行失败**：白话化失败原因（对齐 literature `humanizeError` 思路）由小橘回复，照常记录对话历史。

## 不破坏铁律的边界

- **数据格式零变化**：产物与域面板手动生成完全一致（如文献 frontmatter 五键），旧数据直读。
- **域事件契约复用**：执行成功 emit 对应域事件（如 `literature:tasks` `term-generated`）→ 小橘行为流自动记录（ADR-0069），与 UI 手动生成同口径。
- **命令单点不动**：不新增命令、不改 `bz-<域>-<动作>` 三段式。
- **跨域显式 import**：smartcat → literature（参考 smartcat → diary/config 先例），只调域导出函数，不碰域内 UI。
- **纯增量**：既有面板/聊天流程全部保留。

## 待拍板项（实施前需用户确认）

1. **执行方式**：直接生成落盘（贴合「直接调用函数生成」）还是先预览确认（复用术语面板 AI 预览 → 可改 → 确认写入）。
2. **参数缺失行为**：意图明确但参数不全（如只说「添加文献笔记」没说术语）→ 多轮问答补全 / 打开对应面板 / 不执行仅提醒。
3. **V1 范围**：仅文献盒术语生成（最小闭环）／文献盒 + 备忘录（两域验证通用性）／一次多域。
