# 460 脸谱重构 spec：外部流程合包 + 加密聊天仓 + 画脸谱管线

## Status
ready-for-agent

## Related
- ADR-0194（脸谱入保险库——**取代 ADR-0191 §2**）、ADR-0195（脸谱工具包边界与不分发）、ADR-0196（同步与画脸谱的阶段切分 / 协作式暂停）、ADR-0197（聊天仓唯一权威存储）
- 分期票：issue 458（一期：包成形 + 同步 + 入保库）、issue 459（二期：画脸谱管线）
- 既有机制：issue 446（数据源弹窗与两段增量）、issue 449（语义分流，本票部分取代）、issue 450（生成进度引擎化）、issue 453（批级重试续跑）、issue 456（头像入库，本票改写）
- 术语以 `CONTEXT.md` 脸谱域小节为准（同步 / 转写 / 画脸谱 / 数据根 / 聊天仓 / 保库记录 / 旁路表 / 派生档 / 脸谱工具）

## Problem Statement

我现在维护脸谱靠一堆散装脚本：在 `E:\Obsidian\微信脸谱数据\tools\` 下按顺序人肉跑「取密钥 → 解密 → 导文本 → 导媒体 → 语音转写 → 图片关联 → 表情命名 → 手工分批喂图描述 → 合成导入 JSON」，几十步全靠记，没有版本、没有断点、失败了不知道从哪续。插件侧的数据源弹窗只有一个「重扫」，扫的还是已经导出好的目录——它永远不会去微信里取新数据，所以每次有新聊天我都得滚回命令行。

同时数据是明文的：`people.json`、`people-preview.json`，还有 `CONFIG/FACES/<联系人名>/avatar.jpg`——**头像文件夹名就是人名，等于把联系人名单摊在库里**。我加密了保险库、加密了日记，却把最敏感的一整层（我跟谁在说话、说了什么）留在外面。

而且这份聊天数据还是**有损**的：原始 20773 条进到预览层只剩 18477 条，`type`/`who`/`sid`/`dur`/`wav`/`img` 六个字段全丢。丢了 `wav` 和 `img` 就再也找不到音频和图片，画脸谱只能吃降级素材。更要命的是这层是 **append-only** 的：一旦某条消息的文本后来被升级（补上转写或描述），**永远写不回去**——现网已经这样了（`chat.json` 里 28 条表情带名，仓里却是 52 条，两边对不上且修不回来）。

最后，画脸谱这条链太长且不可控：单人 1631 张图 / 1289 条语音 / 2.8GB，中途关掉面板或重启就前功尽弃；哪一步在跑、跑到哪、还剩多少，全看不到。

## Solution

把整条外部流程收成一个包 `@jwbz/obsidian-face`（bin `bz-face`），由插件驱动；数据源弹窗右上角的「重扫」升级为「**同步**」——一键从微信取数（取密钥 → 解密 → 导出 chat.json → 头像源），在弹窗内走一条进度行。

从「同步」到「画脸谱」之间，人脸谱**不再需要碰命令行**：

- 「画脸谱」是一条可暂停、可中断续跑的完整链：**导出该人媒体（含 AI 用派生档）→ 语音转写 → 图片描述 → 画像生成**，每一步都有精确到条数的进度；
- 图片描述与画像生成各自弹一次确认，报清张数/批数与调用次数，「跳过图片描述」不等于取消整条链；
- 关面板、重启、上锁都能安全中断并从断点续，已完成的批不重跑。

数据侧换血：每个联系人变成保险库里**一条加密记录**（人物卡 + 聊天数据 + 任务 + 头像），跟保险库/密码本共锁同库、共用一个主密码；索引也加密，打开面板即要求解锁。vault 里不再有任何明文聊天数据、不再有明文头像目录。

同时把「聊天数据」从有损投影升格为**完整权威存储（聊天仓）**：保留全部原始字段，转写与描述作为派生文本叠上去，写入语义从 append-only 改为 upsert，断点指纹改为内容哈希——**素材变了就必须能感知到**。

## User Stories

### 同步（从微信取数）

1. 作为脸谱的使用者，我想在数据源弹窗右上角点一下「同步」就从微信里取到最新数据，这样我不用再回命令行手跑脚本。
2. 作为使用者，我想「同步」把密钥提取、数据库解密、逐人导出消息、头像源落位一次做完，这样我不用记住有几步。
3. 作为使用者，我想在同步过程中看到一条进度行告诉我当前在做什么、第几个人，这样我不用猜它是不是卡死了。
4. 作为使用者，我想同步时按钮位置只出现「停止」，这样我不会误点出第二个同步。
5. 作为使用者，我想同步完成后列表自动刷新并标出哪几位有新消息，这样我一眼知道要不要重新导入。
6. 作为使用者，我想同步完成后**不要**自动导入我的数据，这样我的素材准备与画像生成节奏还是我掌控的。
7. 作为使用者，当微信没开着时我想看到「请先打开并登录微信」这样一句中文，而不是一个 Python 报错栈。
8. 作为使用者，当微信版本已经被官方封堵取密钥时，我想被明确告知该退回哪个版本，而不是拿到一个 `errcode=405`。
9. 作为使用者，我想同步是幂等的：重复点不会重复搬数据、不会把已导出的东西再导一遍。
10. 作为使用者，我想在同步进行时画脸谱入口是置灰的，这样数据在变的时候我不会画出一份半截素材的画像。

### 画脸谱（整链）

11. 作为使用者，我想对某位联系人点「画脸谱」后，这条链自动把媒体导出、语音转写、图片描述、画像生成全跑完，这样我不用分四次手工触发。
12. 作为使用者，我想看到阶段化的进度：`媒体导出 312/1631`、`语音转写 45/1289`、`图片描述 3/82 批`、`其人`/`我们`/`时间线`，这样我随时知道在哪一步、还剩多少。
13. 作为使用者，我想关闭面板后这条链继续在后台跑，这样我不用守着。
14. 作为使用者，我想在进度块里点「暂停」，它在这一批/这一条做完后停下，这样不会因为我按了暂停就丢掉正在做的工作。
15. 作为使用者，我想暂停后的进度块给我一个「继续生成」，且已完成的批次不重画，这样我不重复付费。
16. 作为使用者，我想中途重启 Obsidian 后仍能从断点续上，这样长任务不会因为一次意外前功尽弃。
17. 作为使用者，我想崩溃遗留的任务显示为「中断」并给出「继续生成」，而不是假装还在跑；我也不想它自动跑起来烧我的 token。
18. 作为使用者，我想中途中断后已落盘的那部分结果保留（如已完成 1200 张图的描述），这样重跑只补剩下的。
19. 作为使用者，我想某张图或某条语音失败时不影响其余的（最后告我 `失败 N 条` 并可重试），这样单条失败不会废掉 1600 张。
20. 作为使用者，我想密钥/解密这类根本性失败能整链停下并说清原因，而不是继续跑到一半才发现没数据。
21. 作为使用者，我想一个没有任何语音和图片的联系人被自动跳过预处理，直接进画像生成，这样我不必为 0 张图确认一次。
22. 作为使用者，我想已经画过脸谱的人再次画时只跑增量部分，这样我不为老素材重复付费。

### 二次确认

23. 作为使用者，我想在开始图片描述前看到一个弹窗告诉我用哪个服务商/模型、多少张图、约多少次调用、从第几张开始，这样我能判断要不要付这笔钱。
24. 作为使用者，我想这个弹窗有「跳过图片描述」而不仅是「开始/取消」，这样我可以在不想描述图的时候只画画像。
25. 作为使用者，我想跳过描述后整条链继续走到画像生成，这样「跳过」不会变成「全部放弃」。
26. 作为使用者，我想在开始画像生成前看到一个弹窗告诉我用哪个模型、素材多少条、约多少次调用，这样我能决定要不要开始。
27. 作为使用者，我不想在确认窗里看到虚构的金额数字——只要张数与调用次数这种能算准的，这样我不会被假报价误导。
28. 作为使用者，我想两次确认是两个独立弹窗，这样「跳过描述」不会被我误当成「取消画像」。

### 隐私与加密

29. 作为使用者，我想脸谱的全部数据（聊天内容、画像、事件、任务队列）都落在保险库里，这样 vault 被同步/分享/截图时不会泄露。
30. 作为使用者，我想每个联系人是一条记录一个文件，这样改一个人不必解密再加密整库。
31. 作为使用者，我想联系人索引（名单、条数、更新时间）也是加密的，这样「我有哪些联系人」这层不会明文泄露。
32. 作为使用者，我想头像也进保险库，这样 `CONFIG/FACES/<人名>/` 这种明文名单目录彻底消失。
33. 作为使用者，我想脸谱和保险库/密码本共用同一个主密码，这样我不用记第三把锁。
34. 作为使用者，我想在保险库上锁时脸谱面板立刻不可读、后台任务立刻暂停，这样锁上之后不再往磁盘写明文、不再跑 AI。
35. 作为使用者，我想打开脸谱面板时如果没解锁就先要求解锁，这样不会出现「打开了但是空的」这种困惑。
36. 作为使用者，我想清楚知道「加密保护的是 vault，不是本机磁盘」——数据根仍是明文，这样我不会误以为本机已经安全了。

### 外部工具

37. 作为使用者，我想它是一句话能装的包（本地 link 或全局装），而不是一堆散装脚本，这样换机器我能重来一遍。
38. 作为使用者，我想运行 `bz-face doctor` 就把缺的 Python 依赖、ffmpeg、微信进程状态、数据根可写性一次查清，并给我可直接粘贴的安装命令，这样我不用猜环境差什么。
39. 作为使用者，我想工具**不要**自动帮我 pip install，这样它不会污染我自己的 Python 环境。
40. 作为使用者，我想这个包**不发布到公开 npm**，因为它的核心能力是解密微信数据库，公开分发我不想承担。
41. 作为使用者，我想知识盒与脸谱共用同一个 Python 路径设置，这样我不用维护两份相同的路径。

### 设置与配置

42. 作为使用者，我想设置面板里有一个域无关的「外部工具」组（Python / ffmpeg / ffprobe），这样两个域共用一套。
43. 作为使用者，我想微信账号目录默认自动探测、但可以覆盖，这样多账号或旧版本备份我也能处理。
44. 作为使用者，我想数据源设置里的路径键改叫「数据根」，因为它既是同步的产出目录也是画脸谱的读入目录。
45. 作为使用者，我想设置里关于隐私的说明改成与事实一致（完整聊天数据入库、媒体本体不入库只存路径），这样文案不会骗我。
46. 作为使用者，我想语音转写引擎沿用 AI 面板里那个下拉（SenseVoice-Small 缺省 / faster-whisper），这样我不必在两个地方配同一件事。
47. 作为使用者，我想图片描述的批大小可调（默认 20 张），这样我可以按自己的钱包与耐心调。

### 兼容与迁移

48. 作为使用者，我想现有那几位已导入的联系人被迁移成新的加密记录，不用我手动重来一遍。
49. 作为使用者，我想升级之后素材能自愈：下次同步/画脸谱时把旧的有损记录补成完整记录，而不是留下一半新一半旧。
50. 作为使用者，我想留痕导出的 CSV/JSON 那条老导入路径还能用（我不再维护它，但别删），这样我手上万一还有旧文件也不至于断。

### 故障与边界

51. 作为使用者，我想在未解锁状态下「数据体检」跳过脸谱域而不是报错，这样我的体检报告不会因为没解锁就红一片。
52. 作为使用者，我想多设备同步加密记录时只要主密码相同就能读，这样换设备不需要额外操作。

## Implementation Decisions

### 存储与隐私

- **脸谱数据整体进保险库**：每联系人一条保库记录（`SafeNote.kind = 'people'`），内含人物卡（原 `people.json` 一条）+ 聊天仓（原预览桶一只）+ 该人的任务条目 + 头像附件，落成一个 `.enc`。**取代 ADR-0191 §2「聊天原文不落盘」。**
- **共锁同库**：注入与保险库面板**同一个 `SafeManager` 单例**（同一主密码、同一 `.safe.enc` 清单），订阅保险库的「变更」与「解锁态变更」两个事件；**上锁即清明文缓存并暂停后台任务**。接法与密码本一致（本域不新造锁）。
- **索引也加密**；脸谱面板打开即走解锁门禁。
- **头像从明文媒体文件夹迁入保库记录**（作为附件，渲染时解密成 data URL）；原库内媒体文件夹设置键与明文复制逻辑**退役**。
- **加密边界明确**：数据根（vault 外）仍是明文。加密只防 vault 被同步/分享/误传；只做文档与设置面板提示，**不提供**自动清理数据根（不可逆）。
- **工具永不接触 vault**，也不需要任何解密能力。

### 聊天仓（唯一权威存储）

- `chat.json` 退化为**工具的一次性产物**（同步时生成，此后只读、不再被回写）；聊天仓升格为唯一权威存储。**概念改称「聊天仓」，文件名保留**（改名收益小、迁移成本与残留风险大）。
- **消息流存全量原始消息**，保留 `type`（4.x 原始码）/ `who` / `sid` / `dur` / `wav` / `img`；另加一个派生字段 `text` = 合成后的消费文本（`[图片] 描述` / `[语音 N秒·情感] 转写` / `[表情·名]`…），**空串 = 不进时间线**。展示与素材组装只读「`text` 非空」这一行过滤 → 消费行为与现状一致，但存储完整可重算。**取代 449「不进时间线就丢出消息流」的做法。**
- `chat.json` 的定位钉死：只含「从微信解出来的事实」（文本 + 表情命名 + 图片关联 + 音频路径/时长），**不含转写与图片描述**（那是插件侧 AI 产物）。
- **vault 的唯一写者是插件**。工具只写数据根，并只产旁路表：`voice.json`（转写）、`image_map.json`（图片↔消息关联）；表情命名**并入 chat.json 的生成**（不再单独回写）。所有合并进聊天仓的动作由插件执行。
- **写入语义从 append-only 改 upsert**：同键新文本覆盖、原始字段按新值更新；水位与增量逻辑保留。
- **断点指纹从「条数 + 末条派生键」改为组装素材的内容哈希**。理由：回写让「条数不变、内容变了」成为常态，旧指纹**察觉不到**，会拿旧素材静默续跑。
- **结构版本升级**：聊天仓结构版本号 +1；旧结构缺的正是回溯原料、无就地升级路径，判废后从数据根重导。与保库迁移合并为**同一次**。

### 外部工具包

- 单包 `@jwbz/obsidian-face`，bin `bz-face`，放仓库 `tools/` 下（与现有外部工具同处）。形态 = Node 外壳 + 随包 vendored Python（自写脚本 + 裁剪版上游解密库，**保留其 MIT 许可与版权声明**）。
- **不发布公开 registry**：`package.json` 声明 public 但不执行发布。**此处与既有 B 站下载器有意不同**——本包的核心能力是解密微信数据库。
- **边界切在「转写」为止**：工具做「取密钥 → 解密 → 原始导出 → chat.json（含表情命名）→ 媒体导出（含 AI 用派生档）→ 语音转写」；**AI 不做**。
  - 理由一：既有决策已定「AI 回迁插件、服务商凭据不进外部进程」。
  - 理由二（硬约束）：本地语音模型冷加载按分钟计，逐条 spawn 等于每条语音重载一次模型，实际不可跑——转写必须一个进程吃完全量。
- 子命令：`sync`（全量、轻）、`prep <联系人>`（按人、重）、`doctor`（环境自检）。共性参数走一个 JSON 全量下发（与既有外部工具同口径）。
- **进度协议沿用既有四行协议** `[bz-step]` / `[bz-p]{phase,pct}` / `[bz-info]` / `[bz-result]`；顺手把**协议解析 + 进程调用壳抽成核心层共享模块**（既有域本次不动，后续再迁）。
- **断点状态落数据根**（跟数据走，不跟人走）：工具侧状态文件 + 一个**控制文件**用于协作式暂停/停止。
- **重物用户自装**：Python 依赖按用途分组的 requirements 文件；`doctor` 自检并打可直接粘的一行安装命令；**绝不自动 pip install**。
- 运行时路径（Python / ffmpeg / ffprobe）**升格为域无关设置组**（从知识盒的三个键一次性迁移）；语音转写**复用 AI 面板的引擎设置**，不新增第二套。

### 同步与画脸谱的编排

- **阶段切分**：`sync` 与 `prep` 分离；**画脸谱 = prep → 图片描述 → 画像生成**。否决「媒体+转写全塞进同步」（会把一键同步变成搬 9.8GB + 全量转写）与「预热素材独立成第三阶段」（同一段代码不接 AI 段即可，不值当单开一层）。
- **状态机归插件**：既有任务引擎扩一个 `preprocess` 阶段（工具段作为 job 的前两阶段）；工具只保证**单步幂等**。
- **暂停是协作式，不是硬杀**：工具在**步骤边界**与**每条媒体之间**轮询控制文件，看到暂停就在安全点让行、进程待命（不硬杀是因为模型冷加载代价高，杀一次白付一次）。**中断 = 杀进程留状态**，重跑幂等续。
- **进度分两层，不混用**：同步走数据源弹窗内的**一条进度行**（不占生成进度块——同步不是画脸谱）；画脸谱接既有生成进度块，按阶段推进。**系统通知只在完成 / 失败 / 转后台三个阶段发**。
- **失败分两类**：密钥/解密失败 = 硬失败整链停 + 中文原因；单条媒体/语音失败 = 计失败数继续，末了在结果行报 `failed:N` 并提供重试失败项。
- **两次二次确认，两个独立弹窗**：图片描述一次（含「跳过图片描述」，跳过 ≠ 取消整链）、画像生成一次；确认窗只报张数/批数/调用数，**不报金额**；零媒体联系人自动跳过预处理与描述。
- 同步与画脸谱**互斥**；**中断不自动续**（崩溃遗留的「运行中」转「中断」，出「继续生成」按钮）；**上锁暂停**（与保险库解锁态事件联动）。
- 暂停文案沿用既有体系：「这一批做完就暂停」/「继续生成——已完成的批次不重画」。

### 图片描述

- 输入图用**专用派生档**（长边 1280 / JPEG 质量 80），由工具在媒体导出时生成：实测微信自带缩略图仅 115×120px，**读不出截图里的字**（而现有高质量描述恰恰靠读截图文字）；原图 1920px/440KB 直投上行太慢。派生档可删可重建，长边与质量进工具配置。
- **批 20 张/次调用**（可配），上下文窗 = 该批首图前 1 小时 ～ 末图后 1 小时内的对话、**字符上限 6000**（超限按距图片的时间远近裁两端）。时间窗比固定条数稳（一天上万条与一天三条的会话不等价）。
- 走核心层 AI 的 `{text, images}` 多模态通道，**复用 AI 面板的服务商与当前模型**（不新增视觉档设置键；旧的占位值退役）。
- **断点粒度 = 批**：已落盘的批不重跑；单批失败只废这一批。

### 设置

- 数据源设置里的路径键改称「数据根」（同步产出根 = 画脸谱读入根，一个键两端用）；媒体（图片/视频/文件/语音/派生档）全留数据根内、**不入库**（只有头像入库）。
- 新增微信账号目录覆盖键（默认空 = 自动探测）。
- 两条隐私文案改词；补一句数据根明文边界提示。

## Testing Decisions

**什么算好测试**：只断言外部行为——纯函数层断言「同一份输入 → 同一份输出结构」；编排层断言「阶段推进序列、暂停点、续跑跳过集合、错误分流、落盘结果」，不碰内部私有状态与实现细节。既有 `tests/people/` 的写法（夹具全部构造数据、**不含真实聊天内容**）继续沿用——本特性涉及真实聊天，这条尤其重要。

**缝的设计**：本特性横跨三类执行体（外部进程 / 保险库 / AI），强行收成一条缝是假的。做法是**把四个外部依赖全部收敛成注入接口，让整链只在「画脸谱编排入口」这一处缝上测**；其余判定全部下沉到既有纯函数缝。

1. **编排缝（新，主缝）**：画脸谱整链的编排入口接收四个注入依赖——`runTool`（进程调用）、`askLLM`（AI 调用）、`store`（保库记录读写）、`readBytes`（取派生档字节）。测试注入四个假件，喂预录的工具输出行与假 AI 返回，断言：阶段推进顺序、暂停在什么边界生效、续跑跳过了哪些批、`failed:N` 分流、最终落盘结构。**这是唯一必须新增的运行时缝**，也是最高点。
   - 既有先例：任务引擎已经在用「注入 `askLLM`」的接法（生成管线可整管单测），把 `runTool` / `store` / `readBytes` 按同一接法补齐即可。
2. **纯函数缝（沿用既有）**：脸谱数据层的纯函数群——原始→消息流的归一化、增量合并、素材键、统计口径、批切分与上下文窗。断言新结构（全量原始字段 + 派生 `text` 空串语义）、upsert 覆盖（**必须覆盖掉现网「同键保留旧文本」的 bug**）、内容哈希指纹、过滤开关行为不变。先例：现有数据源纯函数测试（增量矩阵 / 开关三态 / 归一分流）。
3. **协议缝（新，纯）**：四行协议的**行解析器**独立成纯函数，喂预录的协议行断言解析出的事件序列（含畸形行不炸）。先例：知识盒既有工具的行协议测试（mock `child_process`）。
4. **存储缝（注入假件）**：保库记录读写注入一个内存假 `SafeManager`，断言「每联系人一条记录」「上锁清明文」「迁移 3 人 → 3 条记录」「头像附件往返（写 → 锁 → 解锁 → 可渲染）」。先例：密码本域的注入式测试。
5. **AI 输入缝（注入假件）**：取图与上下文窗组装注入 `readBytes`，断言批的取图集合、上下文窗口与字符上限裁剪、跳过批不重取。

**要覆盖的模块**：脸谱数据层（结构、合并、指纹）、画脸谱编排入口（阶段机、暂停、续跑、失败分流）、外部工具协议解析、保库记录读写与迁移、设置迁移（路径键搬值）、未解锁时的门禁与体检跳过。

## Out of Scope

- **不在本次做**：图片描述的独立视觉模型档（先用 AI 面板当前模型，等真实成本数据出来再议）。
- **不迁**：`synthesize` 脚本里的「连发归组（120s 合并）」确认退役——消息流本就该一条条，降密度是「切批/素材段」的职责。
- **不做**：自动清理数据根原文（不可逆，只文档写边界）。
- **不改**：留痕 CSV/JSON 嗅探通道保留但冻结（删它要动旧契约与测试，与本重构正交）。
- **不迁**：`tools/tmp/` 下一次性脚本，除被验证过的上下文批次格式与批合并收进包的正规实现外，其余留在原地当历史。
- **不做**：现有知识盒外部工具的协议解析迁移（本次只抽共享模块，知识盒后续再迁）。
