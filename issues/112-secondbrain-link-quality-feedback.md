# Ticket 112：双链质量反馈闭环（审计日志 + 否决记忆 + 互惠加权）

- 状态：待开发（排在 ticket 111 合并之后实施——需叠加在其 link-agent 模块上，避免并行冲突）
- 域：secondbrain
- 来源：双链管线设计交流·增强建议第一档，用户拍板立项
- 关联：issues/111-secondbrain-auto-link.md、`.scratch/secondbrain-link-agent/spec.md`

## 背景

ticket 111 的关联数量默认不限、由 AI 自行决定，质量闸门全押在裁判提示上。本票加入三条校准机制：让人工否决和向量互惠信号参与边界判定，使链路质量随使用时间**变好**而非恒定。

## 任务清单

1. **关联审计日志**：
   - 新增 `CONFIG/STORAGE/secondbrain_link_audit.json`，append-only；
   - 条目结构 `{ ts, source, target, decision: 'linked' | 'rejected', reason }`；
   - 写链成功时追加 `linked` + 裁判理由；用户否决时追加 `rejected`；
   - 用途：误链溯源、后续阈值/置信度参数的真实数据来源。
2. **否决记忆**：
   - 提供用户主动移除某条关联的入口（命令/交互形式实现者细化），移除即记 `rejected`；
   - 必须**区分两种移除**：死链清理的自动移除（不记否决）vs 用户主动移除（记否决）；
   - 否决对子持久化为集合，裁判侧跳过送审 + 候选侧过滤，双层生效；重跑/换设备（Syncthing 同步 STORAGE）后依然有效。
3. **互惠加权**：
   - 候选阶段本地信号：A 的 Top-K 近邻含 B 且 B 的含 A（双向命中）→ 排序前置并标记 `mutual`；
   - 纯向量运算，零额外 API 成本；写入条目的审计理由可注明互惠。

## 明确不做（防蔓延）

块级深链（`#^block`）｜类型化关系（支持/反对）｜MMR 多样性约束｜置信度分级与相似度阈值（等审计日志积累真实数据后另议）。

## 验收标准

- [ ] 每次写链/否决均正确追加审计条目，json 可读、可手工修正；
- [ ] 被否决的对子在后续自动建链中不再出现（含笔记重跑场景）；
- [ ] 死链清理不产生否决记录；
- [ ] 互惠加权有构造双向近邻的单测覆盖；
- [ ] 门禁按仓库惯例：`BZ_TEST_MAX_WORKERS=8 pnpm test` + `pnpm exec tsc --noEmit` 全绿（构建部署由主会话合并后统一执行）。
