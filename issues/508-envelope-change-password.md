  ADR-0019（D2 可靠写契约）、ADR-0194（脸谱共锁同库）、ADR-0124（解锁屏）
- 域：encrypt（另动 main.ts 一行命令注册 + index.ts 导出）
- 反馈来源：用户原话立项（2026-09-28）

> 原话：保险库增加一个修改密码的功能，调整整个加密结构，用户的密码只加密入口文件，
> 为每一个其他文件单独随机生成一个密码，入口文件会记住这个密码，这种情况下，修改密码只需要
> 重新解密入口文件，再用用户新的密码加密即可，这样就实现了快速修改密码的功能。
> 在修改代码之前，先把加密文件夹备份（已备份：`.ENCRYPT-backup-20260928`，125 文件一致）。

## 一、为什么改结构

旧模型（v1）：每个密文镜像（正文/附件原始层/预览层）**直接用主密码**独立加密——
改一次主密码 = 全库逐文件解密再重加密（125 文件 × PBKDF2 10 万次 × 2 遍，分钟级 + 全量重写盘）。
改密码事实上不可用。

新模型（v2，双层信封）：

- 每个密文镜像有**独立随机 fileKey**（43 字符 64 字符表随机串 ≈ 258bit 熵），镜像本体用 fileKey 加密；
- 清单内 `keys[ref] = Encrypt(fileKey, masterKey)`——**清单记住每个文件的密码**；
- `masterKey` 为随机 256bit 中间主密钥，`masterWrap = Encrypt(masterKey, 用户密码)` 随清单落盘；
- 清单本体仍用用户密码加密（验密语义不变：解密 .safe.enc 成功即通过）。

修改主密码 = 解密清单 → 重包 `masterWrap`（1 次 PBKDF2）→ 重加密清单 → 落盘。
**其余文件一个字节不动**，亚秒级完成。

中间主密钥是对用户原话的工程补全：若 wrap 直接用用户密码包裹，改密码仍需重包全部 wrap
（O(N) 次 PBKDF2，百文件库 15 秒上下）；经 masterKey 中转后降为 O(1)，
「入口文件记住每个文件的密码」的语义不变（keys 表仍在清单里）。

## 二、方案要点

1. **清单 v2**：`SafeManifest { version: 2, masterWrap, keys: Record<ref, wrap>, notes }`。
   v1 清单照常可解（迁移前运行态走旧路径，用户密码解 blob）。
2. **迁移（v1→v2）**：解锁成功后自动后台执行，opQueue 串行：
   - 逐镜像：用户密码解密 → 新 fileKey 加密 → 写**暂存区**（新 ref，顶层不可见，
     体检孤儿扫描只扫顶层、绝不误删）；
   - 全部成功后提交：promote 全部新镜像到顶层（此时清单仍 v1，旧镜像俱在，数据完整）→
     清单切 v2（notes 指向新 ref + keys + masterWrap）落盘 → 删旧镜像 → 清暂存；
   - 任一中断均安全：清单 v1 期 = 旧镜像俱在（promote 的新镜像成孤儿，体检可清）；
     清单 v2 后 = 新镜像俱在（旧镜像成孤儿，体检可清）。下次解锁按清单版本重试/跳过。
   - 任一镜像解密失败 → 中止迁移保持 v1（数据完整性优先），下次解锁重试。
3. **changePassword(oldPw, newPw)**：verifyPassword(旧) → masterWrap 重包 → password 更新 →
   saveManifest → clearCryptoKeyCache（旧派生密钥不残留）。未迁移（v1）时拒绝并提示稍后。
4. **UI**：两屏接力复用 uiLockScreen 骨架——屏1 验证当前主密码（同销毁确认语汇）、
   屏2 双输入设置新密码（首设同款确认）。入口两处：面板空白处右键菜单 + 命令
   `bz-encrypt-change-password`（未解锁先走解锁屏）。
5. **API 面不变**：SafeManager 公共方法签名零变化，password-vault / people / diary /
   secondbrain 四域无感。
