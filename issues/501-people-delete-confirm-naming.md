# issue 501：删除的两处修正（确认改真弹窗 / 删完卡片立刻消失）+ 目录后缀不上界面

- 关联：issue 500（详情头删除钮）、issue 448（图标工具条）
- 域：people（脸谱）

## 反馈

用户两条：

1. 「点击删除为什么不弹窗？弹窗让用户二次确认，使用通知消息是什么鬼」——未画 / 未完成档的确认
   做成了「图标红灯 + warning 通知」，用户压根看不出来在等第二次点击。
2. 「删除之后面板的联系人卡片还在，需要重启之后才会消失」。
3. 顺带：「后面不要加这种后缀，允许名字重复」——指 sync 给重名联系人加的目录唯一键后缀
   `点点 (wxid_7470574705922)` 不该进用户视野。

## 根因

1. **确认走错了载体**：issue 500 的二次确认靠 `deleteArmId` 武装态 + `notice('再点一次…')`。
   通知是「事后通报」，不是「等用户回答」，跟密码门（`uiLockScreen`）的强度差太远，
   用户读完通知往往已经不记得自己点过什么。
2. **记录快照没跟着失效**：`wallPeople()` = 保库记录 ∪ **面板记录快照 `recordCache`**
   （issue 452：记录里有、人物卡里没有的 id 会被聊天仓素材合成「待画」占位卡）。
   `deletePerson` 只删了保库记录（`store.remove`），`recordCache` 里那一条还在 →
   占位卡立刻把卡片挂回墙上；快照只在关面板时清（`closePeoplePanel`），所以表现为「要重启才消失」。
3. **目录唯一键漏到了界面**：`plan_targets` 为了让同名联系人落在不同目录，给目录名加了
   `(wxid)` 后缀；而面板 / 数据源列表 / 同步进度全都直接拿**目录名**当显示名。

## 改动

1. **确认改真弹窗**（`ui.ts:handleDelete`）：未画 / 未完成档改用核心流程框 `openFlowDialog`
   （`src/core/flow-dialog.ts`，与设置页「清空聊天数据」同一套壳）——标题「删除联系人」+
   说清代价的正文 + 「取消 / 删除（危险主动作）」，点遮罩 / ESC = 取消。
   已画谱档不变，仍走 `uiLockScreen` 密码门（那本来就是弹窗）。
   **删掉整套武装态**：`deleteArmId` / `deleteArmTimer` / `disarmDelete` /
   `FoldDetailHeadOpts.deleteArm` / `.bz-people-del-arm` 样式全数移除（不留死代码）。
2. **删完立刻摘卡**（`ui.ts:deletePerson`）：`recordCache?.delete(p.id)` + `listCache` 过滤。
   `removeContact` 只清保库自己的缓存与盘上清单，面板那份快照得自己同步。
3. **目录后缀不上界面**（`datasource.ts:plainNameOf` 新增纯函数）：
   `名字 (wxid_…)` / `名字 (m754831096)` / `名字 (xxx@weclaw)` 三种唯一键后缀只在**显示**时剥掉，
   **目录名本身仍是聊天仓键 / `PersonEntry.id`**，prep 定位与勾选钩子不动。
   只剥「括号里长得像联系人 id」的——真名「小明 (同学)」「老周家（3 人）」原样。
   接入点：数据源行（`DsRowState.displayName`）、墙上记录（`wallPeople` 出墙前统一）、
   同步进度当前联系人 / 失败清单 / 完成通知。

## 守住的三条边界

- **目录仍是唯一键**：同名联系人（现网 点点×2、冰玉×2、七七×4）继续落不同目录，
  数据不混；界面允许重名并排（用户明确选择的方案）。
- **id 不变**：`PersonEntry.id` / 勾选 / prep `--name` / 文件路径一律仍用目录名，只有显示层换了字段。
- **密码门只读**：`verifyPassword` 语义不变，不写解锁态。
