# 536 · 影院：拆分「已看日期」——修在看条目凭空多一行「已看」

## 用户报的（2026-10-01，截图 + 原话）

详情弹窗里《续命之徒：绝命毒师电影》状态是**在看**，但足迹时间线已经挂着一行「已看」（金色首看点），
日期和「在看」同一天。用户原话：**「影视还是在看，时间线已经有已看了，是Bug」**。

## 根因

frontmatter「观影日期」在库里兼着两个身份：

- **排序时间戳**——建档（`persistItem` 模板）、编辑保存（`fm['观影日期'] = item.watchDate || localNow()`）、
  标记在看（`markStatus` 里 `item.watchDate = localNow()`）都会刷它，`dateVal` 排序也读它；
- **渲染层却当它是「哪天看的」**——详情时间线把 `watchDate` 无条件渲染成「已看/首看」节点。

于是任何一条**没看过**的条目（豆瓣导入 149 条想看 + 1 条在看，实测 151 条想看里 149 条都带这个键）
在时间线里都会凭空多出一行「已看」，日期 = 入库那天。合集弹窗的季行副行「观影 X」同理（在看季也挂着日期）。
年书各轴当时读的是同一字段，只是先按状态过滤了才没露馅。

## 拍板（2026-10-01 用户口径）

> 「观影日期当做排序语序，增加一个已看日期，观影日期还是保持被多处修改，同时批量修改影视笔记」

| 分叉 | 选定 |
|---|---|
| 观影日期 | **保持原样**：排序时间戳，继续被建档/编辑/标记多处刷新（不改成「只记已看」——那会让新建的想看条目在「按日期」排序里沉底） |
| 已看日期 | **新增独立键**（frontmatter「已看日期」，`YYYY-MM-DD`）：到已看才写，只增不删（同另两个状态日期） |
| 「哪天看的」的读点 | 详情时间线的已看/首看行、合集弹窗季行副行、年书各轴 —— 一律改读「已看日期」 |
| 老笔记 | 读取层在**已看态**回落观影日期（那时它确实就是当初盖的章）；同时批量给库里的已看笔记补上「已看日期」 |
