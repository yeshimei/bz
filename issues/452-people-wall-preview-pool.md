# 452 封面墙成员 = 人物卡 ∪ 预览桶（导入过预览但没画过的人也要上墙）

## 现象（2026-09-25 用户报告）

「脸谱数据文件中有大琳，但是在面板上不显示。」

真实数据核对（`E:\Obsidian\叫我包仔\CONFIG\STORAGE\`）：

| 文件 | 内容 |
|---|---|
| `people.json`（人物卡） | 莫莫 1 张（已画） |
| `people-preview.json`（预览桶） | 莫莫 132 条、**大琳 18477 条** |
| `people-jobs.json` | 空 |

莫莫两处都有 → 墙上有卡；**大琳只在预览桶里 → 面板上根本没有她**。

## 根因

- 折子封面墙的成员只取 `PeopleStore.list()`（`people.json`）。
- 447 拍板「导入所选只进预览」、「画脸谱」才调 AI 并落 `ImportRecord`／建卡——
  于是**卡的建立被推迟到生成完成**，「导入过预览但没画过」的人在面板上无处可见
  （数据源弹窗的水位行是唯一线索，且要打开弹窗才看得到）。
- 451 已经为这种处境预置了「未画谱 / 待画」印章，但**卡本身不存在**，印章无从出现。

## 设计口径

**墙成员 = 人物卡 ∪ 预览桶联系人**（无卡者合成占位卡，**纯内存零写盘**）。

- 合成占位卡：`{ id = name, name, createdAt = 导入时间, imports: [合成导入记录] }`；
  合成记录取预览桶的素材口径（条数 / 首尾跨度）——**这就是「导入了什么」的真实写照**，
  让 `statsText` 计数、折子卡条数与跨度、详情头三处口径自动一致，渲染层零改动。
- 素材水位只在**卡上还没有导入记录**时补（有记录时的「预览桶更新」归数据源弹窗的「有更新」水位管，
  不在本轮扩面）。
- 无素材的桶（清空后残留）不建占位卡。

### 直写风险与兜底

合成记录**只喂渲染**：所有写入路径都走 `PeopleStore.mutate`（读盘上数据），不会把合成记录落盘。
唯一要兜的是「占位卡上写档案 / 随手记」——`mutate` 对盘上不存在的 id 会抛「人物不存在」，
故写前先 `ensureEntry(id)` 落一张空卡（真卡由此诞生，之后画脸谱就正常接上）。

### 预览桶读取缓存

18k 条的预览桶是 MB 级 JSON，`renderBody` 每次切视图都重读会卡。故按会话缓存，
在「导入预览成功」「关闭面板」两处失效。

## 分工 / 接口

- **src/people/ui.ts**（唯一改动面）：
  - `wallPeople()`：人物卡 ∪ 预览桶 → 渲染用的人员列表（`renderList` / `renderDetail` 共用）。
  - `poolRecord()`：预览桶 → 合成导入记录（无素材返回 null）。
  - `previewData()`：预览桶会话缓存（导入成功 / 关面板失效）。
  - `ensureEntry(id)`：占位卡写入前兜底建卡（`saveProfile` / `saveManualNote` 调用）。
- **render.ts / styles.css**：不动（451 的四态印章与折子卡已支撑「待画」呈现）。
- **jobs.ts / data.ts**：不动。

## 已知风险（本轮不修，记在此处）

- 删除人物目前只删 `people.json` 的卡、不清预览桶 → 若日后把删除入口补回来
  （`data-people-del` 现在**只有消费方没有生产方**，447/448 注释说「收进详情头图标工具条」
  但工具条里并没有），删掉的人会立刻以「未画谱」占位卡复活。补删除入口时必须一并清桶。
- 顺带发现：`data-people-del` / `data-people-merge` 均为死钩子，合并 / 删除当前无法触达。

## 验收

1. 预览桶有素材、`people.json` 没卡 → 封面墙上出「待画」折子，卡面条数 / 跨度取预览桶口径。
2. 已有卡（已画）不受影响，不重复出卡；卡上有导入记录时不覆盖成预览桶口径。
3. 点占位卡的印章 → 画脸谱（451 已实现，回归覆盖）；占位卡上存档案 → 先建空卡再写，不抛「人物不存在」。
4. `people.json` 在只看不写时**零变更**（合成记录不落盘）。
