# 466 — 聊天仓 v2：全量原始消息 + 派生 text + upsert + 内容哈希指纹

## Parent

`issues/460-people-face-restructure-spec.md`（spec）。门禁与工作流按 `AGENTS.md`。

## What to build

把现在**有损**的那一层升格为唯一权威存储（概念改称**聊天仓**，文件名保留）：导入后**全量**原始消息都在（补回原始码 / 发送者 / 消息 id / 语音时长 / 音频路径 / 图片定位 六个字段），另加一个**派生文本**字段存放合成后的消费文本（`[图片] 描述` / `[语音 N秒·情感] 转写` / `[表情·名]`），**文本为空 = 不进时间线**。

写入语义从「只补新条目」改成「同键覆盖」，并把断点指纹从「条数 + 末条键」改成**组装素材的内容哈希**。

动因是现网一个修不回来的事故：源里 28 条表情带名、仓里 52 条，append-only 语义导致两边永远对不上。

## Acceptance criteria

- [ ] 导入一位联系人后，聊天仓里原始消息条数与 `chat.json` 一致（不再少掉未命名表情 / 位置 / 名片那一批）
- [ ] 每条消息含原始码、发送者、消息 id、语音时长、音频路径、图片定位（有则存）
- [ ] 展示与素材组装只读「派生文本非空」这一行过滤；四个预览开关（语音 / 图片描述 / 视频 / 系统消息）行为与改前一致
- [ ] **同键文本再次导入会升级为新文本**（现网「仓 52 条 / 源 28 条」的场景必须被覆盖掉）
- [ ] 素材内容变化时在跑的生成任务被**判废**，而不是用旧素材静默续跑；条数不变但内容变也能判出
- [ ] 结构版本号升级；旧结构无就地升级路径，判废后从数据根重导
- [ ] 统计口径（消息 / 语音 / 总时长 / 图片）可从存储重算，且与改前一致
- [ ] 不引入新的外部进程写入者：聊天仓的写者仍是插件

## Blocked by

None — can start immediately.
