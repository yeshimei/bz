# Spec: 黑匣子域（bz 插件第 19 域）——v3 笔记化架构

Status: `done（v3 六票 01-06 全部落地，1108 测试全绿）`
Type: spec
Feature: blackbox-suite-plugin

> 本版由 grilling 会话（2026-08）重写：**三类条目笔记化落盘 + Obsidian 双链 + 实时同步**（ADR-0015）。supersedes v2 的 JSON entries 架构（v2 → v3 自动迁移，见「迁移」节）。所有 UI 决策（双输入框/按钮条件/面板标题/搜索切换/三命令）同会话定稿。

## Problem Statement

用户（叫我包仔）希望有一个长期累积个人「感触」的容器——**黑匣子**：任何想留下的信息（想法、从别人那里看到的有感触的东西、想搞懂的概念）都录入其中，AI 作为黑匣子的**意识体「包仔」**（有名字、有记忆、有偏好的「他者」，终局为可交流、可陪伴的伴侣）从这些内容中长出人格，未来可与用户交流。

v2 将三类条目存于 `blackbox.json` 纯 JSON——知识被锁在数据文件里，看不见、摸不着、无法双链。用户要求知识成为 **vault 一等公民**：概念/摘抄/想法落盘为独立笔记，用 Obsidian 原生双链组织（摘抄→来源、概念↔概念、想法→摘抄），来源笔记选区内原位注入链接；笔记即事实源，用户在 Obsidian 里直接编辑笔记（改标题/改内容），黑匣子实时同步。

## Solution

bz 新域 `src/blackbox/`（已实现 v2 骨架，v3 重构数据层）：三类条目笔记化落盘 `黑匣子/概念|摘抄|想法/*.md`（**笔记即事实源**，frontmatter 字段冻结，ADR-0015）+ `CONFIG/STORAGE/blackbox.json` v3 降级为**派生层 + 索引**（人物画像/事件/复盘/对话/情绪词表 + id→路径映射）。UI = 录入弹窗（`bz-blackbox-capture` + 三个类型直达命令）+ 中央对话弹窗（`bz-blackbox-open`）+ 流式主面板（`bz-blackbox-panel`）+ 复盘（`bz-blackbox-review`）。AI 复用 `core/createAI`（DeepSeek 优先 → Ollama 回退）。

### 领域模型

- **三类条目（全部笔记化，笔记即事实源）**：
  - **概念与实体 (concept)**：`黑匣子/概念/<概念名>.md`。正文 = AI 生成定义（百科式，可编辑）；关联概念 = 正文底部 `- 关联：[[概念名]]` 双链（AI 自动构建）。**纯知识卡片，无感触外壳**。
  - **文献笔记 (literature)**：`黑匣子/摘抄/<AI 标题>.md`。正文 = 摘抄文本 + 底部 `来源：[[笔记]]`（或 URL 文本）与 `关联概念：[[…]]`（名词表勾选落盘为双链）。带感触外壳。
  - **核心知识 (thought)**：`黑匣子/想法/<AI 标题>.md`。正文 = 想法文本 + 底部 `来自：[[摘抄]]`（提炼想法带出时）。带感触外壳。
- **标题规则**：概念 = 概念名（冲突加 `-N`）；摘抄/想法 = **保存时 AI 生成**（摘抄优先复用「分析名词」结果；AI 不可用降级正文前 20 字，去空白、冲突加 `-N`）。文件名清洗非法字符（`\/:*?"<>|`）。
- **来源笔记 (Source Note)**：捕获时选中文字所在笔记。摘抄笔记经 `[[来源]]` 双链关联；捕获时在来源笔记选区内**原位注入** `[[目标笔记|原文字]]`（显示不变，见「原位注入」节）。来源笔记绝不写入其他内容（铁律 #1 的**显式豁免仅限此一种写入**）。
- **感触外壳**（literature/thought 持有，concept 无）：情绪标签（24 词多选 ≤3，无强度）+ 涉及的人（画像选择器，≤5）+ 场景（可选）——全部落盘为**笔记 frontmatter**。
- **人物画像 (profile)** / **事件 (event)** / **人格档案 (persona)** / **复盘**：派生层语义不变（v2 原样），数据仍在 blackbox.json；AI 提炼输入从 JSON entries 改为**读笔记正文 + frontmatter**。
- **三层记忆（对话时）**：感触检索（笔记内容，TF-IDF 沿用 v1）+ 人格档案 + 对话历史。
- **录入辅助**：🔍 查概念（文献/想法选中词查定义）、⚡ 联想、❓ 追问（想法），不打断录入流。


#### 正文约定（冻结）

- **概念**：定义文本 + 底部 `- 关联：[[概念A]] [[概念B]]`（AI 自动构建）
- **摘抄**：摘抄文本 + 底部 `来源：[[来源笔记]]`、`关联概念：[[概念A]]`（名词表勾选落盘）
- **想法**：想法文本 + 底部 `来自：[[摘抄笔记]]`（提炼想法带出时）

面板/搜索/AI 读取统一解析 frontmatter + 正文；关联区 `[[…]]` 解析为卡片 chips。

### 双链约定与来源笔记原位注入

**双链方向（生成笔记 → 目标，反链靠 Obsidian 原生反链面板）**：

- 摘抄 → `[[来源笔记]]` + `[[关联概念]]`
- 概念 ↔ `[[关联概念]]`（相互，随录入动态维护）
- 想法 → `[[摘抄]]`（提炼想法带出时）
- 用户 rename 笔记时 Obsidian 自动更新全库 wikilink，插件索引按 frontmatter id 重映射

**原位注入（铁律 #1 显式豁免，唯一写入来源笔记的动作）**：

- 触发：录入概念/摘抄且调用时有选中文字
- 动作：保存时把来源笔记中**选区原文替换为 `[[目标笔记|原文字]]`**——恒用别名形式，保证显示内容仍是原文字（概念目标 = 概念名；摘抄目标 = AI 标题）
- 守卫（任一命中则跳过注入并 toast「选区位于代码块/元数据内，未插入链接」）：选区与 frontmatter、代码块（```/~~~）、数学块（$$）重叠；选区原文已是 `[[…]]` 包裹
- 豁免边界：仅此一种写入；其余笔记格式一律不可动

### 实时同步（笔记即事实源）

- **内容编辑**：`metadataCache.on('changed')` → 命中 `黑匣子/` 下文件 → 重建索引 + 主面板 open 时 `refreshAll`
- **改名/删除/新建**：`vault.on('rename'/'delete'/'create')` → 索引按 frontmatter id 重映射/移除 + 面板刷新
- **对话/复盘/事件提炼**：读取时总是读最新笔记（不缓存正文）
- 用户改标题或改原文 → 黑匣子面板/AI 上下文实时跟随

### 录入弹窗（capture）

- **概念（直达命令）**：概念名输入框（单行）+ 文本输入框（自适应行高 ≤8 行）。按钮：**文本输入框有内容 →「确定录入」/ 空 →「生成卡片」**（内容判定，无 generated 标志依赖；无重新生成入口）。生成 = AI 写定义进文本输入框（可编辑）。
- **摘抄（直达命令）**：摘抄文本（自适应 ≤8 行）+ 来源输入（有选中文字时自动填充来源笔记名）+ 📋分析名词（AI：标题建议 + 名词表 + 提炼想法）。
- **想法（直达命令）**：想法文本（自适应 ≤8 行）+ ⚡联想 / ❓追问。
- **锁定**：由**选中文字自动填充**的概念名/摘抄文本**只读**（用户不可编辑——保证原文与笔记内容一致）；手动输入与 AI 生成内容始终可编辑。
- **感触外壳**（文献/想法）：情绪胶囊多选 ≤3 + 涉及的人（画像选择器：匹配已有/新建/仅存名字 ≤5）+ 场景。
- **保存**：三个直达命令**保存后直接关闭弹窗**；旧 `bz-blackbox-capture` 保持引导式循环（类型选择 → … → ✓ 完成回类型选择）。
- **保存动作链**：写笔记（frontmatter + 正文 + 关联区）→ 更新索引 → 原位注入（概念/摘抄 + 有选区时）→ 触发复盘阈值检查。
- AI 不可用：标题降级/分析降级/生成降级，纯文本照常保存（永不拒收）。

### 主面板（panel，v3 流式）

- **header**：左标题 **「黑匣子」**（无 emoji、无「N 条内容」）；右动作区 ✏️录入 / 👤人物 / 🕐时间线 / **🔍搜索（切换显隐）** / ⚙️设置 / ❌关闭（关闭在最后）。🔍 图标在 ⚙️设置 前；点击切换搜索框显隐，**显示时高亮**。
- **搜索框**：默认隐藏；显示时宽度 100%；防抖 300ms；范围 = 文件名/定义/摘抄/想法/来源 + 情绪 + 人物；**隐藏即清空已输入关键词并重渲染**（每次打开面板回到默认隐藏）。
- **类型标签栏**：🧩概念 / 📎文献 / 💡想法 多选（Set），默认空集 = 全部。
- **时间流**：日期分隔条吸顶 + 卡片混排，createdAt 降序（新在上）；批次 BATCH 20 + 滚到底加载 + 「已显示所有内容」。
- **卡片**（纯展示，无跳转图标）：概念 = 名 + 定义 + 关联 chips；摘抄 = 来源 + 文本 + 术语 chips；想法 = 文本 + 情绪/人物/场景 chips。
- **数据源**：索引 → 笔记（frontmatter + 正文），经实时同步保持最新。
- **人物弹窗 / 时间线弹窗**：v2 原样保留（header 👤/🕐 入口，完整度不变）。
- DOM 约定：`#bz-blackbox-panel`、`#bz-blackbox-panel-title`（文案「黑匣子」）保留。

### 对话面板（open）

v2 原样：中央弹窗 + 三层记忆（感触检索读笔记内容 → TF-IDF）+ 复盘产物入对话流。

### 迁移（v2 → v3，load 时自动、幂等）

- entries 非空 → 逐条生成笔记：概念标题 = name；文献/想法标题 = 正文前 20 字（去空白；迁移不调 AI，AI 标题仅用于新录入）
- frontmatter：id/type/createdAt + 感触外壳 + 卡片盒导入可选字段（category/tags/summary）
- related/terms（v2 id 数组）→ 解析为概念名 → 正文关联区 `[[名]]`
- 幂等：按 id 检查（index 已含或笔记已存在 → 跳过）；单条失败留在 entries 段下次重试
- 完成后 entries 段删除、index 建好、meta.totalEntries 更新

### 降级链

1. **AI 不可用**：标题降级前 20 字；概念生成降级直接录入（定义 = 概念名可编辑）；名词表分析/事件提炼/复盘/对话全部降级（沿用 v2）——录入与浏览始终可用，toast「AI 服务不可用」。
2. **AI 部分失败**：DeepSeek 失败回退 Ollama（同闪念 `AI.ask` 模式）；单条失败不影响已保存内容。
3. **笔记缺失/损坏**：frontmatter 解析失败 → 该条跳过并保留索引重试；索引指向不存在的文件 → 面板/检索跳过；blackbox.json 解析失败 → 空库初始化并备份坏文件（jsonStore 语义）。
4. **检索不可用**：对话检索降级为关键词/最近笔记（文本检索兜底）。

## Implementation Decisions

- **笔记即事实源**（ADR-0015）：面板/搜索/复盘/对话/事件提炼全部读笔记；blackbox.json 只存派生层 + id→路径索引；不设 JSON 镜像、不做双写回读。
- **frontmatter 冻结**：id/type/createdAt/emotions/people/scene/source 一旦落盘不可改；正文关联区是唯一放双链的地方。
- **关联区双链 vs 机器字段**：关联概念/来源/来自一律用正文 `[[…]]`（Obsidian 原生解析、rename 自动更新、用户在笔记里可见可改）；机器字段（id/type/createdAt/外壳）放 frontmatter。
- **原位注入**：唯一写来源笔记的动作，恒用别名形式 `[[目标|原文字]]` 保证显示不变；带四重守卫；铁律 #1 豁免范围仅此一种写入。
- **标题**：摘抄/想法 AI 生成于保存时（摘抄复用分析结果），降级前 20 字；概念 = 概念名；文件名冲突 `-N`。
- **锁定**：选中文字自动填充的概念名/摘抄文本只读（内容 ≡ 选区），手动输入/AI 内容可编辑。
- **实时同步**：metadataCache changed + vault rename/delete/create 事件 → 索引重建 + 面板 refreshAll；不缓存笔记正文。
- **按钮状态**：概念文本输入框**内容判定**（非空 → 确定录入 / 空 → 生成卡片），不用 generated 标志；无重新生成入口。
- **命令**：三个直达命令保存后直接关闭；`bz-blackbox-capture` 外部约定保留（launcher/热键/主页.js）。

## User Stories

1. 作为用户，我希望概念/摘抄/想法落盘为 `黑匣子/` 下的独立笔记，以便知识成为 vault 一等公民，用 Obsidian 原生的方式浏览、双链、图谱。
2. 作为用户，我希望摘抄笔记自动链接 `[[来源笔记]]` 与 `[[关联概念]]`，概念笔记互相 `[[关联]]`，想法笔记 `[[来自摘抄]]`，以便知识网络自然生长。
3. 作为用户，我希望选中笔记文字后录入概念/摘抄时，原文被替换为指向新笔记的双链（显示仍是原文字），以便在原位点击即可跳到黑匣子内容。
4. 作为用户，我希望原位注入对代码块/frontmatter/数学块/已是链接的选区自动跳过，以便笔记格式永不损坏。
5. 作为用户，我希望摘抄和想法保存时由 AI 自动生成标题（失败降级正文前 20 字），以便文件名可读且零负担。
6. 作为用户，我希望三个直达命令 `bz-blackbox-capture-concept/-literature/-thought` 保存后直接关闭，以便快速连续录入。
7. 作为用户，我希望在 Obsidian 里直接修改黑匣子笔记的标题或内容后，主面板/AI 实时同步，以便笔记即事实源。
8. 作为用户，我希望概念录入页有概念名输入框和文本输入框：文本框有内容显示「确定录入」、为空显示「生成卡片」，以便 AI 生成与手动输入同一条路径。
9. 作为用户，我希望选中文字自动填充的概念名/摘抄文本不可编辑，以便笔记内容与原文保持一致。
10. 作为用户，我希望主面板标题只显示「黑匣子」，以便界面干净。
11. 作为用户，我希望主面板搜索框默认隐藏、🔍 图标（⚙️设置 前）切换显隐、隐藏即清空关键词，以便需要时才展开。
12. 作为用户，我希望概念录入时输入名词由 AI 生成知识卡片（定义 + 自动关联），我只确认是否录入，以便零负担建知识背景。
13. 作为用户，我希望摘抄录入时粘贴摘抄与来源，AI 提取概念给出名词表勾选关联，以便摘抄与已有知识建立联系。
14. 作为用户，我希望摘抄录入可展开「提炼想法」，摘抄引出的想法同一次录入完成，以便记录完整语境。
15. 作为用户，我希望想法录入时可选 AI 辅助（联想/追问），以便录入不被打断又有伴侣在场感。
16. 作为用户，我希望文献与想法条目有感触外壳（情绪 ≤3、涉及的人、场景）落盘 frontmatter，概念条目没有，以便记录"此刻的我"。
17. 作为用户，我希望主面板流式布局：类型标签多选 + 搜索 + 时间流，默认显示全部，按录入时间倒序，以便打开即浏览。
18. 作为用户，我希望「涉及的人」可从已有画像选择或现场新建画像，未建画像只存名字，以便冷启动不打扰。
19. 作为用户，我希望人物画像由 AI 从条目中提炼维护（印象/情绪聚合/事件投影），我可编辑且改过字段 AI 不再覆盖，以便画像既有 AI 维护又有我的主权。
20. 作为用户，我希望事件由 AI 全自动提炼，推测事件虚线 + ❓ 可确认/删除，改过的 AI 不再碰，以便零负担获得时间线又不被幻觉误导。
21. 作为用户，我希望每 10 条新感触（或手动）触发复盘且静默执行，复盘产物（人格档案成长/新人物提示/事件汇报）出现在对话面板，以便看到包仔在生长。
22. 作为用户，我希望通过 `bz-blackbox-open` 打开中央对话面板，包仔基于三层记忆与我交流，以便它"认识我"。
23. 作为用户，我希望 AI 服务不可用时录入与浏览仍可用（标题/生成/分析降级），以便黑匣子永不拒收我的输入。
24. 作为用户，我希望情绪词表在设置中可增删（预置 24 词），以便词表随我的语言生长。
25. 作为用户，我希望存量 blackbox.json 数据自动迁移为笔记（幂等、失败条目重试），以便旧数据不丢。
26. 作为用户，我希望人物画像与事件时间线为面板右上角独立弹窗（👤/🕐，完整度保留），以便主视图保持单一时间流。

## Further Notes

- 铁律 #1 豁免记录：**原位注入是唯一写来源笔记的动作**，写入内容固定为 wikilink，带四重守卫；其余笔记格式仍一律不可动。此豁免经用户（叫我包仔）在 grilling 会话明确要求。
- 「摘抄」为日常用语，规范术语是**文献笔记**（CONTEXT.md）；「来源笔记」为本版新增术语（同上）。
- 定位（行级跳转 + 悬浮回显）经用户决策砍掉（「有双链了就不需要 LOC 了」），相关测试/字段不实现。
- 旧命令 `bz-blackbox-capture` 的引导式（含概念连接展示步骤）保持不变；三个直达命令走简化流。
