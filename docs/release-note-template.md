# Release note 样例（v1.35.0 口径）

下次发版只换「更新日志」那一节里的条目，「安装 / 离线资源包 / 反馈」三节连标题带措辞都不要动。

## 标题层级（2026-10-30 定）

四个一级标题并列，新增与修复是「更新日志」的下级：

```text
# 更新日志          ← 版本内容
  ## ✨ 新增
  ## 🐛 修复
# 安装              ← 以下三节固定不动
# 离线资源包
# 反馈
```

「更新日志」这个一级标题容易漏——只写 `## 新增` 的话，它和下面「安装」「反馈」同级，
读起来是四个平级的节，看不出前两块是一组、后三块是另一组。

## 条目格式（2026-10-30 定）

```markdown
- **标签** ：说明一句话
```

- **标签说人话，不用脚本域名**。changelog 里的域名（`core` / `global` / `other`）是给程序归类用的，
  照搬进正文会出现三个「其他」、两个「通用」，读起来像日志而不是更新说明。
  标签写这条改动本身叫什么：赞赏、关于组、剪藏本、更新日志、番茄钟……同名可重复出现。
- **全角冒号**：，前后各半个空格的位置 —— 只写 `**标签** 说明` 时标签和说明会糊在一起，
  用半角冒号在中文里又太挤。冒号后不再加空格。
- **分组标题带 emoji**（✨ 新增 / 🐛 修复 / ⚡ 优化）：GitHub 会渲染成彩色，是 Release 正文里
  唯一带颜色又不会被 sanitize 的东西——内联 `style` / `class` / `<style>` 一律被 GitHub 剥掉，写了不显示。
- **不用表格排条目**：Release 正文宽度约 830px，两列表格行高和留白都比列表大，十条能占半屏，
  还多出一个「域」表头。
- 条目可**删可合并**：正文是给人快速扫的，与插件内更新日志页面不必逐字对齐。
  同一处功能一版里改了又改（如「加了图标」→「去掉三行图标」），日志里已经并成最终态
  （[docs/changelog.md](changelog.md)「同一版本内的修复」），正文照最终态写、别再分条列出过程。

# 安装

1. 到 [Releases](https://github.com/yeshimei/bz/releases) 下载最新的 `bz-<版本>.zip`
2. 解压到 `<你的 vault>/.obsidian/plugins/` 下，得到一个 `bz/` 文件夹
3. 重启 Obsidian → 设置 → 第三方插件 → 找到「bz」→ 启用

# 离线资源包

在线资源（皮肤、工具包、手册、影视索引）下不动时，用 `bz-offline-<版本>.zip`。解压出的 `downloads/` 整个放进插件目录，再回插件点一次下载——本地校验通过就直接用，不联网。

```text
.obsidian/plugins/bz/
├── main.js
├── manifest.json
├── styles.css
└── downloads/
    ├── manifest.json
    ├── skins/
    └── tools/
```
