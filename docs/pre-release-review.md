# 发布前置 review

发版的第一道工序：把「上一次发布 → 当前 HEAD」整段改动读一遍，出一张**编号清单**给用户挑，
他只挑要修的，修完才进七步。范围、维度、清单格式都固定，不临场发挥。

## 什么时候、什么范围

- 听到「发布」之后、跑七步之前，第一件事就是它。**没有清单就没有发布。**
- 范围 = 上一个 tag 到 HEAD：

```bash
git log --oneline v<上一版>..HEAD
git diff --stat v<上一版>..HEAD
git diff v<上一版>..HEAD -- src/
```

- 只读。这一阶段**不改任何文件**，清单出来就停住等挑号。
- 看的是「这一版要发的东西」，不是已发布的东西——已经推出去的 tag 不改写。

## 四个维度

### 1. 代码

- 域边界：域直接 import 别的域的内部实现、`core` 里冒出业务逻辑、同一件事两处实现。
- 数据落位：路径/键走该域 `data.ts` 的常量（缺省数据根 `storage/`），没有裸拼路径。
- 命令 ID 仍是 `bz-<域>-<动作>`；通知正文不带 emoji。
- 遗留物：`console.log`、注释掉的代码、`TODO`、未定稿探索稿混进 `src/`（探索稿只该在 `.scratch/`）。
- 类型退化：新加的 `any` / 强转 / `@ts-ignore`，以及「为了过编译」放宽的签名。

### 2. 样式与 UI

- 样式只落在 `src/<域>/styles.css`；没有内联视觉样式、没有运行时注入 `<style>`
  （例外只有 ADR-0199 皮肤包、ADR-0243 沙箱框文档内部两处）。
- 禁项：`scrollbar-width: thin/auto`、自绘 thumb。
- 新弹窗穿了本域皮（`uiModal` / `openFlowDialog` 传 `className`），不是裸中性壳。
- 遮罩之上没有压一层可点的铺满层（点遮罩关不掉的经典死法）。
- 深色主题用 `--sp-*` 变量，没有写死的浅底/深字；窄屏（≤768px）不错位、不横向溢出。

### 3. 稳定性

- 未捕获的 promise、`async` 里漏 await、并发写同一个文件。
- 监听与定时器有没有在卸载处注销（`onunload` / `registerEvent`）。
- 失败路径：读写失败、远程资源下载失败、离线时的降级表现。
- 边界数据：空列表、几千条、路径含中文/空格、跨年跨月。
- 老数据迁移：改了落盘格式却没有迁移分支 = 升级后数据读不出来。

### 4. 增强建议

- 不算缺陷，是这版改动顺带能做且成本低的：新样式/新接口没被同类页面复用、同一交互两套写法。
- 一律标注「不影响发布」，默认留到下版；只有用户选了号才做。

## 清单格式

对话里直接给（要留档就落 `.scratch/review-v<版本>.md`）。

**一律用编号列表，不许用表格**（2026-11-02 用户要求：「不要用表格的形式，看起来很
不方便」）——聊天窗里的表格会被挤成窄格子，长句子折成三四行，比列表难读。每条一段，
档位与维度标在条头，**不写位置、不写代码细节**：

```text
一共 4 条：P0 2 条、P1 1 条、P2 1 条

1. **P0 · 代码** —— 换了数据目录就会找错地方，读出来是空的
2. **P0 · 样式 UI** —— 弹窗点空白处关不掉
3. **P1 · 稳定性** —— 某个来源下载失败时整块列表空白
4. **P2 · 增强** —— 收藏本同一套卡片样式各写了一遍
```

- **编号一旦给出就不再变**：用户按号挑，不重排、不合并、不换号。
- **每条只写一句人话**（2026-11-08 用户要求：「用通俗易懂的一句话说清楚，不需要放任何代码的
  细节」「也不要附上位置」）：说清「什么情况下会出什么事」，不出现文件名、函数名、变量名，
  也不附 `文件:行`；判据自己留底，等用户挑了号再去定位。例：写「下载没下全，最后会悄悄交出
  一段被截短的视频」，不写「下载层没校验字节数」。
- 每条必须写得出**判据**（哪个文件哪一行、什么条件下会坏）——判据自己留底，不写进清单。
  写不出判据的不列——「建议重构一下」这种条目是在浪费他的时间。
- 排序：P0 阻断（坏数据 / 关不掉 / 白屏 / 升级读不出库）> P1 该修 > P2 建议。

## 挑完之后

1. **只修被选中的号**，顺手能带上的不擅自扩大；过程里新发现的问题补一条等下一轮，不夹带修。
2. 修完回到发布流程第 1 步（七步）。改到落盘格式、交互口径的，按约定补 ADR 与 `CONTEXT.md`。
3. 没被选中的 P0/P1 落进 `issues/`，别在对话里丢掉；P2 想留就留。
