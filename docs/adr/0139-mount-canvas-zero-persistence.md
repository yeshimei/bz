# ADR-0139 挂载白板：数据与位置零落盘，布局用确定性种子

- 状态：已接受（2026-09-14，grill 评审拍板；**实现待排期**——本条解决 HANDOFF §8.1 那条「布局数据落盘位置未拍板，实现前需一个新 ADR」）
- 关联：ADR-0137（挂载点 / 挂载树）/ ADR-0138（语义建议）/ `.scratch/mount-canvas/HANDOFF.md` §8.1、§8.2
- 影响：`src/knowledge/`（画布视图与数据层）、插件数据存储（**不新增**）

## 背景

挂载白板是「以某张卡片为主卡」的派生视图，用户定调：**所有数据动态生成**。那么图上还有哪两样东西**可能**需要落盘？

1. 用户手动摆过的**节点位置**——不落盘，重开就回到算法摆的位置；
2. **AI 建议候选集**——ADR-0138 已定「不写 related」，但候选集本身是否缓存（下次打开省一次算力）此前没定。

HANDOFF §8.1 把「布局数据落盘位置（frontmatter / 插件数据文件 / .canvas 互操作）」列为实现前必须拍板的待定项。

## 决策

1. **白板零落盘**。挂载树的节点、边、布局坐标一律不落盘，每次打开从卡片目录与文献目录现算。全插件唯一的落盘项仍是 ADR-0137 的**手动挂载**（写卡片 frontmatter）。
2. **位置用确定性布局**。力导向的初始种子由「主卡 + 节点顺序」确定，**不吃随机数**：同一张主卡、同一份数据，每次打开得到同一张图（可复现、可截图比对、测试可在 node 环境断言）。用户拖动只是**当次会话的临时视角**，关闭即丢。
3. **AI 建议候选集落本地缓存**（2026-09-14 同轮修订——初稿写的是「不落盘」，用户定：「结果缓存到本地，下次打开可以继续用，给一个按钮可以重跑」）。候选生成后写入**域内单文件**（`CONFIG/STORAGE/` 下一个 knowledge 域的 json，与 memo.json / review.json 同规格，可单测、可手删），下次打开直接读；白板上给一颗**「重新生成」**按钮强制重跑。
   - **失效按卡片正文 hash**：每片缓存记下生成时的正文 hash，改哪张卡就只让那张卡的建议过期重跑（不连坐全库）。
   - **缓存里存**：候选的锚点范围（词/句在正文中的位置）+ 目标路径 + 一类形态 + 一句话理由 + 打分 + **处置态**（待定 / 已固定 / 已否决）。
   - **否决要留痕**（用户定：「如果用户主动清除了一条链接，下次再让 AI 生成建议时，就不要再生成相同的」）：点过「取消」的候选以**否决记录**长期保留，生成阶段先按它过滤，**同一「锚点 → 目标」不再重复推荐**；点「固定」的那条也保留（转成实线双链后仍留档案，便于回看当时的理由）。
   - **无回答不冒充实答案**（2026-09-14 实机修复补记）：裁判没给出可用回答（空回答 / 认不出一条）时返回 `no-answer` 且**不落缓存**，下次打开重跑——旧口径把「答案被解析丢掉」也写成 fresh 空片，于是每次打开都是「已缓存建议」零候选，故障被缓存永久掩盖。
   - **缓存片带版本号**（`SUGGEST_CACHE_VERSION`）：解析 / 取数口径变更即 +1，旧片（无 `ver` 或版本不符）一律按失效处理、自动重跑，不靠用户手清缓存。
   - 从候选变成持久数据的通道仍只有一条：点「固定」→ 正文锚点写 `[[wikilink]]`（ADR-0138 §3）。

## 后果

- 换来：挂载树零脏数据、零同步冲突；换库 / 改名 / 删链 / 改双链全部自动跟随；布局可在测试里断言。**建议缓存是唯一的派生落盘物**，它的失效策略要单独拍（见后续轮次）。
- 代价：用户手工理过的构图**不保留**（每次重开回到算出来的样子）；大图每次打开都要重跑布局 + 路由，**性能预算必须卡**（HANDOFF §8.2 已标）。
- 与 Obsidian 官方 Canvas 的关系：**不互操作位置**。将来若要导出/live 同步 `.canvas`，是新增功能，需另立 ADR（挂载树的边是派生的，`.canvas` 的边是实体的，转换规则要单独拍）。
