# ADR-0184：设置项瘦身（第二大脑四行 + IP/远程地址两行）与 JEV 常开自动配置

- 日期：2026-09-24
- 状态：已采纳
- 关联：issue 424（落地清单）、ADR-0182/issue 422、ADR-0183/issue 423、ticket 122

## 背景

设置面板长期承担「凡有内部参数就给一个输入框」的角色，导致大量无人调整、调错即坏的档位
（第二大脑的分块最小长度 / 上下文限制 / 防抖 / 轮询四项、JEV 的开关 / 端点 / 超时三项）与
两处只读自查行（本机局域网 IP、移动端远程地址）。用户逐图拍板：能固化的固化、能自动化的自动化、
只剩真正需要人来决定的（服务商与模型）留在面板上。

同时 JEV 判定通道此前默认关闭 + 手填端点，与 LLM/Embedding 的「选服务商 → 取模型」体验割裂；
而端点漂移（DHCP 换网段）会让手机端远程地址静默失效，人工核对成本高。

## 决策

1. **第二大脑四项检索档位退场**：「段落最小长度」「上下文限制」删除且**不做限制**（分块全留、
   上下文不截断）；「防抖延迟毫秒」「光标轮询毫秒」删除并**固化为常量**
   （`SEARCH_DEBOUNCE_DELAY = 300`、`CURSOR_POLL_INTERVAL_MS = 500`，`secondbrain/config.ts`）。
   四键由 `migrateRetiredSecondBrainKeys` 在 onload 清除（无旧键不落盘）。
2. **IP 自查行与远程地址行退场，写入改自动跟随**：删除「本机局域网 IP」（含移动端引导行）与
   AI 面板「移动端远程地址」输入框。`ensureRemoteOllamaUrl()` 升级为**归属判定 + 跟随**：
   - 空值 → 写探测值；
   - 当前值 == 上次自动写入记录（新键 `secondBrainRemoteOllamaAuto`）→ 跟随新 IP；
   - 无记录但形态为插件写出的 `http://<IPv4>:11434`（存量迁移）→ 先认领再跟随；
   - 其余（手改地址）→ 一律不动。

   即：**面板不再要求人工核对，但「人写的地址」永不被覆盖**。
3. **JEV 判定常开**：删除「启用 Jev 判定」`jevEnabled`；有密钥即启用，无密钥自动回落语言模型
   （ADR-0181 的回落链不变）。
4. **JEV 端点改服务商注册表**：「Jev 服务商」select 取自 `JEV_PROVIDER_REGISTRY`
   （现仅 Typesafe 一家，判定端点与模型列表 URL 均由其决定）；`jevEndpoint` 键退役。
5. **JEV 超时固定**：`jevTimeoutMs` 退役，固化 `JEV_DEFAULT_TIMEOUT_MS = 10000`。
6. **JEV 模型在线获取 + 默认 `jev-latest`**：模型行保留，行内「获取模型」走
   `openModelPicker`（与 LLM/Embedding 同款，动作 await 到弹窗关闭再回显）；
   `fetchJevModels()` 经 `requestUrl` 直连 `https://api.typesafe.ai/v1/models`（该域无 ACAO 预检
   响应，故不提供 fetch 回退）。存量默认 `jev-1.13.0`（线上已下架）由
   `migrateRetiredJevKeys` 改写为 `jev-latest`。
7. **模型拉取失败不阻塞使用**：获取按钮仅提供便利，拉不到时报错提示，用户仍可手填模型名；
   默认值 `jev-latest` 保证零配置可用。

## 后果

- 设置面板可见项数变化：`ai` 11 → 12（Embedding 收「Ollama 本地 URL」、JEV 组三行取代五行，
  净 +1 由 Ollama 本地 URL 行贡献）；`secondbrain` → 6。基准锁定于 `tests/sp-contract-lock.test.ts`。
- 常量固化后调参需改代码发版；这是有意的——四项参数无人在用，暴露反而制造误调。
- 已知局限：**手填了一个指向他机、且恰好是 `http://<IPv4>:11434` 形态的地址**（如 `http://192.168.1.8:11434`
  而本机探测到 `192.168.1.45`）时，若当时尚无自动写入记录，会被一次性认领并跟随本机 IP。
  该形态与插件自身输出无法区分，属 ADR-0183「只补空值」局限的收窄（原局限是任何非空值都不跟随、
  含插件旧值）；如需保留他机地址，改用非默认端口（如 `:8080`）即可被判定为人工值。
- `secondBrainRemoteOllamaAuto` 为内部记录键，面板不暴露、用户无需理解。
- 存量两类静默变化（迁移不可逆，用户不感知）：
  1. 曾手填过自定义 `jevEndpoint` 的配置，端点改由服务商决定，自定值随键删除而丢弃——
     目前注册表只有 Typesafe 一家，等于回到官方端点；
  2. 曾关掉 Jev 开关但**保留着密钥**的配置，`jevApiKey` 仍非空 → 升级后判定通道被打开
     （回落链不变，只是判定重新走 Jev）。若要维持旧行为，清空密钥即可。
- 另：手改 `data.json` 清空远程地址会在下次启动被重新探测填入（这是有意的自愈语义，
  面板已无「关掉自动」的开关——要固定某台机器地址请填非默认端口形态）。
