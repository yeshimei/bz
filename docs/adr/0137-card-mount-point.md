# ADR-0137 卡片挂载点：卡片名即汇集点，时间线 + 双链连线成树呈现

- 状态：已接受（2026-09-14，grill 评审拍板；**设计定稿，未实现**——静态原型 `.scratch/mount-canvas/`）
- 关联：ADR-0112（知识盒三部）/ ADR-0122（MarkdownRenderer 追加语义）/ ADR-0135（录入名词与影像两界面）/
  ADR-0136（图版）/ issue 298（link agent 迁移搁置——自动挂载与 AI 关联解耦）
- 影响：`src/knowledge/{ui,data}.ts`、`src/knowledge/styles.css`、`prototypes/knowledge/*`

## 背景

用户的旧体系笔记在卡片盒，想整理进文献盒时遇到「纯知识背景 vs 含自己思考」的分流问题
（2026-09-14 上午的讨论）。由此演化出的方案不是搬笔记，而是**让卡片名成为挂载点**：
以卡片「DeepSeek」为例——创建同名卡片后，名字即成为汇集点，固定挂本卡与同名知识背景文献，
卡片里的双链自动挂载进来，用户还可手动挂其他卡片。知识背景与自己的思考各归其位、天然互链，
旧笔记整理从「迁移」问题变成「命名对齐」问题。

2026-09-14 出静态 HTML 原型（无限画布 + 挂载时间线 + 双链连线成树），grill 四问全部落定。

## 决策

### 1. 挂载点 = 卡片名，派生视图而非新实体

- 卡片名即挂载点名。挂载列表 = **卡片本体（恒列第一位）+ 固定挂载 + 自动挂载 + 手动挂载**。
- 固定挂载的**同名文献按名字持续对齐**（非创建时快照）：文献目录里同名笔记随时录入随时顶上，
  两种诞生顺序（先卡后文献 / 先文献后卡）都成立；卡片改名后对齐对象跟名字走（feature 不是 bug）。
- 固定与自动挂载都是**实时读出、零落盘**（文献/卡片扫描 + 双链解析），只有手动挂载落盘。

### 2. 三种挂载来源（唯一落盘项是手动挂载）

| 来源 | 内容 | 落盘 |
|---|---|---|
| 固定 | 本卡第一位 + 同名文献 | 否（按名字对齐读出） |
| 自动 | 卡片内双链（frontmatter related + 正文 `[[…]]`），指向任何笔记 | 否（派生视图） |
| 手动 | 用户挂的其他**卡片笔记**（仅限卡片） | **是**——卡片 frontmatter 新键 |

- 手动仅限卡片是刻意约束：文献只能从同名/双链进来——卡是思考的组织核心，文献是背景素材，
  与「知识背景 vs 自己思考」的分流一致。
- 手动挂载**单向**：只记在卡片上，被挂笔记不回写；取消挂载零副作用。
- frontmatter 写入走纯字符串行扫描（`appendRelatedLine` 同路子），插件与评审壳两端共用、可单测。

### 3. 双链展开的六类内容形态

整篇笔记 / 标题+内容 / 段落（块引用 `#^blockid`）/ 图片 / 视频 / **卡片**（被挂的卡片继续长双链，成树）。
对应 Obsidian 的文件引用、标题引用、块引用与内嵌媒体解析。

### 4. 画布呈现（grill 四问拍板；树状结构 2026-09-14 二轮复核定稿；布局与连线 2026-09-14 修订）

- **无限画布**：拖拽平移 + 滚轮缩放。
- **树状结构，不是平铺**（二轮复核推翻首版「竖向时间线 + 右侧展开列」）：**主卡为根，主卡里的双链就是它的子卡**——从正文双链文字扯出一根直线线段直指对应的子卡，子卡的双链再往下挂孙卡；固定挂载（同名文献）与主卡同为根级。
- **网状布局（力导向）+ 单向流弱约束**（2026-09-14 修订，取代「发散树状布局」「代际列」「代际带松弛」）：节点在二维里自由散开——所有对斥力铺开、连线弹簧收紧、重叠硬推开；只留两条弱约束保住单向流——**子卡必须在父卡右侧**（软）与**每代一个很弱的 x 锚**（防漂移）。**没有列、没有带**：位置是力跑出来的（「规整缩进网格」「径向散摆」「代际列」「代际带松弛」四次否定后的合题；原型已落地：`.scratch/mount-canvas/transformer-real.html`，见 HANDOFF §3.1）。**连线画在卡片上层**（SVG overlay + pointer-events:none），穿过卡片时保持可见不被遮挡。
- **文献笔记吸附式呈现**（五轮复核后新增）：文献笔记是独立的呈现分类——**不拉线，直接吸附在所属卡片正下方**（堆叠面板，随卡片移动）；线段只用于卡片到子卡的连接。
- **连线：就近出盒 + A\* 栅格避障**（2026-09-14 修订）：起点是正文双链文字后的**锚点圆点**（一眼看出是哪句话链过去的）→ **就近出盒**（**四条边挑离锚点最近的一条**，含左缘——距离最近优先，绕卡的活交给路由器）→ 目标卡**近边进**。**离开盒子后不得进入任何盒子**：路由 = 卡片按格心落进 18px 栅格当墙 → A\* 求最短路（不许剪角）→ 拉直（精确线段判交、不给源卡/目标卡豁免）→ 逐段平滑成贝塞尔（切向三档递减，压卡的那段保持直线）。**只画严格跨代的边：同代互指与逆流一律不画**（与「回指祖先不显示」同属一条剪线规则——剪线不剪数据）。连线颜色区分六类形态（不变）。
- **建议线常驻**（2026-09-14 修订，取代「逐层手动点开」）：以主卡为根、可达的边全部常驻渲染，折叠与徽标方案废除（只剪回指祖先与弱关联，见 ADR-0138 §2.3 / HANDOFF §5）。
- **节点唯一、单向留线**（2026-09-14 修订）：A↔B 互指全画布只画一个节点、不重复展开子树；两根线里只留**严格跨代**的那一根（反向那一根不画，同代互指亦不画）。

### 5. 与现有「关联」区的关系

预览弹层的「关 联」区（related chips，只读）被「挂 载」区吸收——related 本就是双链，
是自动挂载的子集；界面上只留一个挂载区，条目标注来源（本卡/同名/双链/手动）。

## 后果

- 知识盒数据层几乎不动（扫描与解析能力现成），改动集中在知识盒 UI（画布视图 + 选择器 + frontmatter 键读写）。
- 旧卡片盒笔记的整理转化为命名对齐：有同名文献即自动配对；没有的要么是纯思考（留卡片盒），
  要么背景未录（补录一条同名文献）。
- 待实现时再定：frontmatter 键名、断链条目展示（失效不自动清）、双链指向盒外笔记的来源标注。
