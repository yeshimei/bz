# ADR-0221 · 录音单条删除的范围与确认强度（六处同清 · 原件可勾选 · 上锁即不删）

日期：2026-09-29 · 状态：已采纳 · 关联：ADR-0216（旁音留账）、ADR-0217（起点与派生物落点）、
ADR-0219（账本韧性）、issue 516 Q12 / Q13 / Q14

## 背景

一期录音行**没有任何删除入口**（只有 处理 / 续跑 / 重试 / 并仓 / 停止）。用户要求"允许删除某一条录音；
删除之后：没处理过就删文件，已处理就去删对应数据；插件册和脚本册都要一起删干净"。

域内术语先对齐（避免各说各话）：

- 用户说的「**插件册**」= 聊天仓（保库记录里的消息流，`type=9001` 的 `rec:<文件>:*` 消息）；
- 用户说的「**脚本册**」= 录音账本 sidecar（`<名>.turns.json`）+ 控制文件（`rec-control/<联系人>/<名>.control.json`）。

「一起删干净」是硬要求。这里有一个容易漏的连锁：**录音行是按 `recordings/` 目录列出来的**——
若只删账本不删原件，这条录音会立刻回落「待处理」（其实是想要的行为，见决策 2）；
反过来，**若删了原件却漏删仓内轮次，那些轮次就再也没有清理入口了**（行已不在，没人能再点它），
而它们仍在参与统计与画谱素材。

## 决策

1. **删除范围 = 六处同清**（一次性动作，逐项容错、单项失败不阻断其余）：

   | # | 落点 |
   |---|---|
   | 1 | 录音原件（**勾选时才删**，见决策 2） |
   | 2 | `<名>.turns.json`（脚本账本 / 转写成果） |
   | 3 | `<名>.meta.json`（起点等一等数据） |
   | 4 | `<名>.turns.md`（逐轮时间轴） |
   | 5 | `<名>.turns.json.<pid>.<n>.tmp`（落账半截临时档，按前缀扫） |
   | 6 | `rec-control/<联系人>/<名>.control.json`（控制文件——此前**没有任何代码清理它**） |

   外加聊天仓：按 `rec:<文件>:` 前缀清除消息，并重算 `kindCounts` 与 `stats`。
   派生物后缀单源在 `RECORDING_DERIVED_SUFFIXES`（ADR-0217 后果节的要求）：**这份清单同时决定
   「录音页列哪些行」与「删除时清哪些文件」**，漂了就会漏列或漏删，故有单测钉死。

2. **「同时删除录音原件」是一个勾选（默认勾选）**。勾 = 整条消失；不勾 = 只清我们的副本，
   行回落「待处理」，可重跑（适用于"改了阈值 / 重建了质心，想重转一遍"）。
   默认勾选 = 用户的默认意图（"删掉这条录音"）。两者都是**不可逆**的，故走二次确认（决策 4）。

3. **保险库上锁 → 整条不删**（实现期发现的完整性要求）。理由：删原件要求能同时清仓内轮次，
   而上锁时写不了仓。若照样删原件，仓里的 `rec:<文件>:*` 就成**清不掉的孤儿**（行已由
   `recordings/` 驱动，文件没了就没有删除入口），且继续参与统计与画谱素材。
   宁可先请用户解锁——"要么都清干净，要么不动"。

4. **确认强度 = 行内展开的二次确认，不上主密码门**。弹窗里列明代价：删原件？仓里有多少条轮次会被清？
   该联系人**是否已画过谱**（已画过则告知"正文是产物，不会随之改写——要反映这次删除得重新画谱，花钱"，
   **不自动重画**）。理由：录音原件来自用户自己的磁盘，删掉我们的副本 ≠ 素材灭失，与"删整条保库记录"
   （不可逆产物）代价不同级。若日后判断该同档上密码门，另开 ADR。

5. **处理中 / 排队中的行不给删除入口**：先「停止」/「移出队列」再删。理由：进程正握着账本与原件，
   边跑边删的文件状态不确定。

6. **删除不触碰脸谱正文**（画谱产物）。同 ADR-0217 决策 4 的口径：产物不是索引，不自动改写。

## 后果

- 一行上按钮按状态唯一出：`待处理→处理` / `排队中→移出队列` / `转写中→停止` / `已中断→续跑` /
  `失败→重试` / `待并仓→并仓`；`改起点` / `查看轮次` / `删除` 在可操作态并列（互不冲突）。
- 删除后 `refreshSuppStoreInfo` 重读统计并重画册页，计数立即可信。
- 上锁时点删除只得到一句提示，磁盘与仓**都不动**——不会出现"删了一半"的中间态。
- 测试面：`recordingArtifactPaths` / `recordingTmpPrefix` 的覆盖有单测；删除流程的"上锁即不删"
  与"六处清单"由 ui 层用例覆盖（fs 注入假件，不碰真实数据根）。
