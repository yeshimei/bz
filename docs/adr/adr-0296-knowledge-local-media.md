# ADR-0296 · 知识盒本机音视频导入（影像入口 · 音声类型 · 工具包 runLocal）

日期：2026-11-09 · 状态：已采纳 · 关联：ADR-0066（文献盒）、ADR-0067（分P/断点续跑）、
ADR-0071（AI 回迁插件侧）、ADR-0133（解析式录入）、ADR-0222（正文只校对不润色）、
ADR-0295（影像笔记自动分段）、issue 310（影像录入/处理两界面）

## 背景

知识盒「影像」只收 B 站链接——转文字、抽音轨这些活由外部「知识盒工具包」（`bili-downloader`）
完成，插件只调度。用户要「本地的视频和音频可以进行知识盒的转化，在影像当中增加一个导入按钮就行」，
并拍板：视频 + 音声都收、文件**复制进库**、剪辑与保留原件选项都保留、音频类的界面叫法为「音声」。
这是影像入口第一次出现「不是链接的来源」。

## 决策

1. **两个来源共用一个队列与一条 AI 链路**：任务新增 `sourceKind: 'url' | 'local'` 与
   `localPath` / `mediaKind: 'video' | 'audio'`。本地任务 `url` 留空（不占 URL 语义），
   `localPath` 存绝对路径（正斜杠归一）；存量数据无这两字段，按 `url` / `video` 兜底，零迁移。
2. **界面只有一处新增**：影像录入窗的链接行右侧加「导入」钮（原生文件对话框，桌面端专属）。
   选中后链接行整行让位给「本机」行（文件名 + 类型章 + 换文件），标题取文件名，
   **UP 主 / 分P / 清晰度三行隐藏**（本机文件没有这些概念），剪辑行保留（手填起止，时长未知）。
3. **类型命名落在标签上，入口与命令名不动**（用户选定的方案 A + 改词）：
   - 文献类型徽标：视频「影 像」、音声「音 声」；
   - 知识盒部壹入口仍叫「影像」，命令与首页入口仍叫「影像生成文献笔记」；
   - 处理队列标题仍「影 像」，副题改 `VIDEO / AUDIO · TO LITERATURE`；
   - 挂到笔记的量词：视频「个」、音声「段」、图版「张」。
   内部 `type` 值用 `video` / `audio`（界面词「音声」只是显示层，不污染数据）。
4. **处理链路**：插件把 `local: {path, kind}` 下发工具包；工具包新增 `runLocal`——
   读取中（ffprobe 时长）→ 提取音轨中（ffmpeg 抽 16k 单声道 wav，有起止按段切）→
   转文字中（与 B 站任务同一套 Python 引擎）→ 交付中（复制原件进交付目录，重名加序号）。
   **不下载、不分P、不压缩视频本体、不做断点续跑缓存**（没有「下载」那段可省，重跑最多重抽一次音轨）。
5. **文件复制进库、路径进交付目录**：交付目录沿用 `knowledgeOutputDir`（与 B 站视频同一处）；
   `keepVideo=false` 时只转写不复制（笔记正文无媒体嵌入）。库里那份是笔记尾部 `![[…]]` 的目标，
   文件被移动/删除时处理当场报「找不到文件」，不静默跳过。
6. **时长与标题的回填**：录入时不额外起一次 ffprobe（避免为填一个时长卡住录入）；工具包
   在「读取中」后经 `[bz-info]` 回传 title/duration/kind，插件按「只在空时回填」落库
   （与 B 站任务同一口径）。
7. **音频笔记的形态**：`type: audio`、无 `source` 键（本机文件没有出处链接，不写空 source）、
   `sourceTitle` 记原文件名、正文尾部嵌库内那份（Obsidian 原生音频播放器）。
8. **不做的事**：不把本地文件塞进「挂到笔记」的候选、不让 `backfillVideoTasks` 去抓元数据
   （本地任务没有可抓的接口）、不做拖拽进面板（本轮先给按钮）、不做移动端（无 Node 进程与 Python）。

## 备选

- **拆两格入口「影像 / 音声」**：最直白，但五格会挤、两个录入窗九成相同；否决（方案 A）。
- **入口改名「音视频」**：语义准确，但要重排四格、改命令名，首页自定义入口与教程全对不上；否决。
- **库外文件只登记路径不复制**：省空间，但 Obsidian 只能嵌入库内文件——笔记里没有可播放的媒体，
  用户明确要「进库」；否决。
- **插件侧直调 ffmpeg/Python**：等于把工具包的能力在插件里再写一份；否决（维持 ADR-0071 的分工）。
- **录入时先 ffprobe 拿时长**：多依赖一次工具包与进程，且旧版包没有探测动作；
  时长推迟到处理阶段回填，接受「剪辑只能手填、范围条不出现」。

## 影响

- 插件：`types.ts` / `data.ts` 字段与形状兜底；`media-kind.ts`（扩展名白名单 + 「影像/音声」标签）；
  录入窗与任务卡/历史组的本地分支；`processor.ts` 下发 `local` 并在 `[bz-info]` 回填时长；
  `note-gen.ts` 的 `mediaKind` 分支；`core/path-picker` 复用现有 `pickSystemFiles`（Electron 原生链）。
- 工具包：`core.js` 新增 `runLocal` / `extractAudio`，`runBatch` 在解析前按 `task.local` 分流；
  `cli.js` 放开「必须 url」；版本 1.4.0 → 1.5.0，随插件发版经「在线资源 / 自动更新」下发。
- 兼容：老工具包收到本地任务会报「缺少 url 或 local」——用户侧表现为任务失败并给出提示；
  插件侧不主动探测包版本（避免为一句话引入一套版本协议），靠发版说明与自动更新收敛。
- 数据：`knowledge.json` 任务多两键；旧数据读取照常（零迁移）。
