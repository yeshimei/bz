# ADR-0018 加密保险箱——提交式加密事务（暂存 + 清单先行 + 自愈回滚）

状态：已采纳（encrypt 域提交语义修订，经 grilling 逐轮拍板）
日期：2026-08

## 背景

移动端加密笔记中途闪退（多为系统回收内存）会在最终镜像写入后、清单提交前留下**密文孤儿**：`encryptRoot` 顶层已存在 `.随机.enc` 密文镜像，但清单无任何引用——原笔记未加密（原文件未删），数据文件夹多出无引用来源的密文附件（用户观察到的「附件进了数据文件夹、没有引用来源」）。

根因：`SafeManager.lockNote` 现为「边加密边写最终镜像 → 最后 `saveManifest` 提交 → 删原文件」。镜像写入先于清单提交，而加密阶段恰是最长、最可能被移动端杀死的窗口，孤儿因此集中产生。当前实现仅靠「原文件提交后才删」保证不丢数据，从不清理遗留镜像。

用户经 grilling 逐轮拍板：**不做自动清理**；改为**提交式加密**——只有全部附件与正文加密成功才落盘，中途任何意外不产生正式镜像；历史孤儿提供**手动**清理入口。

## 决策

1. **加密阶段流式写入暂存区（Q1）**：密文镜像先写 `<encryptRoot>/.staging/`（点前缀、侧栏隐藏、与最终镜像同盘）。不占内存、不进入数据文件夹正式布局（`encryptRoot` 顶层）。
2. **失败即整体放弃（Q3）**：任一附件/正文加密失败 → 清空本次暂存、原文件不动、提示重试，不产生任何正式镜像。预览层失败不算失败（预览为可选增强，维持「永不阻塞主流程」）。
3. **提交序列（Q2，清单先行 + 自愈）**：S1 写挂起标记 → S2 `saveManifest`（清单先行，引用尚不存在的镜像名；此处即提交点）→ S3 暂存镜像搬入 `encryptRoot` 顶层 → S4 清除挂起标记 → S5 尽力删原文件（失败仅提示、不回滚，见 Q4）。
4. **关键不变量**：挂起标记存在 ⇒ 原文件未删 ⇒ 自愈回滚永远安全；标记于删原文件**前**清除，标记清除后的意外一律视为已提交、绝不回滚。
5. **自愈回滚**：解锁时对挂起标记仍在的条目判定「半提交」，把已搬入的镜像移回暂存区、丢弃该条目、清空标记与暂存——数学上不再产生密文孤儿。
6. **手动清理入口（Q5）**：设置/面板手动按钮「清理未引用的密文」——扫描删除未被任何 `contentRef/blobRef/previewRef` 引用的顶层 `.随机.enc` 与过期 `.staging/` 残留，是清理 2026-08 前历史孤儿的唯二通道之一（另一为解锁自愈）；不自动触发。
7. **不违反数据格式铁律**：`SafeManifest`/`SafeNote` 结构不变、旧数据照读；挂起态由暂存区内**带外挂起标记**表达，不落入清单字段。

## 权衡

- **磁盘暂存 vs 全内存攒齐再写**：全内存满足字面「零字节落盘」，但峰值内存≈今日 2 倍（全原图 base64 与全密文同时在场），而移动端闪退恰因内存被杀——方案不应放大内存。选磁盘暂存（峰值≈今日）。
- **清单先行自愈 vs 文件先行接受窗口**：文件先行在「搬入与写清单」之间崩仍留孤儿，只能靠自动清理兜底（违背拍板）；清单先行 + 自愈把「产生孤儿」数学清零，代价是挂起标记与回滚/自愈逻辑。
- **带外挂起标记 vs 清单内 pending 字段**：挂起态写进清单需改数据结构（违反铁律 1）；带外标记零 schema 变更、旧数据无感。
- **先清标记再删原文件 vs 标记跨删原文件**：自愈本质是「原文件在即安全」的回滚；若标记跨越删除动作，回滚会在原文件已删时误删条目 = 真数据丢失。故标记必在删原文件前清除，标记清除即交易闭合，其后只按 Q4 处理冗余副本、不再回滚。

## 已知限制

- `.safe.enc` 单文件写入本身不具原子性（写一半崩溃可损坏清单、致解锁失败）——两个方案共有、任何提交顺序都不改变它，留待后续「临时写 + 改名覆盖」加固，不在本 ADR 范围。
- 自愈只覆盖**加密**事务；`restoreNote` 还原路径的崩溃窗口（条目在、镜像缺失）不纳入，列为后续单独议题。
- 手动清理须避开进行中的加密提交（解锁后空闲时触发）。
- 移动端跨设备/云同步延迟可能使「标记已清、镜像未同步」的已提交条目短暂呈现缺失（还原时按冲突保留条目、待同步自愈）——透明且可接受。
