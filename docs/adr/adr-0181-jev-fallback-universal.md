# ADR-0181：Jev 不可用一律回落 LLM（含影院）+ 判定编排原语 `core/jev-fallback.ts`

- 日期：2026-09-23
- 状态：已采纳（用户拍板；**取代 issue 395 的影院「不回落」口径**——该票 `decideCinemaType`
  「未配置即抛、失败上抛」的实现形态即本次退役对象）
- 相关：issue 414（本批）/ issue 389（通道）/ 391（设置组）/ 392（关联裁判回落实现）/ 393、395（影院接入批）/ ADR-0173（判定通道总口径）/ ADR-0002（依赖方向）

## 背景

ADR-0173 §2 定下的回落口径（Jev 未配置 / 请求失败 → 当次回落 LLM）在 392（自动关联裁判）
落地时被完整实现；395 影院类型判定落地时反过来定了一条**例外**——该票决策表与实现写明
「影院不回落」（`decideCinemaType` 未配置即抛、失败上抛）：Jev 不可用就当次放弃分类
（留空、由用户手点），理由是「影院是低价值旁路判定，多烧一次 LLM 不划算」。

用户 2026-09-23 审视两处接入点的实际行为后给出统一口径：**不允许存在「Jev 不可用就没人接」
的判定点，凡 Jev 不可用一律由 LLM 补位**。例外取消（原话「这是我要求的，必须有 llm 回落」）。

同时点出一个工程问题：两处接入点各自手写同一套编排（判配置 → 请求 → 解析 → 失败回落），
形态几乎逐字相同，且**都与 `core/jev.ts` 同文件或同域内**，既重复又难以单测回落分支。
要求抽出通用件，「类似 `core/ai`」——即与生成通道平级的、判定侧的唯一入口。

## 决策

1. **判定编排原语独立成件 `src/core/jev-fallback.ts`**，导出 `judgeOrFallback<T>(plan)`：
   调用方按 `{ request, parse, fallback, signal?, config? }` 描述一次判定，原语负责
   「判可用 → 请求 → 解析 → 失败回落」的全部控制流。四类不可用及其归宿：

   | 情形 | 行为 |
   |---|---|
   | ① 未启用 / 未配置（`isJevConfigured()` 假） | **不造材料、不发请求**，直接 `fallback()` |
   | ② 请求失败（网络 / HTTP 非 2xx / 超时） | 记 `console.debug` 后 `fallback()` |
   | ③ 答案畸形（`parse` 抛错：题型不符 / 缺题单键 / **取值越界**） | 同上回落 |
   | ④ `signal` 已取消（含在途取消） | 抛 `AbortError`，**不回落**（取消不是失败） |

   `fallback()` 自身抛错**不吞**——两通道都不可用时由调用点按域降级（关联入队重试、影院留空），
   不引第三层兜底。**在途取消要传导进回落请求，由 `fallback` 实现自行接 `signal`**（原语只保证
   「已取消不调用」）。

2. **单独成件而非并入 `core/jev.ts`**：理由有二——① 纯度高：`jev.ts` 只做「state + 类型化
   问题 → 类型化答案」的透传，编排（含回落策略）是消费侧关注点；② 可测：`jev.ts` 的失败分支
   要靠 mock 网络层触发，抽件后调用点可直接 spy 原语、原语可直接 spy `askJev`（vitest 只能
   拦截跨模块调用，同模块自调用拦不住）。

3. **影院类型判定补回落**（取代 395 的影院例外）：`decideCinemaType` 走同一原语，`fallback` =
   `decideTypeByLlm`——单次 `createAI().json()`（接调用方 `signal`），prompt 由 `buildTypeLlmPrompt`
   拼（候选清单 + 豆瓣信息 state），回执经 `parseTypeLlmOutput` **严格校验**：去 codefence → JSON →
   `type` 字段 trim → 必须 `∈ criteria`（**按自有键判**，见决策 6）且 `≠ 哨兵`，否则 `null`。
   **LLM 侧无校准概率，故用闭集校验顶替置信度门槛**（Jev 侧仍按校准概率 + 哨兵口径）。

4. **弃权不算失败、不回落**：Jev 正常返回但选了哨兵（或置信度未过硬门槛）是**有效判定**
   （「都不合适」），直接返回 `null`，不触发 LLM——否则等于绕过受限分类，把用户明确不要的
   野值放进来（逃逸禁令不变，见 395）。**取值越界则相反**：Jev 吐出清单外的词是答案畸形（接口
   异常 / 模型跑偏），归第 ③ 类走回落，与「哨兵弃权」不同路。

5. **关联裁判改为消费原语**（行为等价重构）：`pipeline.judge()` 的既有三段（配置判定 / 请求 /
   回落）搬进原语，`judgeByJev` 的答案解析进 `parse`，`judgeByLLM` 进 `fallback`；口径与
   ADR-0173 §2 一致。两处有意的小改动——**取消语义强化**：预取消（`signal` 在调用前已 aborted）
   时原语在造 state 之前就抛，材料构造一并省掉；**材料构造抛错改走回落**（`request()` 已移入原语
   try，读 vault 失败不再是直接上抛入队，而是回落 LLM）。

6. **候选清单按自有键判定**：`criteria` 是字面量对象，`'tag' in criteria` 会把 `toString` /
   `constructor` 这类原型链键认成合法候选（LLM 回执真可能吐这两个词，Jev 侧接口异常也会）。影院
   两处判定（`judgeTypeChoice` / `parseTypeLlmOutput`）一律 `hasOwnProperty.call` 判定。

## 被否的备选

- **维持「影院不回落」例外**：用户已拍板取消；且例外本身要求每个接入点各自论证一回，
  口径随接入点数量发散。
- **回落原语内建重试 / 多级兜底**：两通道都挂已是罕见态，此时再重试只是延长用户等待；
  域侧降级（入队 / 留空）本就是正确的收敛点。
- **把原语并入 `core/jev.ts` 当门面函数**：见决策 2，纯度与可测性双输。
- **LLM 侧也做置信度门槛**（如要求模型自报 0–1 分）：生成模型的自报分不可校准（ADR-0150 系列
  的既有结论），拿它做门槛只是把噪声搬了个位置；闭集校验才是 LLM 侧真实可用的约束。

## 后果

- **口径统一**：任何接入点只要用 `judgeOrFallback`，回落行为自动一致，新接入点无需重新论证。
- **有意接受的口径混血扩大**：影院类型结果可能来自 Jev（校准）或 LLM（非校准），不落盘标记、
  对用户不可见——与 ADR-0173 §4 对 related 的既有接受同性质。代价是复盘时无法从数据反查
  某条分类由谁产出的；需要时靠 `console.debug` 临时观测。
- **影院成本上限抬高**：Jev 不可用时每部未分类影视多一次 LLM JSON 调用（同步解析链路内，
  用户在场）；`decideCinemaType` 失败仍不阻断解析（字段已到手，分类可手点）。
- **`core/jev.ts` 保持零业务口径**：新增的回落策略在 `core/jev-fallback.ts`，域侧只描述
  「问什么 / 怎么解析 / 拿不到怎么办」三件事。
