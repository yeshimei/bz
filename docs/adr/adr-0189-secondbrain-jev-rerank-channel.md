# ADR-0189：第二大脑重排第二通道——Jev 重排（云端 noul 判定，与本地 Reranker 二选一）

- 日期：2026-09-24
- 状态：已采纳（设计定稿，实现待启动——七项拍板与实现口径见 issue 431）
- 相关：issue 431（本票，含拍板记录）/ issue 427 + ADR-0186（本地重排通道基线——本 ADR **不改变其任何语义**，只在其旁并立第二通道）/ issue 429（`rerankScore` 显示同尺，Jev 通道复用）/ issue 428 + ADR-0187（取消语义原样沿用）/ ADR-0181（`judgeOrFallback` 编排纪律，本票首个 fallback 槽位不填 LLM 的先例）/ issue 430 + ADR-0188（Jev 服务商注册表——正交：重排走哪家由 JEV 组配置决定）/ ADR-0173（Jev 判定通道）/ ADR-0185（余弦是阈值唯一尺）

## 背景

ADR-0186 的本地重排整条链绑两个前提：本机 Ollama 装有 Qwen3-Reranker，且嵌入模型为 Qwen3-Embedding-8B（显存共驻考量，`rerankActive()` 与设置行可见性共用 `isQwen3Embedding8b`）。非 8B 嵌入、移动端、未装 Reranker 的用户与重排无缘。

用户提出以 Jev 决策模型（ADR-0173 判定通道）作为**第二重排通道**。设计访谈中核实的前置事实决定了本 ADR 的形态：

1. **Jev `noul` 与 P(yes) 语义同构**：noul 返回 0–1 校准概率，一次 `askJev` 可带整批问题（每候选一题），实测单次 1–2s——本地通道是 50 对串行几十 ms/对，Jev 是整批一趟云端往返，两者都在重排段 6s 预算内。
2. **`score` 量表题型被否**：档位粗、并列多，正是 ADR-0186 明令避免的粗糙分（二值/粗分会让「并列全按余弦序」的半排观感回来）。连续概率只有 noul。
3. **Jev 是云端服务**：候选笔记摘录（最多 50 × 300 字）会发往 Jev 服务商——隐私代价已向用户明示，用户知情拍板接受。
4. **state 体积未实测**：服务端对大 state 的上限未知，截断终值留待实现期探针。

## 决策

1. **总闸 + 通道开关，二选一。** 「启用重排」（`secondBrainRerank`）保持总闸、**改常显**；其下新增「重排走 Jev」（`secondBrainRerankJev`，默认 `false`——存量用户零变化）。总闸关 = 重排全关；总闸开 + Jev 关 = 本地通道（ADR-0186 现状，语义零改动）；总闸开 + Jev 开 = Jev 通道，**本地「重排模型」行隐藏**。不取「两个独立开关」：那会出现总闸关了 Jev 却单独生效的怪态，「二选一」由总闸下的通道开关表达。
2. **8B 嵌入门只留给本地通道。** Jev 通道走云端、不吃本地显存，**解绑 `isQwen3Embedding8b`**——任何嵌入模型可用，这是 Jev 通道最大的增量（非 8B / 移动端用户首次可用重排）。两行各自「可见性 = 生效条件」（总闸常显 ∧ 各通道自身门），暗态原则（ADR-0186 决策 3）以通道为单位继续成立。
3. **生效判定收单源 `rerankChannel(): 'off' | 'local' | 'jev'`**（`secondbrain/config.ts`）：设置行可见性与 `applyRerank` 分流共用这一个函数，替代原 `rerankActive()` 双头布尔。`local` = 总闸开 ∧ Jev 关 ∧ 8B 嵌入；`jev` = 总闸开 ∧ Jev 开（不查 8B、不查本地模型）。
4. **Jev 通道判定协议 = noul 每候选一题。** state = 查询词（沿用 `RERANK_QUERY_MAX_CHARS` 1000 字截断）+ 编号候选清单（`doc_0…doc_N`，摘录初值 300 字/条，实现期探针定终值）；问题按候选键编（`{ doc_k: { type: 'noul', instructions } }`）；`answers[key].noul` 直接记 `hit.rerankScore`。整批上限沿用 `RERANK_MAX_DOCS = 50`，超长列表（建链 150 池）整轮跳过不变。**纯换序层性质继承 ADR-0186 决策 1**：阈值仍只读余弦 `hit.score`，`relevancePct` 显示同尺机制原样复用。
5. **失败一律整轮回余弦序，不落 LLM——经 `judgeOrFallback` 编排，fallback 槽位填「维持余弦序」。** 未配密钥（类别①不发请求）/ 超时 / 网络 / HTTP 非 2xx / 响应畸形 / **缺题键**，一律按余弦序返回 + `console.warn`，不触发文本降级（重排是增强层，失败只损失增强——ADR-0186 决策 4 口径）。这未必是 LLM 回落：50 条逐条 LLM 在检索 10s 预算内不可能、还白烧钱——`judgeOrFallback` 的 `fallback: () => Promise<T>` 槽位填「返回原序」即成，**取消不回落**的类别④语义白拿（ADR-0187：取消直抛，回填旧序会盖掉新查询列表）。这是 ADR-0181「新接入点一律消费它」纪律下首个非 LLM 回落的接入点。
6. **缺题键 = 整轮畸形，不做单条计 0。** 有意偏离 link-agent 决策 9（issue 392「缺题单键计 0」）：那是建链「宁少建不误建」场景；重排计 0 会把实际相关的条目沉底——同一列表里一部分按 noul 排、一部分按 0 沉底，正是 ADR-0186 决策 5 反对的「名次无法解释」的半排观感。缺题与畸形同罪：整轮回余弦，单一尺。
7. **空转状态用静态 desc 交代。** 总闸常显后出现「总闸开着但没有通道生效」（非 8B + Jev 关，或 Jev 开 + JEV 组无密钥）的新状态——总闸与 Jev 开关的 desc 静态写明各自门槛（本地需 8B 嵌入 / Jev 需 JEV 组密钥、未填自动回退余弦序），不做动态警示条（不为边缘状态给设置行渲染器加新机制）。

## 后果

- **重排覆盖面扩大**：非 8B 嵌入、移动端、未装 Qwen3-Reranker 的用户第一次能用上重排；8B + 本机 Reranker 用户的默认行为零变化（新开关默认关）。
- **隐私面扩大**：开启 Jev 重排后，每次交互检索最多 50 × 300 字笔记摘录发往 Jev 服务商（Typesafe 或博查，ADR-0188）——用户知情拍板接受；不开启则零上云。
- **无混尺可能**：两通道二选一、同一时刻只有一个生效，列表内永远单一尺；noul 与 P(yes) 校准分布不同、跨通道比较百分比无意义——也不存在需要比较的场景。
- **新增静默失败面**：Jev 云端不可用（断网 / 密钥失效 / 服务故障）时列表回余弦序，观感与本地通道失败一致（`console.warn` 可查），不新增用户可见错误路径。
- **新键一个、无迁移**：`secondBrainRerankJev` 默认 `false` 随 `DEFAULT_SETTINGS` 落盘；旧设置无迁移动作。
- **与 ADR-0188 正交**：Jev 重排消费 `resolveJevConfig`（服务商 → 端点/密钥/模型），换服务商不改本 ADR 任何语义。
