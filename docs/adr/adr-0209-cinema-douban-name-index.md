# ADR-0209：影院名称索引——豆瓣 ID 直取解析，联想数据只收事实性元数据

- 日期：2026-09-27
- 状态：已采纳（实现见 issue 498）
- 相关：ADR-0178（三路检索链）· ADR-0203 / 0205 / 0207（统一下载清单与在线资源组）·
  ADR-0204 / 0208（同型「在线 JSON 数据资产」先例）· ADR-0129（豆瓣字段口径，C1 季集撤回）· issue 498

## 背景

影院「添加影视」靠三路检索链按名搜豆瓣（ADR-0178）：同名片靠运气（搜索返回第一条）、
依赖豆瓣接口在线可用（2026-09-27 实测 suggest 有软拒绝、rexxar 有 IP 限流、条目页有
sec 风控网关）、ApiZero 按量计费。手头有两份本地数据集（自抓 2026 影视表 25,520 条 +
Kaggle 豆瓣数据 67,132 条）可以合并出 **85,288 条唯一名称索引**（名称/年份/评分/类别/豆瓣 ID），
让输入框「边打字边出候选」，命中后跳过搜索页按 ID 直取。

由此先定的模型问题：**索引收多少字段、走什么通道。**

## 决策

1. **只收事实性元数据五字段**：名称/年份/评分/类别/豆瓣 ID。简介、海报、导演/主演、
   短评等血肉字段**有意不收**——全量数据随插件分发是许可红线（Kaggle 部分上游为
   CC BY-NC-SA 4.0，豆瓣协议更严），名称+年份+评分属于事实性元数据，分发风险低一个量级；
   且血肉字段会随时间失效，名称+ID 是稳定键。取数语义仍然完整：候选携带 sid，
   解析时 `ApiZero?id=` 直取**当下**全字段，血肉数据永远在线现取。
2. **rows 用定长数组** `[名称, 年份, 评分, 类别, 豆瓣ID]`，不用对象键——85,288 行省 ~30%
   体积（实测 5.99MB → 4.29MB 明文）。列序是产物 schema 的一部分，validate 逐列校验。
3. **走统一清单 doc 通道，明文 JSON**：`downloads/cinema-douban-index.json` 登记 DOCS +
   ROW_ORDER（ADR-0207，设置面板在线资源组零代码出行）。**不做 gzip/二进制下载**——
   现役链路是 requestUrl 文本 + 文本 sha256（normalizeEol 口径），引二进制/解压要动
   core 下载层，4.29MB 明文不值得。资产层仿 rss-catalog 四件套（ADR-0208）：
   `core/douban-name-index.ts`（validate/load/download + 查询纯函数）。
4. **sid 直取失败回落按名全链**：`queryDoubanForPreview(app, name, sid?)` 在直取
   （ApiZero）失败时**自动回落**三路检索——key 未配、额度尽、网络抖动都不该让
   「索引命中」反而比「手输」少一条路。海报 URL 恒空（ApiZero 无此字段），
   保存后队列按名补抓（issue 397 既有兜底）。
5. **同名条目候选取排名最优一行做 sid 载体**：候选组件（core uiSuggest）以名称串为
   选中值，同名无法二次消歧。候选项内按「前缀 > 包含，评分降序」排序后取首个，
   其余同名片仍可手输名称走按名检索。检索归一口径：小写 + 去空白与常见标点
   （全半角括号/引号/连接号/间隔号）。
6. **索引未下载 = 功能静默缺席**：不加提示、不自动下载（4.29MB 不该未经同意拉取）。
   下载入口就是设置面板在线资源行本身；DESC_EXTRAS 就绪后显示
   `85,288 条 · 电影 80,946 / 电视剧 2,537 / …`（用户点名的按类型条数小字）。
7. **上游数据集不入 git**：构建脚本（`pnpm cinema-index`）从本机合并产物规范出版，
   产物入库（清单 sha256 的事实源），上游可再跑。

## 备选与否决

| 方案 | 否决理由 |
|---|---|
| 全量字段索引（含简介/海报/导演主演），离线填字段 | 公开分发许可红线；且血肉字段时效性差，ID 直取在线现取同样省掉搜索页，语义更优 |
| gzip/二进制资源包（1.7MB） | core 下载链是文本口径（requestUrl text + 文本 sha256），引解压层要动 remote-asset 全链，收益只是 2.6MB |
| 用 M.items（用户已有笔记）做联想源 | 数据源错位：那是 issue 394 重名反馈的事实源，量级是几百条用户记录；联想要的是 8.5 万外部片名库，两者语义无关 |
| 自绘下拉（仿 .dm-pick-list） | core uiSuggest 已有完整候选交互（键盘导航/外点收起/IME 防抖/回车放行），自绘必然漂移 |

## 后果

- 老版本插件读到含本条目的新清单：通用 doc 行正常长出、可下载；DESC_EXTRAS 小字与
  表单联想不存在——向后兼容无害（ADR-0207 后果节同款）。
- 产物入库使 git 每次 data refresh 都新增 ~4MB blob：数据 refresh 是低频手工动作（上游
  数据集更新时），可接受；重跑 `pnpm cinema-index && pnpm manifest` 即翻新。
- `parseDownloadManifest` 条目逐字段重建，本条目只用既有字段（id/name/file/sha256/size），
  无 schema 扩展。
