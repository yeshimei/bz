# ADR-0213 · 录音说话人分离管线（滑窗声纹 + Viterbi）与轮次进仓形态

日期：2026-09-28 · 状态：已采纳 · 关联：ADR-0212（补充素材入口）、ADR-0194（保库记录）、issue 509

## 背景

用户持有两人语音聊天录音，希望作为联系人画谱素材。分离方案三个候选实测
（真值校准：已知 is_sender 的微信语音拼成假录音，时间加权准确率；实现于数据根 `tools/`）：

| 方案 | 思路 | 真值准确率 | 短板 |
|---|---|---|---|
| A | VAD 切段 → 段级声纹二分类 | 66.2%（剔 `?` 85.7%） | 短应答嵌不出特征，`?` 占 22.8% 时长 |
| ① | FunASR 一体件（paraformer+vad+cam++ 句级聚类） | 89.0% | 句粒度粗，接话处归属串线 |
| C | 1s/0.25s 密滑窗声纹曲线 + 两状态 Viterbi | **97.6%** | — |

真录音（76 分钟）复核：C 的轮次 579、接话交替全部正确、不确定时长 ≈0；
A 的 `?` 与 ① 的串线均复现。方案 C 边界来自**说话人分数曲线的跳变**（用户拍板方向），
不依赖语音停顿；VAD 仅作语音门控。

## 决策

1. **管线定型方案 C**（工具脚本 `tools/rec_slide_hmm.py`，全程本地 CPU）：
   ffmpeg 16k → fsmn-vad 门控 → CAM++ 滑窗（1s 窗/0.25s 步）对「我/对方」两条质心
   出 LLR 曲线 → Viterbi（切换代价 3.0 / 增益 10×llr）解码 → 同说话人相邻窗归并轮次
   → SenseVoice 逐轮转写（≤25s 分片）带情感标签。
2. **声纹参考（质心）**：从该联系人微信语音按 is_sender 构建两条质心（剔除口径见工具脚本）。
   **降级阶梯**（用户拍板「只有两个人，非我即对方」）：联系人质心建不出（语音样本过少）时，
   仅用「我」质心做单侧验证——非我即对方；「我」质心也建不出（近乎不可能）才降级
   「说话人 0/1」不映射身份。任何降级不阻断导入，文本证据先落袋。
3. **轮次进仓形态**：每轮一条消息——`type=9001`（自定号，避开微信原始码）、
   `isSender` 按分离归属、`text = [录音 3分02秒·平静] 转写文本`（与 `[语音 12秒·平静]` 同构，
   `media.ts` 增「录音」种类解析）、kindCounts 标签「录音」；轮次 ts = 录音起点 + 轮内偏移。
   长录音切多轮后自然融入时间线，画谱原话/事件证据按归属直接可用。
4. **断点与进度**：处理状态落数据根 sidecar（turns.json + phase 账本，VAD/声纹/转写逐阶段落账，
   声纹窗分块记账），中断续跑只补缺口；进度显示挂画谱任务进度块同一位置（UI 层渲染，不入引擎队列）。
5. **运行配置**：python 路径走设置现有 `pythonPath`（wxtool 环境：funasr/torch/modelscope，
   模型 fsmn-vad/CAM++/SenseVoice 全本地，零 API 费用）。

## 后果

- 录音成为与微信语音同构的一手证据：原话归属、情感标签进画像「情绪逻辑」。
- 每录音一轮一消息，长录音显著增加时间线条数——现有切批抽样与素材上限机制兜底。
- 工具脚本在数据根 `tools/`（不进插件构建）；插件侧只负责 spawn、sidecar 读取与仓合并。
- 质心构建依赖微信语音样本：完全无语音记录的新联系人首次导入时降级运行，事后可补建重跑。
