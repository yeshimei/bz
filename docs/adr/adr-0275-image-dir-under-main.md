# ADR-0275：域图库目录三跳收口——写死缺省退役，第三跳由主目录现算

- 状态：已采纳
- 日期：2026-10-31
- 相关：ADR-0274（域目录缺省留空；本 ADR 修订其决策 4）、
  issue 560（图片目录显示实际落点）、issue 561（本次）

## 背景

ADR-0274 决策 4 定下图片类目录三跳：`设置值 → Obsidian 附件位置 → 域内缺省 <主目录>/assets`。
但第三跳在代码里并不是「由主目录算出来的」，而是四域各写各的：

| 域 | 旧第三跳 | 与主目录的关系 |
|---|---|---|
| 剪藏本 | `归档/网页剪藏/assets` | 主目录的字面量缺省（不是现算） |
| 影院 | `CONFIG/MOVIE POSTER` | 毫无关系（CLI 时代的遗留目录） |
| 游戏库 | `CONFIG/游戏海报` | 同上 |
| 知识盒 | `文献盒/assets` | 挂在文献文件夹，而非卡片文件夹 |

后果有两层：

1. **页面在教错的事**。设置项默认是空串，用户看到的是 `fallbackValue` 算出来的第三跳；
   把它写成常量，等于告诉用户图会进 `CONFIG/MOVIE POSTER`，而他其实把 Obsidian 的附件位置设成了 `CONFIG/APPENDIX`。
2. **主目录改了，图不动**。用户把影视目录从 `我的/影视` 改到 `影视库`，海报仍往老地方堆——
   第三跳跟主目录毫无绑定关系，改设置看起来没生效。

2026-10-31 用户拍板：**在能跟随 Obsidian 附件位置时跟随；跟不了就落到本域主目录下的 `assets`，
不再有任何写死目录**。

## 决策

**1. 三跳固定，唯一实现是 `core/attachment-dir.ts`。**

```
显式设置值 → Obsidian 附件位置（仅固定文件夹形态） → <本域主目录>/assets
```

第三跳由新导出的 `domainAssetsDir(mainDir)` 现算，主目录空则返回空串。四个常量
（`CONFIG/MOVIE POSTER`、`CONFIG/游戏海报`、`归档/网页剪藏/assets`、`文献盒/assets`）全部删除。

**2. 主目录与域的对应是固定的，不按「第一个非图片字段」猜。**

| 域 | 主目录键 | 第三跳 |
|---|---|---|
| 剪藏本 | `articleDirectory`（剪藏文件夹） | `<剪藏文件夹>/assets` |
| 知识盒 | `knowledgeCardboxDirectory`（卡片文件夹） | `<卡片文件夹>/assets` |
| 影院 | `cinemaFolderPath`（影视目录） | `<影视目录>/assets` |
| 游戏库 | `gameshelfFolderPath`（游戏目录） | `<游戏目录>/assets` |

（空态表里用 `imageBaseKey` 显式声明，避免「知识盒的图片跟着文献盒走」这种由字段顺序决定的暗规则。）

**3. 三跳全空 = 不写盘。** 目标目录解析为空串时，写图入口直接拒绝并提示「先配好 X 文件夹」，
**绝不把文件落到库根**。已加的守卫：剪藏 `writeUniqueImage`、知识盒 `writeUniqueBinary`、
影院 `downloadPosterToVault`（返回 `write` 失败）、游戏库 `ensurePosters`（整套媒体队列不启动）。

**4. 图片字段永不参与空态闸门。** 挡人进域的是主目录；图片是可选项，`missing` 恒为 false。
（旧实现在图片目录算不出来时会整域弹「还没定文件夹」，而在主目录必填的前提下这个状态根本不该出现。）

**5. 写盘前逐级建目录。** 新库第一次抓图时 `<主目录>/assets` 多半还不存在。

**6. 设置项默认值仍是空串**，不预填任何路径；空值时由 `fallbackValue` 把实际生效目录显示成
一枚锁定 chip（跟得上 Obsidian 就显示 Obsidian 的目录，跟不上就显示 `<主目录>/assets`，
三跳全空则不挂 chip）。

## 代价与边界

- **`./` / `./子目录`（跟随当前笔记）仍不跟随。** 宿主 `getAvailablePathForAttachment()` 能解，
  但它是 async 且要 `sourcePath`；影院海报与游戏库封面**不属于任何一篇笔记**，只能编一个假来源。
  四域统一按「不可用」处理，避免同一句「跟随 Obsidian 附件位置」在四个域里表示三件事。
- **日记「＋贴一件」不受本 ADR 约束。** 它走宿主 `fileManager.getAvailablePathForAttachment`，
  有笔记上下文、`./` 形态也能跟——那是「笔记附件」，与「域图库目录」是两回事（术语已分列）。
- **知识盒图与笔记分家（知情项）。** 图版笔记正文仍写文献文件夹，图片落卡片文件夹。
- **存量不迁移。** 老图仍在 `CONFIG/MOVIE POSTER` / `CONFIG/游戏海报`，frontmatter 里记的是路径，
  显示不受影响；只有**新**图去新位置。
- **游戏库会重下一轮媒体。** `posters.ts::needsWork` 拿「当前解析目录拼出的路径」与 frontmatter 的
  `封面` 比对，目录一变即判「不是本地那版」→ 封面 / 库内图标 / 截图按新目录重下（上限约 460 MB，
  见 ADR-0166 体量口径）。旧文件不自动删。
- **主目录改了，新图跟着走，老图不动**——这是本 ADR 想要的行为，不是缺陷。

## 后果

- 设置页的「实际生效目录」与真实落点同一处，不再有页面写 A、文件进 B 的域。
- 四个域共用一句规则，新人不再需要知道「影院海报历史上存在哪」。
- `src/settings.ts` 里两条键注释、`posters.ts` 文件头、`note-gen.ts` 的 `IMAGE_ASSETS_DIR` 一并清理；
  `IMAGE_ASSETS_DIR` 因无消费点删除（`assets` 字面量只剩 `domainAssetsDir` 一处）。
- 守卫 `tests/core/image-folder-default.test.ts`：三跳各种形态、空串不发明目录、图片字段不 gate、
  以及一条**源码扫描**——`src/` 里再出现那四个写死目录即红。
