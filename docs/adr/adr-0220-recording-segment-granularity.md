# ADR-0220 · 录音轮次段落化进仓（同人连续合并为一条）

日期：2026-09-29 · 状态：已采纳 · 关联：ADR-0213（轮次进仓）、ADR-0216（旁音）、ADR-0217（起点与 turns.md）、
issue 516 第 4 轮

## 背景

进仓口径是**一轮次 = 一条聊天仓消息**（`applyRecordingTurnsToMsgs`，key `rec:<文件>:<轮序>`）。
一段 76 分钟的录音能切出数百轮 → 时间线被同一段录音灌满几百条，既难回溯也压扁了别的素材。

用户要求：**连续时间范围内只有一个人说话，就合并成一条**。

## 决策

1. **进仓单位从「轮次」改为「段落（Recording Segment）」**：连续同一说话人的轮次合并为一条消息。
2. **无时间间隔阈值**（用户明示）：只按说话人连续性断段。**知情项**：同一个人隔很久（同一段录音内）
   再说会并成同一条，段的跨度 / 时长可能远大于其净说话时长。
3. **断段条件 = 说话人变化**。旁音轮（ADR-0216）与 `?` 不确定轮本就不进仓，但它们被识别为不同说话人，
   故**天然断开**前后同人的段落——正确，不需特判。
   **空转写轮**（静音 / 转写失败）不输出，且**不断开**（它是同一说话人的轮次，只是没转出文本）。
4. **段的属性**：
   - `ts` = **段首轮 start** 的绝对时间（起点 + 偏移，ADR-0217）；
   - `dur` = **段跨度**（末轮 end − 首轮 start）——与单轮口径（end − start）同构，表示"这段持续了多久"；
   - 情感 = **段内各轮一致才带**，不一致**省略**（不拿众数冒充）；
   - 文本 = 段内各轮文本按序直连（无分隔符，与单轮同构）。
5. **key 口径**：`rec:<文件>:s<段序>`（前缀 `rec:<文件>:` 不变——定点清除 / `hasRecordingTurns` 判定照旧，
   `applyRecordingTurnsToMsgs` 本就是"先清后写"的幂等实现）。
6. **存量已并仓的录音不自动重并、也不给「重新分段」入口**（用户明示）：新口径只对**新处理 / 重新并仓**
   的录音生效。理由是重并会改动聊天仓内容 → 已烧过批的画谱任务被指纹判废（`DRIFT_ERROR`，要重新画谱、
   重新花钱）。老录音若要新分段：删仓消息（issue 516 Q12 的不勾"同时删除原件"）→ 行回落「待处理」→ 再处理。
7. **`turns.md`（ADR-0217）仍逐轮**，加段落分界标记；「查看轮次」预览同口径。
   理由：turns.md 的用途是**复核我们没误杀 / 没转错**，粒度必须细到轮；进仓粒度是**素材**，可以粗。

## 后果

- 时间线消息数与 `kindCounts` 的「录音 N 条」按**段数**计；`media.ts` 的 `录音 N 段` 随之变成段数
  ——语义反而对齐了（段 = 段落），不需要改文案。
- 画谱素材更粗：一条素材文本更长、条数更少（对提炼是有利的：连续同人的话本就是一段叙述）。
- **知情代价**：改口径前后，同一段录音在时间线上的形态不同（新录音更粗）。不要在同一批里比对，也不要
  据"条数变少"判断数据丢了（`turns.md` + 「查看轮次」仍能看到全部轮次）。
- 测试面：段落切分纯函数单测（同人连续 / 说话人交替 / 空转写轮不断段 / 旁音与 `?` 断段 / 首尾单轮）；
  并仓幂等（先清后写、段序重编号不残留旧 key）。
