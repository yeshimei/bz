# ADR-0149 · 删除/改名时知识盒来源的回退与摘除语义

日期：2026-09-16 · 关联：issue 335/336、ADR-0144（保存物化回写）、ADR-0116（术语来源）

## 背景

ADR-0144 让剪藏保存物化时把知识盒卡片 `source` 从外链 URL 升级为内部双链
`[[剪藏路径|标题]]`。反向操作（剪藏/影院笔记等被删、被改名）原无任何同步，
产生悬挂引用（实证：菲尔兹奖卡断链，issue 335）。审计确认 knowledge.json、
clipbook.json 的路径字段同样无同步。

## 决策

1. **降级优于摘除（可回退处）**：删除剪藏时，用剪藏自身 frontmatter 的 `url`
   把卡片 `source` 行级改写回外链形态——恢复 ADR-0144 物化前的两态，出处信息零丢失。
2. **摘除兜底（不可回退处）**：任何 md 被删且无 url 可回退（影院笔记、用户经
   Obsidian 删除等）时，行级摘除指向它的 `source` 行，`sourceTitle` 保留——
   卡片回到「无来源」这一合法初始态，而非悬挂。
3. **行级手术不变**：改写/摘除沿用 `upgradeSourceLine` 的边界（只动 source 一行、
   换行符保真、幂等、不整体重序列化）。
4. **JSON 路径字段跟手**：knowledge.json（task.notePath/videoPath）与
   clipbook.json（marks/pendingSource）仿 memo file-sync 范式消费
   `vault:md-renamed`/`vault:md-deleted`，改名跟改、删除剔条。
5. **只管自管结构**：正文里用户手写的任意 `[[…]]` 双链不在扫描改写范围
   （Obsidian 原生改名联动已覆盖其主路径）。

## 后果

+ 出处信息在删除场景可降级保全；悬挂引用与「打开文献笔记报错」在插件管辖内清零。
− 摘除是不可逆信息丢弃（有合并通知告知张数）；用户经外部工具（资源管理器）改名/删除
  仍不覆盖（Obsidian 本身也不覆盖，属全库系统性边界）。
