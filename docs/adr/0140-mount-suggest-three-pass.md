# ADR-0140 挂载建议三段式：AI 全权定粒度（整篇 / 标题 / 段落）

- 状态：已接受（2026-09-15，用户拍板「可以，来实现吧」，按 2026-09-14/15 实测方案定稿）
- 关联：ADR-0138（语义建议：目标六类形态）、ADR-0139 §3（建议缓存零落盘口径）、issue 318/321
- 影响：`src/knowledge/mount-suggest.ts`（链路重写）、`mount-canvas.ts`（渐进渲染 / 进度 / 固定三形态）、
  `mount-types.ts`（建议带单元）、第二大脑只读检索桥（不变）

## 背景

issue 318 的一次性裁判只在「笔记名 + 200 字块摘录」上判断：索引块是 256 字等长窗口（6398 块 99.6% ≤300 字），
没有标题/形态信息，机械分句的锚点还带双链语法噪声。实测（GLM-5.3-Flash / DeepSeek 真库端到端）证明
瓶颈在**候选池精度**与**锚点质量**，而不是模型；且 Ollama 嵌入硬顶 2048 token 静默截断，索引文本不可作为
显示与写链接的依据。

## 决策

1. **三段式链路**（每卡 3 次调用，结果落缓存）：
   - 轮 1 查询官：带编号的正文片段 → `{seg, sentence, keywords, why}`（完整短句 + 关键词双查询，比关键词堆召回好）；
   - 本地召回：范围闸（**只排除归档/网页剪藏**，保留卡片盒/主题盒/文献盒）+ 自指剔除 + 同笔记去重留最高分块
     + 双查询并集按「命中次数 → 最高分」排序（保底多样性：每片段最优笔记必进池）；
   - 轮 2 采纳官：片段 × 候选（名称/路径/命中数/最高分/块摘要）→ `{seg, path, score, reason}`，同一目标最多 2 条；
   - 轮 3 定位官：现读被采纳笔记全文（标题/段落编号，单篇 8000 字封顶）→
     `{unit: whole|heading|paragraph, heading, quote, anchor, reason}`，**允许 skip 否决**。
2. **两条硬约束**（真机实测的教训）：锚点必须是**主卡正文原文**（逐字摘录，本地三级回定位：
   精确 → 去空白 → 退回片段锚点）；目标单元必须带**可回定位的证据**（标题原文或原文摘录），
   证据失效三级降级（标题不存在 → 整篇；摘录找不到 → 去空白匹配 → 段落兜底），绝不写瞎链接。
3. **形态落链接**（ADR-0138 六类形态的落地）：整篇 `[[路径]]`；标题 `[[路径#标题]]`（落前校验标题存在）；
   段落 `[[路径#^块id]]` —— **固定时向目标笔记补写确定性块 id**（`bz-` + 路径与段落文本哈希 8 位，幂等，
   走 per-file 串行写队列）。这是插件第一次写非主卡文件，用户 2026-09-15 拍板允许（Obsidian 段落双链的唯一正路）。
   锚点一律走**别名套句** `[[目标|锚点原句]]`（2026-09-15 用户拍板，从「≤12 字词级」扩到整句）：
   锚点那句原文原地换成双链，句子读起来一字不变、整句可点——比句末追加一个 `[[目标]]` 更贴合
   「这句话挂到那张卡」。套不进去（锚点原文对不上，或锚点里含方括号/换行会撑破链接语法）才退回
   句末追加（`insertLinkAtAnchor` 自带三级重定位与正文末尾兜底）。
4. **思考档**：`reasoning_effort: 'low'`（实测同批候选下默认档 143s / low 7s / 关 5.3s，采纳结果几乎一致；
   关闭档会退回 `a1/t2` 标签式作答，容错解析保留）。预算 131072（GLM 上限即此值）。
5. **渐进呈现 + 进度**：白板先画真实双链（树建完即画），建议经 `onProgress` 驱动进度条与动态文字
   （查询官 → 检索 → 采纳官 → 定位官 → 落缓存）就绪后并入幽灵节点；换卡打开**先清画布**（修重开残留）。
   **例外：空卡（除主卡外一个挂载都没有）与显式重跑（「重新生成」/ 命令）时，进链路前先不画**——
   画布留空 + 「生成中」进度（带一行空板说明），等建议回来或返回空再一次性画全。空卡是「首次调 AI
   看到一张主卡，不像白板」；重跑是「板上还挂着上一轮看过的内容，点了像没反应」（2026-09-15 实机报障）。
   换卡（非重跑、非空卡）不受影响：照旧先清画布再画新卡的真实双链。
   `.bz-kb-mt-pempty` 的文案按场景给（空卡 / 重跑两句），不写死在标记里。
   另：「重新生成」是 3 轮 AI 调用的重活，**点击先二次确认**（`openFlowDialog`，顶栏按钮与命令同一处），
   取消则一行不跑。
   建议幽灵节点的**锚点句在正文里整句高亮**（虚线底纹 + 句末圆点，同一 `data-mt-edge` 悬停联动），
   「AI 指的是哪一句」要一眼可见（同日报障：只有一个 7px 圆点）。
6. **缓存 v3**：建议片带 `unit/heading/quote/subpath`，`SUGGEST_CACHE_VERSION=3` 旧片自动失效；
   「无回答不落缓存」口径不变（no-answer）。

## 后果

- 换来：建议粒度与用户双链同构（整篇/标题/段落），显示内容为现读文件的真实单元，长文不受索引截断影响；
  首卡生成 ~40–60s（low 档），命中缓存 0 调用。
- 代价：每卡 3 次 AI 调用（缓存后为 0）；块 id 写入会触发目标笔记的增量索引与 link-agent 内容哈希重跑
  （接受一次重跑）；模型非确定性 → 同卡重跑选点会漂移（缓存 + 「重新生成」按钮兜住）。
- 索引侧（切块粒度 / 标题路径入嵌入文本 / 2048 token 静默截断防护）仍待办，优先级低于范围闸与多查询召回，
  另立 issue。
