# ADR-0185：检索层收敛为精确全扫余弦（VP-Tree 退役 + 分数去锐化 + 坏向量双重防线）

- 日期：2026-09-24
- 状态：已采纳（用户拍板「全套 + 去分数锐化」，见 issue 425）
- 相关：issue 425（本票，含探针实测证据）/ ticket 103（检索链路原实现与 VP-Tree 出处）/ ticket 46（检索级超时降级）/ issue 330 + ADR-0146（`linkAgentMinScore`）/ issue 360（每周撞车阈值）/ issue 422 + ADR-0182（Embedding 模型与查询指令前缀）/ ADR-0002（依赖方向）

## 背景

用户发现：**几乎每条向量查询的结果列表里都有一张恒定 78% 的卡**（同一篇笔记，同一分数）。探针定位到三段成因叠加（详见 issue 425「现象与根因」）：

1. 向量库里有 5 条**全零行**（模长 0，出自 2026-08-25 一次瞬时写入故障；`mergeWrite` 对未变文件按源偏移拷贝旧段，坏行此后不会再被覆写）；
2. VP-Tree 的距离→余弦换算 `cos = 1 − d²/2` **只对单位向量成立**，零向量到任意单位向量的距离恒 1.0 → 反推出恒定的假 0.5 分；
3. 收尾的 `score^0.35` 锐化把 0.5 抬成 **0.7846 ≈ 78%**，把假分推到了肉眼可见的位置。

同时测得：VP-Tree 的**近似召回**在 20 条最终结果里与暴力全扫有 15/20 条不同（漏真实最近邻），候选窗口 60 条中约 31.4 条是重复节点（实现把 VP 复制进了自己的左子树）；而全扫在这份库规模（3192 chunk × 4096 维）下**单查询 27.5 ms，比 VP-Tree 的 95–122 ms 快约 3.5 倍**。

用户对处置范围拍板：**全套修复 + 去掉分数锐化**；坏数据由他自己点面板「重新索引」全量重建清除。

## 决策

1. **检索 = 精确全扫余弦，VP-Tree 退役**。
   `vectorSearch` 改为：查询嵌入归一化 → 与库内**逐行点积** → 按 `path::chunk` 去重 → topK。`src/secondbrain/vptree.ts` 整体删除（`euclideanSq` / `vptree_build` / `vptree_search` / `VPNode` 无其他消费点）；`normalizeVec` / `isValidVector` 与 `Vec` 类型迁入新文件 `src/secondbrain/vector-math.ts`。
   理由：这份库规模下全扫**更快且精确**——近似索引的收益（亚线性召回）只在向量数远大于此处时才兑现，而它带来的代价（漏最近邻 + 本轮暴露的距离语义陷阱 + 一个自实现的冗余节点缺陷）是实打实的。用户原话「什么查询算法都可以不用写，直接去查询不可以吗？不需要做任何的干涉」正是此意。

2. **归一化矩阵缓存以「来源数组身份」为键**。
   整段向量只归一化一次（`NormCache{src, dim, rows, data, valid}`），命中条件 = `src === this.vectors && dim 相同 && rows 相同`。库内任何内容变更（全量重建 / 增量 mergeWrite / 紧凑重排 / 清库）都**替换缓冲引用**，身份比对即足以失效，不需要内容哈希或版本号；`clearStore` 另显式置空作双保险。行→笔记的定位每次查询现走（meta.notes 键序 × chunks 的计数循环，开销相对点积可忽略），避免把 meta 变动也编进缓存键。

3. **坏向量双重防线（入库 + 检索）**。
   - 入库侧：`getEmbedding` 拒收空/零/含非有限分量的向量；`getEmbeddingsBatch` 另查「条数是否等于输入」「批内是否含零向量或维度不齐」——任一不符即**整批失败**，交逐条回退（逐条再由 `getEmbedding` 把关）。坏段不登记 → 文件 mtime 不写 → 下轮增量自动重试，沿用 ticket 3/114 既有语义。
   - 检索侧：无效行**整行跳过**（零向量、含 NaN/Infinity），`console.warn` 报出跳过条数。存量库可能已带病，故此处不抛错、不阻塞——未重建期间坏行既不占位也不产出假分，面板「重新索引」即彻底清除。
   - 查询向量同样校验；且**维度与索引不符时抛错**（换模型未重建、远程端模型不同）：维度不同的点积无意义——抛错让三处调用方（`search` / `searchMobile` / 建链管线，均有 catch）走既有降级文本路径并给用户降级提示，好过返回空数组被当成「没有相关结果」。

4. **分数去锐化：`score` 即原始余弦 [0,1]，与参考面板百分比同尺**。
   删除 `score^0.35`。锐化原本只为「显示压缩」（把余弦的常见区间拉开），代价却是让域内所有**阈值**变成非线性尺上的数——本轮 78% 幽灵卡就是它的放大效应。负相关归零（显示层不出现负百分比），不改用 `(1+cos)/2` 之类的重标定：多一步换算就多一处「读代码的人以为它是余弦」的歧义，阈值换算的成本只在两处，一次性付清。
   两处阈值同语义换算（`x^(1/0.35)`）：
   - `linkAgentMinScore`：默认 0.65 → **0.30**（≈0.29 取整档），并做**一次性设置迁移** `migrateLinkMinScoreScale`——旧值是锐化尺上的数，留在原位会变成更严的门槛（0.65 在原始余弦尺上是「近乎同文」）。两把尺值域重叠、无法凭数值判幂等，故迁移落一个内部标记键 `linkAgentMinScoreScale: 'cos'`；**该标记同时写进 `DEFAULT_SETTINGS`**——落盘路径写的是整份 `Object.assign({}, DEFAULT_SETTINGS, loaded)`，若缺省值不带标记，首次保存（桌面端 `ensureRemoteOllamaUrl` / 设置页任意一键）写下的默认值 `0.3` 会在第二次启动被当旧锐化尺值换算成 `0.03`，下限静默失效（全量候选直送 AI 裁判）；标记进缺省值不影响存量库迁移——迁移读的是合并缺省值**之前**的 raw `loaded`。换算取两位小数并**下限 0.01**（0.05 这类小值经幂次会掉到 1e-4，取整成 0 就把「极严」翻成「不过滤」，与用户原意相反）。**`0 = 不过滤` 是文档化语义、两把尺上同为 0，原样保留**（换算公式会把 0 幂成 0 再被下限抬到 0.01，等于替用户把过滤打开）。
   - `WEEKLY_COLLISION_SCORE`：0.85 → **0.63**（0.85^2.857）。与建链下限的档位关系（「高度重合该提醒」严于「值得送裁判」）保持 0.30 < 0.63 不倒挂。
   - **存量周摘要的撞车分同批收口**：分数随摘要落盘、空轮还会保留上一份供面板回放，故 `WeeklyDigest` 增口径标记 `scale: 'cos'`；无标记的旧摘要由显示层（`collisionPctOf`）按 `unsharpenScore` 换算后再渲染，**只换算 `mode === 'vector'` 的条目**——TF-IDF 通道的分数是 token 覆盖率，本就有绝对标尺，不属锐化尺。换算不写回落盘、也不做二次换算（幂次不可重放），故必须靠标记而非「读时改写」。
   - 换算实现单一真理源：`unsharpenScore` + `LEGACY_SHARPEN_EXPONENT` 收在 `vector-math.ts`（分数尺的属主），`settings.ts` 的迁移与周摘要显示侧共用，避免幂次公式两处漂移。

5. **不做的事**：不引入外部向量库/索引库（HNSW 等），不把检索搬到 worker（27.5 ms/查询 + 10 s 检索级超时兜底足够），不代用户改数据文件（坏行走重建路径清除）。查询侧 `Instruct:/Query:` 前缀维持 issue 422/ADR-0182 的现状不动——本票只改「怎么比」，不改「怎么嵌」。

## 后果

- 幽灵卡根治：全扫下坏行 0/40 命中；即便不重建索引，坏行也已被整行排除在检索之外。
- 检索结果**精确**：不再有近似召回漏掉最近邻的问题；同分排序稳定，重复节点问题随 VP-Tree 一并消失。
- 单查询耗时从 ~100 ms 降到 ~27 ms（同一份 3192×4096 库），参考面板与对话的等待时间同步缩短。
- 分数语义变直白：面板/日志/阈值/设置页说明共用一把「原始余弦」尺，`linkAgentMinScore` 与 `WEEKLY_COLLISION_SCORE` 的数值不再需要「锐化」这层心算。
- 旧库升级注意：**未点重建前**坏行不参与检索但仍在 `.vec` 里（每次检索一条 warn），重建后彻底清除。设置迁移在 onload 自动完成，用户无需手改阈值。
- 行序不变量（`meta.notes` 键序 × chunks == `.vec` 行数）成为显式契约：`buildNormCache` 在不一致时 warn 并说明本次只覆盖多少行；`doRefresh` 的两条早退分支（失效清理 / 读取失败）都必须落盘对齐，否则本会话后续检索会把被摘条目之后的行认到别的笔记上。
- 退役面：`src/secondbrain/vptree.ts` 删除；`euclideanSq` 无替代（新实现不需要距离），`Vec` 类型从 `vector-math.ts` 导出。
