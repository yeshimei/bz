# ADR-0164 · 游戏架媒体键分工（`封面源`/`图标源` 与 `封面`/`图标`）

> 状态：accepted ｜ 日期：2026-09-17 ｜ 相关：issue 370、ADR-0161、ADR-0163

## 背景

游戏架的封面与图标来自 Steam CDN，用户 2026-09-17 要求「拉取到的数据全部存在本地，
笔记属性里的海报图标也换成本地图片」。

难点：这两个字段**同时**有两个来源与两个消费者的诉求——

- 同步（`GetOwnedGames`）每轮都会给出远端地址（封面是 CDN 直拼，图标带 hash 只能从 API 拿）；
- 媒体队列要把图下到本地，并让**笔记属性**指向本地文件（影院域既有约定：
  `海报: CONFIG/MOVIE POSTER/x.jpg`，Obsidian 属性面板认路径为链接、图片出缩略图）。

如果只用一个键（`封面`）：同步 upsert 每轮把本地路径冲回远端 → 属性的图永远是外链；
若把该键从同步管辖里摘掉：新笔记首次同步后就没有远端地址可下载，图标 hash 也永远补不上
（`img_icon_url` 是 hash，拼不出完整 URL）。

## 决策

**拆成两对键，各归一个写入方：**

| 键 | 内容 | 谁写 | 谁读 |
|---|---|---|---|
| `封面源` / `图标源` | Steam 远端地址 | **同步**（`managedFm`，随库刷新） | 媒体队列（下载源）、显示层兜底 |
| `封面` / `图标` | 本地图片的 **vault 路径** | **媒体队列**（`posters.ts`），同步绝不碰 | 属性面板、显示层首选 |

- **新建笔记**（`noteMarkdown`）四个键都写：源键 + 现值（现值先填远端，媒体队列跑到后改成本地路径）。
- **对旧笔记的迁移**：`NoteSnapshot.mediaPending = fm['封面源'] === undefined` 触发一次 `toUpdate`
  顺带补齐源键（否则「数值没变就不同步」会让老笔记永远补不上源键）。补过即自愈，不再 churn。
- **显示层**（`coverDisplayUrl` / `iconDisplayUrl`）四级兜底：本地文件 → 属性现值 → 源键 → CDN 直拼；
  img 再挂 `data-fallback-src`，本地文件 404 时前端换远端源重试一次（只一次，防死循环）。

## 后果

- 属性面板里看到的是本地图片（本地文件夹被删也能靠源键重下，自愈）；
- 代价 = 每篇笔记多两个键；同步不再刷新 `封面`/`图标` 本身，但这不影响显示（兜底链覆盖）；
- 图标文件命名 `<appid>-icon.jpg`，与封面 `<appid>.jpg` 同目录（不新增设置项）。
