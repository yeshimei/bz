# ADR-0192：脸谱双卷画像——卷一《其人》+ 卷二《我们》，批采集扩六类

- 日期：2026-09-26
- 状态：已采纳（issue 455 任务书拍板；大琳真实数据 18477 条验盘）
- 相关：issue 455（本票）/ ADR-0191（脸谱域立项，隐私口径沿用）/ issue 438（画像深度移植 distilly）/ issues 449/450/453/454（statsNote / 任务引擎 / 批级重试续跑，本票不回退）

## 背景

`buildPortraitPrompt` 一张文混两条轴：人物表达层（口头禅 / 语气）与关系层（称呼 / 冲突 / 演变）互相挤占篇幅，结果两头都浅。画像偏 distilly 表达层方法论，缺人物内核（性格 / 兴趣 / 价值观 / 习惯 / 情感倾向），关系侧散落无结构认知。细化方案对齐社区提示词（titanwings / ex-skill 的 chat_analyzer 四维 + awesome-distill-skills 的 nuwa 五层心智模型 / 反模式 / 保留矛盾），并经大琳真实数据（18477 条）验盘出四个真信号：月度密度 6221→31 是演变证据但没喂 prompt；语音情感「难过 226 > 开心 138」未透用；称呼 / 梗应归关系卷；小样本（莫莫 132 条）无可信度警示。

## 决策

1. **双卷数据模型（types.ts）**：`FaceDigest.portrait`（单卷）拆为 `person`（卷一《其人》，人物画像 7 节）+ `bond`（卷二《我们》，关系画像 8 节）。`portrait` 保留为可选兼容字段（旧数据只读、重画后不再写入），读侧一律走兼容读单源 `personOf(d) = d.person ?? d.portrait ?? ''`、`bondOf(d) = d.bond ?? ''`，不直摸字段。两卷同为受限语法 markdown（`##` 小节 / `-` 列表 / `**粗体**` / `> ` 引用块，域内迷你渲染器消费），各 ≤1200 字。新素材类型 `InterestItem { ts, topic ≤15 字 }`（兴趣信号）与 `ThreadItem { ts, text ≤30 字 }`（未竟之事，只采集不落「是否兑现」的判断——兑现与否由画像阶段对照 events 现场判断）。
2. **管线三调用（digest.ts）**：切批逐批采集（不变）→ 合并去重 → 三次文本调用：卷一《其人》（必产，空则抛错）→ 卷二《我们》（必产，空则抛错）→ 编年史（best-effort 兜空串，现状不变）。`FaceProgress.stage` 扩为 `extracting / person / bond / chronicle`，onProgress 各推一步。批采集 4→6 类：+interests（分享 / 安利的具体内容、反复话题、正在投入的事；单次顺带一提不收）、+threads（约定 / 邀约 / 「下次一起…」/ 聊一半没下文的话题）。`MATERIAL_LIMITS` +interests: 40 / threads: 30，与 moments / traits 同机制（合并去重 + 均匀抽样首尾必保，增量不丢）。卷一素材分段：档案〇（若有）/ 事件 / 原话 / 场景 / 特质 / 兴趣信号 / 互动统计（若有）；卷二：档案〇 / 事件 / 原话 / 场景 / 未竟之事线索 / 互动统计——兴趣信号只进卷一、未竟线索只进卷二，特质线索不进卷二（各卷吃各卷的素材，省 token 且不串轴）。
3. **卷一 7 节**：画像速写（须含一组矛盾感——矛盾是特征不是噪声）/ 性格与思维（行为规则化「当 X 时，TA Y」；TA 的自我描述只当线索引述不当下结论）/ 表达 DNA（每条特征跟 `> ` 原话证据；**称呼 / 昵称不在此节**，归卷二）/ 兴趣爱好（实际投入 → 内容口味 → 精神底色三层，每层要具体名目）/ 价值观与红线（全推断层，每条必须「看来 / 似乎」起头）/ 习惯 / 情感倾向（素材里语音情感计数可直引）。**卷二 8 节**：关系定性（手动档案标签 / metVia 优先，冲突以档案为准并注明）/ 互动结构（不罗列数字，写可感知的相处模式与解读）/ 演变阶段（划阶段 + 转折点 + 沉默与回联 + 最后一句写「现在」）/ 我们的语言（称呼演变 + 梗与暗语小词典）/ 共同记忆 / 冲突与修复（触发点「直接 / 推断」分标 → 第一反应谱 → 升级信号 → 收场；**和解信号单独写**——和解不一定是道歉；收尾雷区清单）/ 未竟之事（threads 对照 events，约定过且一起做了的不收）/ 经营建议（档案标签翻译成相处规则）。两卷共用硬性要求块沿用旧 prompt 全部条目，另加「保留矛盾」。
4. **统计与档案入 prompt（insights.ts / FaceRunOptions）**：`buildStatsNote(i, monthly?)` 增可选第二参——月度消息密度「消息密度：2026-03 6221 条、…」按月升序全列，月份数 > 12 按年合并求和（「2025 年合计 15000 条」式），在素材段末尾追加；`FaceRunOptions.profile` 经新函数 `buildProfileNote`（生日 / 职业 / 家乡 / 怎么认识 / 什么时候认识 / 关系标签 / 备注，逐项成句，空 / 缺省返回空串）转「素材〇：档案」段进两卷头部。**样本警示**：消息量 < 200（`SAMPLE_WARN_THRESHOLD`）时两卷 prompt 头部注入同一段警示（「本次样本仅 N 条消息，素材偏少——证据不足的小节直接写（素材不足），不要脑补」）；jobs 引擎按全量预览桶消息数（`job.msgCount`）判定，增量管线由调用方可覆盖（本层只见新切片）。
5. **任务引擎适配（jobs.ts）**：ask 通道分工不变（提炼批走 `.json()`、成文三次走 `.chat()`）；job 阶段 `portrait` 拆 `person` + `bond`（JobStage：chunked / extracting / person / bond / chronicle / done），成文进度文案对齐四阶段；切批说明的调用预告改批数 + 3。**落盘兼容**：people-jobs.json 里旧 in-flight job 的 `portrait` 字段在 resumeJobs 读入时映射为 `person`（映射发生即重写落盘），issue 453 的批级重试与续跑复用语义不回退——已缓存批次照常复用，从《其人》阶段起重画双卷。`JobTarget` 增 `profile?`（转档案段，缺省回落人物卡现有档案，排队时定稿随 material 落盘）与 `monthly?`（全量月度密度——引擎增量模式自算的 stats 只覆盖新切片，不能当全量密度，故由入参显式携带；透传给 `buildStatsNote(insights, monthly)`）。
6. **隐私口径不变（ADR-0191 §2）**：聊天原文不落盘不进任务文件；interests / threads 是提炼产物（聚合语义素材），与 events / quotes / moments 同级落盘；档案段是用户手动填写的信息（本就在 people.json），进 prompt 不新增暴露面。

## 后果

- 成本：一次完整生成 = 批数 + 3 次调用（原批数 + 2）；两卷各 ≤1200 字上限约束篇幅。
- 旧数据（无 person / bond）靠 personOf / bondOf 兼容读继续可看；重画一次即迁移为双卷，旧 portrait 字段随 setDigest 整卡替换自然消失。
- 未竟之事不落「兑现与否」的盘上结论——每次重画按最新 events 现场判断，避免陈旧判断残留。
- 月度密度依赖调用方传全量 monthly：ui 层从预览桶 stats 取；不传则 prompt 无密度段（静默降级，不出错）。
- ui / render 侧（详情折册「其人」「我们」两折、统计与档案弹窗化、四阶段进度文案）由后续 UI 票消费，不在本 ADR 范围。
