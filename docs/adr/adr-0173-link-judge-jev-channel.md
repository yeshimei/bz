# ADR-0173 关联判定接入 Jev 决策通道（口径以 Jev 为准，存量不重跑）

- 日期：2026-09-21
- 状态：已采纳
- 相关：ADR-0052（core AI 统一通道）、ADR-0141（关联范围恒为三盒）、ADR-0146

## 背景

自动关联（`secondbrain/link-agent`）与知识盒录入的关联预演**共用同一个裁判**：把新笔记与候选笔记的档案卡拼成一段 prompt，交给 `core/ai` 通道，要求模型输出严格 JSON 数组 `[{"id":n,"reason":"…"}]` 并按强度降序。

这是**用生成模型做判定**，两个直接后果：① 输出必须解析，解析失败即整篇失败、入队重试；② 提示词里的 `reason` 字段在 `pipeline.ts` 被解析后**从未被消费**（只取 `path` 写 related），是纯浪费的输出 token。

2026-09-21 用真实库（三盒 61 篇）对 TypeSafe AI 的 Jev 做了一轮同口径实测。Jev 是 System One 决策模型：state + 类型化问题（Choice / Score / Noul）→ 类型化答案 + 校准概率，**不生成任何文本**，本次解析到的版本为 `jev-1.13.0`。

| 口径 | 结果 |
|---|---|
| 硬关系（历史人物 / 事件） | Noul 0.96–0.99，极准 |
| 软关联（心理随笔类弱连接） | Noul 0.29–0.39，比现有 LLM 裁判严 |
| 同领域干扰项误建 | 2/27（7%） |
| 单次成本 / 延迟 | ≈ $0.00017 / 篇，1–2 秒 |

结论：形态契合——判定本就是 Noul 的甜点区；但**它比现有裁判更硬**，只认明确关系，不认「同属一个宽泛领域」。

## 决策

1. **引入 Jev 作为「判定」通道**，与既有 `core/ai`（生成通道）并存。Jev 只承担类型化判定（是否关联 / 关联强度），**不承担任何生成职责**。
2. **优先级：Jev 优先，失败即当次回落 LLM**。回落条件 = 请求失败（含 503 / 超时），发生在同一次处理内、对用户不可见；**降级不通知、不落盘标记**（2026-09-21 用户拍板）。两个通道都不可用时维持现有行为：入队待重试，**不引入第三层兜底**。
3. **判定口径以 Jev 为准**。接受关联数量下降：Jev 判为「无实质关联」的对子不再建链，不通过调低阈值把密度补回来。
4. **存量 related 不重跑**。既有链接维持原样（`linkAgentRespectRelated` 默认门继续生效），新口径只作用于新处理 / 新录入的笔记。**这是一处有意接受的不一致**——库里会同时存在两种口径建出的链。
5. **模型版本默认固定**（`jev-1.13.0`），不默认用 `jev-latest`。口径是这套系统的核心资产，不应由供应商的远端别名决定何时变更。
6. **配置独立成组**，落在设置面板 AI 分区（`core/settings-main-schema.ts` 的 `aiSettingsSchema().groups`）——一组 Jev 配置（启用 / 端点 / 密钥 / 模型 / 超时）+ **一个全局总开关**；**接入点（自动关联，含录入面板关联预演）不设独立开关**。
7. **关联预演与后台自动关联同通道，不拆参数**（2026-09-21 用户决策，Q14）。知识盒录入面板的「关联」行经 `core/link-now.ts` 的 `LinkBridge.preview()` → `pipeline.ts` 的 `previewLinks()`，与后台 `processNote` **共用同一个裁判**。因此两处 `AI.ask` 调用点（`pipeline.ts:280` 后台 / `:336` 预演）**一并改走 Jev**，共用同一套问题构造与结果筛选；预演路径的 `AbortSignal`（issue 327，重新生成即断在途裁判）必须透传到 Jev 通道。
   - 预演路径的失败语义与后台同规则：**Jev 失败即当次回落 LLM**（不因「面板等着」而特判）。`commitEntryLinks()` 已有的「预演 failed → 转后台管线」兜底保留，作为两道都不可用时的最终保障。
   - 两点现状差异（LLM 时代即存在）需在实现时注意：预演传的是**草稿伪文件**，档案卡只有标题 + 草稿正文（无 tags、无 summary），同一篇笔记预演与后台可能给出不同结果；预演有取消通道，后台没有。
   - 注：「**AI 关联建议**」这个叫法在本库指**挂载树的幽灵节点**（`mount-suggest.ts` 顶栏「AI 建议」徽标），**不是**录入面板的关联行。挂载树不接入 Jev，理由见 spec「挂载树为何不做 Jev」。
8. **知识盒的内容生成不接入 Jev**（2026-09-21 用户决策）。`note-gen.ts` 的 `{"domain","title","summary"}` 是**一次流式调用**的产物，领域与内容天然一体；拆开会让属性区「分析中…」失去流式增量语义（`partial-json.ts` 逐帧回填的前提就是一个响应里同时有这三个字段）。**领域维持 LLM 生成，本 ADR 不涉及它。**

## 代价

- **口径混血**：存量 related 由旧 LLM 口径建、新链由 Jev 口径建，且无标记可区分。排查「为什么这篇建了那篇没建」时，必须先问「这条是什么时候建的」。
- **关联变稀**：软关联类（心理、随笔、弱互补上下文）会明显减少。
- **新增外部依赖**：笔记档案卡要发往 TypeSafe 的云端（美西部署）。注意这**不是新增泄漏面**——现 `core/ai` 通道本就发送同样内容；但它是在判定环节多押一个供应商，且该服务 2026-09-15 才公开发布、当天实测出现过一次 `503 no healthy upstream`。
- **成本口径**：$5 额度为**月度赠金**、30 天过期，之后按量计费（$0.042 / M 输入 token，输出免费）。
