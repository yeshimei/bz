# ADR-0176：游戏库成就图标不本地化（改远端直取，`成就` 行恒 6 段）

- 日期：2026-09-22
- 状态：已采纳（**取代 ADR-0167**；修订 ADR-0166 第 2 节的媒体范围）
- 相关：issue 410；前置 ADR-0166（全量落盘）/ 0167（成就图标路径进属性）/ 0164（媒体键拆分）

## 背景

2026-09-18 用户拍板「所有数据一个不差都进属性、图标和图片都存本地文件夹」（ADR-0166 / 0167），
落到实现上：每款游戏除封面 / 库内小图标 / 截图外，还本地化**成就图标**——每个成就两色
（彩色 = 已解锁，灰图 = 未解锁），按 `(appid, apiname)` 逐条落盘。

四天后的实测盘点（用户 vault `CONFIG/GAME POSTER`）：

| 类别 | 文件数 |
|---|---|
| 成就图标 `<appid>-ach-*` | **8,118** |
| 商店截图 `<appid>-shot-*` | 1,104 |
| 库内小图标 `<appid>-icon` | 146 |
| 封面 `<appid>.jpg` | 144 |
| **合计** | **9,512**（占 vault 文件总数 26,247 的 36%） |

而内容体积只有 635 MB、平均 70 KB——**负担在文件数量，不在体积**。Obsidian 每次启动都要
遍历 vault 全部文件建索引 diff；`userIgnoreFilters`（本 vault 已设 `CONFIG/`）只影响搜索 /
反链 / 图谱，**对启动扫描无效**，所以这 9,512 个图仍照扫。

用户拍板：**成就图标不往本地存**，但**照常显示**（在线直取）：

> 代码的常用图标仍然是在线获取的，只是不再保存在本地而已

## 决策

### 1. 判据：**是否随条目数膨胀**（不是「是不是图标」）

| 类别 | 量级 | 处置 |
|---|---|---|
| 封面 / 库内小图标 | 每款各一张（167 款 → 144 + 146） | **本地化** |
| 截图 | 每款 ≤ 8 张（147 款 → 1,104） | **本地化** |
| 成就图标 | **每条成就 × 两色**（147 款 → 8,118） | **不落盘** |

同样叫「图标」，库内小图标与成就图标差 55 倍。判据写在这里，免得后续有人凭直觉加回一类
「看着像小文件」的媒体。

### 2. 成就图标改远端直取

删 `localAchIconPath` / `achIconDisplayUrl` / `AchIconJob` / `ensureAchIcons` /
`achIconsMissing` / `safeNameSeg`（含 `posters.ts` 的第三条队列）。

界面（`ui.ts::achListHtml`）**保留图标列**，`<img src>` 直接用 Schema 给的 `icon` / `icongray`
远端 URL；属性里不存图标地址，所以从属性反解的行没有图标 → 画 `.bz-gs-achicon--none`
占位块（同尺寸底色，行高不跳）。灰图 Steam 没给 → 彩色 + CSS 灰度兜底（原口径不变）。

### 3. `成就` 行从 8 段收回 6 段（撤销 ADR-0167 第 1 节）

```
显示名 | 描述 | 已解锁(1/0) | 解锁日期 | 全球解锁率 | apiname
```

`steam.ts::achRowText` 去掉 `icons` 参数；`achRowFromText` 不再反解第 7/8 段；
`achRowSegCount` 与 `achIconPathsMissing` 一并删除；`achToFm` 去掉 `appid` 参数。
存量 8 段行**不必迁移**：解析只取前 6 段（`parts.length < 6` 判据不变，多余段被忽略），
打开详情且 `成就更新` 过 24h 时静默重拉会写回 6 段，自然收敛。

### 4. `图标` / `图标源` 键、库内图标队列、详情弹窗小图标**全部保留**

`reconcile.ts::managedFm` 照旧写 `图标源`，`notes.ts` 新建模板照旧生成两键，
`posters.ts` 的 `ensurePosters` / `needsWork` / `runQueue` 的图标分支不动；
`.bz-gs-detail-icon` 与其 `iconDisplayUrl` 调用不动。

### 5. `modalRepaintFn` 收窄

原来媒体下载完要重画两处（成就图标 + 截图本地路径）；成就图标不再有落盘产物，只剩截图一处。

## 后果

- **文件数（存量清理后）**：游戏库媒体 9,512 → **1,394 张**（封面 144 + 截图 1,104 +
  库内图标 146），**-85%**；vault 总文件数 26,247 → **18,129**（-31%）。
  改造本身只停止**新增**；已落盘的 8,118 个成就图标由 issue 410 单列清理（2026-09-22 已归档
  到 vault 外 `E:\Obsidian\_bz-media-archive\20260922-ach-icons\`）。
- **属性体积**：全库成就行减少约 150 KB（147 款 × 均 30 条 × 两段路径），回到 ADR-0167 前的口径。
- **观感**：成就列表的图标列**保留**——这是本 ADR 与「整体退役」方案最关键的区别。
- **已知代价：属性反解的行没有图标。** 属性里不存图标地址是「不落盘」的必然结果，于是
  纯离线翻详情时成就段是占位块；打开详情且 `成就更新` 过 24h 会被静默重拉补上（不写盘）。
  数据本身（名字 / 解锁态 / 全球率）仍全在属性里，断网一个不少。
- **可逆性**：若日后要回到「离线也有图标」，把远端 URL 存进第 7/8 段即可（见被否决方案②）。

## 被否决的方案

- **① 成就图标整体退役（列表里不显示图标）**：零文件数代价、实现更小，但用户明确否掉——
  要的是「不存本地」，不是「不显示」。
- **② `成就` 行扩回 8 段、第 7/8 段存远端 URL**：离线也有图标，但属性体积 +约 1.4 MB
  （147 款 × 均 30 条 × 两段 URL），且与「不落盘」的初衷无关——用户要的是别往磁盘堆文件，
  不是把属性撑大。留作日后可选。
- **③ 只停增量、不删存量**：vault 里的 8,118 个成就图标继续被 Obsidian 索引，解决不了启动扫描。
  存量清理已单独执行。
- **④ 只保留「已解锁色」一张**：省一半文件，但仍是随成就数膨胀的量级，且状态翻转会缺图，
  收益远小于「不落盘」。
- **⑤ 连库内小图标一起退役**：收益只有 146 个文件，却丢掉详情弹窗识别度最高的一张小图，不值。
- **⑥ 改扩展名绕开索引**（`.jpg` → Obsidian 不认识的 `.dat`）：能让 Obsidian 跳过这批文件且
  不必搬目录，但读图侧要改走 `app://local/`，且与 vault 内其他媒体盒（APPENDIX / BOOK /
  GALLERY / MOVIE POSTER 合计还有 8,444 个文件）口径分裂。留作后续 vault 级方案。
- **⑦ 强制全库重拉以收敛 8 段行**：147 款 × 3 个接口，为清属性里一段文本不值得；自然收敛已足够。
