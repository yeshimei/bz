# ADR-0111：影院豆瓣盲区补全（打开触碰协议 + 工具补全分支）

日期：2026-09-09 ｜ 状态：采纳（issue 252）

## 背景

豆瓣抓取由外部 PM2 守护进程完成（ADR-0006/0007，插件零抓取代码、不碰豆瓣网络）。用户需求：「每次打开影院界面，自动把没有获取到豆瓣信息的重新跑」。探查发现需求实质是**工具盲区**：

- watcher 收到文件变化后走全目录扫描，扫描口径只认**缺海报**（`watcher.js` `collectMissingPosterNotes` → `!hasPoster`）；`fetchPosterForNote` 的跳过条件虽是「海报+豆瓣链接都齐」（`pipeline.js` 支持补全），但扫描不会把「有海报、缺信息」的笔记入队。
- 实测 673 篇影视笔记：缺豆瓣链接 17 条、**全部有海报**（海报环节成功、信息环节被限流打断的残缺数据；其中 11 条有评分缺链接），另 3 条有链接缺评分。这 17 条永远不会被自动重试。
- 现状重跑隐患：`fetchPosterForNote` 会重新下载海报（时间戳新文件名）→ 旧海报文件成孤儿，且 `insertPosterEmbed` 的去重只认完全相同路径，新文件名必产生**重复 embed**。

## 决策

1. **缺失口径 = 缺豆瓣链接**（`hasDoubanInfo` 取反）。插件判定、工具扫描、工具跳过三方单口径一致。「海报」在语义里是**抓取模式开关，不是完成标志**：有海报 → 只补信息；缺海报 → 完整抓取（watcher 原有职责）。有链接缺评分的 3 条在口径外，不纳入。
2. **触发 = 打开触碰协议**：插件每次打开影院面板（`openCinema` → `rebuildItems` 后）扫描内存条目，对「有海报 ∧ 缺豆瓣链接 ∧ 豆瓣检查 ≠ 今日」的笔记写 frontmatter `豆瓣检查: YYYY-MM-DD`（**日期粒度**）→ chokidar change → 10s 防抖 → 全目录扫描（口径已扩）入队。**完全静默**（用户拍板，无任何通知）。
3. **节流 = 同日一次**：日期粒度天然实现——当日重复打开值未变不写文件不触发；跨天再开再试。插件触碰频率同日一次；watcher 对文件夹内任何文件变化的既有重扫语义不变，抓取限流由 15s 串行间隔兜底。
4. **工具补全分支**：`fetchPosterForNote` 对已有海报的笔记**跳过海报下载、海报字段写入与 embed 插入**，仍执行豆瓣搜索 + 详情请求补全信息字段。杜绝孤儿海报与重复 embed。
5. **工具扫描口径扩展**：`collectMissingPosterNotes` 从「缺海报」扩为「缺海报或缺豆瓣链接」——修盲区本体，PM2 重启或文件变化时盲区笔记自动被捞起（触碰协议不依赖这一条的唯独是即时性）。
6. **职责边界**：插件只 touch「有海报 ∧ 缺链接」的盲区精确对象；缺海报的由 watcher 既有扫描兜底，插件不重复触碰。插件不碰豆瓣网络（ADR-0006/0007 维持）。

## 取舍

- **触碰笔记 vs 队列文件 vs 工具周期扫描**：触碰复用既有 chokidar 文件监听通道，工具侧零新协议；代价是 frontmatter 多一个字段 + git 自动同步仓一次性多 17 文件 diff（补齐成功后该笔记不再被触碰）。队列文件 frontmatter 零噪音但多养一条通道、「待补」出现两个真相源；周期扫描插件零改动但偏离「每次打开」语义且常驻空转。用户拍板触碰。
- **同日一次 vs 每次打开都试 vs 尝试上限**：同日反复打开对持续失败条目纯属空转，日期粒度免费获得冷却，且不需要任何额外落盘（尝试计数方案需状态文件且「放弃」无 UI 呈现即静默失灵）。
- **只补信息 vs 完整重跑**：完整重跑每轮多一个孤儿海报文件 + 一条重复 embed，需再配清理逻辑才能用；只补信息的单条代价 = 一次搜索 + 一次详情请求。
- **静默 vs 通知**：用户拍板完全静默，靠卡片上豆瓣字段逐渐长出感知；可观测性走 `pm2 logs`（工具侧已有逐条日志）。
