# ADR-0108：剪藏本已读原位保留（会话冻结序 + 桌面打开即读 + 已读/已收双折叠段）

日期：2026-09-08 ｜ 状态：采纳（issue 249）

## 背景

现状两端不一致，且都按「即时让位」处理已读：

- **移动端**（ADR-0107 定稿）：「打开即已读」（`openMobDetail` → `markReadOnOpen`，ui.ts:1054-1078），返回目录时该条**立即**沉入默认收起的「已收」折叠段（ui.ts:1069 注释「无需等再次打开目录」）。归档段内容 = `[...saved, ...readSkels]`（ui.ts:988），已读骨架与已剪藏混在同一段。
- **桌面端**：「无自动落读」（ui.ts:760 拍板），已读只能靠右键「标记为已读」/源级「全部标为已读」；且 `queryBySource` 源头就过滤 `read===true`（store.ts:182），已读条目在重渲（refreshAfterAction → renderAll）时**整个从目录消失**，桌面没有让位段，也没有变色残留。

两端目录每次渲染都是实时现算（`sortedView()` ui.ts:453-455 unread 置前稳定排），←→/jk 也用实时序而非快照。

用户实测反馈（果壳科学人）：「打开一篇文章状态马上变已读、目录标题变色，当在目录内打开另一篇时上一篇已读的**保持原位**；再次打开该源目录时已读的才排到未读下面」——即要「会话内冻结、重开才重排」。同时希望桌面端也获得同等动线。

## 决策

**会话冻结序**——打开面板（装载）拍一次目录快照；整个会话内任何状态流转不重排目录，条目**原位**只变肩视觉/计数；**唯一重排点 = 重新打开剪藏本面板**。重排后已读/已收按双折叠段收纳。

1. **打开即已读（两端统一）**：桌面废除 ui.ts:760「无自动落读」拍板，与移动端一致——单击打开（含 ←→/jk 步进）即静默标已读（无 toast/撤销）；仍限 news 订阅源条目（剪藏本源 .md 无未读/已读生命周期，不套用）。
2. **显式动作同样原位**：右键「标记为已读」、rail/章头「全部标为已读（N 篇）」、收藏（saved）——均不即时让位，原位保留到重排点。计数（rail 徽标 / 章头「N 未读」）**即时更新**。
3. **重排去向 = 双折叠段**：重开面板触发重排后——
   - **「已读」段**：放已读条目（打开/显式标读产生）。30 天保留期内可回看（loader 保留策略，newsRetentionUnsavedDays 默认 30）。
   - **「已收」段**：放已剪藏/收藏条目（由剪藏目录文件承接，不随 news 过期）。
   - **移动端**：原 ADR-0107 单一「已收 N 篇」段**拆分**为「已读」「已收」两个折叠段（已读骨架不再与 saved 同段）。
   - **桌面端**：**新增**这两个折叠段（现状桌面无折叠、已读直接消失），源目录结构 = 未读常显 → 「已读 N 篇」折叠 → 「已收 N 篇」折叠。
4. **桌面端无未读兜底展开**（桌面专属，移动端多章平铺不套）：打开目录无未读时，已收段有内容则**默认展开已收**，已收空则展开已读——保证整源读完后不面对空目录。移动端维持 ADR-0107 默认折叠。
5. **适用范围**：仅 news 订阅源（果壳科学人/知乎日报/B 站 UP）。剪藏本源条目维持现状。

## 取舍

- **会话内顺序冻结 vs 即时减肥**：「刚读的还在原位、便于续读顺扫」优先，代价是目录短时间不收缩；重开面板即清（折叠段收纳），30 天骨架在装载时自然过期。
- **打开即读（桌面新增）**：会把连点翻过的条目都标读，接受——与移动同一语义、动线统一，且原位残留是这次设计要的观感。
- **双折叠段而非单段混合**：已读是 30 天必过的骨架、已收是持久剪藏承接，生命周期不同，混段会让「已读回溯」被收藏淹没；拆开各自可点可扫。
- **重排延迟到重开面板而非换站**：换站回切仍要保原位，用户已拍板「仅重开面板才重排」——重开 = 每次装载语义，天然覆盖入内新文与重算。
