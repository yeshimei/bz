# ADR-0288：订阅可见性——左栏补 0/0 行、空源不并栏、换实例重拼路由地址

- 状态：已采纳（2026-11-06）
- 涉及域：clipbook（主）/ core（无）
- 关联：ADR-0082（剪藏本融合域）/ ADR-0108（目录冻结序）/ ADR-0209（RSSHub 路由型订阅）/ ADR-0270（存储落位）

## 背景

用户反馈两件事：**「已经添加了 RSS 源，但不显示订阅；抓取了内容却在剪藏本里看不到」**
与**「左栏 0/0 的那行（剪藏本空着时最容易）点一下就整块收起来，其他内容看不见」**。

查下来是四条独立成因叠在一起：

1. **左栏站点行是从抓回来的文章倒推的**（`aggregateSites` 只看 articles + clipNotes）。
   订阅成功但一条都没抓回来（公共 RSSHub 实例限流/不可达最常见）时，左栏里根本没有这个源——
   界面上没有任何地方能看出「订阅过什么」。
2. **并栏判据过宽**：中栏一旦没内容就 `setVoidLayout(true)`，把左栏和右栏一起收掉。
   左栏没了就切不回别的源，而且 `M.sel` 是常驻内存面，下次打开还是这个空壳样子。
   受影响的不只是剪藏本 0/0——任何空源都这样。
3. **写盘失败假成功**：`writeNewsDataMerged` 在读盘失败（news.json 损坏/瞬时 IO）时静默
   `return`（F8 保护，不清盘正确），但返回 `void`，调用方以为写成功：弹窗里能看到订阅（内存态），
   重开即消失。
4. **单订阅失败完全静默**：`fetchRss` 只在**全部** feed 都请求失败时才传导源级失败；
   单个 feed 挂掉被 `continue` 掉。抓取结束那句「新增 N 条」的 N 来自别的源，
   用户以为 RSS 也抓到了。

另外发现一个连带坑：**路由型订阅的地址在订阅时按当时实例拼死落盘**（ADR-0209），
事后改「RSSHub 实例」不会回头修已订阅条目——用户换到自建实例仍拉不到，只会以为「换了没用」。

## 决策

1. **左栏按订阅列表补行**（`ui.ts renderRailNow`）：文章反推出的站点行覆盖不到的订阅，
   按 `feedSiteName`（title 优先、缺省回退 url，与 `buildRssArticle` 的 platform 同口径）
   补一行。行尾总数取 `countNewsBySite` 的**全量**条数（含已读、已收），不是 0——
   一个抓回来 10 篇全读完的源也会落到这一行，显 `0/0` 会把它伪装成「从没抓到」，
   而 `0/0` 正是用户拿来判断抓没抓到的那一眼。抓到文章后按同名并掉，不出现两行。
2. **并栏只留给「整本真的一无所有」**（`bookIsEmpty`：没 articles、没剪藏、没订阅）：
   空源只让中栏说清楚，三栏留着。剪藏本 0/0 同理（书里有 news 时不再收左栏）。
3. **会话首渲染复位空壳选中源**（`sessionSelCheck`）：打开面板时若停在的站点已不存在
   （不是站点行、也不是某条订阅），回「全部未读」。只在会话首次渲染校验一次——
   会话内点进空源要能看到空态说明，不能被弹回；停在「已订阅但 0 篇」的源上也不复位，
   那条空态正是要给人看的。
4. **空源空态分四类**（`emptySourceView`）：搜索零命中 / **已抓到但都处理过了**
   （`countNewsBySite` > 0：给「去剪藏本」，不引导换实例）/ 已订阅但没抓到（给订阅地址、
   「立即抓取」、换实例指引）/ 其余一句「这个源暂无内容」。
5. **单订阅失败点名**：`fetchRss` 返回 `failedFeeds`（标题优先、回退 url），进
   `NewsFetchResult.failedFeeds`（可选字段），通知里点名前三条；**不并进 `failedSources`**——
   那一列参与 `allFailed` 判据（长度 ≥ 已尝试源数），几个 feed 一起失败会把「别的源明明成功」
   的轮次误判成全失败、`lastFetchAt` 不推进。`notifyManualFetchResult` 也把它当部分失败。
6. **写盘结果如实回传**：`writeNewsDataMerged` 返回 `boolean`；`news-source-settings` 的
   各写入口据此返回 `false` / `'read-failed'`，设置项照实提示，不再假成功。
7. **换实例重拼路由地址**：`remapRssFeedInstance` 把 origin 命中旧实例的订阅重拼到新实例
   （路由路径与查询串原样保留，自备完整地址一条不动），与 `rsshubInstance` 同一笔写；
   设置行回报「已更新 N 条」。
8. **设置写入联动面板**：`markPanelDirty()`（state 单源）在写入成功后触发 ui 注册的回调
   （面板开着立即重读、关着标脏等下次打开）。数据层不反向 import ui，避免成环。

## 代价与不做

- 左栏会出现只有订阅、没有站点行承接的行（`0/0` 从没抓到、`0/N` 抓到了但都处理过）；
  这是有意的——「订阅在不在」「抓没抓到」必须能一眼看见。
- 空源保留三栏后，中栏「这个源暂无内容」会比以前常见；以前是整块收掉，反而看不出发生了什么。
- 单订阅失败的通知会比以前吵一点（最多点名三条）；这是真失败，不是噪音。
- 改实例会改写用户订阅数据（只动 origin 段）。换实例后若仍拉不到，问题在上游/路由，不在地址。
- 不新增 news.json 字段（不记「每 feed 上次错误」），因此体检白名单、迁移、守护进程都不用跟。
- 移动端不动：移动目录是章列表，没有并栏这回事；空态本来就是一句「暂无剪藏内容」。
- 不动数据结构，不给订阅记「来源」（手动粘贴 / 源库拷贝仍然同权同生命周期）。
