# ADR-0062：小橘行为流升级全量日志（双写）+ 渲染时人类文案 + 时间线面板

- 状态：采纳（2026-08-27 grill-with-docs 拍板 + 原型验收定稿，ticket 129）
- 关联：ADR-0055（记忆/行为流拆分，本 ADR 修订其「分流二选一」）、ADR-0056（StructuredMeta 契约，不动）、ADR-0057（描述生成架构，记忆流侧不动）

## 背景

ADR-0055 将单一 memory.stream 拆分为 memoryStream + behaviorStream，addObservation 按 ROUTING_RULES 二选一分流；行为流定位「辅助上下文」。实际使用中暴露三点：① 行为面板看不到聚合讯阅读时长（数据在 metadata.extras.durationMin 但展示层不渲染）；② 列表文案是生硬事件名（`news:skipped 标题`）；③ 用户语义预期是「行为流 = 全量行为日志」——记忆流事件（日记/影视/书评等）也应留下行为痕迹（「任何行为都记录到行为流，包括记忆流中的行为，两边都有」）。

## 决策

1. **行为流升级全量日志**：addObservation 一律**先写行为流**；routing 命中 memory 的再写记忆流条目。两条独立（各自 id/时间戳，不互相标记来源——用户拍板「看起来是独立添加的，只是方便管理」）。ROUTING_RULES 表不动（importance/emotion/credibility 语义保持）。
2. **渲染时生成人类文案**：行为流条目照旧存结构化（metadata=StructuredMeta，description 字段保持 `source:action 名称` 兜底不迁移）；dashboard 渲染按 `entityType:action` 分派模板函数生成「你保存了《x》（平台·读了 N 分钟）」式文案；模板**全覆盖**全部结构化域，无模板兜底旧式；列表不显示事件名。
3. **时间线面板 + 筛选 + 滚动加载**：列表时间线式（左竖线+圆点）；来源统计块点击筛选（「全部」还原）；滚动加载。
4. **提升按钮移除**：面板「提升为记忆」按钮删除；`promoteToMemory` 接口保留（未来手动补录用）。
5. **容量默认上调**：behaviorMaxCount 1000→2000（30 天不变；已有 data.json 值尊重）。
6. **边界保持**：行为流仍不向量化、不入 prompt 槽位；防重守卫（B6 300ms、news 近 20 条）不变。

## 备选

- **memory 事件额外写行为流副本**（routing 表两侧写、入口不改）：语义上行为流仍是「分流出口」之一，双写点分散在规则表——否，改为「一律先 behavior、按规则追加 memory」，行为流为唯一入口，机制更简单。
- **文案拼进存储 description**：渲染能力冻结在写入时刻，模板迭代需迁移旧数据——否，存结构化、渲染时生成。
- **按来源差异化保留**（news 短日记长）：设置面膨胀，暂不做（30 天/2000 条已覆盖用户拍板）。

## 后果

- 行为流条目增速上升（记忆流事件全部入流），2000 条滚动窗口吸收；行为流体积仍远小于向量库。
- 「提升为记忆」的心智入口消失：行为流独有条目（如 news:skipped）不能再从面板手动转正——接口保留，确有需求时另议入口。
- 渲染模板成为新扩展点：新域事件必须同步补模板，否则面板回落事件名兜底（约定写入 description-generators 同层）。
