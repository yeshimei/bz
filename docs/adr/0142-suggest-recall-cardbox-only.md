# ADR-0142 挂载建议召回改卡片盒白名单（修订 ADR-0140 范围闸）

- 状态：已接受（2026-09-15，grill 评审拍板；**设计定稿，未实现**）。修订 ADR-0140 决策 1 的「范围闸」部分
- 关联：ADR-0138（AI 建议不挂 related）/ ADR-0140（三段式链路：查询官 → 本地召回 → 采纳官 → 定位官）/
  ADR-0137（卡片挂载点）/ ADR-0141（自动关联三盒为界——本 ADR 是其姊妹拍板）
- 影响：`src/knowledge/mount-suggest.ts`（`SUGGEST_EXCLUDE_DIRS` → 白名单判定）、相关测试

## 背景

ADR-0140 决策 1 把挂载建议的召回范围定为**排除式**：只排除「归档 / 网页剪藏」，其余全库可当候选。
理由是全库召回 top5 有 4 条是剪藏噪声，且白名单式会误伤。当时也顺手认定「主题盒不用于白名单，
只参与形态判定」。

2026-09-15 用户给出新边界：**挂载建议只在卡片盒范围内**——与同日拍板的「自动关联限三个盒子」
（ADR-0141）分开处理，因为两条链路的产出与粒度都不同（建议落 `mount-suggest.json`、固定后写正文双链；
自动关联写 frontmatter related）。

## 决策

### 1. 召回白名单 = 卡片盒

`mount-suggest` 的召回池从「全库减归档/剪藏」改为**卡片盒目录（`knowledgeCardboxDirectory`）之内**。
判定按前面 ADR-0141 决策 4 的 core 单源取目录，不再维护 `SUGGEST_EXCLUDE_DIRS` 这类排除表。

### 2. 建议只在卡↔卡之间产生

- 建议的目标笔记必须是卡片盒里的另一张卡；**卡 → 文献 / 主题靠固定挂载（同名对齐）与用户自己写的
  正文双链**，不由 AI 推进建议。
- **六类形态实际缩编为四类**：整篇 / 标题 / 段落 / 卡片。ADR-0137 §3 的 image / video 两类目标
  退化为「只服务于用户自己写的双链」——图版图片默认落 `<文献目录>/assets`、视频也不在卡片盒内，
  都不再是召回目标。这是本决策**刻意接受**的缩编（用户拍板），不是遗漏。
- ADR-0140「主题盒不用于白名单」的表述由本 ADR 的「白名单 = 卡片盒」取代：主题盒天然在白名单之外。

### 3. 空盒 = 空建议集

卡片盒为空（如本机现在——旧盒已改名 `卡片盒2`）时，建议集恒空。这是**正常空态**，面板应显示
「暂无建议」而不是错误或空载提示；也不得为了有建议而回退全库召回。

## 后果

- 白板/挂载树上的建议线密度显著下降，但每一条都可指向一张卡片，噪声（剪藏、日记、旧卡）清零。
- `SUGGEST_EXCLUDE_DIRS` 及其「排除式」注释退役；`mount-suggest` 的召回闸与 ADR-0141 的三盒范围
  成为同一族「盒内召回」口径（自动关联限**三盒**，建议限**卡片盒**，两者不可互相套用）。
- 原 ADR-0138 §5 采纳的功能清单里，「盒外双链来源标注」的紧迫性下降（建议已不再指向盒外），
  但用户自己写的盒外双链仍可能出现，该项不撤销。
