# ADR-0105：域 UI 布局×主题分层（ADR-0104 的结构延伸）

日期：2026-09-07 ｜ 状态：采纳（belongings 拍板设计，书库同批落结构）

## 背景

ADR-0104 把 markup 收进域 `render.ts` 单源。用户进一步拍板：**一个域可有多个布局，每个布局自带主题**——布局 = 信息架构（网格/时间轴/书脊墙…），主题 = 同布局下的 token 皮肤（纸面墨黑 vs 其他配色）。结构与颜色正交：`面板类名 = bz-<域>--<布局> bz-<域>-th-<主题>`。

## 决策

```
src/<域>/
  render.ts              ← 域入口：布局工厂分发 + 跨布局共享层（口径计算/管道/详情表单/流转动作）
  layouts/<布局>/render.ts ← 该布局私有 markup 与排布胶水（真正的差异层）
  layouts/<布局>/styles.css ← （自第二布局起分文件）该布局样式 + 其主题 token 组
```

- **共享层（一份）**：视图状态、筛选/口径计算、actionSpecs、表单/详情内容——任何布局不得私有一份口径。
- **controller（一份）**：wirePanel 委托骨架（点选筛选/防抖/再点回全部），副作用经 actions 适配器注入（toast/写盘/弹窗）——行为单源。
- **布局差异层（每布局一份）**：排布 markup、头行形态、KPI 摆位。
- **主题不进 TS**：主题 = 作用域 token 覆盖（CSS 变量组），选主题 = 换根类名，零 JS。
- **入口分发**：域 `render.ts` 持工厂表，对外 API（`panelHtml/renderPanelView/…`）不变；`ui.ts` 与原型壳对布局无感。
- **布局/主题键**：自第二布局（或第二主题集）出现时再加设置键与回落逻辑；单布局期只落工厂机制，不造死键。

## 后果

- 加新布局 = 新建 `layouts/<x>/` 写差异层 + 工厂表加一行；共享层零改动。
- 原型评审 `?layout=` 直达（单布局期参数可缺省）。
- 预览包照旧从域入口打包，layouts/ 属域内文件，纯度守卫自动覆盖。
- 首批落地：bookshelf（layouts/wall/）；belongings（layouts/poster/）排队——等主仓进行中的自绘下拉批落地后迁，避免同文件并行冲突。
