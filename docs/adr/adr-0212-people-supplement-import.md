# ADR-0212 · 脸谱补充素材——详情页导入入口与素材数据路径

日期：2026-09-28 · 状态：已采纳 · 关联：ADR-0191（聊天原文不进 vault）、ADR-0194（保库记录）、ADR-0213（录音分离管线）、issue 509

## 背景

脸谱画谱的素材目前只能来自微信备份全量导入（数据源路径）。用户手里还有零散素材想补给单位联系人：随手记的事（已有「记一笔」＝ ManualEvent）、图片、录音文件。现「记一笔」按钮语义过窄，且图片/录音没有导入通道。

## 决策

详情页「记一笔」按钮改为**「补充素材」**入口（icon 换 import 类），打开三页签子页：

1. **文本页签** ＝ 原记一笔功能原样收编（ManualEvent：日期 + 一句话 + 轻重），数据路径不变；
   「聊天文本导入」经评审**取消**——别处复制的对话归属与时间语义难自洽，不做。
2. **图片页签**：多选文件 → 复制到 `<数据根>/<联系人>/desc/<月>/<YYYYMMDDHHmm>_<序号>.<原扩展名>`
   （**带扩展名落盘**，修正旧库 img 无扩展名导致引擎 describe 段读不到派生档的问题）；
   聊天仓新增 type=3 消息，`img` 字段同格式带扩展名；归属（我发的/对方发的）页内批量二选，默认「对方」；
   时间戳取文件 mtime，页内可改。落盘登记后页内出「生成描述」按钮，显式触发引擎 describe 段
   （AI 面板当前多模态通道，计费动作用户说了算），描述完成自动并仓为 `[图片] 描述` 消息。
3. **录音页签**：多选文件 → 复制到 `<数据根>/<联系人>/recordings/<原文件名>`；
   时间戳文件名解析优先、回落 mtime，可改。处理管线为外部脚本（ADR-0213），
   状态落数据根 sidecar（`recordings/<名>.turns.json` + phase 标记），**断点续跑一次做齐**
   （VAD / 声纹滑窗 / 转写各阶段落账，中断后从完成阶段续跑，不整段重来）；
   进度显示挂在画谱任务进度块同一位置（每条录音一行：待处理/转写中/已并入/失败）；
   处理完成按轮次合成进聊天仓（形态见 ADR-0213），合并动作由插件执行（插件是聊天仓唯一写入者）。

**隐私口径不变**（ADR-0191/0194）：图片、录音**原件一律落 vault 外数据根**，只有派生文本
（描述/转写轮次）进加密保库记录；导入页负责把用户选的文件复制过去，原件绝不进 vault。
**pythonPath**：录音管线经设置现有 `pythonPath` 键定位 python（wxtool 环境），首次处理前校验并引导填写。

## 后果

- 「记一笔」按钮消失，功能在补充素材·文本页签原样可用（ManualEvent 零迁移）。
- 旧库历史图片（img 无扩展名）仍走旁路表兜底路径；新导入图片因带扩展名可直接吃引擎 describe。
- 录音处理是长时外部进程，Obsidian 重启会杀进程——sidecar 断点保证续跑只补缺口。
- 图片 describe 走 AI 通道按张计费，故设计为显式按钮而非自动触发。
