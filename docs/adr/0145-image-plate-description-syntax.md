# ADR-0145 图版描述写入嵌入尺寸位（`![[路径|描述]]`）

- 状态：已接受（2026-09-15，grill 拍板；**设计定稿，未实现**）
- 关联：issue 329 / ADR-0136（图版文献，多图与图片目录 issue 313）/ ADR-0122
- 影响：`src/knowledge/ui.ts`（图版态逐图描述输入框）、`src/knowledge/note-gen.ts`（`generateImageNote` 图片行拼接）、相关测试

## 背景

用户要图版逐图加一段自己写的描述，落进文献笔记，原话给的是 `[[图片路径|描述]]`。
Obsidian 语法事实三案并陈拍板：

- `[[路径|描述]]`（无叹号）= 文字链接：图不内嵌，只显示描述文字，点击才打开图；
- `![[路径|100]]` 嵌入的 `|` 后 = **尺寸参数**，非数字值阅读视图忽略（描述不可见）；
- `![[路径]]` = 现状的内嵌图。

## 决策

1. **语法定 `![[路径|描述]]`**（用户选第三案）：描述写进嵌入 `|` 后位置，图照常内嵌；
   bz 不负责描述的阅读视图渲染——**依赖用户侧一个渲染插件把它显示出来**（用户明示有此插件，拍板接受）。
2. **每张图一个描述框**：缩略图网格下逐图 input（≤9 张逐张对应），单图即一框；
   无描述保持 `![[路径]]`。多图笔记 `[[图1|描述1]]`、`[[图2|描述2]]` 各自对应。
3. **不另设 frontmatter 键**：描述唯一载体是正文图片语法，无程序消费方；日后需要再加（可选字段零迁移）。
4. 正文结构不变：读图解读（文字）在上、图片嵌入在下，图片行按有无描述分叉拼接。

### 被否的备选

- **严格 `[[路径|描述]]`**（用户原话字面）：图不内嵌，笔记只剩一行描述文字，图版观感损失；
- **内嵌 + 图下描述行**：图与描述都可见，但描述不进图片语法，与用户预期的落点不符。

## 后果

- bz 内文献预览与 Obsidian 原生阅读视图均不显示该描述（尺寸位非数字被忽略），属预期行为；
  换渲染环境即失效，是用户自担的依赖。
- 录入面板图片态新增逐图描述框（与缩略图 ✕ 移除、加图作废草稿的既有语义协同：删图连描述一起没）。
- AI 读图把已填描述作为上下文一并喂给模型（用户拍板「喂」），标题/领域/解读更贴合关注点。
