# ADR-0300：知识盒视频交付目录收口——写死机器路径退役，空值跟随卡片盒的 media

日期：2026-11-24 · 状态：已采纳 · 关联：issue 571（本决策）、ADR-0296（本机音视频沿用
`knowledgeOutputDir`）、ADR-0275（图版三跳收口，本轮视频照其同构）、ADR-0293（目录行隐藏，本轮恢复卡片行）

## 背景

外部工具 `bili-downloader` 的 `DEFAULTS.outputDir` / `vaultPath` 写死了作者本机的
`E:/Obsidian/叫我包仔/...`。插件侧 `knowledgeOutputDir` 留空时不下发 outputDir（ticket 149 的
「留空键不下发，避免空串覆盖 rc 兜底」口径），于是工具用写死的默认值落盘；交付目录不在用户
vault 内，`vaultRel()` 只能回传绝对路径，笔记尾部 `![[绝对路径]]` 在别的机器上就是死链。
用户 2026-11-24 报「恶性 bug」并附截图，正是这个症状。

同一张设置面板上还有两个帮凶：「输出文件夹」行藏在「视频处理」组、留空没有回落显示；
「卡片文件夹」行被 ADR-0293 整体隐藏，图版行的说明还写着「跟随 Obsidian 的默认附件位置」。
用户看不见跟随关系，自然认为图版和视频都没有跟随。

## 决策

1. **视频交付目录与图版同一套三跳，且空值也必须算出库内目录**：
   ```
   显式设置值 → Obsidian 固定附件位置 → <卡片文件夹>/media
   ```
   末跳单独给媒体一个 `media/`，不混进配图的 `assets/`；卡片目录按三盒口径归一到「卡片盒」，
   解析函数 `resolveVideoDir()` 不产出空串。复用 `core/attachment-dir.ts` 的 `resolveAssetDir()`，
   不新造第四种目录解析口径。

2. **outputDir 恒下发，且必须是绝对路径**。工具的 outputDir 走 `path.resolve`，下发库内相对目录会
   按进程 cwd 解析、偏离库根；所以插件把算出的目录拼上 vault 根再下发。用户显式填的绝对路径
   （盘符开头）原样下发；拿不到 vault 根时宁可不下发，让工具报「交付目录未配置」，也绝不退回
   某台机器写死的路径。这是对 ticket 149「留空键不下发」口径的**有意例外**，仅限 outputDir。

3. **外部工具不再有任何内置机器路径**。`config.js` 的 outputDir / vaultPath 默认为空；bz 插件每题
   下发，独立 CLI 使用者在 `~/.bilibili-dl.json` 自配，两者皆空时明确报错，不静默落到库外。

4. **设置面板如实呈现跟随关系**：视频目录行从「视频处理」挪进「目录与分类」，带 `fallbackValue`
   显示算出的实际落点；卡片文件夹行恢复显示（图版与视频空值时都跟它走），主题盒仍隐藏；
   图版/视频两行说明按三跳重写，视频行 `help` 讲明「填库外绝对路径 = 换机器打不开」。

5. **存量不迁移**：旧路径下已落盘的视频、笔记里已有的绝对路径不动，只保证新生成的正确。

## 备选

- **只改工具默认值、插件维持留空不下发**：工具默认值改成空串后，插件不下发就会报「交付目录未配置」，
  用户每次都得手动填——否决，这正是「用户配了卡片盒却没跟随」的病根。
- **下发相对目录，让工具按 vaultPath 解析**：语义更干净，但要改工具两处交付分支与配套测试，
  改动面更大；本轮用插件侧拼绝对路径，工具侧零语义变更——采纳。
- **把视频也落 `<卡片盒>/assets`**：与配图混在一起，用户找文件困难；单独 `media/`——采纳。

## 影响

- 插件：`src/knowledge/note-gen.ts` 新增解析函数、`processor.ts` 改下发、`ui.ts` 改 schema；
  可见设置项数 knowledge 21 → 22（测试基准同步）。
- 工具包：`config.js` 默认值清空，README / CONTEXT 文档同步；89 项测试保持全绿。
- 数据：不迁移存量；新笔记里的媒体嵌入从「可能是绝对路径」变为「恒为 vault 相对路径」。
- 兼容：显式填了库外绝对路径的用户仍照旧工作（只是笔记换机器打不开，`help` 已警示）。
