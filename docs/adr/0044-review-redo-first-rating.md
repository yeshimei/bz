# ADR-0044：做题会话首次评级为唯一排期来源，重做不写 FSRS 数据

日期：2026-08-25 ～ 状态：Accepted ～ 关联：ticket 098、ADR-0009（数据路径）、铁律 1（兼容冻结，本 ADR 是唯一例外授权）

## Context

「做题决定难度」开启的复习流程里，自动评级 ∈ {忘了, 困难} 时用户要强制重看笔记并重做到通过。grilling 拍板的关键语义（用户在 Q8/9/10 的原文）：**「第一次做题的难易度作为预期的判断标准，后面的二次复习、三次复习、四次复习等，都不作为预期的判断标准」**。

## Decision

1. **首次评级是唯一排期来源**——做题会话第一次结束的自动评级照常走 `markReview`（写排期/历史），这是本轮复习的唯一 FSRS 结论。
2. **重做不写任何 FSRS 数据**——重做（AI 新题再考）通过时只清除 `pendingRedo` 标记；失败时什么都不写。排期、`lastReviewed`、`reviewHistory` 均保持第一次尝试的结果。
3. **多选计数 bug 解冻（唯一破铁律 1 项）**——`QuizMasterUI._buildOptionButtons` 多选答对分支补 `correctCount++`。冻结原因：原源码缺陷「多选正确不递增计数」使纯多选笔记全对也 rated 忘了（accuracy=0），在「直到标记不为困难」机制下**逻辑死锁、永远无法通过**。其余冻结项（主演计数取单次、flash refresh 不清理已删文件向量条目等）一律不动。
4. **未通过 = {忘了, 困难}（正确率 <70%），通过 = {一般, 简单}**——「直到标记不为困难」的精确化边界。
5. 数据：`ReviewItem` 新增可选字段 `pendingRedo?: boolean`（旧数据零迁移）。

## Options

- **O1 重做也照常 markReview**——❌ 重做会立即撞上 `markReview` 的「未到复习时间」时间门（首次评级已把 nextReviewDate 推后），且会让第二次评级覆盖第一次、自相矛盾；违背用户「不作为判断标准」的明示。
- **O2 重做失败也推后排期（当作一次失败复习）**——❌ 与「首次评级唯一」冲突，失败轮次会无限叠加排期噪音。
- **O3 保留多选计数 bug**——❌ 含多选笔记在重做机制下无法通过（accuracy 恒 0），机制与缺陷互斥，必须解冻一个；用户拍板解冻计数。

## Consequences

- 低阶梯（stage 0-1，间隔 1m/30m）笔记首次失败后，即使重做通过，下次复习仍按首次的短间隔很快到期——这是「首次评级唯一」的自然结果，接受并记录（用户选择）。
- 同一次「开始复习」会话里，重做通过的笔记从当轮逾期集合剔除，防止「1 分钟后」间隔在同会话内立刻再次出题造成循环感。
- 重做只经「待重做队列」触发（不依赖逾期过滤），`markReview` 的时间门不拦截重做路径（重做根本不调用 markReview）。
- 普通复习（做题决定难度关闭）不受本机制影响；手动评级 good/easy 也会清除 pendingRedo（任一途径的好评都化解待重做）。
