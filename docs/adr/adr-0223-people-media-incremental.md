# ADR-0223 · 脸谱媒体导出的增量口径（存在判定先行 · 索引驱动 · 欠账永久化阻断）

日期：2026-09-30 · 状态：已采纳 · 关联：ADR-0196（画脸谱任务链）、ADR-0197（聊天仓唯一写者）、
ADR-0219（Windows 原子写）、issue 515（媒体无欠账跳过预处理段）、issue 520

## 背景

「画脸谱」每次补画都被用户感知为「全量导出媒体、全量派生，特别慢」。查证后是三层原因叠加：

1. **工具侧存在判定顺序错**（`bz_prep.py`）：`do_image` / `do_video` 先 `read_bytes()` +
   `decode_dat()`（AES 多密钥轮试）**然后**才判 `target.exists()`——已导出的文件每轮都要完整读盘
   和解密一遍，算完直接丢。四类媒体里错的两类正是体量最大的两类（1631 张图 936MB + 全部视频）；
   `do_file`、derive 段、语音段都是「判定在前」，是对的。
2. **三次全量目录遍历**：段 1 `attach_dir.rglob('*')`、段 2 与段 3 各 `img_root.rglob('*')` 一遍。
3. **欠账永久化**：插件侧 `pendingMediaCounts` 的欠账口径是「媒体消息且 `text` 为空」。图片描述
   失败的图 `text` 恒空 → 永远判有欠账 → 每次补画都重起 prep 进程，把 1、2 重走一遍。

issue 515 已在**插件侧**挡掉「无欠账」这条路径（不起进程），但「确实有欠账时」的那一次仍是全量
白读；且只要有一张图描述失败，就永久落回这条昂贵路径。

## 决策

1. **存在判定先行（档 A）**：`do_image` / `do_video` 先探测产物存在再决定是否读源字节。
   `do_image` 的目标名取决于解密后才知道的扩展名（`jpg/gif/png/bin`）→ 用四种候选探测，命中即
   `skip`（`.bin` 命中仍走 `try_wxgf` 补解码，语义不回退）；`do_video` 目标名与 ext 无关，一次
   `exists` 即可。**已导出文件的代价从「读全字节 + AES 轮试」降为一次 `stat`。**
2. **索引驱动增量（档 B）**：段 1 不再每轮全量 `rglob` attach 目录，改用
   `<数据根>/<联系人>/.bz-face/media-index.json`——存各月份子目录 mtime + `hex → 月/文件名` 映射。
   **mtime 未变的月份直接读缓存，变了的月份只重扫那一个目录**并并入索引；首次运行全量建一次
   （一次性代价）。导出队列 = 索引里**产物缺失**的条目。
3. **派生与关联段复用产物清单**：段 2 derive 与段 3 map 不再各自 `rglob` 一遍 `image/`，共用同一
   份产物清单（同样按月份目录 mtime 判失效）。
4. **保留「全量源文件过一遍」的结构，而非纯消息流驱动**：`thumb/`（微信自带缩略图）与未挂消息的
   附件不进消息流，纯消息驱动会漏。索引把「遍历」变成内存操作、档 A 把「读盘解密」消掉，两条
   合起来才是完整增量。语音段沿用既有水位口径（本就按 `voice.json` 跳过），不动。
5. **索引只决定「要不要重扫」，不决定「扫到之后怎么判」**：产物存在判定（决策 1）独立成立——
   即便索引因 mtime 异常而漏收某文件，产物在就不动作、产物不在则当轮仍会被捞到。正确性不押在
   mtime 上。
6. **欠账永久化阻断**：任何「确定性失败、永不重试」的媒体项（如 ADR-0224 的敏感标注）必须同时从
   `pendingMediaCounts` 的口径里排除，否则每轮补画都会重新触发一次全库扫描。**这条是硬约束：
   新增任何终态跳过标记时，欠账口径必须同步。**

## 备选

- **只在插件侧加缓存、不改工具**：插件能拦「完全无欠账」，拦不住「部分欠账」时工具侧的全量白读；
  根因在工具侧，改在插件侧是错层。
- **纯消息流驱动（照搬语音段）**：语义最正，但漏 `thumb/` 与未挂消息的附件；且 `img` 字段到源文件
  的映射仍需一次目录遍历，省不掉首次成本。
- **按「上次水位时间戳」裁剪**：微信可能把补下载的历史文件写进旧月份目录，按时间戳裁剪会漏。
- **把 attach 目录整体当可删缓存**：不可逆，且那是微信自己的数据。

## 后果

- 媒体无变化的第二轮 prep：媒体段与派生段近乎瞬时（内存索引 + `stat`），日志里 `skip` 计数远大于
  `done`，与「已经导出过」的事实一致。
- 代价：数据根多一个索引产物（与 `state.json` 同处，跟数据走不跟人走），并在 `.bz-face/` 的盘点
  与清理面里登记；首轮仍全量。
- 与 ADR-0197 不冲突：索引是工具侧产物，**权威仍是聊天仓**，索引丢了只是退回全量重扫，不丢数据。
