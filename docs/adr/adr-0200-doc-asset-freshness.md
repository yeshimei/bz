# ADR-0200：文档资产的新鲜度核对——本地秒开 + 后台核对 + 开着才热替换

- 日期：2026-09-26
- 状态：已采纳（实现见 issue 476）
- 相关：ADR-0198（手册 / 更新日志改为在线下载）· issue 473 / 474（两个入口与弹窗）· issue 475 / ADR-0199（皮肤包 sha256 清单，同源思路）· `src/core/remote-asset.ts` · `src/core/manual.ts` · `src/core/changelog.ts` · `src/settings-panel/ui.ts`

## 背景

ADR-0198 把手册与更新日志搬成「不随构建分发的远端资产」：入口点一下，现场从 GitHub 拉，
写入插件安装目录，弹窗用 iframe srcdoc 内嵌渲染。落盘策略是 `ensureAssetReady`
——**本地没有才下载，有就直接用**。

这套策略有一处结构性缺口：这两个资产**可以独立于插件版本重新生成并 push**
（`scripts/_gen-changelog.mjs` 重出日志、手册重出），而插件端没有任何机制会去发现
「远端已经是新版了」。已装插件会一直用第一次下载下来的那一版。

2026-09-26 用户报此现象，实测确认：

| 文件 | 本地（插件目录 / 仓库 `manual/`，sha 一致） | 远端 master |
|---|---|---|
| `bz-manual.html` | 275139 B（`cadef4b1…`） | 327093 B（`479d7ab8…`） |
| `bz-changelog.html` | 74313 B（`4add54a9…`） | 72338 B（`61a2a7f6…`，含 `v1.24.0`） |

同时实测到一条影响方案取舍的环境事实：`raw.githubusercontent` 在国内直连超时
（20s 未完成，`git ls-remote` 也不通），双远端链路里的主源基本用不上，实际由
jsDelivr 兜住。**这条直接否决了「每次打开都先拉远端」的候选方案**——那等于每次点开
先吃一次主源超时。

## 决策

### 1. 打开口径：本地秒开，网络不参与首屏

入口保持「本地内容立即渲染」：`ensureAssetReady`（无则下载）不变，就绪后**立即**开弹窗。
网络只出现在两条路径上——首次没有资产时的下载（前台，带 loading 转圈），以及下面的核对（后台）。

### 2. 新增新鲜度核对 `refreshAsset`：同版不动、变了才覆盖、失败静默

`core/remote-asset.ts` 增 `refreshAsset(app, fileName, validate, label)`：

- 拉远端（沿用双源与内容校验）→ 与本地比 `textSha256`（内建 `normalizeEol`，
  Windows CRLF 与仓库 LF 不误判为新版）→ **不同才**写盘并返回新文本；
- **同版 / 离线 / 被墙 / 双源内容都不可信 → 返回 `null`，全程静默**：
  不通知、不转圈、不动本地。它是后台动作，失败不是用户的操作失败。

与 `ensureAssetReady` 的分工写死在一处注释里：**那个管「有没有」，这个管「新不新」**。

### 3. 打开时 `void` 起一次核对；弹窗还开着才热替换

`runManualOpen` / `runChangelogOpen`：开完弹窗后 `void refreshDocInBackground(...)`
（**不 await**，按钮 loading 只覆盖前台下载那一段，阅读不被网络拖住）。
拿到新文本时：

- 弹窗**仍开着**（`isManualViewerOpen()` / `isChangelogOpen()`）→ 调 `open*Viewer(fresh)`
  热替换（该函数本就有「重复打开 = 抬顶 + 换内容」语义，零新机制）；
- 弹窗**已关闭** → 只落盘，**不重新弹出**（不打扰已经结束的阅读），下次打开即新版。

热替换会重置 iframe 内滚动位置——只在「内容真变了」时发生，属可接受代价（用户此时
要么刚打开、要么正在读旧版，前者无感，后者罕见）。

## 备选与否决

| 方案 | 否决理由 |
|---|---|
| 每次打开都先拉远端 | 离线要等网络失败，且主源（raw）国内必先超时；每次点开都吃流量（手册 275KB+），而多数时候内容没变 |
| 只加「检查更新」按钮 | 用户要的是自动更新，多一个必须记得按的钮等于没解决 |
| 沿用皮肤包的清单 sha256（ADR-0199） | 清单随插件版本分发，只能解决「插件升级后刷新资产」，解决不了「资产单独重出推送」——而后者正是本票的起因 |
| 核对加时间窗节流 | 现在不需要（入口点击频率低，一次核对 ~70–330KB）。真嫌费流量再加时间窗，属增量 |

## 后果

- 手册 / 日志「重出即生效」：push 后打开入口就能看到新版，无需发插件版本。
- 日常打开仍是零网络等待；离线、被墙、CDN 错误页都不会打扰用户，也不会污染本地已存版本。
- 代价：每次打开入口多一次后台请求（内容不变时不写盘）。若某些环境觉得费流量，
  在 `refreshDocInBackground` 前加时间窗即可，不影响本 ADR 的其余部分。
