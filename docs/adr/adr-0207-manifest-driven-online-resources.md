# ADR-0207：在线资源行集合改由下载清单驱动——行序进清单 + 组级全部更新 + doc 版本区间 + 条目体积

- 日期：2026-09-27
- 状态：已采纳（实现见 issue 494）
- 相关：ADR-0203（统一下载清单 + 在线资源组成立，本 ADR 修订其行集合来源）· ADR-0205（组回归通用声明行，本 ADR 续其「行集合恒定」口径）· issue 480（清单与组落地）· issue 490（清单与产物一致性守卫）· issue 492（组动作拦重入与跨入口同步）· `src/core/remote-base.ts`（新增）· `src/core/download-manifest.ts` · `src/settings-panel/online-resources.ts` · `scripts/build-manifest.mjs`

## 背景

ADR-0203 把「更新日志 / 使用手册 / 主题」三行收进设置面板「在线资源」组，issue 478 又并入「归物分类表」，
四行的 id 与行名**写死在 `FALLBACK_ROWS`**（`settings-panel/online-resources.ts`），构建侧的 `DOCS` 表另写一份。
issue 480 当时明确把「清单里出现未认识的条目时动态加行」列为**非目标**（「扩展留待真实资源出现」）。

此后「真实资源」真的出现了：一次全域盘点（`review-online-resources.md`）列出十余条可资源化候选
（日记标签表、跨域提示词包、FSRS 权重与拟合边界、学科词表、平台映射表、剪藏源清单、预置卡组…）。
按当时的形状，每加一条都要同时改两处代码 + 重出清单；而 ADR-0203 给这条路的承诺是
「后续任何在线资源：清单加条目 → 新组加行 → 下载动作复用 remote-asset 通道」——**「加行」这一环还是手工的**。

同时暴露三个小缺口：

1. 组里没有「一次全下」的入口：皮肤行内部已是批量（`downloadSkinUpdates`），doc 行只能一行一行点；
2. doc 条目没有版本区间：`SkinPackEntry` 有 `since` / `until`，doc 条目没有——资源格式演进时，
   旧版插件拉到新内容只能靠各自的 `validate` 兜底；
3. 行描述不带体积：主题行说「已下载 N 套」、分类表行说「N 组 M 条」，但移动端在大批量下载前没有量级预期。

另有一处重复：仓库双源地址（GitHub raw 主 → jsDelivr 备）在 `core/remote-asset.ts` 与
`core/self-update.ts` 各写一份字面量。

## 决策

### 1. 行集合与行序都进清单，删掉 `FALLBACK_ROWS`

清单顶层新增可选 `rowOrder: string[]`（`docs` 的 id + 保留 id `'skins'` 的排列）。消费侧：

- 有 `rowOrder`：按它出行（不在 `docs` 里的 id 忽略；`skins` 是皮肤聚合行的保留 id）；
  漏提的 doc 与漏提的 `skins` 都**补在末尾**——清单是事实源，漏登记不该让条目凭空消失；
- 无 `rowOrder`（旧清单）：回落「`docs` 顺序 + `skins` 末位」；
- **无缓存清单：没有资源行**（组里只剩「检查更新」「全部更新」两行操作行）。

行名一律取清单 `name`（皮肤聚合行不是 doc 条目、清单里没有 name，故行名内置为「主题」）。
唯一的「按 id 特判」收成一张 `DESC_EXTRAS` 注册表（现役只有归物分类表的「N 组 M 条」），
只做**描述补充**，不影响状态机与动作分发——动作面本已通用（doc 行统一走 `ensureAssetWithHash`）。

### 2. 行序进清单的同时加构建期守卫

`build-manifest.mjs` 显式维护 `ROW_ORDER`，并守卫三件事：覆盖 `DOCS` 全部 id、含保留 id `'skins'`、
除 `'skins'` 外不得出现 `DOCS` 没有的 id。理由是行序表与 `DOCS` 表是两份要同步的事实
（与 issue 490 的「downloads/ 不许有清单外文件」同性质），漏登记的后果是**资源在组里掉行**，
而这类错误只在用户机器上可见——必须在构建期炸。

### 3. 组级「全部更新」行恒在 `rows[1]`

`rows[0]` 仍是门控显隐的「检查更新」行（ADR-0205 §2），新增一行恒在 `rows[1]`：

| 状态 | 按钮 |
|---|---|
| 有待办且有更新 | 全部更新 N（N = 待办**行数**，皮肤行算一行） |
| 只有未下载 | 全部下载 N |
| 全部就绪 | 已是最新（禁用） |
| 无清单 | 等待检查更新（禁用） |

动作按行序**串行**跑未就绪行（皮肤聚合行内部仍限并发 4），每条落盘后同步一次行态（逐条可见，
不是憋到最后一起翻）；失败行聚合计数，收尾一条 error 通知。重入拦用独立哨兵 `__all__`
（与 issue 492 的单行拦重入同口径：置忙提到首个 `await` 之前）。

### 4. doc 条目补 `since` / `until`

字段语义与 `SkinPackEntry` 完全一致，判定复用同一条 `isInVersionRange`
（首参泛化为 `{ since?: string; until?: string }`，不为 doc 另写一份）。**区间外 = 该行不呈现**：
旧版插件看到声明「需新版」的资源，既不该报「可下载」也不该报「已下载」。

### 5. 条目体积由构建期现算，只在就绪态描述里捎带

清单的 docs 与 skins 条目各加可选 `size`（字节，`fileSize` 对已出版产物 `statSync` 现算——与 `sha256`
同源同口径，绝不从 src 重算）。行描述只在**已就绪**态捎带体积：

- doc 行：`已是最新版本（26 组 515 条，318 KB）`（规模补充在前、体积在后）；
- 皮肤行：`全部主题已是最新（已下载 12 套，共 96 KB）`。

皮肤体积取「版本区间内已登记 size 的条目合计」——只在全部就绪态展示，此时它与已下载集合等值。
清单没登记 size 时，描述逐字退回旧口径（不出现空括号）。

### 6. 双源基址收成 `core/remote-base.ts`

零依赖叶子模块导出 `REPO_BASES` / `repoRemotesFor(name)` / `downloadRemotesFor(fileName)`。
`remote-asset.ts` 的 `remotesFor`（保留导出与签名，测试在用）与 `self-update.ts` 的 `REMOTE_BASES`
都改为消费它；行为逐字不变（raw 主 → jsDelivr 备、第一个成功的就用）。

## 备选与否决

| 方案 | 否决理由 |
|---|---|
| 行序不进清单，在代码里维护顺序数组 | 「加资源零代码」就是假的——顺序仍要改代码，且顺序与清单两份事实必然漂移 |
| 无清单时保留内置四行骨架（原来 `FALLBACK_ROWS` 的形态） | 等于把清单内容复制进代码当缓存；且状态未知时给用户「四行禁用」的假象，不如直说「还没检查到更新」 |
| 清单变化后自动重渲整组（新增一条组重渲通道） | 补丁按行序对位，行数一变必错位；但远端增删条目是低频事件，重开面板即得——不为它加跨模块通道 |
| 皮肤体积按本地已下载文件实测求和 | 要逐个读文件算体积（N 次读盘），而清单构建期已算好；且仅在「全部就绪」态展示时两者等值 |
| 全部更新逐条渲染进度（每行显示 1/12 之类） | 与「半自动 + 磁盘单源」口径冲突；逐行按钮本身已是进度面，行态在每条落盘后就地翻转 |
| `rowOrder` 含未登记 id 时让整份清单失效 | 与「清单是远端事实源」冲突：旧版插件应当忽略不认识的条目而不是炸掉整份清单（同理 `size` / `since` 对新版是可选、对旧版是多余字段） |
| `downloads/manifest.json` 不重出、由插件容错 | 体积与行序都靠清单承载，不重出等于新能力不生效；旧插件读新清单只取已认识字段，天然兼容，没有版本闸门需求 |

## 后果

- **新增一条在线资源 = 出版产物 + `DOCS` 加一行 + `ROW_ORDER` 加一个 id + `pnpm manifest`**；
  插件侧零代码改动（只用通用状态机的资源不必碰 `online-resources.ts`，要描述补充才加一条 `DESC_EXTRAS`）。
- **双向兼容**：新版插件读旧清单（无 `rowOrder` / `size`）回落默认行序、不提体积；
  旧版插件读新清单只取已认识的字段（`id` / `name` / `file` / `sha256` / 皮肤形状），多余字段忽略——
  因此发布顺序无硬约束，清单可以先出。
- **已交付的 `downloads/manifest.json` 必须重出**（新增 `size` 与 `rowOrder`），否则体积与行序不生效；
  `pnpm manifest --check` 守卫会把它标成不同步。
- **已知变化（知情项）**：无缓存清单时组内不再显示四行禁用占位，只剩两行操作行——「不知道有什么可下载」时
  不该假装知道。
- **已知变化（知情项）**：远端清单在会话中途增删条目时，已打开的面板不会当场多/少行（本轮同步刻意不补丁），
  重开面板按新清单重建整组。
- **已知变化（知情项）**：全部更新是串行（严格按行序），耗时 ≈ 各行之和；皮肤行内部仍限并发 4。
- 组卡徽标仍不计 `button` 行（ADR-0205 §后果那条不变）：本组现为「2 行操作行 + N 行资源行」，全 button，徽标恒隐藏。
