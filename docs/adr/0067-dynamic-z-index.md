# ADR-0067: 动态 z-index 层级制——谁后显示谁在上

日期: 2026-08-28
状态: 已采纳
前置: e3 层级收敛（静态档位类架构，见各域样式源「冻结面」注释）；ADR-0051/0052（第二大脑与统一 AI）

## 背景

全站 overlay 层级原为**静态档位制**：settings-modal.ts 内维护一张「z-index 家族表」（主面板 9997/9998 → 域模态 10001-10060 → 设置弹窗 10050 → 确认框 10250 → 抽屉 10999/11000 → companion 11100+ → 路径选择器 11200 → movie 小窗 12000 → toast 100000），每个弹窗按语义固定档位，e3 起收敛为「JS 挂档位类、值由样式源裁定」。

问题：新增弹窗要人工对表选档、档位空间耗尽要「抬档授权」，跨域叠加关系靠开发者记忆维护，认知负担持续累积。用户提出「动态 z-index，谁打开谁在上面」，并拍板**小橘桌宠保持最高**。

## 决策

1. **层级规则只剩一条：谁后显示谁在上。** 废除静态档位家族表与全部档位 z 规则；overlay 显示时由 `core/z-order.ts` 分配器发号（`allocZ` 单元素 / `topifyZ(els...)` 成组，遮罩在前本体在后，保持本体=遮罩+1）。
2. **显示即发号**：一次性弹窗创建即显示即发号；show/hide 复用的主面板在每次显示路径上 `topifyZ` 重新发号（构造时也发号一次作初始值，与 createOverlay 行为一致）。计数器单调递增、起点 100000（历史最高档），混合残留静态值不钻底；上限 2^31-1 足够使用数十年。
3. **恒顶层注册（用户拍板：小橘保持最高）**：`registerAlwaysOnTop(el)` 注册的元素（smartcat 桌宠容器）由分配器在每次分配后自动抬到最新档之上，语义同旧「猫 z 100000 盖过一切弹窗」；`#smart-companion-cat` CSS 静态值保留为初始兜底，其子元素（思考/语音指示器、气泡）在猫层叠上下文内相对取值不变。
4. **结构性保证弱化为顺序保证（用户拍板全量替换）**：旧表「确认框永远压过域弹窗」「路径选择器压过设置弹窗」等保证，动态制下依赖「确认框总是后开」这一现实操作序列，不再有结构性兜底。旧档位修饰类名（`bz-movie-overlay--1200`、`bz-lib-overlay--11100`、`bz-belongings-overlay--modal` 等）**保留作为 JS/测试的标识钩子，不再携带层级语义**；其中 library `--1100` 仍承载 0.3 半透明底视觉差异。
5. **样式源清档**：各域 `styles.css` 与根聚合 `styles.css` 删除全部 overlay z 规则（notice/确认框/抽屉/跟手菜单/todo/news/pomodoro/difficulty/library/movie/belongings/secondbrain/launcher 档位类段）；局部布局 z（diary 置顶分隔符 10/20、news 关闭按钮 10、encrypt 加载指示 2、launcher 格子拖拽 9999）与猫族 z 不动。
6. **notice toast 每次弹出抬顶**：与 overlay 共享动态层级空间，保证 toast 永远可见。

## Consequences

- 新增弹窗零档位心智：`createOverlay`（自动成对发号）或显示路径一行 `topifyZ(mask, popup)` 即可，不再对表。
- 20+ 域与 core 共享组件（settings-modal/flow-dialog/item-actions/path-picker/notice）全部接入；`createOverlay` 移除 `zIndex` 参数，`PATH_PICKER_Z_MASK` 常量删除。
- 已知取舍：模态弹窗打开期间若脚本在遮罩下刷新再重显示某底层面板，其 z 会晚于弹窗——现实无此操作序列；确认框/路径选择器失去「无条件压过」的结构性保证（见决策 4）。
- 测试：档位值断言全部改写为动态断言（有限数字、成对相邻、后开更高）；解锁弹窗等按 z 值查找元素的测试改按钩子类查找；pomodoro/library 反向断言样式源不再持有 z。
- 兼容性：DOM 契约（id/类名/结构）不变；数据格式不变；档位类名保留（仅语义变化），外部 CSS 若依赖 `.bz-*-overlay--<档>` 的 z 规则需自行发号（无已知外部依赖）。
