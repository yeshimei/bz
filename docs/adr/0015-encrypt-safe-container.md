# ADR-0015 加密保险箱——移出式清单容器加密

状态：已规划（encrypt 域，新域）
日期：2026-08

## 背景

用户要求实现"对整个 MD 文件加密，文字加密，图片和视频也可以加密"。经 grilling 会话逐轮敲定，落在**移出式清单容器加密**架构：把加密笔记从 vault 移出（原路径消失），正文与附件密化落盘到设置根目录，解锁两段式（清单解锁 → 压缩预览 / 真还原）。

`src/password/crypto.ts` 的 `CryptoService`（PBKDF2 100k + AES-GCM-256，salt16+iv12+ct，Base64）是唯一可复用加密资产；密码本域确立"主密码只存内存、解密成功即校验、无落盘校验值"范式。多个既有域（movie/library/clipping/reading-report/auto-summary）强依赖 `metadataCache.getFileCache().frontmatter`——若走"原地密文化"会破坏它们；移出式因解锁后文件完整还原而**规避了跨域降级链**。

## 决策

1. **移出式**：加锁＝笔记全文 + 双链图片/视频附件从 vault 移出，密文镜像到 `encryptRoot`（默认 `CONFIG/ENCRYPT`，可配置库外绝对路径）；原路径文件消失，vault 内"直接不见"。
2. **加密清单**：`<encryptRoot>/safe.enc` 整库唯一清单，整体 AES-GCM 加密；记录每篇原路径/状态/内容 blob/附件镜像引用。附件独立镜像文件放 `<encryptRoot>/附件/<原相对路径>`（用户明确：配置文件记录路径，新建文件夹放附件）。
3. **密钥体系（主密码代理）**：复用密码本主密码语义，主密码只存内存。**每个 blob 直接用主密码经 `CryptoService.encrypt` 独立加密（各自随机 salt+iv，PBKDF2 100k + AES-GCM-256）**——与密码本 `passwords.enc` 同模型，零额外密钥原语、完全可测；换主密码需全量重加密（与密码本一致）。逐条文件密钥 + 主密钥包裹的优化留作未来（本期不引入）。
4. **两段式解锁**：层面1 清单解锁（解清单列列表）；层面2 快速预览（压缩预览层：图片 canvas 缩放 / 视频抽帧成图，零外部依赖，本域不引入 ffmpeg 重依赖——用户拍板视频抽帧）；层面3 真还原（解原文+原质量附件写回原路径，`metadataCache.trigger('changed')` 让各域恢复）。
5. **生命周期（临时取阅）**：真还原＝借出来用，笔记带 restored 状态；加锁收回。崩溃幂等：加锁先写密文 blob + 增量更新清单、全部成功才删原文件；还原目标被占→指纹校验不盲盖。
6. **独立预览窗**：点列表某篇弹出独立只读弹窗，Markdown 渲染正文 + 图片/视频压缩预览；不写 vault。
7. **命令三段式** `bz-encrypt-open/lock/lock-all`，main.ts COMMANDS 裸注册；懒加载 ensureEncrypt。

## 权衡

- **移出式 vs 原地密文化（加壳/裸全文）**：移出式最贴近"直接消失"，且解锁后各域 metadataCache 完全恢复（无降级链）；代价是 Obsidian 同步/备份不覆盖 encryptRoot（库外时），容灾需用户自理——文档写明。
- **抽帧 vs ffmpeg 转码**：抽帧零重量依赖、跨平台简单；预览窗里视频只有清晰首帧图，播放靠真还原后在 Obsidian 内播原质量。若未来要"预览即播小视频"再引 ffmpeg（本 ADR 明确不引入）。
- **复用 CryptoService 而非复制**：密码本 crypto.ts 已是纯函数、无 window 依赖、可单测；直接 import 复用满足 ADR-0002 依赖方向。

## 已知限制

- Obsidian 文件恢复快照里"首次加密前的旧版本"仍含明文——明确不处理（清 .obsidian 内部缓存=与 Obsidian 搏斗，接受残余通道）。
- 主密码丢失＝加密笔记及附件永久不可解（AES-GCM 无后门）——首设弹窗含醒目警告与备份提示。
- 解密/加锁对大视频为整块内存读取（本期不流式），大视频操作可能占用较多内存——列为后续可迭代项。
