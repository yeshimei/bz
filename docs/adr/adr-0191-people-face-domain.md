# ADR-0191：脸谱域（people）立项——外部工具导入微信聊天 + AI 提炼脸谱，聊天原文不落盘

- 日期：2026-09-25
- 状态：已采纳（用户拍板 MVP 两件事：「先做两类，一个是微信聊天记录导入，根据这些聊天记录来生成脸谱，就这样就可以了」）
- 相关：issue 435（本票）/ ADR-0071 + ADR-0072（bili-downloader 外部工具模式，本票照办）/ ADR-0173（Jev 判定通道，本域 MVP 不消费，留给后续亲疏/提醒票）/ issue 367（微信账单导出调研，域外先例）

## 背景

21 域管了物（belongings）、管了己（diary），独缺管「人」。用户想要的是**脸谱**——给每个人一张卡：这个人的档案 + 交往历史，聊天记录是素材来源之一而非全部；明确不要「虚拟人聊天」（角色扮演）。用户手头已有留痕导出的聊天记录文件。

社区工具现状（2026-09-25 调研）：**chatlog（sjzar/chatlog）已死**——2025-10 收微信官方函件后代码全量移除，不可依赖；**留痕（LC044/WeChatMsg）在维护**，支持导出 CSV / JSON / SQLite 等。

## 决策

1. **外部力量模式（bili-downloader 同款）**：微信数据库解密与导出全部交给社区工具（留痕 GUI 手动操作），插件只消费其产物文件（CSV / JSON）。不自研解密、不做自动同步——灰色、易碎、随微信版本失效的层完全外包；插件侧只保一层**嗅探式字段映射**（格式变更只改 `parse.ts` 薄层）。
2. **聊天原文不落盘**：导入 → 内存解析 → 分批 LLM 提炼（交往事件 + 特质线索）→ 汇总脸谱 → 落盘物只有人物卡 / 事件 / 画像 / 导入元数据。原始消息用完即弃——隐私面最小化，与 encrypt / password-vault 的产品隐私定位一致；重画脸谱以事件流 + 旧画像为素材，不依赖原文。选 **JSON 通道提炼、文本通道画像**（`.json()` 与 `.chat()`，同一次导入两条通道各司其职）。
3. **域形态**：`src/people/`（types / parse / digest / data / ui / index / styles），数据 `CONFIG/STORAGE/people.json`（`jsonFileStore` + `enqueueFileTask` 串行写）；命令 `bz-people-open` / `bz-people-import`（COMMANDS 表裸注册，ADR-0004）；域图标 `drama`（戏剧面具，贴「脸谱」本义）。
4. **AI 依赖注入**：digest 管线以 `AskLLM` 函数注入，本层纯编排可整管单测（假 ask），不直连 `core/ai.ts`。

## 后果

- 留痕 / 微信格式变更需适配 `parse.ts`——已知易碎性由外部工具侧承担升级，插件侧改动收敛在字段映射。
- 大聊天记录提炼的耗时与 token 成本随消息量线性增长；`digest.ts` 以 maxChars / maxCount 双限切批、maxBatches 均匀抽样封顶。
- MVP 无独立设置键（AI 配置复用全域 LLM 面板），故设置面板导航暂不接入；home 磁贴后续票再上。
- 脸谱 markdown 只允许受限语法（## 小节 / - 列表 / **粗体**），域内迷你渲染器消费——全仓无 MarkdownRenderer 用法先例，不引新依赖。
