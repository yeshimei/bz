# ADR-0295 · 影像笔记正文自动分段（机械排版 · 不改字 · 单一开关）

日期：2026-11-09 · 状态：已采纳 · 关联：ADR-0222（转写 LLM 校对，正文只修错不创作）、
ADR-0261（切片任务元数据依据）、issue 310（影像录入界面）

## 背景

知识盒「影像」生成文献笔记时，正文 = 转写稿按 4000 字分块后**直接拼接**（`chunks.join('')`）——
1 小时的视频生成出来就是一万多字的一整坨连续文本，没有段落。用户反馈「生成的时候排版是否可以
自动进行排版」，并拍板：**给开关、默认开、旧笔记不动**。

## 决策

1. **正文只做机械分段，一个字不改**：按句末标点（。！？!?；;）切句，累积到约 150 字即断段，段间空行。
   不使用 AI 生成小标题/要点——那属于改写，会破 ADR-0222 决策 6「知识盒影像的正文文本处理只剩
   LLM 校对一档」；ADR-0222 之后要重开改写，须另立 ADR 并重新拍板。
2. **单一开关，默认开**：设置键 `knowledgeAutoParagraph`，挂在设置面板「知识盒 · 视频处理」组
   （「详细进度提示」之上）。关 = 整段直出（旧行为，逐字节不变）。
3. **只影响新生成的笔记**：不回改存量笔记、不提供批量重排（用户拍板「旧笔记不动」）。
4. **边界规则**（`paragraphizeTranscript`，纯函数）：
   - 原文已有空行分段（校对通道分段 / 用户手改过）→ 保留原段落，逐段重排、不并段；
   - 单句超过「目标段长 ×2」才硬切（先按逗号/顿号/冒号断，断不出来按长度等分），
     否则宁可这一段略长，也不把一句话劈成两段；
   - 中文行内换行/空格归一（英文单词间保留一个空格）；右引号/右括号收回上一句末尾；
   - 右引号、括号这类闭合标点不能甩到下一句开头。
5. **落点**：`generateVideoNote` 在拼接正文之后、嵌媒体之前调用；与校对开关正交
   （先校对后分段），分段不调 AI、不增加请求。

## 备选

- **AI 生成小标题 + 要点**：结构更强，但属于改写，与 ADR-0222 冲突，且要多一次 LLM 调用、多一层
  「模型把原文没有的结论写进小标题」的风险。否决（用户先要的是「能读」，不是「能跳读」）。
- **按转写分段（SenseVoice/faster-whisper 原生分句）**：转写稿在工具包侧已被合成一段，拿不到原始
  分段边界；要拿就得改 CLI 交付格式（带时间码），是一次更大的改动。留作后续（见「优化方向」）。
- **默认关、用户自己去开**：用户明确要「默认开」。

## 影响

- `src/knowledge/note-gen.ts` 新增 `paragraphizeTranscript`（纯函数，单测覆盖句边界/已有空行/
  超长无标点/中英混排/闭合标点/空输入）。
- `src/settings.ts` 新增键与缺省值；`src/knowledge/ui.ts` 的域设置加一行开关。
- 正文观感变化只发生在开关开 + 正文原本没有空行的笔记；段落数变多，文件字节数只多出空行。
- 已有笔记、以及「编辑正文」手改过的内容不被触碰（不回改）。
