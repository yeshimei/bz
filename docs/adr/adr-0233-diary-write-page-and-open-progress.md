# ADR-0233 · 撤销首屏窗口化（影院 + 日记本）· 日记本开册出进度条 · 写日记改书内写作页

日期：2026-10-03 · 状态：已采纳 · 关联：ADR-0231（首屏窗口化，**本次撤销**）、ADR-0230（书页 UI；
其决策 8「写日记仍走 `openAddDialog`」**本次推翻**）、ADR-0170（墙数据预热与会话缓存，保留）、
ADR-0171（首帧让位，保留）、ADR-0106（三层单源原型）、issue 539

## 背景

### 窗口化两版都被用户判死

ADR-0231 给影院与日记本各自做了「首屏只渲一小批、其余后台补齐」的窗口化，日记本一侧随后又经历两次
回修（索引/检索改吃已加载全量、读盘结束后台一次排到全量）。真机上用户的判词是：

> 「完全没实现，和全量加载没任何区别，非常卡，而且每次打开窗口都重新全量渲染一遍，非常糟糕，
> 退回之前所有的日记本的性能相关的修改，直接使用进度条吧」
> 「直接 git 回溯版本即可，影视也不用做性能」

也就是说：窗口化省下的那点首屏时间，读者根本感知不到（书桌壳先出来、书页随后到），而它带来的代价
全都实打实——开册要**建两次书**（30 则一次、全量一次），加上读盘/索引/检索/台历围绕「窗口 vs 全量」
两套口径，几百行状态机只为把一个「其实只是慢」的过程伪装成「快」。用户拍板：不要伪装，**给出真实的
进度**。

### 写日记还停在旧弹窗，没上原型的内页

ADR-0230 整域换成「桌上那本」时，写作页是刻意没搬的（决策 8）：原型 `.scratch/diary-quill` 的
「铅笔写」会在书上摊开一张素纸，而单源当时仍走回忆墙时代的 `openAddDialog`——**只选日子与类型、
正文传空串**，落盘之后再把新笔记甩进 Obsidian 编辑器去写。用户报回：

> 「日记本写日记也没实现原型的内页，使用的是旧代码的弹窗，并且可以加载媒体资源」

后半句经确认是**新增要求**：内页要能「从本机选，放到 vault 中」（照片/录音/视频）。

## 决策

### 1. 撤销 ADR-0231 全部窗口化：影院与日记本都回到「一次全量」

- **影院**：撤掉首屏 20 张 + 空闲分片补渲 + 冷启动骨架 + `metadataCache` 就绪守卫 + 卡片
  `content-visibility`；`openPanel` 仍是同步 `rebuildItems` + `renderAll`（全量），二次打开同路。
- **日记本**：撤掉首屏 30 则排版窗口、读盘结束后台续排、书尾续叠、按需推宽、索引行「未展开」、
  检索/台历的跨窗口径；`show()` 回到「读全量 → 一次成册」。读盘也退回 `vault.read` + 每批 10
  （用户口径：全退）。
- `src/core/paging.ts` 与两份窗口化测试（`tests/cinema/firstpaint-window.test.ts`、
  `tests/core/paging.test.ts`）一并删除——两域都不再分批渲染，没有别的消费者。
- **留档**：ADR-0231 全文保留（标「已撤销」），issue 539 与之同。撤销理由是可复用的经验：
  「让首屏看起来快」在**书/面板这类整体式界面**上不成立——读者等的不是第一屏，是**能翻**。

### 2. 日记本开册出进度条（`core/ui` 的 `uiProgress`）

- 数据层加一条**只读**的进度订阅：`onWallProgress((done, total) => …)`，日记正文每读完一批
  （`READ_BATCH_SIZE = 10`）发一次；它是模块级订阅而不是 `loadWallEntries(app, cb)` 的入参——
  预热可能已经在读同一轮，UI 打开时命中的是**在途**那个 promise，入参式回调用不上。
- UI：`show()` → `afterPaint` → 摆出进度纸条（**延时 120ms**：预热缓存命中就读完了，不闪这一下）
  → 读盘（读数 `N / M 篇` + 填充百分比）→ 读完换「正在装订…」（100%，这一段是同步的量高/切页/建书）
  → 成册即收纸条 → 吐司。
- 进度纸条 `pointer-events: none`：读盘期间点遮罩、点收起照样能关掉整本，不拿进度条当挡箭牌。
- 缓存命中不报进度（没有等待可言），纸条也不会摆出来。

### 3. 写日记改书内写作页（推翻 ADR-0230 决策 8）

- 位置与形态照原型：`.bz-diary-wsp` 盖在 `.bz-diary-book` 里、书页之上；桌面落在**右页**，单页档
  铺满。它**不进 StPageFlip 的页流**（草稿不该被分页），但盖住书页的指针区——「草稿在时不许翻页」
  由此是物理事实，不靠事件拦截。
- 一页四件：**日戳**（与正文日戳同源 `writeDaystampHTML`，多一枚「改日子 · 时辰」小签）、**正文**
  （`textarea`，素纸无格线）、**贴纸**（`getSortedTagsForAddDialog` 同源，不预选）、**揉掉 / 落笔**。
- 「改日子 · 时辰」复用本域台历的**写作模式**：整月格子都可点（给空白日子补写是常事），底下那行认
  **时辰**（`21:30` 直读；`1 分钟前` / `昨天 21:30` 走 `parseFlexibleDateTime` 取时分），
  「就这天」回写草稿日戳；认不出来就报错留在框里，不猜。跳日模式（文具「跳」）保持原样：只给落过笔
  的日子挂监听、不显时辰行。
- **落笔即落盘**：`store.addEntry(date, time, tags, content)`——写层守卫、同刻唯一、串行队列一条不绕；
  没有正文时提示「一个字都没写呢」并不落盘；写完翻回第 0 页（新条目就是最新那篇），
  `diary:entry-added` 的防抖回刷把它排进册子。**不再打开新笔记**（旧路径的收尾动作随弹窗一起退役）。
- 草稿在纸上时：滚轮 / 方向键 / 索引行 / 台历跳日一律让路（`writeGuard()`），Esc 只提醒一句
  （「先落笔，或把这张纸揉掉」），点遮罩 / 收起钮同样先过这道闸；有正文时点「揉掉」先在纸条层问一句。
- `bz-diary-write`（命令面板 / 首页快捷创建）改为**先摊开册子、排好了再摆出写作内页**
  （`controller.openWrite()`）——写作内页是书里的一张纸，得先有书。

### 4. 内页媒体：从本机挑一件，写进 vault，正文里留一条 `![[名字]]`

- 工具行第一枚「＋ 贴一件」→ 原生 `<input type="file" accept="image/*,video/*,audio/*" multiple>`。
- 落点**优先交宿主**：`fileManager.getAvailablePathForAttachment(name, '我的/日记/')`——它按用户设的
  「附件默认位置」给一个不重名的路径（本机 vault = `CONFIG/APPENDIX`）。旧宿主 / 评审壳没有这条 API
  时退到日记目录下的 `附件/`，自己避重名（`_2` 后缀，永不覆盖）。
- 落盘 `vault.createBinary(path, await file.arrayBuffer())`，随后在**光标处**插一行 `![[名字]]`
  （媒体块自占一行，省得排成「字![[图]]字」）；单件上限 64MB（与 encrypt 的附件上限同源：正文是纯
  文本、媒体是外链文件，这里只挡「一次读进内存会卡住」的大件）。
- 引用的是**文件名**（与全库既有日记一致：正文里写 `![[1690097373565.png]]`），渲染仍走
  `mediaSrc()` 的 `getFirstLinkpathDest` → `getResourcePath`。

## 不做的

- **不再给影院/日记本做任何「分批渲染」「视窗化」「虚拟滚动」**：真要动，先拿真机数据证明确有必要，
  并且**进度要真实**——不做「先给一个假的完整界面、再在背后补」。
- **不做旧弹窗与新内页的双轨**：`openAddDialog` 已无任何 UI 入口（`bz-diary-write` 与书桌「写」都
  改走内页），只余标签选择器 `showTagPicker` 在「换张贴纸」上用。
- **不给内页做富文本编辑器**：正文是纯文本 + `![[媒体]]` 引用（与条目文件的存储形态一致）。

## 后果

- **开册多等一会儿，但看得见**：日记本开册 = 读全量（上千篇磁盘读，几秒）+ 一次成册；这期间桌上那张
  纸条在报数，读者知道它在干活。二次开册命中的是预热缓存，纸条不会出现。
- **一次成册就是一次**：不再有「先建一本薄的、读完再拆了重建」——书只建一遍，页码/书口年份带/当前页
  从第一次落定就是终局。
- **写作不再借道编辑器**：正文、日子时辰、贴纸全在书上一次写完，落笔即入盘。
- **已知代价**：① 全量成册的那一下是同步的（量高 + 切页 + 建书），纸条会停在「正在装订…」——这是
  「不做假进度」的诚实代价；② 写完一篇触发的回刷是整册重读重排（沿旧口径），大库上要一拍才看到新
  条目排进来；③ 读盘退回 `vault.read` + 每批 10（用户点名的「全退」），比 `cachedRead` + 每批 50 慢，
  慢在明处。
- **旧写日记弹窗的代码尚未删除**（`ui/dialogs.ts` 的 `openAddDialog`/`saveNewEntry` 与
  `ui/datetime-picker.ts`）：已无 UI 入口，删除要与三个测试文件一起做，留下一批专门清理。
