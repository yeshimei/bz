# ADR-0170：日记本墙数据启动预热 + 会话级缓存（四目录并行）

- 日期：2026-09-19
- 状态：已采纳
- 相关：issue 381；ADR-0003（懒加载）、ADR-0115（回忆墙升格日记本）、ADR-0047（domain-bus / 全插件唯一 vault 订阅点）

## 背景

用户反馈「日记本加载特别慢」。核查：`loadWallEntries` 每次整盘重读四目录（日记/影视/信/书），
四段 `await` **串行**（wall-clock ≈ 四目录耗时之和），且无任何缓存——每次开墙、每次写后回刷都全量重来。
用户拍板做 ①四目录并行 + ②启动后台预热（③跨会话持久缓存缓议）。

## 决策

1. **四目录并行读**：`readWallEntriesFresh` 用 `Promise.all` 并发四类加载后合并排序。
   成功路径结果与旧串行等价；失败路径有差异——旧实现前段抛错则后段不启动，`Promise.all` 下四路恒启动，
   单路失败时其余目录可能多读盘并伴随各自告警（不影响成功语义与异常重抛）。
2. **缓存放数据层、按 app 键控**：`loadWallEntries` 内部持有 `WallLoadCtrl`（promise + invalidated）。
   缓存键控在 app 实例上：换 app 即作废（插件重载 / 测试逐例新建 app 天然隔离）。
   在途 promise 直接复用 → 预热与开墙并发时只读一盘（去重）。
3. **失效经 domain-bus，不自挂 vault 订阅**：只订 `vault:md-*` 四事件（created/modified/deleted/renamed），
   路径命中四目录才作废。遵守「全插件唯一 vault 订阅点」（ADR-0047，core/obsidian-adapter 转译）；
   通用路对范围内 md **恒发**（adapter 契约），diary/letter 语义通道不重复订阅。
   读盘期间被作废（并发编辑）→ 本轮结果**不落缓存**（不被后续调用复用），在途调用者仍按既有语义
   拿到本轮结果——墙开着时由 UI 侧 vault-modify 防抖回刷自愈。
4. **开墙吃缓存，刷新恒回源**：UI 层 `_allowCacheNext` 闸门——`show()` 置真（每次开墙，含关后再开），
   `loadAndRender` 消费即复位，其余调用（刷新/写后回刷/重试）一律先 `invalidateWallCache()`。
   理由：这些刷新路径在改动前**每次都是读盘**（测试依赖此语义，如「modify → 防抖重读刷新」），
   缓存只服务「打开时秒开」这一新场景，不改变既有刷新节奏；关墙期间的写改由 domain-bus 事件作废，
   重开读到的缓存仍是「上次读盘时的真实态」。
5. **预热纯数据、无 DOM**：`prewarmDiary` 只调 `loadWallEntries`，不实例化控制器/不建节点（ADR-0003 兼容）；
   rAF + setTimeout 延迟一拍避开启动关键路径；幂等；C13 守卫（延迟窗口内禁用插件则不预热）；
   失败不打扰用户（仅 console.warn 供诊断，真正打开时自会重读并呈现错误态）。
6. **加密条目不进缓存**：`mergeEncryptedEntries` 仍在 UI 层每次现取，缓存层不触碰解密态。
7. **失败不缓存**：异常时复位 ctrl 并重抛（保持旧语义）；`unloadDiary` 调 `invalidateWallCache()` 全清缓存 + 订阅。
8. **目录判定单源**：`config.inWallDirs`（日记/影视/信/书命中判定）供 data 失效订阅与 ui 两处订阅共用，
   改口径只动一处。

## 后果

- 开墙：四目录并行 + 命中预热/上次刷新缓存（若有效）→ 秒开；预热未跑完时命中在途 promise，不重复读盘。
- 会话内重复开关墙：每次开墙都可能吃缓存；刷新/写后回刷仍每次读盘（语义不变，不影响既有测试与刷新时机）。
- 外部工具（绕过 Obsidian）直改 vault 文件不触发 vault 事件 → 缓存可能陈旧（含关墙后再开这一场景）；
  由「刷新路径恒回源」兜住（用户任何手动刷新即重读），且缓存只活一个会话，重启即清。
- `unloadDiary` 需复位 `prewarmed` + `invalidateWallCache()`：重新启用插件后预热照常工作。

## 被否决的方案

- **UI 层做缓存（控制器实例上）**：预热无控制器可挂（预热的目的就是不实例化控制器），数据层才是天然归属；
  且 UI 双实例（桌面/移动）会各缓一份，数据层一份全共享。
- **刷新路径也吃缓存（只靠事件失效）**：测试 MockVault 不发 vault 事件，写后回刷读到旧缓存（DW3/N5 实测红）；
  且会改变「按年月跳转/筛选重载即读盘」的既有节奏。开墙吃缓存 + 刷新恒回源是最小语义扰动。
- **订阅 diary/letter 语义通道**：adapter 对范围内 md 恒双路派发（通用 + 语义），
  通用路已覆盖，语义订阅纯冗余（ADR-0047 通用路为契约）。
- **跨会话持久缓存（③）**：收益递减 + 失效面大（外部改文件即脏），缓议。
