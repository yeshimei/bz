# ADR-0196：同步与画脸谱——阶段切分、协作式暂停、状态机归插件

- 日期：2026-09-26
- 状态：已采纳
- 相关：ADR-0195（工具包）/ ADR-0197（产物归属）/ issue 450（生成进度引擎化）/ issue 453（批级重试续跑）/ `src/people/jobs.ts`（状态机母体）

## 背景

用户要求整条链路「可暂停、可中断恢复、完整的进度通知（精确到每一步在做什么）」。而这条链路横跨两类执行体：工具段（媒体导出、语音转写，**单人实测 20–60 分钟**：大琳 1631 图 / 1289 语音 / 2.8GB）与插件段（图片描述、画像生成，走 `core/ai`）。现有 `jobs.ts` 已有 `running | paused | interrupted | done | error` + `pauseRequested` + 批级续跑，但只覆盖 AI 段。

## 决策

1. **阶段切分（A 案）**：`sync` 与 `prep` 分离。
   - `sync`（全量、轻，分钟级）：取密钥 → 解密 → 导出 `chat.json`（含表情命名）→ 头像源落位。
   - `prep`（按人、重，可几十分钟）：媒体导出（含 `wxgf` 解码与 `desc/` 派生档）→ 图片↔消息关联 → 语音转写。
   - **画脸谱** = `prep` → 图片描述（AI）→ 画像生成（AI）。
   - **否决「媒体+转写全塞进 sync」**：那会把「点一下就同步」变成搬 9.8GB + 全量转写（几十分钟到几小时），且 90% 是不看的联系人。
   - **否决「预热素材独立成第三阶段」**：数据源弹窗提供一个批量触发 `prep` 的动作即可，实现上是同一段代码不接 AI 段，不值当单开一层。
2. **状态机归插件**：扩 `people-jobs.json` 的 `preprocess` 阶段（工具段作为 job 的前两阶段），工具只保证**单步幂等**（`export_all.py` / `voice_transcribe_all.py` 本来就跳过已存在产物），不持跨步骤状态机。
3. **暂停 = 协作式，不是硬杀**：工具在**步骤边界**与**每条媒体之间**轮询数据根内 `.bz-face/control.json`，看到 pause 就在安全点让行、进程待命；不硬杀是因为 funasr 模型冷加载代价高，杀一次白付一次。**中断 = 杀进程留状态**，重跑幂等续。
4. **断点状态落数据根** `.bz-face/state.json`——**跟数据走，不跟人走**（换机器、换 vault 都不丢）。
5. **进度协议沿用** `[bz-step]` / `[bz-p]{"phase","pct"}` / `[bz-info]` / `[bz-result]` 四行协议（与 bili-dl 同口径）；顺手把**协议解析 + spawn 壳抽到 `core/external-tool.ts`**，知识盒本次不动、后续再迁。
6. **进度分两层，不混用**：
   - `sync` 走数据源弹窗内的**一条进度行**（不占生成进度块——同步不是画脸谱，别让人以为在画像）。
   - 画脸谱接现有生成进度块，步骤行逐段推进：`媒体导出 312/1631` → `语音转写 45/1289` → `图片描述 3/82 批` → `其人` → `我们` → `时间线`（后三段是现有的）。
   - **系统通知只在完成 / 失败 / 转后台三个阶段发**，不逐步发（1631 张图逐步通知是骚扰）。
7. **失败分两类**：密钥 / 解密失败 = 硬失败，整链停 + 中文原因；单条媒体 / 单条语音失败 = 计失败数继续，末了 `[bz-result]` 报 `failed:N`，进度块给「重试失败项」。单条失败不该废掉 1600 张里的 1 张。
8. **两次二次确认，两个独立弹窗**：图片描述一次（`用 <服务商>/<模型> 描述 N 张图片，约 M 次调用；已完成 X 张，本次从第 X+1 张开始`，按钮 **开始 / 跳过图片描述**——跳过不等于取消整链）；画像生成一次（`用 <服务商>/<模型> 画《X》的脸谱，素材 M 条、约 K 次调用`，按钮 开始 / 取消）。确认窗只报张数 / 批数 / 调用数，**不报金额**。
9. **零媒体联系人自动跳过** `prep` 全段，直接进画像生成（不为 0 张图弹一次确认）。
10. **同步与画脸谱互斥**（同步期间画脸谱入口置灰——数据正在变）；**中断不自动续**（崩溃遗留 `running` → `interrupted`，出「继续生成」按钮，沿用现状）。
11. 暂停文案沿用现有体系：「这一批做完就暂停」/「继续生成——已完成的批次不重画」。

## 后果

- `jobs.ts` 的 job 从「AI 生成」扩成「预处理 + 生成」，指纹与续跑判定需要跟着改（见 ADR-0197 决策 5）。
- 工具的 `control.json` 轮询粒度决定了暂停的响应延迟上限（每条媒体一次），这是可接受的。
- 上锁（保险库）时后台任务必须暂停，与暂停机制共用同一入口（见 ADR-0194 决策 5）。
