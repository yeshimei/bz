# ADR-0202：设置面板「通知」页并回通用——跨域横切偏好不再单占导航页

- 日期：2026-09-27
- 状态：已采纳（实现见 issue 479）
- 相关：ADR-0080（设置面板）/ ADR-0153（设置入口收敛）/ issue 186（AI 自全局拆域先例，方向相反的同类决策）/ `src/core/settings-main-schema.ts` / `src/settings-panel/ui.ts` / `manual/bz-manual.html`

## 背景

2026-09-12 有过两道相关拍板：

1. 原「设置」页（外观组：布局/主题）撤销，并入「通用」页排最前；
2. 通知组自「通用」拆出，在面板左栏独立成一页（`noticeSettingsSchema()`：通知级别 / 停留时长 / 弹出位置 / 同屏上限，四行全 select）。

十四天后用户回看面板「基础」组（通用 / 通知 / 首页 三页）：通知全部内容就是四行横切偏好，独占一页导航不值——外观组当初并入通用的同一逻辑反过来也适用于通知。下令把「通知」并回通用（「设置」部分 09-12 已并完，本次实际只动通知）。

## 决策

### 1. 通知组回到 `generalSettingsSchema()`，`noticeSettingsSchema()` 退役

通知组（icon `bell`，四 select 行，键零变化）整体移入 core `generalSettingsSchema()`，排在「数据存储路径」组**之前**；面板侧再把「外观」组 unshift 至最前，通用页终序 = **外观 → 通知 → 数据存储路径**（「数据体检」按钮仍挂存储组尾，锚点测试按组名定位不受组序影响）。独立的 `noticeSettingsSchema()` 删除。

### 2. 面板导航退役 `notice` 域条目

`DOMAINS` 删 `notice` 项（通用 desc 更新为「面板外观、通知与存储路径等跨域偏好」），`NAV_SECS` 基础组 = `[global, home]`。移动端搜索不受损：通知行随通用 schema 进 `schemaRowCache` 行缓存，搜「通知」命中通用页（现状行为不变）。

### 3. 键与行为零变化

`noticeLevel / noticeDuration / noticePosition / noticeMaxVisible` 四键、行型、默认值、即时生效语义全部不动——本票只动导航结构与 schema 归属，不碰任何数据。

### 4. `mainSettingsSchema()` 聚合收敛为 AI + 通用

该聚合器自 issue 345 起只作测试与文案 lint 断言入口，通知组并回后自然覆盖，`noticeSettingsSchema` 聚合项删除；`settings-copy-lint-d` 里独立的 `notice` lint 目标随之撤（通知行文案改由主聚合目标继续覆盖，不留 lint 空窗）。

### 5. 手册同步（`manual/bz-manual.html`，远端资产手编源）

- 通用章 FAQ「这一页能改通知相关的设置吗？」答案反转：能，就在「通知」组里；
- 通知章导览句由「左栏找到通知这一页」改为「左栏第一组点开通用页，找到通知组」；
- 「这一域没有命令」措辞改「通知没有自己的命令」（通知已非面板域）。

## 后果

- **用户可见变化**：基础组少一页（通用 / 首页）；通知四项改在通用页内调整。无迁移、无键变化、无命令变化。
- **深链安全**：全仓无 `openSettingsPanel(app, 'notice')` 调用点；且未知域 id 本就回退通用，双保险。
- **契约锁重锚**：`sp-contract-lock` 基准表 `global: 3 → 7`、`notice: 4` 行删除；面板集成测试导航计数 20 → 19、通用分组 2 → 3。
- **拆而复合的成本记录**：本次是一日之内导航结构的反转（09-12 拆出 → 09-27 并回），特此留档。日后再想把通知拆成独立页，理由需要强于「看着整齐」——例如通知项数实质膨胀、或出现通知专属的复杂控件。
- **不可逆性**：低。反向操作（再拆出）只是把组对象移回独立函数 + 导航加一项，机械且廉价。
