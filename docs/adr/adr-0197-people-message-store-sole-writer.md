# ADR-0197：聊天仓——唯一权威存储，全量原始消息 + 派生 text，vault 的唯一写者是插件

- 日期：2026-09-26
- 状态：已采纳
- 相关：ADR-0194（加密存储）/ ADR-0196（状态机）/ issue 446（预览桶来历）/ issue 449（语义分流，本票部分取代）/ `src/people/datasource.ts`（素材源与增量）

## 背景

原本的分工是「`chat.json`（数据根，工具产物）= 素材源；`people-preview.json`（vault 内）= 有损投影 + 展示层」。用户拍板改为：**`chat.json` 完整一份写入 `people-preview.json`，后续语音转文字与图片描述也回写后者**。

实测当前投影的有损程度（大琳）：`20773` 条 → `18477` 条，且丢失 `type`（4.x 原始码）、`who`（发送者）、`sid`、`dur`（语音秒）、`wav`（音频路径）、`img`（图片 `月/文件名`）六个字段。**`wav` 与 `img` 的丢失是致命的**——画脸谱要靠 `img` 精确关联图片、靠 `wav` 找音频，桶里都没有。

同时实测到一个现网不一致（`chat.json` 里 28 条表情带名、桶里 52 条），根因是 `mergePreview` 的 **append-only** 语义（按 `key` 过滤已存在条目），一旦文本升级就**永远修不回来**。

## 决策

1. **`chat.json` 退化为工具的「一次性产物」**（同步时生成，此后只读、不再被回写）；`people-preview.json` **升格为唯一权威存储**，概念改称**聊天仓 (Message Store)**（**文件名保留** `people-preview.json`——改名收益是"读代码的人不困惑"，成本是文件迁移 + 旧文件残留 + 路径引用；一行注释加 glossary 足够）。
2. **`msgs` 存全量原始消息**（保留 `type` / `who` / `sid` / `dur` / `wav` / `img`），另加一个派生字段 **`text`** = 合成后的消费文本（`[图片] 描述` / `[语音 N秒·情感] 转写` / `[表情·名]`…），**空串 = 不进时间线**。
   - 展示与素材组装只读 `text !== ''` 这一行过滤 → 消费行为与现状完全一致；
   - 但存储层完整可重算（改过滤规则不用重导），`stats` 口径也能从存储重算。
   - **取代 issue 449 里「不进时间线就丢出 msgs」的做法**（改成进 msgs 但 `text` 为空）。
3. **`chat.json` 的定位钉死**：只含「从微信解出来的事实」——文本 + 表情命名 + `img` 关联 + `wav`/`dur`；**不含转写与图片描述**（那是插件侧 AI 产物）。语音在 `chat.json` 里保持 `[语音 14秒]`。两边职责干净，重跑互不污染。
4. **vault 的唯一写者是插件**；工具只写数据根。工具产旁路表：`voice.json`（转写结果）、`image_map.json`（图片↔消息关联，已在产）；表情命名**并入 `chat.json` 的生成**（一次写完，不再单独回写）。所有合并进聊天仓的动作由插件执行。
   - 附带收益：原「两个进程写同一个文件」的问题**消失**了。
5. **写入语义与指纹**：
   - `mergePreview` 从 **append-only 改 upsert**（同 `key` 用新文本覆盖、原始字段按新值更新），`watermarkSid` 与增量逻辑保留。
   - resume 指纹从「消息条数 + 末条派生键」改为**组装素材的内容哈希**。理由：回写让「条数不变、内容变了」成为常态，旧指纹**察觉不到**，会拿旧素材静默续跑——这不是妥协，是必须修。
6. **结构升级**：`PreviewData.version` bump 到 **2**；v1 桶缺的正是回溯原料，**无就地升级路径**，判废后从数据根重导。与 ADR-0194 的存量迁移（`people.json` + `people-preview.json` → 每人一条保库记录）合并为**同一次迁移**，不重复做两遍。
7. 旁路表**保留**（`voice.json` / `image_desc.json` / `image_map.json`）：它们是工具产物、也是 `img` 关联的输入端与兜底通道，但**权威是聊天仓**。

## 后果

- 桶体积估涨 30–50%（现在 3.93MB / 3 人，大琳一人 2.79MB；补回原始字段后 74 人估 15–30MB），且它会被 Obsidian 同步——现由 ADR-0194 的加密兜底。
- `src/settings.ts` 两条隐私文案要改词：原「预览只存文本」已不成立，改为「完整聊天数据入库、媒体**本体**不入库（只存路径）」。
- `image_ct_map.py` 不再回写 `chat.json` 的 `img` 字段（改为只产 `image_map.json`）；`voice_writeback.py` 不再回写（改为只产 `voice.json`）。两个脚本的职责收窄。
- `synthesize.py` 的「连发归组（120s 合并）」**退役**——预览/聊天仓本就该一条条消息，降密度是「切批 / 素材段」的职责（`jobs.ts` 的 `chunkMessages` 已在做），不该污染存储层。
- `parse.ts`（留痕 CSV/JSON 嗅探通道）**保留但冻结**：删它要动 445 契约与 `parse.test.ts`，与本重构正交；文档标注「非主路径」。
- 单批图片描述或单条转写失败时，该条 `text` 保持空前态；重跑该批/该条即补齐，不需要重导。
