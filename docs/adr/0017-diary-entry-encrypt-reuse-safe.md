# ADR-0017 加密日记条目——复用保险箱 SafeManager 的块级移出

状态：已规划（diary 域加密功能，ticket 67）
日期：2026-08

## 背景

日记本需要一个「加密分类」：把用户选中的日记条目真·密文化（区别于既有正文含 🔐 仅隐藏的伪加密）。经 grilling 会话逐轮敲定，落在**复用加密保险箱（encrypt 域）的 `SafeManager`** 上——加密日记条目作为一篇 `SafeNote` 存入保险箱 `safe.enc` 清单，逻辑与数据落点与保险箱完全一致，**不新增独立数据文件**。

驱动本设计的既有约束：
- **数据格式铁律**：`我的/日记/*.md` 的 `# emoji序列 HH:mm` 格式不可改。加密条目若残留正文于 md 会被 `writeFile` 整体重建时写回明文。
- **可复用加密资产**：`src/password/crypto.ts` 的 `CryptoService`（PBKDF2 100k + AES-GCM-256）+ `SafeManager.lockNote/restoreNote` 已是完整、可单测、无 window 依赖的实现。
- **无共享主密码服务**：密码本/保险箱各自独立内存解锁态（共用同一密码字符串）。日记加密与保险箱**共享同一 SafeManager 实例**（同一主密码、同一解锁态、关面板即上锁）。

## 决策

1. **复用保险箱本体，不新增 .enc 文件**：日记加密 = `SafeManager.lockNote` 把「加密分类」条目作为一篇 SafeNote 存入 `CONFIG/.ENCRYPT/.safe.enc` 清单；降级 = `SafeManager.restoreNote` 取出即删。主密码、解锁态、锁面板即上锁全部复用。
2. **来源标记 `kind?: 'diary-entry'`**：SafeNote 加可选字段（缺省=普通加密笔记）。**保险箱面板渲染时过滤 `kind==='diary-entry'`**（列表不显示日记加密内容）；**日记面板单独读 `kind==='diary-entry'`** 的条目并解密混排。两面板各自只看各自源，数据同一份。
3. **块级移出/merge 还原**：加密时从 md 摘出**完整条目块（含 `# emoji HH:mm` 标题行与正文，Q25-B）** 作为 SafeNote；`note.path` = 原日期文件（`我的/日记/YYYY-MM-DD.md`）；`title` = `日期 · 时间 日记`（可辨不泄露）。恢复时按原 date+time 把该块 **merge 重插** 回原 md（md 已删则新建），**非整文件覆盖**（Q23-A）。`kind` 让日记面板识别该条走 merge 而非整文件还原语义。
4. **附件随加密入保险箱**：加密日记正文里 `![[...]]` 引用的图片/视频附件作为 SafeNote 的 attachments **一并加密镜像入库**（复用 `lockNote` 的附件流程），原 vault 附件删除；恢复时按原路径还原，正文 `![[原路径]]` 引用文本不变、可直接显示。
5. **加密仅发生在「改类型」**：写日记弹窗**不提供**「加密」标签（新建不管加密）；在日记面板改分类（标签选择器）时提供「加密」标签。流程：选加密 → 若未解锁先弹主密码 → 因正文将离笔记再二次确认 → 块级移入（Q4-c）。**已加密条目改类型 = 自动降级**（触发 restoreNote merge），不显示「加密」按钮（Q20-a）。
6. **解锁/展示**：未解锁时 `originalDiaryEntries` 不含任何加密条目（完全不可见，Q21-a）；筛选栏「加密」标签显示 🔒 锁定态、无计数、点击触发解锁，**固定排在筛选栏最后**（用户决策）。解锁后解密成标准 `DiaryEntry` 并进现有排序/筛选/搜索管线（Q30-a）。
7. **正文即预览**（用户修订，取代 Q17-b 预览窗）：加密条目卡片与普通条目一致渲染正文，**不提供预览弹窗、点击无操作**（不跳 md，无锚点）；**不提供面板内编辑**。改正文须降级回普通 → md 改 → 再加密。卡片时间旁**不显示**额外 🔐 角标（识别靠标题 emoji 序列本身，用户决策）。
8. **不加新命令**（Q8-a）：功能纯由「改类型选标签」驱动；解锁走筛选栏标签点击。新增日记条目识别/过滤所需的 `kind` 字段为 `SafeNote` 纯增量（旧数据缺省普通笔记，不影响）。

## 权衡

- **复用 SafeManager 本体 vs 独立 diary-encrypted.enc（Q3-b 曾议）**：复用省去一套主密码、清单、解锁流程，且附件/正文用同一条加密管线，实现最简；代价是日记加密与保险箱在数据上同库（用户可接受，且保险箱面板已过滤 diary-entry 保持视图隔离）。
- **块级 merge vs 独立 .md 再 lockNote**：把日记条目当成日期文件里的一块、恢复 merge 回原 md，保持日记数据格式稳定（铁律 1）；独立 .md 会改变日记数据形态、违背铁律。
- **`kind` 字段 vs 路径推断**：显式字段语义明确、不依赖目录字符串、老安全笔记兼容（缺省普通）；路径推断脆弱不可取。
- **只读不提供面板编辑（Q17-b）**：牺牲加密态下的就地编辑便利，换取实现最简与「降级→md→再加密」的清晰闭环；加密日记改动频率通常低。

## 已知限制

- 加密日记与保险箱**共享同一把主密码与解锁态**：任一解锁则两边都开；任一「关闭面板即上锁」触发整体 lock（Q28-b）。日记关闭面板即上锁为固定行为，不加 securityMode 开关。
- 加密条目正文不可在面板内编辑；改正文须降级回普通。
- SafeNote 整体加密，解锁前 `kind`/标题/时间不可见——保险箱面板过滤 `kind==='diary-entry'` 需在清单解密后才能执行（解锁是展示前提，语义一致）。
