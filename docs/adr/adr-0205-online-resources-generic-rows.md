# ADR-0205：「在线资源」组回归通用声明行——自绘骨架退役 + 下载落盘事件驱动跨入口状态同步

- 日期：2026-09-27
- 状态：已采纳（实现见 issue 492）
- 相关：ADR-0203 / issue 480（在线资源组成立，本 ADR 修订其渲染形态与状态刷新通道）· issue 434（行按钮三态助手 `setRowBtnState`）· ADR-0047（域事件总线）· `src/settings-panel/online-resources.ts` · `src/core/settings-schema.ts` · `src/core/remote-asset.ts`

## 背景

issue 480 落地「在线资源」组时用了 `type: 'custom'` 单行自绘：组内自带
`.bz-sp-res-*` HTML 骨架与样式段。用户看实测截图指出两处偏离通用行：

1. **左侧多一段幽灵缩进**——自绘行的空 `.bz-sp-set-info` 与右侧插槽之间吃通用行的
   16px `gap`，内容起点 34px，而通用设置行是 18px；
2. **字号偏大**——自绘 14px vs 通用行 13px，观感上「加粗了」。

根因不是样式写错，而是**自绘行与通用行共享外壳、各自供内容**：外壳的间距/字号是给
「左边信息、右边控件」两栏结构设计的，自绘行把两栏当一栏用，必然对不齐。同性质问题
会随任何自绘行重现，逐处调 CSS 是打地鼠。

同时暴露两个状态面的缺口：

- 主题行就绪态描述没有规模信息（对照归物分类表「（26 组 515 条）」的既有口径）；
- **跨入口状态不同步**：更新日志/使用手册可从导航入口打开并触发后台更新，但组内按钮
  仍停在「更新」直到面板重开——用户明确要求：谁触发的下载不重要，组态要跟磁盘事实。

## 决策

### 1. 整组回归通用声明行，自绘骨架删除

全部行改 `type: 'button'`（检查更新 + 更新日志 / 使用手册 / 主题 / 归物分类表），
行视觉、行距、控件基线由面板通用行渲染器单源保证；`.bz-sp-res-*` 骨架与样式段（约 80 行）
整体退役。**域侧不再持有任何行级视觉**。失败横条（自绘）同步退役，改由「检查更新」行
承载失败态（见 §2）。

为此 `ButtonRow` 增可选 `disabled`：状态未到（已下载 / 状态未知）时按钮禁用。落在
core 类型上而非面板单侧补丁——core 原生渲染器（⚙️ 弹窗）与面板渲染器同调，
「禁用是行能力」不外溢成两套语义。

### 2. 「检查更新」行恒在 `rows[0]`，`visibleWhen` 门控显隐

有清单且核对成功 → 隐藏；无清单或核对失败 → 置顶呈现失败文案 + 「重试」按钮。
行集合恒定（渲染/计数/补丁的对位序稳定），显隐走通用 `visibleWhen` 通道，
不用「按需 push/pop 行」——行序漂移是补丁错位与计数抖动之源。

### 3. 状态刷新 = 磁盘事实单源，行对象可变 + DOM 补丁双落

- 状态永远现算（缓存清单 + 本地文件 sha256），组内**不持久任何状态**；
- 重算后就地改写行对象（面板 schema 会话内缓存 → 下次重渲即新值）**且**补丁已渲染
  DOM（打开中即所见即所得）；`syncSeq` 序号防并发同步旧结果后到覆盖新态；
- 构建期现算一次（`onlineResourcesGroup()` 改 async，与剪藏本数据源组同范式）；
  打开面板顺手后台核对一次，60s 节流（快速开关面板不狂拉；启动链不受此限）。

### 4. 跨入口同步：下载落盘事件（`downloads:asset-changed`）

派发**收口在 `writeAssetText`**——所有下载资产（文档 / 皮肤 / 分类表 / 清单缓存自身）
的唯一落盘口，上层通道（`ensureAssetWithHash`、`downloadSkinUpdates`、`refreshAsset`）
自然带上，不必逐个动作埋点。组订阅一次 → `syncGroupRows()`：

- 导航入口更新文档 → 组内按钮翻「已下载」；
- 分类表自动拉取落盘 → 同上；
- 派发方不感知订阅方存在（总线 fire-and-forget，ADR-0047 口径不变）。

**不新增轮询、不在导航入口回写组态**——磁盘是唯一事实源，事件只是「事实变了」的提示。

### 5. 主题行描述带套数

就绪态 `全部主题已是最新（已下载 N 套）`；混合态分别说清更新数与未下载数
（`N 套主题有更新，另有 M 套未下载`）。与分类表行的「N 组 M 条」同口径：
就绪描述捎带规模，不另开行。

## 备选与否决

| 方案 | 否决理由 |
|---|---|
| 保留 custom 行，只补 CSS（缩进/字号） | 打地鼠：外壳间距给两栏结构设计，自绘即错位；下次任何自绘行重现 |
| 让自绘行也走通用「信息栏 + 槽」但字号自定 | 同上——通用行的价值是「域侧零行级视觉」，破一次例就没有锚 |
| 按需 push/pop 行表现失败态 | 行序漂移（补丁按序对位、计数徽标抖动），且显隐已有 `visibleWhen` 通用通道 |
| 导航入口更新完回头改组态 | 入口回写组态 = 跨模块私有耦合；且分类表自动拉取、皮肤下载等多入口都要各写一遍 |
| 组内自轮询/定时重算 | 半自动铁则下磁盘变化稀疏，轮询是纯浪费；事件已覆盖全部落盘口 |
| 为组卡「N 项」徽标给 button 行计数 | 「项数 = 设置项数」是面板与 ⚙️ 弹窗的同口径锚点；为单组破例会让徽标语义分叉 |

## 后果

- **已知变化（知情项）**：组卡「N 项」徽标不再显示——本组五行全为操作行，项数口径
  不计 `button`（既有通用口径）→ 计数恒 0 → 按既有规则隐藏徽标；
- **已知变化（知情项）**：打开面板顺手核对由「每次进入该组」变为「按面板会话 + 60s
  节流」（schema 会话缓存 → loader 每次开面板只跑一次）；启动链核对不受影响；
- 会话中途的外部变化（其他窗口/命令面板触发的下载）落地即有事件 → 组态自愈；
- 后续在线资源加行 = 加一条 button 行 + 清单条目，无渲染面成本；
- 面板域新增操作类组的范式确立：**全 button 行 + 恒在首位的门控状态行**。
