# ADR-0240：影院重温即一刷，界面评分 = 首评分与所有刷次评分的平均值

日期：2026-10-05 ～ 状态：Accepted ～ 关联：ADR-0044（结论相反，见 Consequences）、issue 536（观影日期 = 排序戳）、ADR-0087（影院接管影视）、ADR-0026（影视动作感知观察）

影院原本「一次评分定终身」：`重看` 只存时间戳不存评分，重温既不改评分也不改 `观影日期`，所以重温过的片评分永远是首看印象、排序也永远沉在首看日。本次拍板给重温加上二次打分，界面显示的评分改为**首评分与该片所有已打分刷次的算术平均**，并在重温后把该片顶到排序最前。

## Decision

1. **`重看` 由字符串数组升为对象数组** `{ at: string; rating: number | null }[]`——一次落盘、单一真相源；旧的字符串数组读取时补 `rating: null`，**磁盘零迁移**。
2. **平均评分 = 首评分 + 每次重温打分的算术平均**（等权，一位小数）。分母只数**真的打过分的刷次**：某一刷跳过打分就不进分母，**不以首评分或上一刷分兜底填充**。因此「N 刷」与「参与平均的分数个数」可以不等。
3. **平均评分是界面唯一显示的分值**，也是评分排序 / 推荐 / 观影分析等下游的统一口径；**首评分保留在 `评分` 键，永不因重温被覆盖**。不做「最新一次覆盖前一次」，也不做近因加权。
4. **重温只刷 `观影日期`（排序戳）**，`已看日期`（真看过日）一律不动——排序上出现在今天，归档仍算首看年，不在两年年书里重复计数。「最靠前」只在「按观影日期」排序模式下成立，评分模式 / 创建时间模式不插队。
5. **打分强制**：弹窗只有评分一项（预填首评分），不打分即取消，这次 +1 完全不生效（`重看` 不追加、排序戳不刷新）。
6. **新增域事件 `rerated`**（载荷带刷次号、本刷分、平均评分），不复用既有 `rated`——后者是「改分」，前者是「又刷了一遍」，下游要能区分。
7. **历史数据一次性回填**：存量重温的每刷评分一律补成该片首评分，于是平均评分恰好等于首评分，**界面零跳变**。

## Options

- **O1 平行数组 `重看` + `重看评分` 下标对齐**——❌ 两个数组任一处只写一半就永久错位，且错位不可自愈。
- **O2 最新一刷覆盖前一刷**——❌ 抹掉历史，与「多刷收敛」的初衷相反。
- **O3 缺分按首评分 / 上一刷分兜底填充**——❌ 伪造数据；宁可样本数少于刷数。
- **O4 新增 `lastActivityAt` 独立排序键**——❌ 未采纳。`观影日期` 本就被 issue 536 定义为排序戳（「建档/导入/标记在看都会刷它」），再立第二个排序戳是重复概念。
- **O5 重温同时刷 `已看日期`**——❌ 年书按 `已看日期` 归档年份，会让一部片在首看年与重温年各出现一次。
- **O6 全库 822 篇的三个日期字段批量回写成带时刻**——❌ 未采纳。改为在排序取值处归一化（缺时刻按当日 0 点），零磁盘风险、全域立即生效；仅全库唯一一条 date-only 的 `重看` 孤例在回填时补成 `00:00:00` 以求视觉一致。

## Consequences

- **与 ADR-0044 结论相反，这是有意为之，不要拿它来「纠正」本 ADR。** ADR-0044 判的是 review 域「首次评级唯一、重做不写 FSRS 数据」。两者对象不同：复习评级是**排期算法的输入**，FSRS 要求单一稳定信号，多写一次就是噪音；影院评分是**用户态度的表达**，一部片多看几遍本来就该收敛成一个平均印象。同名的「重做 / 重温」在两域走相反语义，读到此处的人别误判成 bug。
- `normalizeRewatches` 现走 `normalizeTags`（过滤非字符串项），会把对象数组整条吞掉——解析必须重写并同时兼容旧的字符串数组。
- 存量极小：全库 822 篇影视笔记里只有 3 篇带 `重看`，其中 1 篇（《藤本树 17-26》）按用户指示直接撤销重温，实际回填 2 篇 2 刷。改回字符串数组或换结构的成本接近于零。
- 首看与重温的日期分工因此更硬：`观影日期` 再也不能当作「哪天看的」使用，任何需要真实观看日的口径必须读 `已看日期`。
