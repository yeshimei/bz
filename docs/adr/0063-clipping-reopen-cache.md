# ADR-0063：剪藏本重开缓存复用（幽灵卡片防护由重载改常驻监听）

- 状态：采纳（2026-08-27 grill-with-docs 拍板，ticket 130）
- 关联：ticket 08（B1 幽灵卡片，本 ADR 修订其「重开即重载」）、ticket 125（「重开先显示加载提示」，其重开半边语义作废）、ADR-0047（域事件总线）

## 背景

剪藏本面板历史上有「外部删除/改名/换目录后重开残留幽灵卡片」缺陷（B1），当时的修复拍板是**重开即重载**：每次重开都 `showLoadingHint()` + 全量重扫（解析零 I/O，纯 metadataCache）。ticket 125 进一步让重开也先显示加载提示。实际体验：每次打开都闪「正在加载」、旧列表先被清空——用户反馈「每次打开剪藏本都重新加载数据」，要求缓存复用。

现状事实：面板首建时挂载 modify/delete/rename 三通道域事件监听（防抖 300ms 结算，面板隐藏不卸、unloadClipping 才退订），常态增量维护已覆盖 B1 场景；重开重载只是跨重开的一次性全量校验保险。

## 决策

1. **重开缓存复用**：重开（窗口已存在）仅 `setVisible` + 移动端全屏类，显示旧列表，**零扫描零加载提示**；首开保持「先弹窗 + 加载提示 + 全量加载」。
2. **完全信任常驻监听**：B1 防护由「重开即重载」改为「常驻监听增量维护」（三通道在面板隐藏期间同样工作）。
3. **目录变更才重载**：设置里 `articleDirectory` 变更 → 清空模块列表（含筛选态）+ 全量重载一次，此后重开零扫描。

## 备选

- **每次打开后台静默重扫**（显示旧列表 + 后台校验双保险）：监听已可靠维护增量，重扫属冗余 I/O——否（用户拍板「完全信任监听，打开不重扫」）。
- **限频重扫**（N 分钟一次）：引入新配置与隐形刷新时机——否。

## 后果

- 打开剪藏本恒瞬时出列表，「正在加载」只在首开出现一次。
- 若监听通道漏事件（理论面：域事件总线故障），重开不再自愈，幽灵卡片可能存活到下次目录变更/重启——接受（用户明确拍板信任监听；总线监听本身有测试保护）。
- ticket 125 的重开加载提示用例作废改写；首开用例不变。
