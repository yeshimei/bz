# ADR-0130：日记条目文件格式（一目一文件 + core 契约单源）

- 状态：已采纳（2026-09-13）
- 涉及域：diary（主）/ smartcat / recap / home / encrypt / core（path-classify）
- 关联：issue 304 / ADR-0115 / ADR-0030 / ADR-0002

## 背景

日记自 QuickAdd 时代起是「一天一文件多条目」：`我的/日记/YYYY-MM-DD.md`，`# emoji序列 HH:mm` 一级标题既是条目边界也是 UI 锚点。该格式把 markdown 结构当数据用（标题行耦合 emoji 表、行号定位、解析容错难），且与 Obsidian「一篇笔记一件事」的生态（双链、属性、检索、移动端编辑）天然错位。用户拍板迁移为**一目一文件**，并要求日记墙等所有消费方无感继续工作。

关键实测：Windows NTFS 文件名禁英文 `:`（创建即 ENOENT），故文件名用 `-` 连接时间，而 frontmatter 属性值保留英文 `:`（`2026-03-23 12:32`）。

## 决策

1. **条目文件格式（v2）**
   - 路径：`我的/日记/YYYY-MM-DD HH-MM(-N)?.md`，同刻冲突加 `-2`/`-3` 后缀（库内 3 例）。
   - frontmatter 恰两属性：`日期: YYYY-MM-DD HH:mm`（英文冒号）+ `类型:`（YAML 多值列表，存标签名，无 emoji）。
   - 正文 = 条目内容原样（无一级标题；#人名/#书名 行留在正文）。
   - 旧日期文件迁移后归档 `归档/日记/`；`我的/其他/` 非日期笔记不动。
2. **契约单源 `src/core/diary-format.ts`**：文件名正则 / 命名与路径 / 日期提取 / 序列化 / 解析全部收编，六个消费方（diary、smartcat、recap、home、encrypt、core/path-classify）只准从这里取格式知识。落 `core` 是依赖方向（ADR-0002）下唯一无环位置——`core` 不依赖任何域，六个消费方全在其下游。
3. **解析无旧格式兼容**：`parseEntryFile` 只认新格式；frontmatter `日期` 损坏时**从文件名优雅降级**取日期时间（`类型` 照常提取）；文件名非合法真实日期的条目文件才视为不可解析。运行时宽、**体检（lint）严**：缺 `日期`、文件名与内容不一致、旧格式残留都列为体检项，供用户手工修。
4. **写层条目粒度 + 串行队列**：`addEntry` 建文件前按目录现有文件取空闲名（撞名循环 + 队内复检，防并发同刻竞态）；改标签只重写 frontmatter；删除即删文件。事件语义对齐：条目新增/改标签照发，文件腾空即条目消失。
5. **加密日记块格式 v2**：SafeNote 块头 `# 标签名/标签名 HH:mm`（标签名替代 emoji，emoji 表不再参与加密链路）；还原走 `mergeDiaryBlock` 序列化为条目文件、遇外来内容后缀让位、同内容幂等跳过。库内加密日记条目为 0，无数据迁移。
6. **记忆流引用迁移**：smartcat 记忆 ref `path#HH:mm` 只重写路径段（日期文件路径 → 条目文件路径），定位符 `#HH:mm` 语义保留，解析端对 `meta.time` 校验存活。

## 后果

- 一级标题不再是数据结构：emoji 表只服务 UI 展示（由标签派生），行号定位退场（lineNumber 恒 0，locator 按 filePath+time）。
- 复盘 AI 摘要、小橘观察、首页 streak 等消费方全部改走「文件名即元数据」，对文件的写入收敛到契约层序列化。
- 迁移一次性（脚本 dry-run 报告 → 关 Obsidian 实跑），旧格式文件归档后插件内不再出现。
