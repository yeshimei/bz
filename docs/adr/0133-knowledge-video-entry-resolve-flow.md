# 0133 — 知识盒视频录入改链接解析式（替换 ADR-0122 要点 5 的防抖拍板与 ticket 146 的范围交互）

## Context

现状（issue 278 / ADR-0122 拍板要点 5）：「视频录入」添加弹窗 = 链接单框 450ms 防抖自动解析（只补空回填）+ 手动「视频标题（可选）」「UP主（可选）」输入框 + 整片/剪辑片段 toggle（剪辑才出开始/结束时间框）+ 分P 数字输入框 + 清晰度四选（跟随全局/最高/1080P/720P）。保存只入队，处理靠 ▶️ 批量按钮手动触发（ticket 146 单钮态机）。

用户 2026-09-14 提出重做录入流程，并先要求实测分 P 与时长可行性。实测结论（Node 直调 `api.bilibili.com/x/web-interface/view`，本机网络）：

- 单响应同时给出 `title` / `owner.name` / `videos` / `duration`（总时长，多 P 时为各 P 之和，12P/54P 两次逐项求和验证一致）/ `pages[{page, part, duration, cid}]`（54P 视频全量返回，part 非空）。**现有 `video-meta.ts` 已在调同一接口拿 title/uploader，扩展分 P 与时长为零新增请求**；CLI 侧 `tools/bili-downloader/core.js` 早就在消费 pages。
- 清晰度档位实测：未登录 playurl 一律只返回 720P/480P/360P 档（账号级限制，与视频无关；4K 视频同样）；**带登录 cookie 的 wbi playurl 返回完整档位**（实测 `[1080,720,480,360]`）。CLI 的 `~/.bilibili-cookies.json` 含完整登录 cookie（SESSDATA）。
- 剪藏本 news.json 的 `bilibiliCookie` 是自动引导的匿名 cookie（buvid3），非登录态，拿不到 1080P——不可作档位来源。
- 插件已有 `getFs()` 桌面端门禁先例（processor.ts）；wbi 签名需 md5，移动端无 Node crypto → 需纯 JS 实现才能两端单源。

用户拍板链（四轮问答，2026-09-14）：解析按钮替代防抖；精调走「时间输入框双向联动 + ↑/↓ 键一次 1 秒」；失败态手填分 P 与时间范围、下次打开弹窗自动重抓并替换显示；去 toggle、进度条常显（全选 = 整片）；抓取成功即落库（只补缺失、不重置手填）；单 P 隐藏分 P 字段；B 站 cookie 全部内置插件设置并支持移动端；设置面板 AI 组改名「AI 与凭据」并收编影院两项凭据；档位默认选中全局设置对应的具体档位；保存按钮两端统一「保存」、都只入队不自动处理（否决了首轮「保存即自动处理」的选择）；打开主面板对缺信息任务自动重抓。

## 决策

- **弹窗改链接解析式**：单输入框（B 站链接 / BV 号）+「解析」按钮——防抖自动解析（`addUrlTimer` / `addUrlSeq` / `addUrlResolve`）退役；解析中按钮「解析中…」且保存禁用；改动输入内容作废已解析信息（信息区清空、重解析前不可用）。解析成功渲染只读信息区：标题、UP 主；多 P 出下拉（选项 `P{n} · {part} · {mm:ss}`），**单 P 隐藏分 P 字段**（落库 page=null）。标题/UP 主输入框删除（`#lit-add-vtitle` / `#lit-add-uploader` 退役，值只来自解析）。
- **范围选择重做**：整片/剪辑 toggle 退役；双把手进度条常显，默认全选 = 整片，任意拖动即剪辑，另给「整片」一键重置。两个时间框与把手双向联动（拖把手实时更新、框内改数把手跳位），沿用 `normalizeLooseTime` 宽松输入，显示格式 `M:SS` / `H:MM:SS`；**时间框 ↑/↓ 键 ±1 秒**。切换分 P → 进度条量程换成该 P 的 duration 并重置为全选。保存时全选范围落 `start/end = null`。
- **失败态退化**（解析失败：断网 / 风控 / 老式 b23.tv 短链 / 视频被删）：解析提示行示失败原因（重试 = 再点一次「解析」）；分 P 退化数字输入框（1 起，留空 = 第 1 P）；时间范围退化两个时间框（无时长画不出进度条）；清晰度用固定列表；**仍可保存**，标题/UP 留空、卡片回落显示链接。
- **清晰度档位**：新增设置项「B站 Cookie」（设置面板「AI 与凭据」组；默认空）——cookie 存插件设置（`.obsidian/plugins/bz/`）随 vault 同步，移动端可用。桌面端该设置行带「从 CLI 导入」按钮（`window.require('fs')` 读 `~/.bilibili-cookies.json` 一键填入；非桌面端不渲染该按钮——schema 模块保持 node 环境可安全加载，故用零依赖 `window.require` 判定而非 import core/mobile）。解析时带 cookie 走 `x/player/playurl`（fnval=4048 取 dash）拿实测可用档位——**实现期实测确认免 wbi 签名**：未签名带 cookie 即返回完整档位（实测 `[1080,720,480,360]`，裸请求无 UA/Referer 亦通），故不移植 wbi 签名与 md5（省约 150 行，且绕开移动端无 Node crypto 的跨端风险）；档位采用前置 **nav 登录态校验**（未登录时 playurl 档位受账号级限制只给 720P 以下，采用会误导，宁可回落）。**档位下拉 = 实测可用档 +「最高」**，默认选中全局设置对应的具体档；全局档不可用时默认最高可用档（提示渲染在档位下拉下方）；「跟随全局设置」选项取消（默认值即其一次性落地）。cookie 未配 / 失效 / 接口失败 → 回落固定列表（最高 / 1080P / 720P），静默。
- **保存与处理**：按钮两端统一「保存」（移动端「暂存」与桌面端「保存至文献」措辞退役）；保存 = 只入队（`pending`），**不自动处理**——▶️ 批量按钮角色不变（唯一处理入口）。**打开「视频录入」主面板时对所有缺标题任务串行自动重抓**（任务间 300ms 间隔防风控，已尝试 id 会话内不重复），成功即落库并刷新卡片。
- **编辑态**：打开编辑弹窗自动重抓一次（无需用户操作、不阻塞保存）；**抓取成功即落库**（标题/UP/duration 写入任务，只补缺失；duration 取所选分 P 时长，与弹窗保存同口径），失败不覆盖已有值。
- **数据层**：`KnowledgeTask` 新增 `duration: number | null`（秒；旧数据缺省 null，向后兼容）——供编辑回显进度条与卡片展示；`quality` 落库值扩展为 `'highest' | 具体档位数字串`；卡片显示分 P（如 `P3 · 12:00 ~ 30:00`）。
- **CLI 配套**：`tools/bili-downloader/core.js` 的 quality → height 映射从只认 `'720' | '1080'` 扩展为任意档位数字串（`'480' | '360'` 等精确档），`'highest'` / 缺省维持取最高可用。
- **设置面板 IA**：AI 组改名「AI 与凭据」；影院「数据抓取」组的 ApiZero Key / 豆瓣 Cookie 挪入该组。

## Consequences

- ADR-0122 拍板要点 5（防抖 450ms + 只补空 + 无解析按钮）与 ticket 146 的范围交互形态（toggle + 时间框）被本 ADR 替换；「录入元信息」词条重写。
- 分 P / 时长数据链路零新增请求（复用 view API 响应）；档位查询为新增请求（nav + playurl，仅在解析时触发）。
- cookie 明文存插件设置并随 vault 同步（用户环境本已同步 CONFIG/STORAGE，拍板接受）；cookie 过期表现为档位回落固定列表，更新方式 = 重新「从 CLI 导入」或粘贴。
- 未配 cookie 的移动端设备：档位显示回落固定列表（真档位能力依赖 cookie 同步到达）。
- 解析按钮取代防抖后，粘贴链接不再自动出信息——多一次点击，换取可控与显式失败态（用户拍板）。
- **流程要点（实现期发现）**：`prototypes/` 产物的源指纹对**工作区文件字节**敏感（worktree 与主仓库的换行符差异即致指纹不匹配）——worktree 内跑 `node scripts/build-preview.mjs` 得到的产物合并回主仓库后过不了 `preview-freshness` 守卫；`pnpm run build`（esbuild production）只重出 render 产物、不重出 behavior 产物。结论：**原型产物应在主仓库重出**（本次收尾即如此修正）。
- 术语表：「录入元信息」词条重写；新增「清晰度档位」相关表述。
