# ADR-0183：Ollama 地址两行归 AI 面板「Embedding」组（桌面端启动自动补全）＋ 模型选择器动作收口时机

- 日期：2026-09-24
- 状态：已采纳（用户拍板三行处置，见 issue 423）
- 相关：issue 423（本票）/ issue 422 + ADR-0182（Embedding 行迁入 AI 面板，本票为同批收尾）/ ADR-0002（依赖方向）/ ticket 122（局域网 IP 行与「填入远程 URL」）/ ticket 173（「获取模型名」范式）/ issue 291（便利值动作不标 danger）

## 背景

issue 422 搬迁「Embedding 模型」行时，刻意把三行服务地址（Ollama 本地 URL / 移动端远程地址 / 本机局域网 IP）留在第二大脑。用户随后对这三行提出：前两行**能否自动获取**（能则去掉输入框），不能就搬进 AI 面板；第三行保留。

同批暴露第二个问题：AI 面板「Embedding 模型」行的「获取模型」按钮**要选中两次输入框才刷新**——第一次点选只写内存不回填显示，用户得再点一次按钮才看到值。

## 决策

1. **三行逐行定性**（先答「能否自动获取」，再定去处）：

   | 行 | 能否自动获取 | 处置 |
   |---|---|---|
   | ① Ollama 本地 URL | **不能**——它编码「Ollama 跑在哪台机器、哪个端口」，非约定可推（默认值只是留空兜底） | 迁 AI 面板「Embedding」组 |
   | ② 移动端远程地址 | **桌面端能**（局域网 IP + 11434）、**手机端不能**（无 `window.require`，且手机连的是电脑的 IP，自探测无意义） | 迁 AI 面板「Embedding」组 + 桌面端启动自动补全（只补空值）；输入框保留可手改 |
   | ③ 本机局域网 IP | 探测得来（已有） | 保留（用户明示）；承接②迁来的「填入远程 URL」按钮 |

2. **AI 面板「Embedding」组 = 服务地址在前、模型在后**：`Ollama 本地 URL → 移动端远程地址 → Embedding 模型`（先知道服务在哪台机器，再拉它的模型列表）。理由同 ADR-0182 §2 的切割线修订——原判「地址属域部署问题」在处理「能否自动获取」时被推翻：地址与模型同属「用哪套向量化」，且自动补全后用户**不需要**手填地址，留在域设置页只会把「手机连不上」的排查面切碎成两页。

   **键位与值零迁移**：`secondBrainOllamaUrl` / `secondBrainRemoteOllamaUrl` 键名、默认值、消费路径（`secondbrain/config.ts` 端点解析）一律不变。

3. **自动补全只补空值，静默执行**：`ensureRemoteOllamaUrl()` 在 `main.ts` onload 调一次——`secondBrainRemoteOllamaUrl` 为空才探测写入 + 落盘；**已有值一律不动**（用户手改的值可能指向另一台机器，覆盖即静默改坏连接目标）；探测不到不写、无通知（无变化即无打扰）。手机端 `getLanIPs` 恒空 → 天然不写，只读桌面同步过去的设置值。

4. **探测实现留域、core 只放普通 text 行**：`detectRemoteOllamaUrl` / `ensureRemoteOllamaUrl` 落 `secondbrain/local-ip.ts`（`core/settings-main-schema.ts` 只 import core 内模块，node 可加载口径不变，ADR-0002 不破）。「填入远程 URL」按钮随②迁到③行——探测展示与按钮同处，DHCP 漂移时就地自查自修；它写的是 AI 面板的设置项，确认框文案据此改指「AI 面板的「移动端远程地址」」。

5. **模型选择器：动作必须等弹窗关闭才 resolve**（修「选中两次才变」）。
   两渲染器都在**动作 Promise resolve 之后**重读绑定回填输入框显示值（`core/settings-schema.ts` / `settings-panel/renderer.ts` 同口径），而 `openModelPicker` 是打开即返回的弹窗——动作若不同步等，回填发生在**用户选中之前**（回填旧值），用户选中写内存后输入框再无刷新机会。
   定式：`await new Promise<void>((resolve) => openModelPicker({ …, onClose: () => resolve() }))`。`onClose` 在「选中关闭」与「取消（遮罩/Esc）」两路各触发一次 → 动作 Promise 必有归宿，不回填悬空、不泄漏挂起 Promise。**此后凡「动作触发弹窗、结果需回填输入框」的行，一律按此定式写**（LLM「获取模型名」、Embedding「获取模型」两行现为范例）。

## 后果

- 第二大脑设置页「服务」组只剩「本机 IP 自查（+ 一键刷新）」与「额外检索目录」；手机上不再需要手填任何地址。
- 首次安装即用：桌面端启动后远程地址已就位，手机端同步设置即可连（不必回电脑查 IP 手抄）。
- 「选中两次才变」在全域同类行上一次修净（两行同源修复），并留下可回归的 UI 测试锚点（core 渲染器 + 面板渲染器各一条；经变异实证：注入旧行为后两锚全红）。
- **已知局限**：早于「默认留空」改动的安装若把历史默认串（`http://192.168.1.8:11434`）持久化过，会被当作「用户已配置」而跳过自动补全（决策 3 只补空值的代价）。不为此加特判——该串是他机地址，覆盖即静默改坏远程连接目标。
