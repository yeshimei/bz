# ADR-0067: 文献盒 v3——断点续跑、历史归档、行内信息与 AI 自愈

日期: 2026-08-28
状态: 已采纳
前置: ADR-0066（文献盒 v2：进度/设置/行为流接入）；ADR-0062（小橘行为流）；ADR-0047（域事件总线）

## 背景

用户在实测反馈基础上追加四组诉求（含一次纠偏）：

1. **AI 步骤失败**：「最后一步失败了，报错『AI 返回的不是 JSON』」——产出含围栏/杂讯；且请求可见的失败重试入口。
2. **断点续跑（拍板纠偏后主诉求）**：「重试时，当所有视频处理完成后，可以再次点击批量处理，从依次从每个失败的视频出错的步骤继续，也就是说之前的成功的步骤数据会被存下来。」
3. **历史界面**：完成的自动归档到历史；清空入口移入历史视图（主面板不再设清空按钮）；行内「封面」拍板不要（Q2 自拟）。
4. **行内信息**：解析到信息后，链接换成「文字 + 链接」（点击浏览器打开）+ 封面和 UP主；后续细化为仅标题链接 + UP主（封面放弃）。添加界面增加清晰度与分P 可选。
5. **小橘侧纠偏**：「不是解析信息同步到行为流，是更新之前添加转文献任务（这里只有 BV），替换成更丰富的语义信息」——parsed 事件**充实既有 added 条目**，不新增行为流条目。
6. **进度显示收窄**：除「下载中」外其余阶段不显示百分比。

## 决策

1. **AI JSON 自愈（工具层）**：`aiJson` 先剥 markdown 代码围栏（```json … ```）再解析；仍失败自动重试一次（模型偶发围栏/杂讯）；二次失败才抛「AI 返回的不是 JSON」并带 120 字片段。失败原因更准 + 一次自愈，减少人工重试。
2. **失败重试入口**：失败行行内新增可见「重试」按钮（悬浮菜单保留）；**批量处理范围扩为 待处理 + 失败**——整批跑完后再次点击批量处理，失败项自动续跑。
3. **断点续跑（核心）**：工具层把成功步骤产物按任务指纹留存缓存目录（`cacheDir`，cleanupCache 同保留期回收，文件名 `resume-*`）：
   - 剪辑件 `resume-clip-<bv>_<cid>_<s>-<e>_<h>.mp4`（命中跳过 ffmpeg，交付后不删缓存件）；
   - 转写稿 `resume-transcript-….txt`（命中跳过 python/whisper）；
   - AI 元数据 `resume-meta-….json`（命中跳过元数据调用）；
   - 润色分块 `resume-polish-….json`（**逐块追加落盘**——润色失败重跑从已成功块数继续，不重跑已成功块）。
   指纹 = BV + cid(分P) + 起止（0.1s 精度）。同一任务重跑自动跳过已完成步骤、从出错步骤继续；下载原件本就按清晰度缓存（ADR-0011 既有），无需另存。
4. **历史归档**：`BiliTask` 新增 `archived/archivedAt`（成功即自动归档，processor `_finish` 写终态时一并落库）；主列表只显示 待处理/处理中/失败；面板新增 🕘 历史视图切换（标题「文献盒 · 历史」），历史行 = 成功徽标 + 标题链接 + 笔记路径 + 完成时间，行操作：打开文献笔记 / 打开B站链接 / 复制视频路径 / 移出历史；历史条带「历史 · N 条 + 清空历史」；**主面板 🧹 清空按钮删除**（拍板：清空入口只在历史视图）。全量保留 + 手动清理（拍板）。历史含「打开B站链接」= 外部浏览器打开。
5. **行内信息**：工具 `--batch` 新协议行 `[bz-info] {"title","uploader","bvid","url","duration"}`（解析完成后回传）；插件落库 `title/uploader`（先落库再发 `onTaskInfo`，确定性刷新）并整表重绘——主列表/历史行链接形态：**标题 = 文字链接**（点击外部浏览器打开，app.openUrl 优先、Electron shell 兜底），次要行显示 UP主（`UP主 xx`）；未解析到信息前仍显示原始链接。封面拍板不要。
6. **添加界面清晰度 + 分P**：任务级字段 `quality`（null=跟随全局设置 / highest / 1080 / 720）与 `page`（1 起，null=第 1 P）；添加/编辑弹窗可选，校验正整数；处理时任务级 `quality` 覆盖全局设置、`page` 写入任务 JSON（工具按 P 选 cid，文件名第 2 P 起带 `_N`，缓存/续跑指纹按 P 区分）。
7. **小橘语义充实（纠偏）**：`parsed` 事件照发，但 smartcat 侧**不新增行为流条目**——`enrichBiliAddedWithParsed` 按 `extras.url` 匹配最近一条 `added` 条目，把 `name` 从 BV 号替换为标题、`extras` 补 `title/uploader`（描述同步更新，面板文案随之变「你添加了转文献任务（《标题》）」）；未命中（旧数据/已清理）静默跳过。仍只收两个新建节点（added/converted）。
8. **进度显示收窄**：行内百分比/进度条仅在 `phase === 'download'` 渲染（其余阶段只显示步骤时间线 + 耗时）；协议层 pct 照发不删。

## Consequences

- 工具侧：core.js `aiJson` 自愈、`runBatch` 续跑产物四档 + `onInfo`；cli.js `[bz-info]` 行；cleanupCache 覆盖 `resume-*`；tests 87 用例（新增续跑三连跑/剪辑复用/info/分P/aiJson 围栏与重试）。
- 插件侧：`BiliTask` +6 字段（title/uploader/archived/archivedAt/quality/page，零迁移缺省）；data.ts `clearHistory` 取代 `clearFinished`；processor 解析 `[bz-info]`（先落库后事件）、终态写携带内存态新字段（修读-改-写竞态覆盖）、批量范围含失败项、成功自动归档；ui 历史视图/行内链接/重试按钮/添加弹窗扩展/仅下载百分比；smartcat `bili-source.ts` 增 `enrichBiliAddedWithParsed`，index 订阅 parsed 分支；tests 66 用例（bili/smartcat 组）。
- 文档：ADR-0067；CONTEXT.md 文献盒词条更新为本轮语义。
- 兼容性：`bili-tasks.json` 新增字段全部可选（旧数据零迁移）；`--batch` 契约向后兼容（旧 CLI 不认 options 按默认走，新 CLI 不认旧载荷按默认走）；`bz-bili-open/bz-bili-tasks-open` id 不变。

## 未采纳方案

- **parsed 新建行为流条目**（用户纠偏）：解析是过程信息不是用户动作，改为充实既有条目。
- **封面缩略图**（拍板不要）：远程图加载与离线体验权衡后放弃，只留文字链接 + UP主。
- **续跑状态显式标记文件**：存在性即状态（产物在 = 步骤完成），免维护状态文件漂移。
- **主面板保留清空按钮**（拍板：移入历史视图）。
- **续跑产物进 vault**：产物是瞬态中间件，放 cacheDir 随保留期回收，不污染 vault。
