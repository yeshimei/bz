# 0135 — 知识盒录入链路重构：三名词入口 + 显式双链通道 + 影像三界面直达

## Context

2026-09-14 用户在同一轮原型评审里提出两组需求（issues/309、issues/310）：

- 录入入口「文字录入 · 术语 / 视频录入 · 任务」命名不直白，且两类之外还要能整段收文字；属性区看不到「关联」这一步，用户在面板上无从判断自动双链是否发生（现状：issue 298 让第二大脑 link agent 订阅 `knowledge:tasks`，笔记落盘后被动异步建链，**不向调用方回报进度**）。
- 「影像」入口打开的是处理队列面板（任务列表），要进录入得再点 ➕；处理 / 录入 / 历史三个窗口与主窗观感不统一；录入弹窗一打开就把整张表单铺出来（未解析的字段全是空壳）。

## 决策

### 1. 入口收成三个名词 —— 名词 / 段落 / 影像

- 一个词 = 名词、一段文字 = 段落、一个 B 站链接 = 影像。入口按钮下方的灰色说明小字删除（命名本身已足够）。
- 「术语」在界面文案上一律改称「**名词**」（列表类型标签、预览头、属性卡行标签、通知、命令名、首页域菜单）；**数据契约不动**：`type: term` 与 frontmatter `term:` 键保持原样（老笔记零迁移）。
- 名词与段落**同壳双态**：同一面板壳按 `data-lit-entry` 切首行控件（单行 input ↔ 多行 textarea），来源行与其余行完全一致；段落落 `type: passage`，与名词同目录、同样有来源行（ADR-0116 沿用）。
  （后续：ADR-0136 在该壳上加第三态「图版」，成为同壳三态；本 ADR 其余结论不变。）

### 2. 关联时机 = AI 出内容即起跑，且由录入面板自己等结果（取代 issue 298 的被动订阅）

- 关键事实：近邻检索与 AI 裁判**只需要正文**（查询向量由正文算、候选来自索引库），**只有写 related 才需要文件**。故拆成三段能力，走新的 `src/core/link-now.ts` 通道：
  - `preview`（AI 出内容即调用）：只算不写 → 属性区「关联」行 `分析中… → 关联名`；
  - `apply`（确认写入落盘后）：把预演结果写进新笔记 `related`，**不重跑检索与裁判**；
  - `now`：兜底单篇管线（等价旧 `processNoteNow`）。
- 第二大脑侧实现 `createLinkBridge(agent, initialLoad)`：先等索引装载完成、通知静默（进度由面板呈现）、附带一次性索引覆盖引导。
- **删除** `LinkAgentWatcher` 对 `knowledge:tasks` 的订阅与 `onNoteGenerated`（issue 298）。视频笔记不再即时建链，回落 60 秒批次的常规路径；被动路径与调用方写入结果本就无法对齐，且它不回报进度。
- 面板交互：分析期间「重新生成 / 总结 / 确认写入」整体禁用（分析落地或失败即恢复）；属性卡新增「关联」行；确认写入后**直接关窗**；面板不设取消钮（退出走点遮罩 / ESC）、不自动打开笔记。

### 3. 影像：入口直达录入界面，录入 + 处理两界面同皮（历史是处理面板内的视图）

- 「影像」入口（主窗按钮 / 命令 / 聚合讯「保存至文献」）**直达录入界面**；处理面板随**「保存」**进入——保存即落队列并打开处理面板（录入界面标题栏**不放出口钮**，2026-09-14 用户复核删掉）。
- **历史不再另开弹窗**（2026-09-14 用户复核「点击历史，在面板内打开」）：处理面板持 `videoView: 'tasks' | 'history'`，切过去题字换「历 史」、图标组只留返回箭头（`arrow-left`，退回队列）、计数换「共 N 条」；ESC 在历史视图先退回队列、再按一次才关面板。原 `createHistoryUI` / 历史遮罩与弹窗窗口、`hideHistory()` 一并删除。
- 两界面头部同用主窗词典头（`.bz-kb-head` + 中列题字 + **左列状态计数 / 右列图标组** + 底部双细线；计数与图标组的位置在 2026-09-14 复核里对调过——说明性文字在左、可操作钮在右）；录入弹窗改词典皮行内标签行（与名词/段落同壳）。
- **处理面板比主窗小一号且不完全遮挡**（2026-09-14 用户复核）：`min(660px, 100vw-48px) × min(480px, 100vh-96px)`（主窗 900×640），遮罩降到 `--bz-overlay` 的 30% 且 `backdrop-filter: none` —— 遮罩此时只承担「点外部关闭」的命中层，层级由窗口自身的边框 + 投影立起来（主窗留在视野里可辨认）。
- **emoji 全部退役，改 lucide 图标**：处理面板钮（新增 plus / 批量 play↔square / 历史 history / 返回 arrow-left）、卡片笔记路径（file-text）、历史行（file-text + clock）、批量横幅（loader）、行内计时（timer）——均走 `core/ui/str.iconSpan` 占位 + `core/ui/icons.mountIcons` 兑现（插件 = setIcon，评审壳 = 各自 `prototype-icons.js` 白名单），单钮态机改用 `setIcon` 就地换字符。
- **录入界面初始只出链接行**（+「解析」），解析流程结束（成功或失败）才展开下半表单（标题 / UP 主 / 分P / 剪辑 / 清晰度 / 保存）；链接被改动 → 收起，须重新解析；编辑既有任务直接展开。
- 保存后关窗 → 通知 → 打开处理面板（录入界面不再兼作列表，给出明确落点）。

## Consequences

- **ADR-0133 的两处口径被本 ADR 修正**：① 其「打开主面板时对缺标题任务自动重抓」改挂到**处理面板**（录入界面已不是列表）；② 其流程隐含的「粘贴后不解析也能直接保存」不再成立——未解析时保存钮在收起的下半表单内，界面不可达。**失败态仍可保存**（解析失败同样触发展开）不变，失败原因提示行照旧。
- 「关联」行的进度只有面板知道，因此 link agent 的即时 toast 不再需要（`preview` / `apply` 均静默）；索引白名单未覆盖文献笔记目录时的一次性引导提示保留（避免「生成了却零关联」的静默失效）。
- 段落文献复用名词的落盘路径与来源行，知识盒部壹的列表类型标签新增「段 落」；CLI / 批处理链路零影响。
- 原型评审壳补演示数据（影像任务 处理中 1 / 待处理 2 / 失败 1 / 已归档 3）与演示级建链通道，使录入 / 处理两界面（含面板内历史视图）与关联过程可在浏览器内手动走通。
- **数据层读整表补形状兜底**（issue 310 实测事故）：`knowledge.json` 被写成非数组（旧格式/手改/原型壳旧种子 `{version,tasks:[]}`）时，`data.push is not a function` 会打断面板刷新与保存——`KnowledgeData.read` 现按空库兜底，首次读改写事务把文件收敛回数组形状。原型壳另加种子形状自愈（每次启动检查一次，不受种子标记保护）。
- 术语表：「知识盒」「录入元信息」词条重写，新增「影像」「段落文献」「关联行」相关表述。
