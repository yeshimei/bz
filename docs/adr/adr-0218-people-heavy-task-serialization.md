# ADR-0218 · 重进程串行化（跨域闸门：画谱任务 ↔ 录音处理）

日期：2026-09-29 · 状态：已采纳 · 关联：ADR-0196（画谱任务引擎与 prep 协作式让行）、ADR-0213（录音分离管线）、
ADR-0214（工作收编）、issue 509 / 511 / 516

## 背景

脸谱有**两条互不相识的重进程通道**：

- **画谱任务引擎**（`src/people/jobs.ts`）：持久化队列、会话级单例、批间 checkpoint；`preprocess` 段起
  `bz-face prep`（funasr：VAD / 声学模型 / 语音转写），单会话（`startPrepSession` 保证至多一个 prep）。
- **录音注册表**（`src/people/recording.ts`）：模块级 `running` Map，**无上限**；一条录音一个 `bz-face rec`
  进程，各自 `AutoModel` 冷加载 vad / CAM++ / SenseVoice（数 GB 内存 + 分钟级）。

两者都吃同一批本地模型、都吃内存与 CPU，却没有任何资源闸。实测后果（截图证据）：

1. **录音之间并发**：「录音处理 · 2 条在跑」，两条都停在「启动模型…」——双份模型内存，两份都在等冷加载。
2. **画谱与录音并发**：画谱任务在 prep 段时手动起一条录音 = 两个 funasr 同时驻留。

还有一条容易漏的事实：**暂停 ≠ 释放**。`pauseJobs` 只写控制文件让 prep 进程**待命**（模型不卸载，
ADR-0196 决策 3 为省冷加载有意为之）；只有 `removeJob`（删任务）才 `abortPrepSession` 真杀。
所以「画谱任务已暂停」时，funasr 仍在内存里躺着，此时起录音照样内存翻倍。

## 决策

1. **新增域内单例闸门 `src/people/heavy-gate.ts`**：至多一个持有者，两类持有身份 `portrait`（画谱任务）/
   `recording`（录音处理或质心构建）。纯状态机，**不 import 任何 `people/` 模块**（`jobs.ts` 与
   `recording.ts` 都 import 它，故不可反向依赖，守 ADR-0002 依赖方向）。
2. **粒度 = 整条画谱任务**（用户明示"画谱在跑，不能跑录音"）：任务从 `running` 到终态持闸，**AI 段也持**
   （describe / extracting / person / bond / chronicle）。知情项：吞吐代价——录音最长会等到整条任务跑完，
   故必须有可见的等待状态与出口（见 5 / 6），否则观感是卡死。
3. **占用判定含待命进程**：任务虽 paused 但 prep 会话仍活着 → **仍算占闸**（模型在内存里）。任务在 AI 段
   暂停（无进程在手）→ 不占闸，闸门为空。
4. **抢占只针对待命进程**：录音请求遇到「有任务在 `running`」→ **不抢**，排队等；遇到「仅待命 prep 进程占闸」
   → 写 prep control `stop` 协作式终结（超时兜底 `abortPrepSession`）后起跑，并提示
   「为腾出内存已结束预处理进程；恢复画谱任务时会重新加载模型」。
   语义：用户主动点录音 = 明确表达了"现在机器给我用"，可恢复的代价（冷加载）由提示交代。
5. **录音侧队列**：全局一条串行（跨联系人也是——瓶颈是进程内存 / CPU，不是单个联系人）；入队即返回，
   行状态 `queued`（`待处理 → 排队中 → 转写中 → 待并仓 / 已并入`），排队行 = 「移出队列」。
   **出队那一刻才判是否需要质心前置**（前面的任务可能刚把质心建好，入队时判会白建一次）。
   **内存队列、不持久化**（N2）：续跑唯一依据永远是 sidecar；持久化会引入"重开 Obsidian 自动 spawn
   一批进程"的惊讶面，而录音重排只是再点一次。
6. **画谱侧等待**：`runQueue` 在拾起任务前 acquire；拿不到就 **`await` 闸门释放**（不是 `break`——保住
   `whenIdle()` 的语义：有任务在等闸时 `whenIdle()` 不能提前 resolve）。任务此时**不入 `running`**，
   留 `paused` + 文案「等待录音处理结束」；闸门释放时 `kick()`。
7. **停止语义**（N3）：行上的「停止」= **停当前这一条，队列自动继续下一条**；进度块另给「**清空队列**」。
   两个动作语义正交（这条不对 / 腾机器）。排队中、处理中的行**不给删除**（issue 516 Q14）；建质心阶段的
   停止 = 直接杀进程（Q23，npz 原子写不留半截）。
8. **先到先服务（FIFO）**，不做优先级。理由：可见、可预测；等待窗口在有抢占（决策 4）后本就不长。
9. **不做**"跨域重进程池"（画谱与录音统一调度器）。闸门已足够，池化要动引擎的持久化队列与阶段机，
   收益不抵成本。

## 后果

- 任何时刻**至多一个 funasr 在手上**。两条录音不再并发，「启动模型」不再双份付。
- 代价：整任务互斥使任一侧可能被另一侧长时间堵住。缓解 = 决策 5/6/7 的可见状态与出口
  （录音：「排队中 · 第 N 位 · 等待画谱任务结束」+ 移出队列；画谱：「等待录音处理结束」+ 暂停 / 删任务）。
- 进度块文案：`录音处理 · 1 条在跑 · N 条等待`。
- 测试面：闸门纯状态机单测（互斥 / 排队 / 抢占待命 / 释放后 kick）；两个通道各一条接入测试
  （引擎持闸时录制不入 running；录音持闸时 `runQueue` 不拾起且不提前 resolve `whenIdle`）。
- **知情项**：本闸只覆盖「画谱任务 ↔ 录音处理 / 质心构建」。其他外部流程（数据源全量导入等）不在闸内，
  若将来同样撞内存，另开 ADR 扩持有身份。
