# ADR-0203：归物本分类表——远端可下载的物品分类表 + 两次 Jev 归类

- 日期：2026-09-27
- 状态：已采纳（实现见 issue 478）

## 背景

用户要求：给归物本做**一张物品分类表**，可在设置面板里自行下载；表按「组 → 分类」两层组织，每个分类配一枚图标；归类用 **Jev 调两次**（第一次只给分组、第二次给组内具体分类），单次上限 255 个选项，两层合计可容纳 65025 个分类。

四项先期调研决定了本 ADR 的形状：

1. **GitHub 上没有现成的中文家庭物品分类表**。最接近的是 UNSPSC（5 级 / 8 万+ 条 / 官方含中文）与 GS1 GPC（4 级 / 36 段），但两者粒度是采购供应链（「工业螺栓 M6×20」），对「个人归物」是灾难。Homebox（MIT）只有位置树+标签的数据模型，无预制分类。
2. **Jev 是判定通道，不生成文本**（ADR-0173）。它的 `choice` 题型只做「从注入的清单里选一个」——所以「两次 Jev」只能是**运行期**归类（先选组、再选类），不可能是让 Jev 造表。
3. **lucide 是英文物件库**，`kettle`/`mug`/`oven`/`iron`/`vacuum`/`curtain`/`glove`/`socks`/`tie`/`candle`/`razor`/`shelf` 这些在 lucide 官方最新版里**也不存在**（不是 Obsidian 版本旧）。「一枚图标配一个分类」有天然天花板。
4. **Obsidian 内置图标集的唯一权威清单是运行时 `getIconIds()`**；构建期只能近似。实测本机 `obsidian@1.13.4` 的 `app.asar` 可抽出 1675 个规范名（+252 别名），逐条在 `app.js` 中可搜到、零假阳性。

## 决策

### 1. 表是真两层，组 ≤255、组内 ≤255，不拆

组 = 收纳语义分区（26 组：数码影音 / 家具家纺 / 厨房餐茶 / 衣物鞋帽 …），分类 = 具体物品名（515 条）。两层各自作为一次 `choice` 的候选清单，天然落在 255 以内；容量上限 65025 留作扩展余量，**当前不做第三层**，也不把组当作纯分片技巧。

### 2. 表是「建议来源」，不是唯一合法分类

`category` 仍是自由字符串（ADR-0201 的结论不动）。表只决定**AI 给出什么建议**与**选择器里能翻到什么**；用户手打任意分类名不受限，也不因表里没有而被拒绝。

### 3. 图标按语义择优，允许重复；候选池构建期抽、运行期兜底

分类行数由收纳体系决定，**反向由图标数决定行数**（不为塞满 1675 个图标去造分类）；同一枚图标可跨组、跨分类复用——「合适」优先，「不重复」不构成目标。候选池落 `src/belongings/catalog/icon-pool.json`（来源 obsidian@1.13.4，含导出方法说明），渲染时再用运行时 `getIconIds()` 取交集，交集为空才回落组图标 → `package`。理由：`mountIcons` 对未知名**静默忽略**，不兜底就是无声丢图。

**前缀坑（必须两种形态都认）**：`getIconIds()` 对内置 lucide 图标返回的是**带 `lucide-` 前缀**的 id（实测 1.13.4 实现：`Object.keys(<内置表>).map(e => 'lucide-'+e)`，再拼自定义图标），而表里存的是**不带前缀**的规范名（`setIcon` 两种都接受）。只做单向成员判定会把 515 条 + 26 个组图标全部判成「未知」，于是**每一行都静默退化成组图标**——不报错、看起来「就是这样」，比丢图更难发现（实现里 `resolveIconName` 已按两形态判定，并有回归断言钉住）。

### 4. 两次 `choice` + 哨兵，失败一律回落「表内选择」的 LLM

第一次 `choice` 的 `criteria` = 全部组（键 `g001` 形态）+ 哨兵 `__other__`「以上都不合适」；第二次 = 该组的分类（键 `c0123` 形态）+ 同一哨兵。命中哨兵、Jev 未配置、请求失败、答案畸形 → 转 LLM 回落，**但候选集仍取自表**（选组失败给全表、选类失败给该组），返回值必须在候选集内，否则抛错——有表时 AI **绝不造表外分类**。取消（`signal.aborted`）抛 AbortError 且**不回落**（照 ADR-0173 §2 的既有纪律）。

### 5. 别名直配短路

每条分类可带 0–5 条别名（口语名/简称/常见英文名，全表不得跨分类重复）。点 AI 按钮先做本地直配：精确命中分类名 → 最长别名包含匹配 → 命中即返回，**一次网络都不发**。

### 6. 资产形态照皮肤包范式；只在点按钮时联网

源 `src/belongings/catalog/categories.json`（人工整理、可 diff）→ `scripts/build-catalog.mjs` 出版到 `manual/belongings-categories.json` + `manual/belongings-categories.index.json`（version + sha256，带 `--check` 守卫）→ 运行时 `src/core/category-table.ts` 复用 `core/remote-asset.ts`（GitHub raw + jsdelivr 双源）下载、校验、落盘、查询。

**与手册/更新日志不同**：分类表**不做启动静默同步、也不在打开设置页时后台核对**——用户原话是「在设置面板中自行下载」，这是「自己要了才下」的数据资产，不是需要常新的文档资产（ADR-0200 的适用面因此不扩张到本表）。

### 7. 两个消费面共用同一张表

① 表单 AI 按钮 → 两次 Jev 归类（`src/belongings/catalog-suggest.ts`，`ai.ts` 只做分流保持对外签名不变）；
② 表单分类选择器（`src/core/ui/catpicker.ts`，以 `openPathPicker` 为骨架 + 分组头 + 每行图标 + 搜索命中分类名与别名）。**非搜索态全量渲染**（26 组 515 条），另设 1200 条硬上限（防呆阈值，非性能调优——它是防这张表未来被加厚到离谱量级，不是给 515 条截断用）。

## 后果

- **用户可见**：通用设置页多一个「数据资产」组 + 一行「归物分类表」（未下载 / 已下载 · v0.1.0 · 26 组 515 条，点按钮下载，busy 期间禁点防重入，失败走 `notifyActionError` 人话提示且**不动本地已有的表**）；添加/编辑物品弹窗分类行多一个选择器按钮；AI 按钮的建议改为「从表里选」。
- **行为变化（需知情）**：表下载后，AI 归类**不再复用表外的历史分类**（例如用户手打过的「岳父送的茶壶」不会被 AI 再建议）。这是「建议只来自表 + 手打不受限」这条口径的必然结果，不是缺陷。
- **未下载表时的降级**：AI 按钮回落旧的 LLM 自由生成路径（`AI_ICON_MENU` 118 条与 `AI_FALLBACK_ICON` **保留**作最后兜底，不清退）；选择器显示「尚未下载分类表」空态并提供跳转设置面板的入口。
- **成本取舍（已记账，未做）**：Jev 未配置时，回落给 LLM 的候选集是**全表 515 条**（约 4k token 的清单）。若日后嫌贵，可把 LLM 回落也改成两步（26 组 → 该组），本 ADR 不预先优化。
- **天花板（诚实记账）**：lucide 缺大量日用品名词，衣物组 18 条共用 `shirt`、清洁工具 13 条共用 `brush` 之类是**池的极限**而非偷懒；能做到「不难看、能认出」，做不到「一一对应」。
- **先天限**：两次选择是「先选组再选类」，跨组同物（保温杯 / 水壶 / 手套）在组之间会摇摆；别名直配只救一部分。
- **维护约束**：改 `categories.json` 后必须重跑 `pnpm catalog` 更新 `manual/` 产物，否则插件端 sha256 校验不过（与皮肤包同约束）；`tests/belongings/catalog-table.test.ts` 是盯着表源的完整性回归测试（组/类 ≤255、id 与名唯一、图标 ∈ 池、别名不跨分类重复）。
- **不可逆性**：中低。表与运行时代码是新增面，删掉即回到「LLM 自由生成 + 118 条图标菜单」的旧形态；唯一有迁移成本的是用户已存物品的分类名——但它们只是字符串，不受表影响。
