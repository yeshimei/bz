# ADR-0291：日记格式切换先试运行，整批都能转才真跑

- 状态：已采纳
- 日期：2026-11-06
- 相关：ADR-0284（加密日记还原按 HH:mm 插回）、ADR-0286（原生日记整篇一条）、ADR-0130（条目文件）

## 背景

「存储 → 切换并转换」原来是**边转边切**：转换函数逐文件搬运，只要 `converted > 0`
就写设置切格式。而日记的两种格式是互斥的读法——日记本只按当前设置找文件。

于是出现一个两难：转换是破坏性的（原文件进回收站），一旦半批成功、半批失败
（某篇有游离正文被跳过、某天的目标文件已存在、某篇被占用读不动），无论切不切格式，
都有一部分日记在日记本里看不见：

- 切了：没转成的那些（还是旧格式）读不出来；
- 不切：已经转成的新格式文件读不出来（源文件已在回收站）。

2026-11-06 发版前置 review 把这条列为 P1（`src/diary/settings-format.ts` 只要有一个
文件转成功就切格式）。同类问题还有一处：entry→day 转换把「写目标文件」和「把原条目
移进回收站」放在同一个 try 里，回收站不可写时会把刚写好的目标删掉——而此时前面几个
条目已经在回收站了。

## 决策

**1. `convertDiaryFormat` 两段式：先试运行（只读不写），整批都能转才真跑。**

试运行复用同一套解析/冲突判定，只是不 `create`、不 `trash`，返回的 `skipped` / `errors`
就是「这批里哪些转不了」。有任何一个不能转 → **一个文件都不动**，`converted: 0`，
调用方不切格式，把第一处原因说给用户。

执行期仍可能失败（磁盘满/权限），报告里带 `errors`，设置页照旧不切格式并在提示里
写明「已转 N 个，还有 M 个没转」——这是残余风险，不再是常态路径。

**2. `skipped` 只记「有内容但没转成」。空文件不算问题。**

空日期文件没有可拆的块、也没有可丢的行，原来记进 `skipped` 会把它当成失败拦住整批
切换。现在直接跳过、原文件留着。

**3. entry→day：目标写好与原文件回收分开记账。**

- 目标写失败 → `errors`，此时还没有任何原文件被搬走，无需回滚；
- 原文件回收失败 → `leftovers`（目标保留，绝不跟着回滚——否则用户两边都没了）。

**4. 幂等自愈：目标已存在且内容一致 = 上次已转换，只补移原文件。**

不做这条的话，`leftovers` 留下的原条目文件会让那一天永远卡在「目标已存在，整日跳过」，
用户重跑多少次都过不去。同内容判定忽略行尾差。

**5. day 格式的写层串行键统一为真实文件路径。**

`addLegacyEntry` 原来用「目录/日期」伪路径入队，而改字/撕标签/删块都用 `filePath`
（见 `removeDiaryEntries` / `updateDiaryTags` / `updateDiaryContent`）。同一份日文件两套键
互不互斥：一边追块、一边改块时，后写者覆盖前者的读-改-写结果。日期格式含子目录
（`YYYY/MM/DD`）时两个键甚至不是同一个字符串。

**6. 加密还原对「整篇无头行」的原生日记拒写。**

日记写层早就有 `refuseHeadlessDay`（ADR-0286），但加密还原走 vault 直写、绕过了它。
不拦的话，还原一个块就把纯正文变成「游离正文 + 头行块」，之后体检报游离行、
格式转换整份跳过。判据与写层同口径（有正文、且没有任何合法 `# emoji HH:mm` 块头），
命中返回 `false`（密文保留可重试），UI 文案说明「先切换日记格式」。

## 代价

- 转换要读两遍日记文件（试运行 + 真跑）。日记通常几十到几百个 md，可接受；
  试运行不报进度，进度条会先在 0% 停一小会儿。
- 试运行与真跑之间文件若被外部改动，仍可能失败——报告会如实列出。

## 测试

`tests/diary/convert.test.ts`：

- 有游离正文时 `convertDiaryFormat` 一个文件都不动；
- 回收站不可写 → `leftovers` 记一条、目标保留；重跑只补移原文件、不重复写；
- 空文件不算 `skipped`。

`tests/encrypt/diary-day-restore.test.ts`：目标是原生日记时还原返回 `false`、文件逐字不变。
