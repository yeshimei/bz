# ADR-0230 · 日记本换「桌上那本」书页 UI：整域 UI 替换、内嵌 StPageFlip、不带外链字体

日期：2026-10-02 · 状态：已采纳 · 关联：ADR-0115（回忆墙升格正名）、ADR-0104（渲染纯层）、
ADR-0106（样式/渲染/行为三层单源原型）、ADR-0020（样式按域拆分）、ADR-0122（界面级单源）、
ADR-0199（皮肤包）、issue 538

## 背景

日记本（diary）域当前的 UI 是「回忆墙」（ADR-0115 升格正名）：头行 + chips + 章节栏 + 瀑布流 + 灯箱。
2026-10-02 在 `.scratch/diary-quill/`（v43：`index.html` 145 + `app.js` 1882 + `style.css` 968）做了一版
**自由拟物探索稿**——「桌上那本」：一本书落在台灯下的桌面上，翻页即翻日记，所有功能都是桌上实物
（书口抽册页索引 / 台历跳日 / 放大镜检索 / 铅笔写 / 贴纸册分类 / 火漆信封加密 / 撕页删除 / 相纸显影灯箱 /
那年今天明信片 / 票根·信笺·藏书票）。该稿不接单源、不参与门禁，其 README 既定口径是
「拍板后若上岸，按 `src/diary` 单源口径**重写**，勿回灌」。

用户拍板：**实现到单源，单源所有 UI 全部废弃，全部采纳原型中的。**

把探索稿搬进单源，暴露了四处不入代码看不出来的落差：

1. **字体是外链的。** 原型观感的一半靠四个 webfont（Ma Shan Zheng / Long Cang / Zhi Mang Xing /
   霞鹜文楷屏幕版），`index.html` 里走 Google Fonts + jsdelivr。插件不能依赖 CDN；CJK 字体又无法
   子集化（正文是动态的），全量打包十几 MB 起。
2. **翻页引擎是 vendored 的第三方。** 原型翻页动画（纸张弯曲 / 拖拽 / 页角提示）全部由
   StPageFlip v2.0.7 渲染；仓库当时的那份是**无 license 头的压缩 UMD**。经核实上游为
   `page-flip`（Nodlik），**MIT、零依赖**。
3. **样式聚合是固定清单。** `scripts/build-css.mjs` 的 `SOURCES` 是显式数组、只做文件拼接
   （**不认 `@import`**）——vendored 库的 CSS 必须登记进去才会进产物。
4. **数据层已经把影视/书库压平了。** `src/diary/parser.ts` 把影评 + `![[海报]]` 拼进 `content`、
   把「`**《书名》**` + 书评 + `![[cover]]`」拼进 `content`；导演/类型/片长/年代/评分/作者/分类
   这些 FM 字段**解析时就被丢弃**。原型的票根（`meta`）与藏书票（`author`/`category`）要显示它们。

另有一处**有利**的发现：`prototypes/diary/fake-sim.ts` 在评审壳里跑的不是复刻件，而是真
`openDiary` → 真 `controller.show()`（FakeApp + 快照种子）。所以「域 UI 的唯一真理源是与评审壳
共用的实现源码、两侧不一致 = 缺陷」（AGENTS.md）在本次改造里**由构造保证**，不需要人工同步两份。

## 决策

1. **整域替换，且是重写不是搬运。** `src/diary/ui.ts`（3053 行回忆墙）+ `src/diary/styles.css`
   （1758 行）整体作废，按原型的新形态重写；**不保留回忆墙、不做双视图开关**。数据层
   （`data.ts`/`store.ts`/`encrypt.ts`/`config.ts`）不动，只换 UI 与样式。
   `index.ts` 对 `main.ts` 的契约（`ensureDiary`/`openDiary`/`openDiaryWrite`/`prewarmDiary`/
   `unloadDiary`）与 `DiaryAppController` 的对外面（`getInstance`/`show`/`hide`/`cleanup`/
   `getYearRange`）保持不变——命令 ID `bz-diary-open` / `bz-diary-write`、懒加载口径
   （ADR-0003）、启动预热口径都不动。

2. **三层结构照旧，`render.ts` 仍是 markup 纯层。** 书桌 DOM 骨架与全部纯渲染函数
   （`seal` / `ticket` / `exlibris` / `para` / `entryBlocks` / `daystamp` / `photo`）落 `render.ts`，
   受 render-purity 守卫约束（不 import obsidian/moment/core 服务，类型取自 `./types`）；
   行为（分页测量、StPageFlip 建书与翻页、文具五项、台历/贴纸册/检索/信封/撕页/灯箱/便签菜单、
   懒加载与 markdown）留 `ui.ts`。

3. **不带任何字体。** 不打包、不挂 CDN、不加「字体名」设置项。`font-family` 回归宿主
   （`inherit` 与 Obsidian 主题变量）。**观感从「手写」转向「印刷」，这是明确接受的代价**——
   换来的是一条零体积、离线可用、不向外部发起请求的路径。
   （原型里那条「不靠外链字体就立不住」的观感假设，就此作废；后续若想要手写感，
   属于新决策，须另开 ADR。）

4. **内嵌 StPageFlip v2.0.7**（`page-flip`，Nodlik，**MIT**，零依赖，压缩后 44KB）。
   位置随 `src/core/vendor/` 先例（与 `normalize.css` 同级），文件头保留上游署名、
   另附 MIT 原文；补 `.d.ts` 声明（上游 UMD 无类型随文件走）。
   实现方式上，UMD 的首分支就是 CommonJS（`typeof exports === 'object'`），
   在 esbuild 的 CJS 包装下 `require`/`import` 可直接拿到 `{ PageFlip, HTMLPage }`，
   不需要改库源码、也不需要挂 `window`。
   其 `stPageFlip.css` 登记进 `scripts/build-css.mjs` 的 `SOURCES`（紧邻 normalize.css 之后），
   与「唯一例外：远端皮肤包只在 `src/core/skin-pack.ts` 单一注入点」（ADR-0199）不冲突——
   本项是**构建期内联**，不涉及运行时注入。

5. **数据层只做两处加性扩展。** ① `DiaryEntry`/`WallEntry` 增设可选字段承载影视/书库的
   FM 余项（`导演`/`类型`/`片长`/`年代`/`评分`/`作者`/`分类`），`parser.ts` 填充、
   `toWallEntry` 透传。不改既有字段语义、不改解析结果里已经压平的 `content`——
   加性变更，存量测试的断言面不动。
   ② `parseEntryFile` 补 `id`（`makeEntryId('diary', …)`，与影视/信/书同口径）。
   原型是拿 `data-eid` 定位条目的，而单源里**只有**影视/信/书有 id、日记条目一直是 `undefined`——
   全册日记塌成同一个 `data-eid=""`，便签菜单（`!menuEid` 早退）、撕页的碎纸动画、
   明信片「展信」跳页都会落到最后一篇日记上。这是移植时才会暴露的落差，属加性补齐。

6. **域内选择器全部命名空间化。** 原型的裸 id（`#book` / `#desk` / `#tools` / `#menu` /
   `#sheet` / `#slip` / `#album-pop` / `#cal-pop` / `#lightbox` / `#toast` / `#hint`）在插件内会与
   宿主及其他域撞（多个域共用同一个 `document`），一律加 `bz-diary-` 前缀；样式选择器同步。

7. **回忆墙测试整体退役，覆盖面由新测试重建。** 删除 `tests/diary/ui.test.ts`(1700) /
   `wall-fix-c.test.ts`(571) / `wall-event-contract.test.ts`(275) / `ui-logic.test.ts`(51)；
   新写「桌上那本」的 UI 测试（分页测量与块高度、块类型映射、命名空间守卫、翻页与文具动作契约、
   灯箱/信封/撕页）。`data` / `parser` / `store` / `encrypt` / `thumb-cache` 等非 UI 测试保留。

8. **两处「偏离仓库惯例」是刻意的，一并记录在案。** 书页界面不是面板，凡「按面板写的口径」
   在这里都不适用，涉及两条现役惯例：
   ① **域根不再是任何面板帧**：原 `.bz-diary-mob bz-panel-mtop`（回忆墙挂 core 面板壳、吃移动
   全屏顶距）随墙退役，改 `.bz-diary-scene`（`position:fixed; inset:0` 的拟物全屏场景），与 cinema
   的整屏布局域同档。挂 `bz-panel-mtop` 只会得到一份无用的顶距垫，故明确不挂——`enh-sweep-c`
   的断言随之改成「不得回潮」（`not.toContain('bz-panel-mtop')`）。
   ② **拟物浮层不掺 token 遮罩**：纸条 / 贴纸册 / 台历 / 抽出的纸 / 火漆密码框这五层的压暗底是**材料**
   （`rgba(20,12,5,…)`），不是「遮罩」——故既不挂 `.bz-overlay-mask`、也不带 `backdrop-filter`，
   与决策里「不改调色板」同源（材料 ≠ 主题表面）。`overlay-glass` 的 diary 组断言据此改写为
   「保留域内拟物压暗底 + 不得掺 `--bz-overlay` / `backdrop-filter`」，防「只抄底不抄 blur」的
   中间态。**除这五层外，本域不再有任何手绘遮罩。**
   （整屏木纹桌面后经用户拍板撤掉——「只要日记本本身，遮罩与其他域一样点了能关」：场景根不再铺
   底色，desk 层退化为 token 遮罩并承接「点遮罩收起」；这五层压在遮罩上再压暗的一层仍是材料。
   火漆密码框为后补的第五层：动保险箱前的封，收主密码后交真保险箱校验，本域不碰密码学。）
9. **收起的三条路 + 翻页节奏 + 解锁门禁，按首轮原型实测回修（2026-10-02 迭代）。**
   ① **收起**：原型第一版「按 Esc 只翻回第 0 页、不收窗口」是 bug——Esc 栈走到底后必须真收起
   （`escapeStack` 末级 `hide()`）；另补两条与其他域同口径的出口：点遮罩空白处收起、桌面端不设
   右上角关闭钮（移动端书页铺满整屏，顶留 44px 刘海位，关闭钮在右上）。
   ② **翻页**：`flippingTime` 620ms 实测偏拖（一页要等半拍），收到 **380ms**，`ui-book` 的建书
   契约断言随之改值（数值是手感档位，不是常量契约，改了就要同步测试）。
   ③ **解锁门禁**：动保险箱前不再借通用解锁屏 `ensureSafeUnlocked('diary')`——那会弹出 encrypt
   域的锁屏，与本册材质割裂；改问真保险箱状态 `getSafeManager().unlocked`，未解锁则由本域火漆
   密码框收主密码、交 `SafeManager.unlock()` 校验。测试契约因此从「mock `ensureSafeUnlocked`
   的返回值」改为「mock `getSafeManager()` 返回的解锁态」；「没解锁」那条用例也改为断言
   「先摆火漆密码框、二次确认框还没轮到」，点「算了」原地退出。
   ④ 「那年今天」明信片与「这本册子」引导便签用户点名无用，一并退役（控制器 `checkOnThisDay`
   删除，测试反向断言其不存在）。

10. **移动端改「整本铺满整屏」+ 页宽回归单一真理源（2026-10-16 迭代，用户实测回修）。**
   ① **顶部不再留 44px 空条**：决策 9 那版让书从第 44px 起铺满，于是刘海那一条透出遮罩下的宿主
   底色，看着就是一条空白（用户原话「距离顶部的 44px 是空白，不对，应该也有日记本的背景」）。
   改成 `--pg-h: 100vh` + 书顶 `top: 50%`：书自己顶到窗顶，那 44px 就是**纸面天头**；
   关闭钮跟着挪到距顶 44px（`max(44px, env(safe-area-inset-top, 0px))`，兼顾真安全区），
   正文顶距 56px 仍让它落不进字区（正文右缘 361 < 钮左缘 368）。
   顺带：书签条不能再「从书顶翻出来」（`top:-20px` 会整条出屏），改挂关闭钮底下（`top:88px`）。
   ② **页宽回到「书的宽度说了算」**：`pageWidth()` 原先在单页档另写一份 `min(innerWidth*0.92,480)`，
   与移动端 CSS 的 `100vw` 一旦不等，StPageFlip 那个**按宿主宽度**折算的 aspect 盒就算错
   （实测 947 而非 871）——纸面被整体下推 38px 冲出屏底、离屏测量盒比真页宽 33px 导致正文按错宽度
   分页（页底截字），并且库的「四角点击」判据把 `flipNext/flipPrev` 一并挡掉，
   **滚轮 / 方向键 / 跳页三条翻页路全废**。现改为只读书宽做单页/跨页的除法，CSS 是唯一源；
   `walkthrough-fix-c` 的窄屏断言按新口径重写（反向断言 `--bz-diary-pg-w: 100vw` 不回流）。
   ③ **落笔必回册首**：写完那一轮回刷是防抖来的，`cursor` 可能已被迟到的 `flip` 回调写脏，
   `keepRatio` 便把书停到半路（用户看到「回了最新那页，可刚写的内容不在」）。新增 `pendingHome`：
   `diary:entry-added` 触发的回刷显式落第 0 页，不再靠游标推断。

11. **库的无条件 rAF 循环由域侧守卫收窄；写作期间不让路给软键盘（2026-10-16 迭代）。**
   ① **空转守卫**：StPageFlip 的 HTML 渲染器跑一条**无条件** `requestAnimationFrame` 死循环
   （`render.start()` 自己递归），每帧 `clear()` 给**所有非当前页**重写同一个
   `style.cssText = "display:none"`。真实 vault 那本 213 页的册子实测 **36 720 次 style 变更/秒**
   （≈ 页数 × 帧率），手机上折算 ~12.8k 次/秒 —— 持续烧 CPU、持续样式失效，与「读久了烫手」对得上。
   本域加 `flip-idle-guard.ts` 把「写同一个值」省掉：逐页判（已隐藏的只读不写）+ 可见页组没变就整段短路；
   翻页动画与拖拽期间那组引用一直在变，判据自然落空、逐帧照画。实测 **36 720 → 342 次/秒**，观感逐像素不变。
   **这是域侧对第三方库内部结构的唯一一处耦合**（`app.getPageCollection().getPages()` /
   `leftPage/rightPage/flippingPage/bottomPage`），集中在那个文件里，结构对不上就原样不动；
   改 vendor 源码仍是**新决策**，本决策不做。
   ② **判据换成书盒 + 写作期间让路**：分页的输入只有「书宽 / 书高 / 页内边距 / 单页模式」，
   前三个由书盒与媒体查询决定，页宽更是直接 = 书宽；按 `window.innerHeight` 判会白跑一次全量重排
   （移动端书高是 CSS 的 `100vh`）。快照落在 `relayout()` 里而不是 resize 处理里。另外写作内页摊着时
   **不重排**（纸是浮层，底下没人看），记 `resizePending`，收纸时走同一条防抖回刷补排 ——
   写一篇原先要白冻两次（开键盘一次、收键盘一次），一次全量成册在无头 Edge 实测是一个 57ms 长任务。
   ③ **一次性全量渲染不动**：它是上面那条「每帧开销 ∝ 页数」的乘数（实测 213 页 = 3343 个 DOM 节点；
   一次成册 = 一个 57ms 长任务），但守卫装上后每帧已与页数脱钩；真要做惰性分页是**新决策**
   （ADR-0171 的「一次全量成册」是当时的拍板，窗口化渲染是一条被回滚掉的路线）。

12. **窄屏改「一天一卷、正常滚动、滚到头换天」，翻页库退到桌面（2026-10-16 第二轮拍板）。**
   ① **窄屏不再建 StPageFlip**：用户原话「移动端去掉翻页特效，一次展示一天的日记，上一页下一页和中间页数
   去掉，用户可以正常滚动页面，滚动到当天日记的顶或底，自动翻到下一天或上一天」。落地为
   `buildDayStack()`：一天一卷（`.bz-diary-day`），一次只在屏上摆一卷（其余 `display:none`），
   换天是**纯显隐、零过渡**；卷内 `.bz-diary-page-inner` 可滚。这是「一天一屏」与「页面正常滚」
   两条要求的唯一自洽解——StPageFlip 的页是定尺的，塞第二次滚动进去必然和它的翻页手势打架。
   ② **窄屏的 `this.pages` = 天列表**：`groupByDay()` 按日戳块上的 `data-date` 分组，于是
   **页号即天号**，书口索引 / 台历跳日 / 检索定位那几条按页号算的路**一行未改**即可用。
   连带两个好处：窄屏不做 `splitParagraph`（那条路**逐行切开长段落**，改的是原元素）——手机上
   一天就是完整的一天，不该被纸边切在句子中间；也省掉一整轮逐块 reflow（成册 200+ 页时是最大的
   单笔开销，而它量出的高度窄屏无人使用）。
   ③ **滚到顶/底才换天**：滚轮与触摸各一条边判——先把滚动让给这一天，滚到头那一下才换天；
   往下落在下一天**开头**、往上回到上一天**末尾**，于是「一路往下滚」就是一页连一页读下去。
   触摸那条**不要求内容溢出**（窄屏没有别的换天手势，短的一天也必须能滑走）。
   ④ **页脚整段撤销**：上一轮为窄屏加的页码 + 「上一页/下一页」随本决策删除，`.bz-diary-page-no`
   回到原状（窄屏不再有页码这回事，桌面档页码本就在纸上居中）。
   ⑤ **配套两处版式**（同轮拍板）：纸左右通栏 `100vw`——上一轮刚把 `pageWidth()` 改成只读书宽，
   「CSS 与 JS 两份页宽」这个前提不复存在，1.8 版那次 aspect 盒错位不会再发生；底部工具条由
   浮在纸上的木牌改**贴底通栏玻璃条**，且**只留图标**（纯层两套面孔同一份 markup：桌面档是
   纸签上的墨字 `<b>`，窄屏档是 `.bz-ic` 图标，由媒体查询各取所需）。
   ⑥ **翻页动画按「简单为主」收**：`flippingTime` 380 → **240**，并补上 `drawShadow: false`
   （库有这一项，此前只在声明里留了 `maxShadowOpacity`）——那道扫过纸面的深影是拟物感的主要来源，
   也是每帧重算渐变的主要开销。滚轮节流 560 → **320**（节流窗 = 动画 + 一口气的余量；动画缩了
   节流不跟着缩，连滚会每一下都卡在上一段的收尾上）。
   注：决策 11 的**空转守卫此刻只对桌面生效**（窄屏连库都不建），它仍在库里没有别的消费方之前保留。
13. **正文段落「原文一段就是一段」，灯箱零文字（2026-10-16 第三轮拍板）。**
   ① **段首不缩进**：`.bz-diary-b-para` 去掉 `text-indent: 2em`，段距仍为 0 —— 段与段的间隔
   只由原文的空行块（`.bz-diary-b-blank`）给出。`.bz-diary-p-indent` / `.bz-diary-p-cont`
   **整对退役**：它们存在的唯一理由就是表达首行缩进（`splitParagraph` 里那次「续块换类」随之删掉）。
   ② **超长段落不再按字数硬切**（这条是「正文莫名其妙换行」的根因，先诊断后修）：
   `splitTextBlocks` 旧版把 >240 字的段落按句读切成 ~200 字的续块、**每块 `emit` 成一个 `para`
   块**，而块是块级 div、各起一行 —— 原文一段在册子里断成好几段。实测本机 vault：1244 篇 /
   2837 段里 **43 段超 240 字**，最长 `2511012023.md` 1256 字被切成 **6 块**（5 处多出来的换行）。
   现在一段就一块，折行交给排版自己：窄屏纸面自然折行；跨页档真要切开时走 `splitParagraph`
   （Range 二分，按页尾实际高度切），不再预先制造段界。
   ③ **灯箱只留图与左右两枚翻页箭头**：底部题注（`日期 时间 · 文件名`）与「第 n / N 张」计数
   连同两条 CSS 一并退役；`.bz-diary-lb-photo` 的内边距收成四边等宽 `16px`（原来的下边 12px
   是给题注让的位）。看照片时就只看照片。

## 后果

- **一次性可见的回归面很大**：单源 diary 域 UI 从「墙」变「书」，1758 行样式与 3053 行控制器整体换代；
  约 2597 行测试在同一轮删掉，**覆盖率在新测试写完前会掉**（这是第 7 条决策的已知代价，
  不是意外；故门禁要求测试与实现同批交付，不留「先删后补」的中间态）。
- **观感差异可预期且已知**：没有手写体后，标题/日戳等原依赖毛笔字的层级需要靠字号、字重、
  字距与留白重建（决策 3 的代价由这条承接）。
- **多一个第三方进产物**：`main.js` 增约 44KB（压缩前）；发布侧需在 README/许可说明里
  体现 StPageFlip 的 MIT 署名。
- **评审壳零额外工作**：`build-preview.mjs` 的 `PREVIEW_DOMAINS` / `BEHAVIOR_DOMAINS` 两份清单
  都含 `diary`，重写后 `prototype-render.js` 与 `prototype-behavior.js` 自动重出，
  人工同步两份 UI 的风险归零。
- 若日后要恢复手写体观感、或要换掉 StPageFlip，都属**新决策**：前者（字体）与后者（引擎）
  在本 ADR 里是明确被排除的选项，不是悬置项。

## 补记（2026-10-31）：兜底纸也要算「点遮罩」的命中

决策 10 的「点遮罩空白处收起」在实现上是一条 target 判据：`ev.target === 根` 或
`=== .bz-diary-desk` 才收起。这条判据漏了一类节点——**兜底纸** `.bz-diary-fallback`
（`position: fixed; inset: 0`，铺满整屏，`z-index: 600`）。它一显示，桌面被整块盖住，
点哪儿 target 都是它自己：没设日记文件夹时的引导纸（「这本册子还没定文件夹」）、读盘失败时的
「册子的数据没读出来」，两种状态都只剩右上角 X 能关（2026-10-31 用户对照报障：有内容的库
点遮罩能关，测试库不能）。

现在判据多认一个节点：`ev.target === fallbackEl` 也算命中。纸上那几个节点（`.bz-diary-fb-paper`
及其子）照旧不认——点纸不该误收起，纸上还挂着「设置日记文件夹」。不做 `pointer-events` 穿透，
是因为穿透会让点击落到纸上元素之下，命中的是谁反而要看层级，判据写死更好查。
