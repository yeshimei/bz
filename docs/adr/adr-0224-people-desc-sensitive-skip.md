# ADR-0224 · 图片描述遇敏感拒绝：批内降级逐张 + 敏感标注进聊天仓

日期：2026-09-30 · 状态：已采纳 · 关联：ADR-0196（画脸谱任务链决策 8/9）、ADR-0197（聊天仓
唯一写者）、ADR-0223（欠账口径必须同步）、issue 470（图片描述段）、issue 520

## 背景

用户实测：进度块报 `生成失败 · 图片描述 4/17 批`，原因
`AI 请求失败: 系统检测到输入或生成内容可能包含不安全或敏感内容…（fallback: Request failed, status 400）`。
一批 20 张里只要有一张（如 `Clipboard_Screenshot.png` 这类截图）被服务商判敏感，**整批 20 张全废**，
且 400 与网络抖动、5xx、额度错共用同一条「退避重试 → 耗尽 → 整段 error」路径——对敏感拒绝重试
必然再被拒，纯属白付费。用户建议：敏感批改逐张走，确定有问题的图标注、下次不再描述。

叠加 ADR-0223 决策 6：被拒图的 `text` 恒空 → `pendingMediaCounts` 永久判欠账 → 每次补画都重扫全库。

## 决策

1. **敏感拒绝独立成类**：错误分流里新增 `sensitive` 类，判据 = 响应文案命中敏感关键词（「敏感」
   「不安全」「content policy」「sensitive」「flagged」「moderation」）**且不是 429 / 5xx**。
   **除这一类，其余错误一律走既有重试路径**（网络超时 / 服务端错 / 额度错）。
   关键词匹配是启发式的：**宁可漏判退回重试 + 报错，也不误判**——误判会把一次网络抖动放大成
   20 次逐张慢调用。判据放宽到「不强制要求 400」是因为不同服务商的措辞与状态码包装不一
   （实测样本的 400 只出现在 fallback 那半句里），但 429/5xx 一律排除——那两类重试有救。
2. **命中即降级逐张，不退避重试整批**：整批必然再次被拒，重试是纯浪费。该批立即拆成单张调用。
3. **降级后的落账**：
   - 逐张成功的照常 upsert 进聊天仓（`[图片] 描述` 进 `text`）；
   - 被拒的那张在消息上标 `descSkip = 'sensitive'`，`text` 留空；
   - 本批照常推进 `doneBatches`，**整段返回 `ok` 继续走画像生成**——不再让一批毒图废掉整条链。
4. **标注落聊天仓消息字段（用户 2026-09-30 拍板）**：`descSkip?: 'sensitive'` 作为消息的派生字段
   与 `text`、`img` 同级，加密在保库记录内。**与 ADR-0197 一致：插件是唯一写者**，工具侧永不产出。
   选它而非数据根旁路表的理由：跟数据走、跨设备同步、与聊天仓同锁同库；代价是结构版本 +1。
5. **先标注、后并仓（实现期暴露的次序要求）**：同一笔 `safe.write` 里，标注必须先于
   `applyImageDescToMsgs` 执行。否则被拒的图会被**「同月 ct 最近邻兜底」借到邻居的描述**——
   一张毒图反而顶着别人的描述进时间线。配套收窄该兜底：`items` 里**明示了 `file` 但描述为空**
   的图不再借用邻居的描述（那是「本轮确实没拿到」，不是「调用方没提这张」），最近邻只服务
   「旁路表只给 `ct` 不给 `file`」的老场景。**这是实现期才暴露的既有缺陷，顺手修掉。**
6. **不动结构版本**（落笔前核实过）：`descSkip` 是 `StoreMsg` 上的**可选派生字段**，旧记录的
   `msgs` 经 `normalizeRecord` 的 spread 原样保留、缺字段读作 `undefined` = 未标注。类型上加一个
   可选字段即天然兼容，不需要迁移脚本，也不动 `PeopleSafeRecord.version`（那个号留给真正不兼容的
   结构变更）。原先设想的「结构版本 +1」是多余的改动面。
7. **标注即终态，必须排除出欠账口径**：`pendingMediaCounts`、describe 段的 `refs`、
   `applyImageDescToMsgs` 与补充素材图片页签的 `undescribed` 四处口径都要排除标注项——等价 done、
   永不重跑。**这是 ADR-0223 决策 6 的具体落实**，漏掉任何一处，标注都会形同虚设或口径打架。
8. **必须留撤回入口**：图片页签里已标注的格子给「敏感 · 解除」入口，一点 = 解除标注 + 走
   `runDescribeOnly` 重试描述（这一次点击即计费授权，与「生成描述」按钮同口径）。启发式判定一定
   有误伤，没有撤回入口的错杀不可挽回。
9. **通知归 UI 层**：引擎只把 `sensitive` 计数落进任务账本（`job.describe.sensitive`），完成通知由
   `ui.persistJobDone` 拼出。引擎不碰 DOM——顺带避免了在 node 环境测试里触发通知渲染炸掉整链。
10. **不做本地打码 / 模糊后重试**：那是新的图像处理管线，收益未验证，用户未要求。

## 备选

- **标注落数据根旁路表**（如 `desc_skip.json`）：轻、不动结构版本，但明文且数据根删了就丢、多设备
  不同步。用户选保库内。
- **任何批失败都降级逐张**：更不易整段卡住，但网络抖动会被放大成 20 次逐张调用（更慢更贵）。用户
  选只对敏感降级。
- **被拒图标记后仍定期自动重试**：服务商策略会变，图可能后来能过；但静默重试等于反复付费被拒，
  且违反「标注即终态」。要做也只能是显式的「解除标注并重试」。
- **把敏感图直接删出聊天仓**：丢素材且不可逆，画谱时图片数会与事实不符。

## 后果

- 一批毒图不再废掉整条链：要么拿到描述、要么拿到明确标注，画谱照常出。
- 代价：被拒张数会以 1 张 = 1 次调用的代价重试一遍同批（上限 = 批大小）；这是「宁可多花几次也要
  分清哪张中毒」的必要成本，且只在**已确定被拒**的批上发生。
- 诚实边界：`sensitive` 判定依赖服务商文案，不同服务商措辞不同；未命中的 400 会退回原有重试路径
  并以错误收尾（用户可重试失败项），**不会**被静默标成敏感。
