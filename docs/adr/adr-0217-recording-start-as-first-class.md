# ADR-0217 · 录音起点升格为一等数据（`<名>.meta.json` + 导入时确认 + 改起点回写）

日期：2026-09-29 · 状态：已采纳 · 关联：ADR-0212（补充素材入口与数据路径）、ADR-0213（轮次进仓）、issue 516

## 背景

轮次的绝对时间 = **录音起点 + 轮内偏移**（ADR-0213 决策 3）。偏移是精确的，**唯一的误差源是起点**。
而起点的现状（读源码核实）：

- `recordingTsOf` = 文件名解析 → **mtime** → now。三种常见导出名能解析准；解析不出的
  （如 `大琳 周六 10点14分✔️.aac`）落到 **mtime = 复制进 `recordings/` 的那一刻**，错到离谱。
- ADR-0212 写的"时间戳可改"**从未实现**：`suppRecTs`（ui.ts）只声明 / clear / get，**零写点**，
  录音行上既看不到起点也改不了。
- 起点**不落盘**：只在并仓那一刻用一次，之后无处可查、无法修正、无从复核。

## 决策

1. **起点升格为导入时必须确认的一等数据**：导入页列出每个文件解析出的起点，**解析不出 → 标红必填**
   （不再静默回落 mtime）；解析出的也可改。
2. **相对时间信息不自动反推**：文件名含「周X / N点N分」这类信息时给出候选让用户点一下确认，
   默认取「**不晚于 mtime 的最近一个**」——mtime 在这里的正确用法是**上界**（文件不可能早于录制时刻落盘）。
3. **落盘 = `<数据根>/<联系人>/recordings/<名>.meta.json`**（插件写、插件读），**不进 sidecar**。
   理由：sidecar 是**脚本的账本**，而既有口径"要重转就删掉 `.turns.json`"会**连起点一起删掉**——
   起点是用户确认过的输入，不该被"重转"这个动作清掉。
   `recordings/` 的过滤清单（`.turns.json` / `.meta.json` / `.turns.md` / `.tmp`）收成**单源**，
   新后缀不得被当成录音文件列出来。
4. **改起点 → 回写已并仓消息**：按 `rec:<file>:` 前缀重算 ts（复用 `applyRecordingTurnsToMsgs` 的
   "先清后写"幂等实现，天然可重入）并重算 kindCounts / stats。**已生成的脸谱正文不自动改写**
   ——那是产物，不是索引（要反映改动需重新画谱，属花钱动作，交用户显式触发）。
5. **逐轮时间轴 `<名>.turns.md`（人类可读）由插件写**：并仓成功时生成、起点变更时幂等重写；
   内容 = **全轮**（含旁音，带「旁音」标记）。理由：唯一写者（与"插件是聊天仓唯一写入者"同构）；
   改起点时脚本没在跑，插件写才能一处改完两处一致。
   **录音原件一律不动**——不写容器元数据、不重编码（aac / amr 支持参差，且改原件不可逆）。
6. **录音行显示起点 + 「查看轮次」入口**（读 sidecar 预览，含被滤的旁音轮）。

## 后果

- `suppRecTs` 死代码转正：页内改的起点**落 meta**，重启不丢。
- 改起点是"便宜的重写"（消息 ts + `turns.md`），**不重跑管线**——无需重新分离 / 转写。
- 录音原件与全部派生物内聚：`recordings/` 装 原件 / meta / sidecar / turns.md（control 在数据根
  `.bz-face/rec-control/`）；换数据根整体搬，无布局假设。
- `recordings/` 下多两个需过滤的后缀——过滤清单必须单源，否则派生文件会被当成录音列进 UI。
