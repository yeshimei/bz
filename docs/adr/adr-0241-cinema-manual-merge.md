# ADR-0241：影院合集支持手动归入（新增 frontmatter「合集」键）

日期：2026-10-05 ～ 状态：Accepted ～ 关联：ADR-0168（合并 = 纯渲染层分组，本 ADR 部分突破）、issue 376（按季合并）、ADR-0087（影院接管影视）

## 背景

影院「按季合并」把同一部作品的各季合成一张卡，特别篇 / 电影版 / 外传靠**片名前缀**并入同名卡：`seasons.ts::specialHostOf` 认「⟨剧名⟩ + 分隔符 + 副标题」（2026-09-20 拍板「只按前缀认」）。

前缀判断覆盖不到真名：《续命之徒：绝命毒师电影》（El Camino）是《绝命毒师》的续集电影，中文片名前缀是「续命之徒」而不是「绝命毒师」，自动规则认不出，于是单独出一张卡，割裂了它与剧集的归属关系。改名是最直接的绕法，但会篡改用户自己的笔记名——不可接受。

## Decision

1. **新增 frontmatter 键 `合集`**，值 = 目标合并卡的归一名称（如 `绝命毒师`）。键写在**被并入的那条笔记**上，语义是「这条属于哪张卡」。
2. **声明优先于前缀**：`mergeSeasonCards` 的特别篇并入阶段先看 `合集`——命中某张卡就直接进那张卡（哪怕它按片名本会进另一张，或谁也进不去）；没有声明才走原有前缀判断。自动规则不变。
3. **右键入口**（普通卡，以及合并卡弹窗里的行）：未并入 → 「归入合集…」（弹层列出现有合并卡供单选）；已并入 → 「移出合集「X」」。合集是**单归属**，两条互斥、按状态只出一条；要改挂先移出再归入。
4. **悬空声明优雅降级**：目标卡不成立时（如某季被删到只剩一季，卡不再存在），条目回落普通卡——不报错、不吞条目、不自动清键（季补回来就自动重新挂上）。
5. **建档 / 编辑不写此键**，只有右键动作落盘；`合集` 为空或缺失 = null。

## Options

- **O1 改片名让它命中前缀**（「续命之徒：绝命毒师电影」→「绝命毒师：续命之徒」）——❌ 篡改用户笔记名与既有引用，且每遇到一部都要手工改名。
- **O2 维护别名表放插件设置里**（片名 → 剧名）——❌ 关系脱离笔记，笔记改名 / 移动即悬空；且影院的数据契约一贯是「数据跟笔记走」（`状态` / `片单` / `重看` 都在 frontmatter）。
- **O3 集中存 CONFIG/STORAGE 的 json**——❌ 同 O2 的解耦问题，另多一处需要备份的运行时状态。
- **O4 放宽自动规则**（如按副标题反查剧名）——❌ 「续命之徒」与「绝命毒师」之间没有任何字面关系，规则再宽也够不着；放宽还会带来误合（ADR-0168 对「之」的取舍同此理）。

## Consequences

- **部分突破了 ADR-0168**：那条写着「合并是纯渲染层分组，不新增任何存储」。`合集` 是合并功能的第一份落盘数据。理由是手动归入本质是**用户的数据声明**而非渲染派生——不落盘则重启即失，也就不成其为「手动」。
- `合集`（标量，单归属）与 `片单`（数组，可多归属）是两层不同的归属，别混用。
- 存量笔记零影响：无键 = null，渲染与排序一字不变。
- 悬空声明不清理是刻意的：清理需要写盘，而写盘发生在读取路径上会带来意外改动；季补回来时声明自动重新生效。
