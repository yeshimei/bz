# ADR-0199：皮肤包云端分发——主题轴远端化、唯一注入点、只搬多值域

- 日期：2026-09-26
- 状态：已采纳（设计定案；实现见 issue 475）
- 相关：ADR-0020（样式按域拆分，**本票开例外**）/ ADR-0105（布局×主题分层）/ ADR-0095（备忘录皮肤）/ issue 473·474（手册与更新日志的远端通道范式）/ issue 246（外观组范式）/ `src/core/remote-asset.ts` / `src/core/self-update.ts`

## 背景

皮肤（主题轴）全部编译进 `main.js` / `styles.css`（现 2.38MB / 1.17MB），新增一套皮肤必须发一个插件版本。仓库已有两条远端资产通道（使用手册、更新日志，issue 473/474），但皮肤与之**不同构**：

- 手册是**旁路内容**——自包含单文件 HTML，与插件代码零耦合，坏了顶多少看一页，「有就跳过、没有就拉、覆盖旧版、浅校验」这套粗糙策略完全够用；
- 皮肤是**运行时依赖**——靠面板作用域类 + `--bz-*` token 咬住组件 DOM，损坏时**不报错、只是静默不生效**，用户会以为「这皮肤本来就难看」。

原始诉求是「皮肤也做成手册那样的在线下载」，理由是「不想撑大插件包」。实查后该理由**量化不成立**：现有皮肤零二进制资源（无 `url()`/字体/图片，预览卡是纯 CSS 渐变 + 伪元素画的），几十套纯 CSS 皮肤只值几十 KB。真正成立的理由是**解开发版耦合**——新增一套皮肤不必发插件版本、不必进 changelog（本仓 changelog 正文 = commit message，直接给用户看，皮肤噪音会灌满它）。

本轮经六轮 grilling 依次拍板：动机 → 通路 → 包形态 → 兜底 → 落盘 → 分发单元 → 获取时机 → 迁移节奏。

## 决策

### 1. 术语先统一：布局 × 主题，只有主题轴承载真皮肤

ADR-0105 的「布局×主题分层」在代码里是两条独立轴，但**键名混乱、读改前必查**：

- **布局**：`XxxLayout`（bookshelf/memo/home）或 `XxxSkin`（diary/clipbook/encrypt/favorites/knowledge/password-vault/review/secondbrain/cinema 的布局语义）；值恒 `'default'` 单卡占位，`memo/settings.ts:22` 注释写着「布局维度待皮肤设计时接入」
- **主题**：`XxxSkin`（**bookshelf/memo 把主题放在这里**）或 `XxxSkinTheme`（其余域）

实查真皮肤**全在主题轴**：`bookshelf/settings.ts:11` 注释「主题=bookshelfSkin 五肤」、`memo/settings.ts:22` 注释「主题=memoSkin 两肤」。**本 ADR 起，本仓语境中「皮肤」一律指主题轴。**

### 2. 分发对象：只搬主题轴 ≥2 值的域

| 域 | 主题轴键 | 总套数 | 搬走 | 留内置 |
|---|---|---|---|---|
| smartcat | `appearance`（存 `smartcat.json`，非设置键） | 13 | 12 | orange |
| pomodoro | `pomodoroSkinTheme`（`src/pomodoro/render.ts:30`） | 10 | 9 | tomato |
| bookshelf | `bookshelfSkin` | 5 | 4 | nordic |
| memo | `memoSkin` | 2 | 1 | editorial |

**合计搬走 26 套。**

**不搬**：

- 13 个主题轴单值域（diary/clipbook/favorites/review/secondbrain/knowledge/encrypt/gameshelf/home/cinema/password-vault/belongings…）——每域只有 1 个主题值，搬走等于断网时连唯一主题都没了，纯亏
- `settingsPanelSkin`（经纬/晨昏）——「下载皮肤的界面」不得依赖下载来的皮肤；且设置面板外观组是唯一的救援入口（下载状态显示在此），必须**永远离线可用**

**首套锚定** = 主题清单首项。口径已由 `memo/settings.ts:28` 确立：「第一张卡就是新装 / 缺省时落到的那个」，四域直接沿用。

### 3. 分发单元与通道

- 清单 `manual/skins/index.json` + 每皮肤一个 `.css`，**复用手册所在目录与双源通道**（`raw.githubusercontent` 主 → `cdn.jsdelivr` 备，`src/core/remote-asset.ts`）
- 清单条目：`id / domain / name / 预览色值 / 版本区间 / sha256`
- 落盘 `<configDir>/plugins/bz/skins/`（复用 `assetVaultPath`，与手册/日志同一条路径规则，不引入第二套）
- **sha256 是本通道新增的一环**：现有 `remote-asset` 只有 `looksLikeManual` / `looksLikeChangelog` 式「像不像」浅校验；手册吃这个亏顶多少看一页，**皮肤吃这个亏是把垃圾直接注入 `<style>`**。清单里的 sha256 同时兼任增量判据（本地文件存在 + hash 匹配则跳过；现状是「存在即跳过、无版本比对」）

### 4. 注入：唯一例外点（本 ADR 的核心风险条款）

皮肤 CSS 要生效，在 Obsidian 里**只能走运行时注入**——远端 CSS 进不了构建期聚合，而每个插件只加载一个 `styles.css`。这与 ADR-0020 的明确否决直接冲突：

> 运行时注入 `<style>` 已被铁律 9 废止（ticket 60），不能回退到注入模式。
> 备选 2. 恢复旧 `styles/<域>.css` 多文件 + 运行时注入——被 ticket 60 明确废止，**否决**。

本 ADR **开此例外**，并把边界钉死（否则铁律 9 的价值「样式静态、单源、可审查」会被慢慢侵蚀）：

- **只有 `src/core/skin-pack.ts` 一处**恢复注入能力（`injectStyles` 只在该文件内复活），其余代码路径继续禁
- 加**静态守卫测试**：全仓除该文件外不得出现 `<style>` 注入
- 例外**不扩散**：任何其他用途要注入样式，必须另开 ADR

### 5. 加载：启动静默同步，不用按钮

照 `src/core/self-update.ts` 范式（延迟躲开启动高峰、失败一律 `console.warn` 静默、只有「真的有事」才发通知），但**不采用其 24 小时节流**——用户拍板「重启时拉一次；拉不到就等下次重启再拉」。

编排上**串在自更新检查之后**：`self-update` 会覆写 `manifest.json` **改掉插件版本号**，而皮肤的版本区间校验正是拿这个版本号算的；两件事并发会导致「皮肤按旧版本校验通过 → 插件随即更新 → 皮肤当场变不兼容」这种自我打脸的时序。

拉取范围过滤：只下**版本区间内**的皮肤（区间外的下了也不让用）。几十套并发会打爆请求，需限并发、失败不阻塞其余。

### 6. 兜底与失败面

- 内置首套**恒在**——任何情况下面板都有皮肤样式，不允许裸奔
- 未下载成功 / 已下架 / 版本区间外的皮肤**一律不进选择卡**（统一原则：**不生效的东西不许出现在选择卡里**）
- **下架 = 清单移除 + 删本地文件**（用户拍板）。已选中该皮肤的用户回落首套——`normalizeSkin` 既有的「退役肤/非法值读取回落」先例直接承接
- 预览卡**随包下发**（皮肤搬到远端后不再有内置预览 CSS）；选择卡只显示本地已有的皮肤

### 7. 排序

内置首套恒排首位，其余按清单数组顺序追加。随皮肤陆续远端化、内置只剩兜底，此序自然演化为「清单顺序即展示顺序」——**内置顺序不作为长久契约**，不要依赖它。

### 8. 迁移节奏

**一次全搬**（用户拍板，不分批）。被接受的风险见「后果」。

## 后果

- **铁律 9 / ADR-0020 被开例外**，边界见决策 4；`AGENTS.md` 铁律条目同步补例外条款，并修正「铁律 9 → 铁律 4」的历史编号错位。
- **一次性迁移冲击（用户已知悉并接受）**：本机制上线时，所有老用户本地 `skins/` 为**空**——其当前所选皮肤（如 bookshelf noir）会在升级后立即回落首套，直到某次启动下载成功；墙内 / 离线用户在此之前只有内置首套可用。
- **跨版本契约**：皮肤与面板 DOM / token 的耦合，从「同一发版内保证」变成「跨版本契约」，**版本区间成为唯一闸门**。
- 必改代码（`normalizeSkin` 的写死白名单是首要拦路虎）：
  - `src/bookshelf/ui.ts:285 / 289 / 307` —— `SKIN_IDS` 白名单校验会把远端皮肤 id **静默回落成 nordic**（`SKIN_IDS.includes(v) ? v : 'nordic'`）；`classList.remove(...SKIN_IDS.map(...))` 靠静态数组列举皮肤类。两者都必须改为「内置 id ∪ 本地已下载 id」。其余被搬三域同款问题。
  - `src/core/remote-asset.ts` —— 补 sha256 校验与 hash 比对增量判据（现为「存在即跳过」）。
- **预览卡规则可能跨文件**：如 pomodoro 的预览卡在 `src/settings-panel/styles.css` 里引用 pomodoro 的 `--pz-<id>-*` 变量（`src/pomodoro/render.ts:25` 注释「三处同表」）——皮肤包必须**同时切走「皮肤规则 + 预览卡规则」**，而这两处现在分居不同文件，切分脚本要处理这个跨文件依赖。
- 未纳入本次范围：`XxxSkin` 布局轴的远端化（布局轴现全为单值占位，无分发价值）、单值主题域、设置面板自身皮肤。

## 被否决的备选

- **token 值表方案**（远端只下发 JSON 白名单，插件 `setProperty` 逐个套变量，零 `<style>` 注入、最接近合规）：表达力只够改颜色/字号/圆角/阴影，**改不了结构**——bookshelf 五套的结构层、smartcat 13 套的渐变辉光与一次性动画全部做不出来。等于把皮肤降级成换色板，否决。
- **按域分清单 / 一个大 CSS 全打包**：前者无法「只下用到的」，后者等于换个地方放整包、动机归零。
- **保留内置皮肤、只新增云端皮肤**：不解决发版耦合，且两套来源并存会让「为什么这套在云端那套在内置」无法解释。
