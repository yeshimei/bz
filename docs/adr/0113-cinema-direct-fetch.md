# ADR-0113：影院豆瓣抓取插件直调（守护进程退役 + 卡片 loading）

日期：2026-09-09 ｜ 状态：采纳（issue 255）

## 背景

ADR-0111 的触碰协议上线当天，用户报障「唐顿庄园 第二季加了很久没数据」。根因：外部 PM2 守护进程自 9 月 5 日起**静默僵死**——进程活着但 chokidar 监听全聋（活体探针实证：touch 笔记 20 秒零反应），期间新增影视全部无人抓取，且无任何报警。守护架构的固有缺陷暴露：**插件对抓取一无所知，守护死了用户无从察觉**。重启后两季数据即刻抓齐，但「下次僵死怎么办」无解。

用户拍板架构转向：**不走守护进程，插件内存队列直接调脚本**。同时新增功能：后台抓取中的卡片显示 loading（海报遮罩 spinner）。

## 决策

1. **插件直调**：插件维护内存队列，入队即启动串行泵——逐条 spawn `douban-poster fetch <笔记绝对路径>`（桌面端 child_process，文献盒先例；复用现有 CLI 单条命令与工具包全部抓取逻辑）。条目间 15s 间隔防限流；单条 3 分钟硬超时杀进程防悬挂。
2. **完成信号 = spawn 退出 + 字段验证**：退出后重读笔记——海报/豆瓣链接到齐 → 完成（清 loading）；搜索无结果/退出码非零 → 失败。**失败才聚合提示**：一批队列跑完有失败则聚合一条错误通知（含片名清单）；进度零通知。重试交给下次会话首轮面板打开。
3. **队列口径 = 缺海报或缺豆瓣链接**（插件继承守护全责，ADR-0111 的盲区口径并入）。入队时机：面板打开扫描（sweep 改直录入队）+ 新建笔记落盘时。同会话内存去重；**每次 Obsidian 会话首轮打开补抓一次未齐条目**（自愈节奏）。
4. **触碰通道退役**：`豆瓣检查` 字段不再写入（ADR-0111 的触碰协议退役；今日已写入的存量字段休眠无害，不清理）。节流由会话内内存承担。
5. **新建流程归一**：`poster-watch.ts` 通知轮询退役（progress「正在获取海报和豆瓣信息…」/ 成功 / 5 分钟超时通知全撤）——新建落盘即入队，纯卡片 loading 反馈；quickAddWant（AI 荐片）同。
6. **卡片 loading**：海报区半透明遮罩 + 居中 spinner；pending/去重集合均为会话级内存态（入队登记，字段到齐或终态清除；插件卸载或 Obsidian 重启重置），面板重开不重置。
7. **守护进程退役**：`pm2 delete douban-poster` + `pm2 save`；全局 npm 包保留（手动 CLI 仍可用）；开机自启 bat 早已失效（指向已删路径），顺手核验。设置页「安装与运行指引」更新为直调前置说明（npm i -g 一次）。
8. **平台边界**：移动端无 child_process → 队列禁用、无 loading；移动端新建同步到 PC 后，打开面板触发补抓（与现状一致）。

## 取舍

- **直调 vs 守护**：直调消灭「守护僵死无报警」整类事故，loading 状态真实（spawn 退出即知），插件全权掌握生命周期；代价是 Obsidian 不开就不抓（守护可无头常驻）——用户接受：抓取本来就是交互场景。CLI 定位用 `npm root -g` 解析全局包路径，找不到则队列禁用 + 一次性提示。
- **失败聚合 vs 全静默**：用户拍板失败才说话——进度是卡片的事，事故（守护没了/豆瓣搜不到）必须可感知。
- **字段彻底退役 vs 保留节流**：用户拍板彻底退役；代价是跨会话失败条目每次会话首轮多一轮重抓（≤17 条，串行后台，可接受），换来 frontmatter 契约回到 ADR-0111 之前。
