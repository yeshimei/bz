# ADR-0165 — 首页入口：持久化顺序里没有的域，插到声明序前驱之后

- 状态：已采纳（2026-09-17）
- 关联：issue 267（入口顺序与显隐 v3）、issue 368（游戏库建域）、issue 371（本次落位）

## 背景

首页入口顺序持久化在 `CONFIG/STORAGE/home.json`（v3：`desk` / `mob` 各一份 + 各自 hidden）。
渲染走 `home/shared.ts::applyOrder(order, domains)`：已列出的域按持久化先后排，
**未列出的域（此后新建的域）旧口径是一律排到已列出项之后**（`MISS = MAX_SAFE_INTEGER`）。

问题在游戏库建域时暴露：用户 `home.json` 是建域前落盘的 14 项，新域没有位次 →
磁贴显示在「设置」后面。用户 2026-09-17 点名「放到正确的位置，而不是最后」。
同类隐患对任何后续新增域都成立。

## 决策

`applyOrder` 对未列出的域改为：**插到它在 `DOMAINS` 声明序上紧邻的前驱之后**：

- 前驱缺失（新域声明在首位）→ 落最前；
- 多个新域按声明序逐个落位，紧邻的前驱允许是刚插入的新域（链式，结果确定）；
- 已列出域的先后**零改动**（用户自己排的次序仍完全生效，新域只是"补进"某个缝里）。

现场结果：`desk` 里书库在第 4 位 → 游戏库插到书库之后（影院 → 书库 → 游戏库 → 复习计划…），
末位仍是设置。

## 取舍

- **不改 `home.json` 数据**：不往用户文件里塞 id（等价效果，且下次用户拖动保存即固化）。
- **不用「按声明序整体重排」**：那会覆盖用户自己排过的顺序，等于把排序功能作废。
- **不用「新域统一置顶 / 置底」**：置底就是本次的 bug；置顶会把入口首页的门面挤掉。
- 声明序是开发者写 `DOMAINS` 时的意图（游戏库紧邻书库），用它当落位锚最贴近意图且可预测。

## 影响面

`applyOrder` 的三个消费方一并受益：首页渲染、`visibleDomains`（渲染 × 设置弹窗共用）、
`reorderTo`（拖拽落点归一化，首次拖动即落盘完整序列，含新域）。

守卫：`tests/home/domain-order.test.ts`（合成 domains 的插入/链式/无前驱/未知 id +
真实 `DOMAINS` × 真实 vault 顺序快照：游戏库在书库之后、设置仍末位、已列出域先后不变）。
