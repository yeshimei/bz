# ADR-0278 · 影院取豆瓣字段改走豆瓣自己的移动端接口；个人片单导入以 Cookie 定位账号

日期：2026-11-01 · 状态：已采纳（同日实现合入 master，issue 562）

## 背景

1. 影院取豆瓣字段的末端一直是 ApiZero（第三方 keyed 服务，ADR-0129 移植 / ADR-0178 三路检索链的字段段）。2026-10-31 实测：该服务转会员制，未登录按天限额、登录态也只有 20 次/日——而影院是「每部片过一次详情」，一次批量导入就是几百次，作为主通道已经不可持续。
2. 用户需求：把**自己豆瓣账号**的想看 / 在看 / 看过整份导进影院（实测 408 部看过、15 部想看、0 部在看），带星级映射（5 星 → 10 分制）与豆瓣标记日，且**不要落进影院「片单」**——它进的是影院全集。
3. 期间另一处静默故障暴露了同一根因：按 sid 直取依赖 ApiZero，未配 key 时 105 部全部失败，因为那条链路除了 ApiZero 没有第二个字段来源。

## 决策

1. **字段主通道换成豆瓣自己的移动端详情接口**：`m.douban.com/rexxar/api/v2/movie/{sid}`（无片则退 `tv/{sid}`，按返回里有没有 `title` 判成败）。免密钥、带登录 Cookie 即可，返回 122+ 键，含评分 / 导演 / 主演 / 类型 / 地区 / 片长 / 上映 / 海报（`pic.large`）。`queryDoubanByName` / `queryDoubanBySid` 一律它在前，ApiZero 退为**可选兜底**，且只剩一个独有用途：补「热门短评」。
2. **个人片单不引第三方服务**：三份名单直接打 `movie.douban.com/people/<uid>/{wish|do|collect}`，账号由设置里已有的豆瓣 Cookie 定位（`dbcl2` → uid）。没 Cookie 或 Cookie 里没有 `dbcl2` → 拦在抓取之前，提示里带「去设置」直达**设置面板 AI 页**「数据源凭据」组的豆瓣 Cookie 行并高亮两秒（凭据组在 AI 页，最初指向影院页，锚点行根本不存在）。
3. **抓完落本地缓存** `cinema-douban-mine.json`（`<数据目录>`，只存 `sid / name / stars / at / group`）。开层读缓存即时出清单，重抓只在用户点「重新导入」时发生（且只在缓存态出现这个钮）。缓存存的是**豆瓣原始清单**，不是影院条目——删了不影响已导入的影片。
4. **节奏**：批量建档 `IMPORT_GAP_MS = 4s/部`（实测约 0.5 req/s 稳定），被限流 `BLOCK_BACKOFF_MS = 45s` 后重试一次；后台抓取队列原 `FETCH_GAP_MS = 15s` 不动。开层暂停队列、关层恢复，避免两条链同时打豆瓣。
5. **建档语义**：按状态写 `想看 / 在看 / 已看`；已看写 `评分 = 星 × 2`（5 星制 → 10 分制）与豆瓣标记日（不是今天）。**不归入任何片单、不打「片单收纳」**——「我的影片」是影院全集，不是片单。
6. **整单动作两步确认**：侧栏片单行右键 / 移动端 chip 长按出「收录进影院 · 改名 · 移除」，收录与移除都先出确认框，确认框穿本域皮（`cn-skin` + `bz-cinema-flow-dialog`，与「删除影视」同一张纸）；收录不删东西，主钮不挂危险色。

## 后果

- 正面：字段来源不再受第三方额度摆布，未配密钥的库也能正常补字段与导入；一批 408 部不再消耗 ApiZero 调用；「重新导入」不再重复踩豆瓣限流。
- 代价：rexxar 是移动端私有接口，没有公开契约，豆瓣改版的风险由插件自己承担；`movie` / `tv` 两条只能按 `title` 是否存在来判类型。
- 未做（已知缺口）：批量导入的类型判定仍硬编码「电影」，没走 `type-decide` 的 jev → LLM → 静态三级链，剧集/纪录片导入会落成电影；后续接在完成队列上补。
- 动画与样式侧无新增 token：弹层沿用影院午夜场调色板，动效走域内既有 `--cn-m-*` 时长档。

## 补记（2026-11-01 用户试用后两处改口径）

1. **确认框不再走 core 流程框**：三处危险/二次确认（删除影视 / 移除片单 / 收录进影院）改为本域 `confirmCinema()`——`ovl` + `.cn-modal--confirm`，挂面板树内所以域样式直接生效。决策 6 里「确认框穿本域皮」原先是给 core 流程框套 `cn-skin bz-cinema-flow-dialog`，而流程框挂 `document.body`、影院样式全在 `.bz-cinema--midnight` 作用域下，只能靠 id 选择器映射颜色，形制套不进来；这条改为「确认框就用本域弹层」。
2. **移除片单只删导入条目**：原实现把片单内所有成员一起移入回收站。改口径后按来路分流——带「片单收纳」（只在这个片单里可见）的导入条目移入回收站；同时也在影院主体里的影片保留，只摘掉该片单归属。理由：整单移除不该连带删掉用户自己收藏进主列表的条目。
