# ADR-0209 · RSSHub 路由型源收录（源库 via 通道，全参数化）

日期：2026-09-27 · 状态：已采纳（同日二轮拍板修订）· 关联：ADR-0208（黄页模型，`via` 预留方）、issue 495/497

## 背景

issue 495 建立源库黄页模型时预留 `via` 字段给 RSSHub 路由型源。本期立项落地。调研实测：

- **数据源存在且理想**：RSSHub-Docs 仓库的 `src/public/routes.json`（约 8.5MB，随主仓每日重建）
  是机器可读全量路由清单——2020 命名空间 / 3862 路由，带命名空间中文名、heat 热度、
  example（参数填好的示例路径）、官方 categories、features 标记
  （requireConfig / requirePuppeteer / antiCrawler）。
- **公共实例现实骨感**：官方 rsshub.app 国内直连超时；公共实例 rssforever 国内可达且功能正常，
  但国内平台路由（微博/B站/知乎/抖音/小红书）全部 503——上游反爬封公共实例出口 IP；
  各实例路由覆盖不一致（同一路由 404/502/200 并存）。

## 修订（2026-09-27 二轮拍板：全参数化）

初版把「带参数路由 + example 已填」的 2647 条按示例地址直订收进黄页。复核发现**产品语义缺陷**：
example 是上游文档的演示值（如 `/bilibili/user/video/2267573` 指向文档作者举例的某位 UP 主），
用户在源库点「订阅」以为订到「UP 主动态」这个能力，实际订到的是一个陌生人的投稿——
RSSHub 的本质是「路由 + 参数」的能力，示例标本不该当源卖。用户拍板**全参数化**：

1. **收录**：三免全收不变，且不再依赖 example（无 example、example 含 `:参数` 占位照收）——
   实测路由 3305 条 = 无参数（开箱直订）1110 + 带参数（走表单）2195。
2. **条目形状升级**：`via` 语义从「示例路径」改为**完整路由模板**（含 ns 前缀与 `:参数` 段，
   如 `/bilibili/user/video/:uid/:embed?`——注意 routes.json 的键才是完整路由，`path` 字段是
   省略 ns 的子路径，拿它拼 url 会跨命名空间撞车，出版实测去重 1052 的教训）；
   新增表单素材三件套：`viaExample`（示例路径，表单预填）、`params`（参数名 → 中文说明）、
   `desc`（描述截断 200 字）；条目按路由级 `heat` 降序（黄页浏览序 = 热度粗排）。
3. **订阅口径**：无参数路由照旧一键直订（按实例重拼）；带参数路由**一律走参数表单**——
   按 `parseRouteTemplate` 渲染参数输入框（`params` 说明作 placeholder、`viaExample` 反解预填、
   可选段 `?` 标注），`buildRouteUrl` 实时预览（按段 encode、保留通配段内 `/`、可选空剥段、
   必选空拦下），试拉成功才入库（失败可「仍要订阅」——公共实例上游挂不代表参数错）。
   订阅=拷贝表单拼出的 URL，黄页口径不变。
4. **已订阅匹配**：只对无参数路由做（带参数条目的订阅地址用户参数各异，没有单一「已订阅态」，
   行内恒可再订；数据层按 URL 去重天然防重）。
5. **添加框路由识别**：`/` 开头的输入在源库 `via` 里匹配模板，命中即开表单；未收录提示
   （不收源库外裸路由，粘贴完整 URL 的能力本来就有）。
6. **脏示例清洗**：上游 example 偶见未编码空格/查询串（linkedin/google 新闻实测），
   `viaExample` 形状不过 `/^\/\S*$/` 不入库——校验器形状门保持严格。

## 决策（初版要点，修订后仍然成立的部分）

### 1. 数据源与快照蒸馏（上游第二家）

上游登记 RSSHub-Docs `routes.json`。快照**蒸馏后入库**：全量命名空间/路由只保留
必要字段（ns 名称/站点/heat + 路由模板/name/example/categories/features/parameters/
heat/description 截断，修订后扩），8.5MB → 约 1.6MB，保持「出版只吃快照、可离线复现、
可 diff 审查」的 495 口径；「三免」筛选放 lib.mjs 纯函数，口径可随出版报告迭代。

### 2. 收录口径：三免全收（用户拍板；全参数化修订后不再依赖 example）

免 requireConfig / 免 requirePuppeteer / 免 antiCrawler 的条目全收。初版曾剔除
「example 含 `:参数` 占位」的条目（参数没填的地址不能直接订阅），全参数化修订后
该剔除废止——带参数路由走参数表单，example 只是预填素材。不做热度精选。

### 3. url/via 双字段，校验器零改动（修订后：via 存完整模板）

- 路由条目 `url` = 出版期用**默认实例**拼好的完整合法地址（带参数条目是含 `:参数` 的
  形状地址，只为校验与全表唯一性；可用地址由表单产出）；
- `via` = 完整路由模板（修订）；修订前存的是示例路径；
- 校验只加形状门（`/` 开头、无空白；`viaExample` 同门、`params` 键值约束），
  url 的 http(s) 校验与全表唯一性、「已订阅匹配」的黄页口径**全部不变**；
- 订阅动作：无参数走 `resolveCatalogFeedUrl(feed, instance)` 重拼；带参数走
  `buildRouteUrl(instance, via, values)`（表单产出）。

### 4. 不测活，features 筛选代替（对 495 测活口径的显式豁窄）

495 的「出版期测活、剔确定性死亡」只适用于**直连源**（可用性一维）。路由型源可用性
= 实例 × 上游 × 路由 三维：测活结果时效极短、实例是用户可配项（测了不代表用户手里能用）、
公共实例对并发测活限流。故路由型条目**不进测活管线**，以 features 标记筛掉
结构性不可用（要配置/要无头浏览器/自认易反爬），死亡由徽标与文案管理预期。

### 5. 实例地址：news.json 新段 `rsshubInstance`，默认 rssforever（用户拍板）

- 默认 `https://rsshub.rssforever.com`（实测国内可达的社区公共实例）；
- 键放 news.json（与 rssFeeds 同文件同段级合并机制，RSS 配置一处安家），
  容错解析（非 http(s)/空白 → 回退默认）；
- **订阅=拷贝当时 URL**（用户拍板）：订阅那一刻按当时实例拼完整地址存 rssFeeds，
  改实例不影响已订阅——黄页纯度不变，news-fetcher 零改动；要换实例删了重订。

### 6. 固定大类扩 3 类：新闻资讯 / 校园学术 / 财经（总 15）

495 的 12 大类按独立博客画像设计，装不下 RSSHub 路由的三大块（new-media 488 /
university 487 / finance 153）。扩 3 类后 RSSHub 官方 25 分类全部**直接映射**
（不走关键词映射，官方分类比自由打标可靠），`other` → 综合；timqian 既有归类不变，
chips 顺序调整（新闻资讯列首位）。

### 7. UI：徽标 + 搜索纳 via + 参数表单（修订扩）

源库列表路由条目加「RSSHub」小徽标（区分来源形态、管理死亡预期）；搜索命中面纳入
via 路径段；无参数条目已订阅态按重拼后的最终 URL 匹配；带参数条目行内「填参数订阅」
开参数表单（修订第 3 条）。

## 后果

- `rss-catalog.json` 约 2MB（直连 1151 + 路由 3305，含表单素材三件套），下载资产与
  内存缓存量级可接受；
- 路由条目在公共实例上死亡率高——徽标 + 实例可配 + 自建引导是预期管理手段，
  不做出版期测活是**显式决策**而非疏漏；
- `via` 通道为「其他路由生成器」（如自建实例的定制路由）留了通用形态：
  url 恒为默认实例拼好的合法地址，via 恒为模板素材；
- 带参数条目没有单一「已订阅态」，同一能力可多次订阅不同参数值（数据层按 URL 去重防重）；
- 将来如做「已订阅跟随实例」，须动 rssFeeds 数据模型与 fetch 链路，另立 ADR。
