# ADR-0209 · RSSHub 路由型源收录（源库 via 通道）

日期：2026-09-27 · 状态：已采纳 · 关联：ADR-0208（黄页模型，`via` 预留方）、issue 495/497

## 背景

issue 495 建立源库黄页模型时预留 `via` 字段给 RSSHub 路由型源。本期立项落地。调研实测：

- **数据源存在且理想**：RSSHub-Docs 仓库的 `src/public/routes.json`（约 8.5MB，随主仓每日重建）
  是机器可读全量路由清单——2020 命名空间 / 3862 路由，带命名空间中文名、heat 热度、
  example（参数填好的示例路径）、官方 categories、features 标记
  （requireConfig / requirePuppeteer / antiCrawler）。
- **公共实例现实骨感**：官方 rsshub.app 国内直连超时；公共实例 rssforever 国内可达且功能正常，
  但国内平台路由（微博/B站/知乎/抖音/小红书）全部 503——上游反爬封公共实例出口 IP；
  各实例路由覆盖不一致（同一路由 404/502/200 并存）。

## 决策

### 1. 数据源与快照蒸馏（上游第二家）

上游登记 RSSHub-Docs `routes.json`。快照**蒸馏后入库**：全量命名空间/路由只保留
必要字段（ns 名称/站点/heat + 路由 path/name/example/categories/features），
8.5MB → 约 1MB，保持「出版只吃快照、可离线复现、可 diff 审查」的 495 口径；
「三免 + example 无参数占位」的筛选放 lib.mjs 纯函数，口径可随出版报告迭代。

### 2. 收录口径：三免全收（用户拍板）

带 example 且免 requireConfig / 免 requirePuppeteer / 免 antiCrawler 的条目全收
（实测 3304 条，example 含 `:参数` 占位的剔除——参数没填的地址不能直接订阅）。
不做热度精选。

### 3. url/via 双字段，校验器零改动

- 路由条目 `url` = 出版期用**默认实例**拼好的完整合法地址；
- `via` = 路由路径（如 `/bilibili/platform/-1`）；
- 校验只加 via 形状门（以 `/` 开头、无空白），url 的 http(s) 校验与全表唯一性、
  「已订阅匹配」的黄页口径**全部不变**；
- 订阅动作：`resolveCatalogFeedUrl(feed, instance)`——有 via 按当前实例设置重拼，
  无 via 原样。

### 4. 不测活，features 筛选代替（对 495 测活口径的显式豁窄）

495 的「出版期测活、剔确定性死亡」只适用于**直连源**（可用性一维）。路由型源可用性
= 实例 × 上游 × 路由 三维：测活结果时效极短、实例是用户可配项（测了不代表用户手里能用）、
公共实例对并发测活限流。故路由型条目**不进测活管线**，以 features 标记筛掉
结构性不可用（要配置/要无头浏览器/自认易反爬），死亡由徽标与文案管理预期。

### 5. 实例地址：news.json 新段 `rsshubInstance`，默认 rssforever（用户拍板）

- 默认 `https://rsshub.rssforever.com`（实测国内可达的社区公共实例）；
- 键放 news.json（与 rssFeeds 同文件同段级合并机制，RSS 配置一处安家），
  容错解析（非 http(s)/空白 → 回退默认）；
- **订阅=拷贝当时 URL**（用户拍板）：订阅那一刻按当时实例拼完整地址存 rssFeeds，
  改实例不影响已订阅——黄页纯度不变，news-fetcher 零改动；要换实例删了重订。

### 6. 固定大类扩 3 类：新闻资讯 / 校园学术 / 财经（总 15）

495 的 12 大类按独立博客画像设计，装不下 RSSHub 路由的三大块（new-media 488 /
university 487 / finance 153）。扩 3 类后 RSSHub 官方 25 分类全部**直接映射**
（不走关键词映射，官方分类比自由打标可靠），`other` → 综合；timqian 既有归类不变，
chips 顺序调整（新闻资讯列首位）。

### 7. UI：徽标 + 搜索纳 via

源库列表路由条目加「RSSHub」小徽标（区分来源形态、管理死亡预期）；搜索命中面纳入
via 路径段；订阅成功/已订阅态匹配逻辑不变（按重拼后的最终 URL）。

## 后果

- `rss-catalog.json` 体积约翻倍（+3300 条 × ~300B），下载资产与内存缓存量级可接受；
- 路由条目在公共实例上死亡率高——徽标 + 实例可配 + 自建引导是预期管理手段，
  不做出版期测活是**显式决策**而非疏漏；
- `via` 通道为「其他路由生成器」（如自建实例的定制路由）留了通用形态：
  url 恒为默认实例拼好的合法地址，via 恒为路径素材；
- 将来如做「已订阅跟随实例」，须动 rssFeeds 数据模型与 fetch 链路，另立 ADR。
