# bz 界面两条基线：MarkdownRenderer 追加语义 + 界面级隐藏滚动条

日期：2026-09-11 ｜ 关联：ADR-0080（隐藏滚动条首拍）、ADR-0112（知识盒建域）、ADR-0116（术语来源 URL 净化）、issue 275–278

背景：issue 275 的「文献预览正文重复两遍」暴露了一条**跨域渲染契约的缺失**——Obsidian `MarkdownRenderer.render` 是追加语义（类型定义写明 "The element to append to"），而测试共用 mock 与原型 fake 层都实现成覆盖语义，导致「预填兜底 + 追加渲染」这类双份缺陷在两侧都看不见。同批 issue 277 暴露另一条：手册早已拍板「全站隐藏滚动条」，实现却是 12 个域各写一份、30+ 条规则，还留着可见细条（`scrollbar-width: thin`）与自绘 6px thumb，新域（知识盒自有面板壳）则完全漏网。两条都不是单点 bug，而是基线级口径问题，故立 ADR。

## 拍板要点

1. **MarkdownRenderer 追加语义契约（实现侧义务）**：任何 `MarkdownRenderer.render` 调用前，目标容器必须为空——要么渲染进**新建空容器**（clipbook `ui.ts:799`、encrypt `ui.ts:2285`、secondbrain `ui-tools.ts:45` 范式），要么渲染前**显式清空**（diary `ui.ts:827/834` 范式）；不得把「纯文本预填」留在同一容器里当兜底。兜底改为事后判定：渲染抛错或渲染后无产出元素时才写入纯文本段落（知识盒 issue 275 修法）。空正文的「（无正文）」空态属于必须显式保留的分支。
2. **测试与原型层必须复刻宿主语义**：共用 mock（`tests/mock-obsidian-entry.ts`）与原型 fake 层（`prototypes/<域>/fake/fake-obsidian.ts`）的 `MarkdownRenderer.render` 一律实现为**追加**，与真机一致。凡「假层语义与宿主不一致且恰好掩盖缺陷」的，视同缺陷（本条为通用判据，不限于渲染器）。**先例已存在**：同日 `setIcon` mock 因「宽容 mock 让 `undefined` 图标名的真机崩溃全绿通关」（真 Obsidian `getIcon` 首行 `name.startsWith('lucide-')`，名字为 undefined 即抛异常）改成严格档——本票按同一条判据处理 `MarkdownRenderer.render`；后续凡照宿主 API 写的替身，先查官方类型定义的行为描述再写。
3. **界面级隐藏滚动条（作用域 = bz 自有界面全量）**：在 core 一条通杀规则里解决，选择器按「bz- 前缀类/ID + 面板壳整树 + 非 bz 前缀的遗留弹层」枚举；**刻意不用 `*` 通配**——Obsidian 核心 UI（文件树/编辑器/核心设置）不属 bz，不被波及。各域不再自建滚动条样式；已存在的可见条写法（`scrollbar-width: thin`、`::-webkit-scrollbar-thumb` 自绘）视为违规并删除。**滚动功能一律保留**：只隐藏条，不动 `overflow`。
4. **域归属口径（命名纠偏）**：「文献预览」「文献笔记」「视频录入」属**知识盒（knowledge）域**；第二大脑（secondbrain）域是向量检索 / AI 对话 / 自动双链，三者均不在其中。用户口语中的「第二大脑」在本次需求里实际指知识盒，任务分派与文档措辞据此纠正。
5. **视频录入元信息回填口径**（issue 278）：URL 净化单源 = `normalizeSourceUrl`（`src/knowledge/source.ts`），数据层与保存路径同源收口，不另造第二份实现；B 站 view API → 页面标题兜底 → 静默三级降级；**回填只补空字段**，且 `[bz-info]` 的下载期合并与之同口径（标题同样只补空）。

## Considered Options

- **预览修法**：① 渲染前清空 + 事后判产出（选）——与 diary/encrypt/clipbook 既有范式一致；② 删掉纯文本兜底——渲染异常时用户看不到正文；③ 双容器（渲染容器 + 独立兜底容器）——结构最清晰但改动面大于收益。
- **mock 语义**：① 改追加语义 + 加回归断言（选）——根治「假层掩盖真机行为」；② 保持覆盖语义只加空容器断言——下次同类缺陷仍然测不出。
- **滚动条落地**：① bz 前缀通杀 + 清理违规点（选）——一处生效、新 UI 自动覆盖、不碰宿主；② 真·全局 `*`——连 Obsidian 本体一起隐藏，插件越界改宿主；③ 只修知识盒——违反手册既有口径，其余域继续露条；④ 逐域逐容器补——30+ 条规则继续蔓延。
- **回填覆盖策略**：① 只补空（选）——异步回包不会盖掉手填内容；② 抓到即覆盖——手改被冲掉；③ 区分「手改」与「未动」（记回填基线）——交互最精细，但为一次性回填引入状态机，收益不足。
- **回填触发**：① 输入防抖自动（选）——覆盖粘贴与手输两条路径，零额外点击；② 加「解析」按钮——多一步操作；③ 仅粘贴触发——手输 BV 号不覆盖。
- **URL 净化接入点**：① 输入防抖写回 + 保存兜底 + 数据层收口 + 既有 `normalizeSourceUrl` 单源（选）；② 只在保存时净化——用户看不到净化结果，一个 URL 两处写法易混。

## Consequences

- 知识盒预览、卡片预览、主题预览三类弹层共用 `openPreview`，语义修正后**三面同时**只出一份正文；其余四域 render 调用点已符合契约，无需改动但纳入同一判据。
- 测试 mock 改追加语义后，凡「同容器二次渲染」的写法会在测试中**双份可见**——这是一次性的回归收益，后续同类缺陷前置暴露。原型侧 fake 渲染器同步后，评审壳可复现真机双份。
- 全站隐藏滚动条规则收敛为 core 一条：新增域/新弹层只要带 `bz-` 前缀即自动生效，域内滚动条样式成为代码审查的违规项；副作用是「滚动条被隐藏」也意味着**无视觉滚动提示**——手册已拍板保留滚动功能、用户接受（ADR-0080 延续）；宿主界面（文件树/编辑器）不受影响，与「插件不改宿主」原则一致。
- 文献标题与剪藏标题的生成契约为**完整陈述句**（issue 276）：prompt 措辞为唯一约束点，存量笔记不迁移；后续若仍出现疑问句式标题，属 prompt 层可调而非代码缺口。
- 视频录入回填为用户可见的**新增网络行为**（B 站 view API + 页面标题兜底），全链路静默失败；`b23.tv` 短链拿不到 UP主（响应无重定向目标可读），由下载期 `[bz-info]`「只补空」兜底补齐。抓取范围仅限用户正在录入的单个链接，无批量轮询，不引入守护进程。
- 手册与词表同步：`docs/ui-design-manual.md` 滚动条节改指界面级单源规则；CONTEXT.md 新增「文献预览」「录入元信息」词条并补文献笔记 title 契约；实现与验收细节见 `issues/275`–`issues/278`。
