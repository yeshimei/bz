# ADR-0152 知识盒录入草稿的流式成形：单次 JSON 调用 + 无状态前缀抽取

- 状态：已接受（2026-09-16，全部待定项已拍板，实现已合并部署）。交互契约（范围 / 即时界面形态 /
  中断收场 / 降级 / 中止时机 / 观感）与正文来源均经用户逐项确认；正文来源在探针验证后由
  「拆两次调用」改回「单次 JSON + 前缀抽取」，否决理由见「否决的替代方案」。
  **同日晚间追加决策 12-15**（生成入口 / 总结退役 / 属性行次序 / 属性区 loading 统一）
- 关联：issue 343 / ticket 141（`onDelta` 流式基建）/ ADR-0148（max_tokens 面板独裁）/
  issue 309（关联预演）/ issue 326（关闭二次确认）/ ADR-0145（图版描述）
- 影响：`src/knowledge/ui.ts`、`src/knowledge/note-gen.ts`、`tests/knowledge/*`、`CONTEXT.md`；
  `src/core/ai.ts` **只消费不改**（流式基建已齐，见背景 §3）

## 背景

### 用户诉求
点「生成」之后**界面立刻在位**，正文**依次动态长出来**，而不是盯着一个「生成中…」的按钮等整段返回。

### 现状
预览区 `#lit-term-preview` 默认 `display:none`，AI 整段返回后才在 `presentTermPreview`
（`ui.ts:3147-3171`）里一次性把属性行 + 正文填满；等待期唯一的信号是生成按钮文案变「生成中…」
（`setTermGenLoading`，`ui.ts:2867`）。属性区里只有「关联」行有自己的 loading（`ui.ts:2883`）。

### 三条已核实的事实（决定了方案形状）

1. **传输层已经是流式，缺的只是「接上回调」**。`prompt()` 无条件把 `stream: true` 写进请求体
   （`core/ai.ts:732`），`ai.json()` 只是多带 `response_format`，走的是同一个 `prompt()`；SSE 解析
   （`core/ai.ts:480-561`）带 `onDelta` 增量回调 + `signal` 中止。但**全插件只有第二大脑聊天面板在用**
   （`chat-panel.ts:257`，先建空气泡再逐字灌）。也就是说：名词生成今天已经在收 SSE，只是把增量全丢了。

2. **拦路石是 JSON 模式，不是传输层**。三态草稿都走 `ai.json()` → `response_format: {type:'json_object'}`
   （`note-gen.ts:199/290/392`），流出来的 delta 拼起来是**一段未闭合的 JSON 文本前缀**
   （`{"summary":"从…`），不是能直接往正文区写的散文。

3. **首字延迟由思考期主导，不由 JSON 壳主导**。默认模型 `deepseek-v4-flash` 是思考模型，且
   `enable_thinking:false` 对它无效（2026-09-16 实测）。正文开始吐字之前要等思考跑完，
   流式缩短不了这一段——它只保证「界面立刻在位」。

## 决策

1. **单次 JSON 调用不变**：`ai.json()` 与三态 prompt 一字不改（零契约变化、零迁移）。正文来源 =
   从**同一次调用的流**里抽。
2. **新增无状态前缀抽取器** `partialStringField(prefix, key)`：定位 `"<key>"` → `:` → 开引号 → 顺扫取值；
   遇到未闭合的转义（结尾一个孤 `\`，或不足 4 位的 `\uXXX`）**当帧丢弃、下帧重算**。
   **每次拿完整累积前缀重算，不维护任何增量状态**——转义被切段自动自愈，没有状态机、没有漂移。
3. **流式只作用于渲染**：`onDelta` 把累积文本喂抽取器 → 逐字写进 `#lit-term-content`。草稿对象、
   落盘路径、收尾解析全部不变（收尾仍走现成的 `parseAiJson`）。
4. **立即开界面**：点下即 `setTermPreviewVisible(true)`；属性行给出名词/日期，领域行「分析中…」，
   正文区在第一个正文字符前显示「正在生成…」。再次点「生成」立刻清空正文回到「正在生成…」
   （沿用「新草稿作废旧状态」语义，避免用户把旧正文误当新一轮结果）。
5. **非流式降级不改变界面契约**：fetch 失败 → `chatCompletionsNonStream`、`noCors` provider
   （如 opencode-go）直连 requestUrl——这两条路没有 `onDelta` 可喂。行为 = 预览区照旧立即展开，
   正文区一直挂「正在生成…」到整段回来一次性填入。用户无需知道走的是哪条路。
6. **中断即可见但不可写**：流断在半个 JSON 上 → 保留已流入文字 + 报「生成中断」，草稿标记为
   **不完整**、`确认写入` 保持禁用，必须重新生成成功才放行。**顺带收掉一个既有口子**：
   `generateTermDraft` 原本对空 summary 无守卫（`note-gen.ts:200-204`），而 `onTermConfirm` 只从内存
   `termPreview` 取值——「半篇」原本是能被写进文献盒的。
7. **中止时机**：再次点「生成」= abort 在途请求并重开；关窗 / 点遮罩走 `requestTermClose`
   （`ui.ts:3286`）的二次确认，**用户在确认弹窗里确认之后才 abort**（取消关闭 ⇒ 请求继续跑下去）。
8. **观感**：不加打字光标、流式期间不自动跟随滚动（仅预览区首次展开时 `scrollIntoView` 一次）。
9. **AI 产出的属性行一律只读（推翻 issue 309 的「属性行可改标题」）**：段落 / 图版的标题行由可编辑
   `input` 改为只读展示行，与名词 / 领域 / 日期行同构。规则统一为**「用户输入可编辑、AI 产出只读」**
   ——用户自己填的（名词、段落文本、来源）照旧可改，AI 产出的（标题、领域、正文）不再给编辑出口。
   好处：标题覆盖冲突从根上不存在，也省掉一条「用户正在输入 vs AI 回填」的竞态。
   代价：AI 标题不合适时只能重新生成。连带：`onTermConfirm` 的标题取值从 input 改读草稿
   （空标题守卫 `ui.ts:3184` 保留）。
10. **录入 prompt 的字段顺序调成 `{"domain":…,"summary":…}`**（名词 / 段落 / 图版三态）：领域是短字段、
    正文是长字段，让领域先落地——属性区的领域行早早出值，正文随后逐字长出，与「界面立刻在位、
    内容依次到位」一致。抽取器对字段顺序不敏感（探针已验证颠倒顺序仍正确）。
11. **title 也走同一抽取器、到达即填**（段落 / 图版）：只读属性行与领域行同构，值一到就填，
    不再等收尾一次性回填。

### 同日界面修订（2026-09-16 晚间，用户提出，实现已落地）

12. **生成入口按状态只出一条**：「生成」与底部按钮**不再并存**——预览收起时入口是输入行下方的
    「生成」；预览一展开（`setTermPreviewVisible(true)`）该行隐藏，入口移交底部「重新生成」，
    紧邻确认写入并排在其之前（底部 = `[重新生成] [确认写入]`）。两键在生成流在途时都可点
    （重新生成 = 中止重开，决策 7）；**中断草稿下「重新生成」保持可点**——它是从「中断」回到
    可写状态的那唯一一条路，锁的只有确认写入。
13. **「总结」入口退役**：底部「总结」按钮及其 UI 侧处理（`onTermSummarize` / `setTermSummarizing` /
    `termSummarizing`）一并删除，槽位让给「重新生成」。数据层的 `summarizeTermSummary`
    （`note-gen.ts`，`ai.chat` 精简 + 空值守卫）**保留**：它是可复用的纯函数且带单测，
    本次只摘 UI 出口。若要连数据层一起删，另开 issue。
14. **属性行次序定为**：名词/标题 → 领域 → 来源 → 关联 → **日期（沉到属性卡最末行）**。
15. **属性区的「分析中…」与关联行共用同一套信号**：领域 / 标题行的占位改用与关联行 loading
    相同的滑动墨条（`bz-lit-rel-bar`）+ 同一句文案——属性区里凡「AI 正在算」的行都长这样，
    不再有的是静态灰字、有的是滑条。

## 否决的替代方案

### 拆两次调用（正文走纯文本流式 + 领域另发一次 JSON）
曾是首选方案，用户一度采纳，**经探针与延迟分析后否决**：

- 它唯一的收益是「首个可见字符提前几个 token」——但两种方案的**空窗期都由思考期主导**，
  JSON 那点壳（`{"summary":"`，约 3-5 个 token）在延迟上可忽略，收益近乎为零。
- 代价却是**思考开销翻倍**：思考模型每个请求都要各自思考一遍，而 `enable_thinking:false` 对它无效。
- 附带丢掉两个东西：JSON 模式对输出格式的**天然约束**（纯文本下 AI 加一行 `## 标题` 会直接
  同时出现在预览和笔记正文里），以及下面「后果」里那条截断检出能力。

### 放弃 JSON、改用约定分隔符的纯文本流
同上去掉格式约束；且要新造一套输出协议，收益不足以抵偿。

## 后果

- **截断从静默变可检出（保留 JSON 模式的实质收益）**：`core/ai` 两条请求路径都不看
  `finish_reason`，撞 `max_tokens` 是**静默截断**。JSON 模式下被截断的正文会让收尾 `parseAiJson`
  抛错（`note-gen.ts:50-56`）→ 走现有报错路径；若正文改纯文本，一段被截短的简介看起来完全合法，
  会静默落盘。这条与决策 6 的「不可写」正好咬合。
- **抽取器必须与 `parseAiJson` 同源验收**：测试要钉住「抽取终值 == `JSON.parse` 终值」，
  否则会出现「预览看到 A、落盘写入 B」的静默不一致。
- **属性行取值时机由 JSON 字段顺序决定**：`{"summary":…,"domain":…}` 时领域值最后才到，
  领域行整段生成期挂「分析中…」。想让它早出值只能调 prompt 里的字段顺序（不改契约）。
- 三态共用预览出口，**一处生效三态同时生效**；段落/图版多一个 title 字段可走同一抽取器。
- 视频转写链路（元数据 JSON + 分块润色）**不在本次范围**。

## 修订：决策 16-19（2026-09-16 晚，issue 344）

用户在「知识盒合理性评审」后拍板把「生成 → 落盘」这一步从**签收**改成**编目**——
录入面板是全流程里唯一一次用户能用自己的脑子过一遍的机会，而此前标题与领域都是只读的。

| # | 决策点 | 结论 |
|---|---|---|
| 16 | 标题可编辑 | **推翻决策 9 的「AI 产出一律只读」**：标题行可编辑；点「重新生成」= 清空用户覆盖层（**覆盖**语义，用户明确拍板）。**正文仍只读**（那是 AI 的产出，改它等于重写）。名词行同样可就地改（提交写回顶部输入框）。 |
| 17 | 领域可编辑 + 候选 | 领域行可编辑并给联想候选 = **已用过的领域 ∪ 设置词表**，去重后按使用频次降序、词表独有的排后。以「已用过」为主来源，是因为词表可能为空（本机现状就是空的）。 |
| 18 | 关联可点掉 | 关联候选改 chip，每条可点掉、**本轮不可恢复**（用户拍板不给恢复入口）；点「重新生成」会重算，被点掉的可能再出现。 |
| 19 | 属性行编辑形态 | **点一下才变**（用户拍板）：静态与只读展示逐像素一致（画出的 padding 用负 margin 抵消，不跳布局），hover 才浮出极轻提示，点一下就地换输入框；回车 / 失焦提交，ESC 放弃并恢复原值。 |

同批落地的三条补充口径：

- **关联行只在正式开跑后出现**：`idle` 态整行隐藏。此前草稿到达前挂着「待写入 → —」，
  可那一刻关联根本没开始跑，展示一行静止的假状态只会误导（用户要求）。
- **同轮流式不覆盖用户改过的字段**（`userEdited` 集合）——用户刚打完的标题不该被下一帧 delta 冲掉；
  「覆盖」只发生在点「重新生成」时（新一轮清空覆盖层）。
- **属性行输入框的 Enter / ESC 必须 `stopPropagation`**：否则冒泡到 document 会撞上「ESC 关面板」
  的分层处理器——用户按 ESC 想放弃编辑，实际弹出的是关闭确认框。
