# 0017 黑匣子改为日记智能分析层（容器 → 派生层，ADR-0013/0015 作废）

黑匣子（bz 第 19 域）经 v1（感触录入）→ v2（三类条目）→ v3（笔记化 `我的/黑匣子/*.md`）演进后，用户（叫我包仔）在 grilling 会话（2026-08）判定方向错误：**黑匣子长成了第二个容器**——有自己的录入弹窗、概念/摘抄/想法条目与笔记目录，与日记本「书写」体系平行重复；用户真正书写的载体是日记本，黑匣子却要求额外录入，负担重且内容割裂。

**决策：黑匣子不再做容器**。数据仍由日记本书写（`我的/日记` + `我的/影视` + `我的/信` 三目录，唯一事实源），黑匣子只读日记、AI 提炼、产出派生层（`CONFIG/STORAGE/blackbox.json` v4：profiles/mentions/events/reviews/chat/cursor/settings）。删除录入弹窗与 `bz-blackbox-capture` ×4 命令、三类条目、`我的/黑匣子/` 笔记目录（存量已删，1492 文件）；保留并改造对话（三层记忆 = 日记 TF-IDF 检索 + 画像概要 + 对话历史）、画像（从日记提炼，provenance 分层：印象区用户主权字段级锁 + AI 观察区可采纳，出现 ≥2 次跨日期自动建）、事件时间线（从日记提炼，两级置信度 ≥0.7 入线 / 0.5–0.7 推测 / <0.5 不入库，证据链 `{path,lineNumber,time}` 行号跳转）、复盘（纯手动，JSON 落盘 `reviews[]` 四段事实锚定）、情绪（24 词表 AI 推断 1–3 词，失败不标注）。增量链路：vault modify/create 监听（防抖 30 分钟）+ 打开黑匣子即时提炼双触发，一次 AI 调用批量处理新增条目（{people, events, emotions}），首次启用历史全量分批 50 条/批串行。

**Considered Options**：① 保持容器（v3 笔记化）——已被用户否决，两套书写体系割裂；② 元层聚合（黑匣子直接读全部 vault）——ADR-0014 曾否，本次收敛为「只读日记流」而非全部 vault，保持职责清晰；③ 日记分析层（选定）——日记是唯一事实源，黑匣子零录入零持有。

**Consequences**：
- ADR-0013（三类条目 schema）、ADR-0015（笔记化落盘）**作废**；ADR-0014（平行新流）**方向反转**——日记从「次级内容未来接入」变为「唯一事实源」，备忘录/剪藏等仍为未来演化路径。
- 黑匣子是第一个「读他域数据」的域：日记读取复用 `src/diary/parser.ts` 纯函数与 `src/diary/config.ts` 目录常量（显式 import，铁律 6），不重造扫描轮子。
- v4 schema 自落盘起冻结（铁律 1）；v3 存量数据已删除，无迁移链。
- 用户手动修改画像/事件标记 `humanEdited` 后 AI 重提炼跳过（改过不再碰）；4218 处 `[[我的/黑匣子/…]]` 断链不清理（仅显示断链不影响功能）。
- 黑匣子从「积累输入」变为「分析输出」：AI 成本由增量提炼（写日记后）+ 手动复盘（用户触发）构成，无自动定时消耗。
