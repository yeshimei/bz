# ADR-0234 · 自动关联：建链显式跳过重排、确认写入接住在途轮

日期：2026-10-03 · 状态：已采纳 · 关联：ADR-0186（重排接线）、ADR-0189（重排双通道）、
ADR-0141（自动关联三盒）、ADR-0185（单一余弦尺）、issue 327（预演中断）、issue 541

## 背景

用户报「创建文献笔记时自动关联每次都特别慢」。拆链路实测，慢的不是裁判（Jev 一次请求 1–2s），
而是两处**没人消费的计算**：

1. **建链白跑一轮重排**。`applyRerank` 靠 `hits.length > RERANK_MAX_DOCS(50)` 判别"后台长列表"
   并跳过重排，而建链候选池是 `max(TopK×3, 24)` —— 只有 TopK ≥ 17 才够得到 51，TopK ≤ 16 时
   池 ≤ 48，判别失效。于是每篇白跑一轮重排（走当前生效通道：本地 4B 交叉编码，或 Jev noul 批问；
   两通道共用 `RERANK_BUDGET_MS = 6000` 的整轮预算）。而重排的产出（顺序 +
   `hit.rerankScore`）在链路里没有任何消费方：成员集在重排**之前**已按余弦锁定
   （`vectorSearch` 先去重截断、后调 `applyRerank`），下游 `findCandidates` 只读 `hit.score` 做
   过滤 / 排序 / 截断，`rerankScore` 全仓唯一读取点是显示层的 `hitPercent`。

   本地通道更糟一层：4B 冷启动载入实测 4.7s，加 45 对（热态 2.0s）＝ 6.7s，**撞穿 6s 预算即抛错
   回落余弦序**——那 6 秒白付，连重排结果都没拿到（issue 541「实测」节）。

2. **一次确认付两遍**。分析中点「确认写入」＝ abort 在途预演 + 从零重跑一整轮。abort 是假的：
   判定通道走 `requestUrl`，该 API 无中止能力（`core/jev.ts` 模块头已记），**已发生的算力与 token
   收不回来**，abort 只是丢弃结果。

## 决策

### 1. 重排的跳过判别权移交调用方（`vectorSearch(query, topK, baseUrl, signal, opts?.skipRerank)`）

"我需不需要重排"只有调用方知道——重排是**换序层**，对只读 `score` 的链路（建链）等价于空操作。
故 `findCandidates` 显式传 `skipRerank: true`，不再靠列表长度隐式区分前后台。

- 保留 `hits.length > RERANK_MAX_DOCS` 的早退，作为"未声明跳过的大列表"兜底（不半重排的不变量不变）。
- **跳过 = 与「重排失败回退余弦序」逐条同产出**（成员 / 顺序 / `score` 三项一致），这条一致性
  由测试钉住——它是"零行为变化"的判据，也是将来判断能否再扩大跳过面的依据。
- 交互检索（参考面板 / 对话）仍在限内整列重排，语义零改动。

### 2. 确认写入"接住"在途轮，abort 语义收窄为两种

知识盒录入面板：分析中点确认 → 把刚落盘的路径交给**在途那一轮**（`commitPath`），它出结果后
直接 `apply` 落库。这一轮就此从面板生命周期摘出——面板复位 / 关窗**不得** abort 它。

`abort` 自此只对两件事生效：**内容变了**（重新生成 / 图版重读 / 新草稿）与**明确放弃**
（关面板且没点确认）。点确认不是放弃，它是"我要这一篇"的信号。

- 一次动作 = 一次检索 + 一次裁判 + 一次本地写入，无论用户什么时候点确认。
- 落盘与通知与后台兜底共用 `settleEntryRelCommit`（同一条通知键，用户视角只有一条）。
- 边界：状态是 loading 却捞不到在途句柄（错位态）→ 仍走原 `backgroundRelCommit` 从头算一遍——
  算不出来就不能假装有结果。

## 后果

- 建链每篇省掉一整轮重排（实测：本地通道 45 对冷态 6.7s／热态 2.0s，Jev 通道 45 条一次批问；
  两通道同吃 6s 预算）——也顺带不再把 4B 重排模型拉进显存。分析中点确认不再付第二遍。
- **关面板不再中止"已被接住"的轮次**：它会跑完并写进那篇笔记，结果由通知呈现（同键单条）。
  这是有意的——那一轮的钱已经花了，丢掉结果才是真的浪费。
- 「关面板且没点确认」照旧作废，语义未放宽（由测试与「加图/删图作废在途预演」用例共同守住）。
- 已知边界：挂载建议 / 每周撞车未一并声明跳过（不属本次范围，见 issue 541「明确不做」）。
