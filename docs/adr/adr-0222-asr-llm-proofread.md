# ADR-0222 · 转写 LLM 校对（单一开关 · 只修错 · 并仓前内嵌 · 知识盒替换润色）

日期：2026-09-29 · 状态：已采纳 · 关联：ADR-0196（画脸谱任务链）、ADR-0197（聊天仓唯一写者）、
ADR-0213/0217/0219（录音 sidecar 与派生物）、issue 444（AI 面板语音转写组）、issue 518

## 背景

SenseVoice 转写补齐 `language="zh"/use_itn` 参数后（f2c9670a），标点与内容覆盖回满，但同音错别字
仍在（5 分钟样本实测 11 处/千字 10.7）。在线 LLM 校对实验（同日，`.scratch` 口径）证实：只修错
不创作的校对可把确证类错字清零且零过度改写。用户拍板把它产品化：AI 面板「语音转写」组加开关，
脸谱语音条 / 脸谱录音 / 知识盒影像三处共用。

## 决策

1. **单一总开关**：设置键 `asrLlmProofread`（缺省关），挂在 AI 面板「语音转写」组（issue 444 组内
   第三行）。三处链路同键生效，不按域拆分。
2. **校对口径 = 只修错不创作**：提示词单源 `src/core/asr-proofread.ts`——仅修依上下文可确证的
   同音/近音错字与串音噪声；数字金额存疑不猜、语序口语原样、不书面化润色。实验口径直接收编。
3. **LLM 通道 = 复用全局配置**：走 `core/ai.ts` 的 `createAI()`（aiProvider + 模型覆盖），不设
   校对专用 provider/模型键。批级请求（约 3500 字 / 16 条一片， consecutively 编号喂入，模型自带
   邻条上下文），每批失败自动重试 1 次。
4. **生效时机 = 并仓前内嵌**：语音条在 prep 产物合并进聊天仓之前校对 `voice.json` 旁路表；录音在
   sidecar 轮次并仓之前校对 `.turns.json`；知识盒影像在转录稿进文献正文之前校对分块。入库即定稿，
   无「先错后对」中间态。任务进度出现「LLM 校对中」步。
5. **失败回退 = 原文落库可重试**：整档任一批重试后仍失败 → 该档不写回（校对原子性：全成才算成），
   按原文并仓/成文，通知（无 emoji）；缺口 = 校对标记不落——重跑 prep / 录音任务（Python 秒级补账，
   不重转文字）或再点并仓即只补校对。知识盒影像失败按原文直出文献正文（任务不炸）。
6. **知识盒影像替换 AI 润色（用户 2026-09-29 拍板）**：`generateVideoNote` 的「分块润色」步退役，
   文本处理只剩 LLM 校对一档——开关开 = 校对后正文；关 = 转写原文直出正文。元数据那次 JSON 调用
   （标题/标签/简介/领域）不是文本润色，保留。旧润色提示词（口语转书面、删口水词）随之下线。
7. **出域口径**：开启 = 转写文本发送到 AI 面板所配服务商，是对「文本不出本地」默认的显式突破；
   提示只落在设置项描述（用户拍板：功能界面不重复提示）。历史已并仓转写不批量补校，开关只对
   新转写生效。

## 备选

- 按域/按场景多开关：控制粒度更细，但设置面变重；用户明确要单一开关（需要时再拆）。
- 校对专用模型键：批量校对可配便宜模型，代价是多键多文案；跟随全局配置已足够。
- 入库后异步覆盖：文本先错后对，聊天仓需二次写入且 turns.md 要重写；并仓前内嵌无中间态。
- 本地 hotword/词典纠错：无出域顾虑但上限远低于 LLM 校对，且 SenseVoice 已支持 hotword 另票。

## 影响

- 插件三域新增同一消费入口 `core/asr-proofread.ts`；脸谱两处为「插件写工具旁路表」的少数场景
  （voice.json 条目加 `proofread` 标记、turns.json 顶层加 `proofread` 标记，均 additive 字段，
  工具重跑即失效重校，语义自洽）。
- faster-whisper 引擎下开关同样适用（校对的是文本，与引擎无关）。
- 不加「已校对/未校对」的界面状态标记（通知 + 重跑即补，避免文本形态污染）。
