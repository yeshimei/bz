# 0054 — 日记「未解析行」手动驱动一键修复

## Status

Accepted（ticket 121，用户拍板：2026-08-27 盘问定案）。

## Context

UX-9（25c79a7，ticket 9）为 `parseFile` 增加「未解析行」统计并在 `loadAll` 结束时弹一次性 warning toast「N 条未能解析，请检查日记文件格式」——只报数字，不指文件、不指行。真机审计（521 个日期文件）发现 24 条未解析行实际只来自 3 个文件的**头行格式不合规**（`# 🤝02:43` 缺空格、`# 📖 9:33` 单数字时间、`# 📖12:28` 缺空格），头行无法被标题正则 `^#\s*((?:\S+)+)\s+(\d{2}:\d{2})` 识别为条目边界，其下正文随之全部成为「游离于首个条目之前的非空行」被静默丢弃——这些行**从未显示**，且解析行为自始如此（UX-9 只是把静默变成数字通知）。

用户拍板（盘问四轮）：去掉启动自动 toast；改在日记⚙️设置弹窗加「检测日记解析」按钮 → 检测面板（进度条 → 逐文件解析 → 汇报）；**手动驱动**修复（非自动触发）：可修项展示修改前后预览、确认后一键批量写回；不可修项列清单、点击跳转定位；修复不额外备份。这与铁律 1「兼容性冻结」存在张力，故立此 ADR 划清边界。

## Decision

**「一键修复」把不合规数据修复到既有格式，不改变既有格式本身**——不属铁律 1 冻结范围：

- **冻结的是什么**：日期文件格式契约（`# emoji序列 HH:mm` 标题结构）、`CONFIG/STORAGE/*.json` 与 frontmatter 数据形态、文案/CSS/公式、已知缺陷清单。
- **修复改什么**：仅限**不合规的头行**（无法被标题正则识别的行），按规则白名单改写为该正则可识别的形态；正文行（含行尾 `#标签` 等原内容）**一字不动**，随头行合法化自动归位。等价于用户手工把 `# 🤝02:43` 改成 `# 🤝 02:43`，不引入任何新格式。

### 规则白名单（仅此三类，其余一律进「不可修」清单）

| 规则 | 输入形态 | 输出 |
|---|---|---|
| R1 标题补空格 | `#` + emoji序列 + 时间（无空白），如 `# 🤝02:43` | emoji 与时间间补一个空格 |
| R2 时间补零 | emoji 与时间间有空白但时间非两位，如 `# 📖 9:33`、`9:3` | 时/分补零至 `HH:mm` |
| R3 正文归位（非改写规则） | 头行修复后其下正文 | 归属该条目，内容零改动 |

- 唯一合法化操作是 R1/R2 对**游离的头行**（首个条目之前、形似标题的行）的格式改写；`parseFile` 解析结果不变式（entry 结构、数据文件格式、其它行）零影响。
- 时间越界（如 `24:99`，虽匹配 `\d{2}:\d{2}` 但值非法）等无法确定合法值的形态 → **不可自动修**，列清单由用户跳转手工改。

### 手动驱动与落盘

- 检测入口与修复触发均为**手动**：日记⚖️设置弹窗「检测日记解析」→ 检测面板（复用 `parseFile` 的 `onUnparsed` 统计与 `loadAll` 的分批并发模式，带进度条）→ 「一键修复」前展示每处修改前后预览 → confirm 后批量 `vault.modify` 写回 → toast 汇报成功/失败 → 日记面板数据刷新。
- **移除** `loadAll` 启动时的自动「N 条未能解析」toast（统计可保留，仅不通知）。
- **不额外备份**（用户拍板）：Obsidian 文件历史/同步/文件恢复兜底；接受 mtime 副作用（smartcat ticket 077 会产生「你更新了日记」观察）。修复窗口为单次确认，不做全局配置项。

## Considered Options

- **保持纯数字 toast（现状）**：拒绝——用户无法定位，信息量趋近于零（真机 24 条=3 个头行的教训）。
- **自动修复（无需确认直接落盘）**：拒绝——改写历史日记文件须用户显式确认，且手动驱动是用户原话边界（「增加一个手动解决，不是自动解决」）。
- **全自动修 + 逐条确认**：拒绝——当前真实数据仅 3 处，面板内一次性预览+批量确认信息密度最高；逐条确认是可用性噪音（真不可修项已进清单）。
- **修复前自动备份到 CONFIG/STORAGE**：拒绝——用户拍板不备份（Obsidian 文件历史兜底），备份目录还会污染同步流。

## Consequences

- 日记域新增：设置弹窗按钮、检测面板（新 UI，`bz-` 前缀样式收敛根 styles.css）、纯函数修复计划引擎（`buildRepairPlan`，node 环境可测）。
- `loadAll` 不再启动打扰；检测面板成为「未解析行」的唯一汇报入口。
- 铁律 1 边界以「修复不合规数据 ≠ 改动格式」立此 ADR 备案；后续其它域若出现「自动改写用户数据」一律先过 ADR。
- 测试：修复计划引擎（R1/R2 规则、不可修分类、正文不改写断言）、面板流程（按钮/进度/预览/确认/写回/跳转）、smoke（无新命令注册）。
