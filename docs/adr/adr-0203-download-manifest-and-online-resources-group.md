# ADR-0203：下载清单与在线资源组——皮肤分发从「启动静默全量」反转为「用户显式决定」

- 日期：2026-09-27
- 状态：已采纳（实现见 issue 480）
- 相关：ADR-0199（皮肤包远端分发，本 ADR 修订其加载策略）· ADR-0200（文档资产新鲜度核对）· issue 473 / 474 / 476（手册/日志在线下载与核对）· `src/core/remote-asset.ts` · `src/core/skin-pack.ts` · `src/core/download-manifest.ts`（新增）· `src/settings-panel/ui.ts`

## 背景

插件在线资产已散落三套机制：手册与更新日志走 remote-asset 按文件名直拉（无清单），
皮肤包走自己的 `skins/index.json` 清单（sha256 校验 + **启动静默全量同步**，ADR-0199
拍板「不要按钮」）。三者共同的问题：

1. **用户不知情**——皮肤被静默装了 26 套、日志/手册在后台被换掉，用户没有任何一处
   能看到「有什么可下载、什么有更新」；
2. **无扩展形状**——下一个在线资源没有现成挂靠点，只能再复制一轮「文件名常量 + 校验函数 + 入口」。

用户拍板反转皮肤分发的默认值：下载/更新由用户决定，启动只对比清单更新状态；
三件东西收进设置面板通用域新组「在线资源」，一张统一下载清单驱动。

## 决策

### 1. 统一清单 `downloads/manifest.json`，仓库 `manual/` 目录让位

- 远端唯一事实源 = 仓库 `downloads/manifest.json`，**内联全部资源条目**：
  `docs[]`（bz-changelog.html / bz-manual.html，id+name+file+sha256）与
  `skins[]`（沿用 SkinPackEntry 形状，id+domain+file+previewClass+since/until+sha256）。
  启动只拉这一张清单，未来加资源 = 加条目。
- 仓库目录 `manual/` **copy 冻结**为过渡副本（旧版插件的双源 URL 继续可达，功能不坏、
  内容不再更新），新家在 `downloads/`；过渡若干版本后整体删除。`manual/skins/index.json`
  远端清单随退役，sha256 数据并入统一清单。
- 双源通道不变（raw.githubusercontent 主 → jsDelivr 备），仅路径 `manual/` → `downloads/`。

### 2. 本地 = 远端 `downloads/` 的同名镜像

清单缓存落 `<configDir>/plugins/bz/downloads/manifest.json`——本地路径与远端路径
逐字同构（远端 `downloads/<path>` ↔ 本地 `plugins/bz/<path>`），清单本身也是清单的
下载产物之一。不叫 `plugins/bz/manifest.json` 是因为**插件自身的 Obsidian 清单就住在那**
（skin-pack 的版本区间校验读它），撞名即事故。

皮肤本地就绪表 `plugins/bz/skins/index.json` 随之退役：**就绪 = 缓存清单条目 + 本地文件
sha256 匹配**，启动快路径（`loadLocalSkinPack`）改读缓存清单。磁盘上的单源只有一份。

### 3. 半自动：启动只对比，下载只听用户的（修订 ADR-0199）

- **启动链**（仍串自更新检查之后）：拉清单 → 写缓存 → **皮肤下架清理**（清单移除的
  删本地文件，沿用 ADR-0199 口径）→ 重验注入 → 算出各项状态。**绝不下载任何资源。**
- **下载仅两个入口**：用户点新组里的「下载 / 更新 N」按钮；或点手册/日志导航入口
  （ensure 无则下载 + 后台 refresh 热替换，现状保留）。
- 拉清单失败：有缓存 → 沿用缓存状态渲染 + 组内细字提示 + 重试按钮；无缓存 →
  三行禁用 + 失败横条 + 重试。**每次启动都对比**（清单几十 KB，不节流）。

### 4. 新组「在线资源」：三项统一状态机

通用域最后一组，三行（更新日志 / 使用手册 / 主题——组内行名用「主题」，各域选择卡叫法不变），右侧状态按钮：

| 状态 | 按钮 | 说明 |
|---|---|---|
| 未下载（missing） | 下载（皮肤带套数） | 点击下载 |
| 有更新（本地 hash ≠ 清单 sha256） | 更新 N（N=可更条目数） | 皮肤按套计 |
| 已最新（ready） | 已下载（禁用） | — |
| 检查中 / 下载中 | 转圈禁用 | — |

皮肤行同时存在未下载与可更新时合并为一个动作（拉全部非就绪），按钮文案更新优先；
下载仅入库——皮肤进了各域选择卡仍由用户手动切换（下载 ≠ 应用）。

### 5. 手册/日志入口的省流优化

`refreshAsset` 增可选 `expectedSha256`：调用方（manual/changelog）从缓存清单取该文件
的清单 hash，与本地一致即直接返回 null，**跳过每次点入口白拉 327KB 的后台核对**。
清单缺席时回落现行为（全量拉取对比），行为只省不破。

## 备选与否决

| 方案 | 否决理由 |
|---|---|
| 两层清单（顶层三项引用 skins/index.json 子清单） | 两张清单两次拉取、两套解析，皮肤机制以外的资源仍无挂靠点 |
| 已下载皮肤启动静默保新版 | 违背本票「用户知情并决定」初衷；皮肤无弹窗兜底入口，静默等于回退 ADR-0199 |
| 下架皮肤本地保留 | 「清单说没有、本地还装着」的分裂态，且与 ADR-0199 已拍板口径冲突 |
| 清单缓存叫 `manifest.json` | 与插件自身 Obsidian 清单同路径撞名，版本区间校验会读到下载清单 |
| 统一清单进 git 由 `pnpm changelog` 顺带重算 | changelog/skin-pack/manifest 三产物三节奏，合一步会让「只改皮肤」也重写清单 sha，diff 噪声大；独立 `pnpm manifest` 收口 |

## 后果

- 皮肤从「装了就有」变「不下载没有」：全新安装的各域选择卡只剩内置首套，直到用户去
  新组下载。这是本票的**目的**（知情+决定），不是回归。
- 旧版插件在过渡期内拉 `manual/` 冻结副本：功能可用、内容停更——由插件自更新链条
  自然收敛，不做迁移代码。
- `pnpm skin-pack` 不再产 index.json；`pnpm changelog` 产物路径改 `downloads/`；
  发布链多一步 `pnpm manifest`（守卫测试盯 `--check`）。
- 后续任何在线资源：清单加条目 → 新组加行（或并入现有行）→ 下载动作复用
  remote-asset 通道，无需再立分发机制。
