# ADR-0143 知识盒重名防护只做名词入口（口径 = 文件名）

- 状态：已接受（2026-09-15，grill 评审拍板；**设计定稿，未实现**）
- 关联：ADR-0136（图版）/ issue 326（四入口与同壳三态）/ cinema 同名拒绝先例（`cinema/ui.ts` 保存查重）
- 影响：`src/knowledge/ui.ts`（`onTermConfirm` + 名词输入框）、`src/knowledge/note-gen.ts`（查重工具函数）、相关测试

## 背景

知识盒四入口（名词 / 段落 / 图版同壳三态 + 影像）生成笔记统一走 `writeUniqueNote`「永不覆盖」契约：
重名标题**静默加 `_2` 后缀并列成新文件**，frontmatter `title` 仍重复，部壹列表出现两条同名，用户零感知。

用户最初诉求「知识盒四个入口，都加上防止标题重复」，grill 后自我收窄：**只有名词的标题是用户手输的**，
段落 / 图版 / 影像的标题都由 AI 生成，「重复了重新生成即可」——防重只对人工输入有意义。

## 决策

### 1. 范围：只做名词入口

段落 / 图版 / 影像**刻意不做防重**（用户拍板）：三者标题皆为 AI 产出，重名时用户的应对是点生成重来，
软件层拦截是打扰；维持静默 `_2` 现状。这是接受的缩编，不是遗漏。

### 2. 口径：只查文件名

输入术语经 `sanitizeMdTitle` 清洗后与文献目录下已有 md 的 basename 比对——与 `writeUniqueNote`
的撞名判定同源，**被拦的正是「不拦就会变成 `_2`」的情况**。frontmatter `title` 重复但文件名不同
（如手动改过文件名）不拦，刻意接受。

### 3. 两道防线，都在名词侧

- **实时提醒**：名词标题输入框下方内联提示，命中即显、改名即消（不阻断输入）；
- **确认硬拦截**：`onTermConfirm` 校验后查重，命中 → error 通知「已存在同名文献笔记：…」+ 不写入；
  预览与草稿保留，改个名即可重试（仿 cinema「已存在同名影视」拒绝先例）。

`writeUniqueNote` 的「永不覆盖」契约**不动**——图版二进制落盘与 backfill 等都依赖它，拦截放调用方。

## 后果

- 名词入口不会再产生「两条同名文献」，且用户在输入时就能看到撞名，不用等确认才被拦。
- 段落 / 图版重名仍会静默 `_2` 并列——若将来要收紧，提醒可借同壳 meta 标题框自然覆盖，本 ADR 不预做。
- 文件名截断 50 字意味着超长术语按清洗后前缀比对，极端近似名可能漏拦（`_2` 兜底仍在，不会覆盖）。
