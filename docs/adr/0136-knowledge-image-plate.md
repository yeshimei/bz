# ADR-0136 图版：图片作为知识盒第四类文献录入（读图成文）

- 状态：已接受（2026-09-14，原型评审拍板）
- 关联：ADR-0112（知识盒三部）/ ADR-0116（来源行）/ ADR-0135（录入三名词 + 影像两界面）/
  issues/311（AI 多模态通道）/ issues/312（本决策落地）/ issues/313（多图 + 正文顺序 + 图片目录可配）
- 影响：`src/knowledge/{ui,note-gen}.ts`、`src/knowledge/styles.css`、`src/core/ai.ts`、
  `src/smartcat/*`、`src/home/behavior-timeline.ts`、`prototypes/knowledge/*`

## 背景

知识盒部壹原有三类录入：名词（一个词）/ 段落（一段文字）/ 影像（B 站视频转文献）。
2026-09-14 用户提出「另外一种文献的入口，图片」，讨论后确认要做**读图成文**：
丢一张图 → AI 看图出标题 / 领域 / 正文 → 预览 → 确认写入。

前置能力在 issues/311 已落地：DeepSeek V4.1-Flash（2026-09-10 起）原生支持文 + 图输入，
`core/ai` 的 `prompt` / `chat` / `json` 等已能收 `{text, images}` 并组装 OpenAI 多模态 content 数组。

## 决策

### 1. 第四类录入叫「图版」（顺序：影像之前——2026-09-14 第二轮复核改序）

- 「影像」已经指视频（issues/309/310 定的名），中文里它本可涵盖照片，与「图片」并列会互相吃掉语义。
  拍板：**影像不改名**，新的一类用词典味的**图版**（一页图称一版，与知识盒的词典皮同调）。
- 入口行四枚单字词按钮，顺序 `名词 / 段落 / 图版 / 影像`（312 落地时在影像之后，当日复核改到影像之前——图版与名词 / 段落同壳，而影像自成一条任务链路，分类上贴着放更顺）。
- 面板壳仍是**同壳多态**：一类 = 一态，由 `data-lit-entry` 切首行控件与属性首行
  （`term` 单行 input / `passage` 多行 textarea / `image` 图片拖入区；段落与图版共用 `.bz-lit-titled-only` 可改标题行）。

### 2. 图只在内存，确认写入才落盘

- 拖入 / 粘贴 / 点选得到的 `File` → `arrayBuffer` + data URL 存内存，data URL 供预览缩略图与投喂 AI。
- **确认写入**时才 `createBinary` 到图片目录（默认 `<文献目录>/assets/`，可配——见 §5），随后写笔记。
  理由：与「草稿不落盘」同口径——取消就什么都不留，不会在 assets/ 里攒孤儿图。
- 正文嵌入写 **vault 相对全路径**（`![[文献盒/assets/x.png]]`）：库里同名图很常见，裸文件名会指错。
- 图片与笔记各自判重加序号（同扩展名才判重）；来源行照旧走 ADR-0116 的 `source` / `sourceTitle`。

### 5. 一组图 = 一篇（多图，2026-09-14 第二轮复核）

- 一次录入可放**多张**图（上限 9 张）：`entryImages` 数组，顺序 = 放入顺序 = 笔记里的嵌入顺序；
  加图 / 删图都作废旧草稿（`draftInvalidate()` 单一出口）。
- AI 侧**不拆请求**：全部 data URL 一次投给模型，提示词按张数分叉（单图「看这张图片」／
  多图「看下面这 N 张图片，把它们作为一组生成一篇文献笔记」）。
- **正文顺序：文字在上、图片在下**（用户拍板）。原文是「图在上、解读在下」——读起来先看图再看说明，
  但多图时图会挡住正文，且与「先读后看」的笔记习惯相反。
- 面板的图片行随之从「单缩略图（点它换图）」改成**缩略图网格**（每张右上角 ✕，hint 报「已放 N 张」）。

### 6. 图片目录由设置决定（2026-09-14 第二轮复核）

- 新键 `knowledgeImageFolder`；**留空 = `<文献目录>/assets`**（`resolveImageDir` 纯函数做回落，
  两侧斜杠归一）。填了就完全以它为准（含跨目录场景，如统一放到「我的/图片」）。
- 设置面板「目录与分类」组加 path 行「图版图片文件夹」，带 `fallbackValue`：
  空值时 chips 区显示**实际生效目录**（同书库先例）——不让用户猜「留空到底落哪」。

### 3. 不新增「读图模型」设置

默认 provider 的模型名（`deepseek-v4-flash`）已是 V4.1-Flash 的别名，能直接读图（issues/311）。
加一行「读图模型」等于多一个需要用户想明白的旋钮，收益不足 → 直接用当前模型；
模型万一不透传图片，错误由既有的生成失败提示（`noticeTermError`）如实抛出。

### 4. 不加命令面板条目、不加「从库里挑」

（2026-09-14 第二轮复核后维持；多图、正文顺序、图片目录见 §5 / §6。）

- 名词 / 影像有命令，段落当初没加；图版与段落保持一致，只给面板入口。
- 图片来源只做三条路：拖入、点选文件、Ctrl+V 粘贴截图（用户选定）。
  「从文库已有图片里挑」需要把只选文件夹的路径选择器扩成能选文件，本轮不做。

## 结果

- 第四类文献 `type: image`：frontmatter 五键（title / type / domain / date + 可选 source/sourceTitle），
  正文 = **读图解读（文字）在上、图片嵌入在下**（一张或多张）；列表标签「图 版」，预览头「图版预览」。
- 事件 `knowledge:image-generated` 进小橘行为流（「你把『X』读成了一篇图版文献」）与首页时间线（「读图『X』」）。
- 关联行（issues/309）对图版照常工作：读图解读文本即预演查询体，写入时把预演结果落进 `related`。
- 评审壳：`injectDemoPlate` 给图版拖入区补一枚壳专用的「载入示例图」（可连点，多图演示），
  `loadDemoPlate(count)` 用画布造图（逐张换配色与题字）并**经真实 drop 事件**（DataTransfer + File）送进面板——
  走的就是产品路径，不是给面板开后门；AI 罐头回包里报出「已收到图片（N 张）」，
  自检据此证明图确实到了模型层。
