# ADR-0227 · 会话流单源（详情页「查看聊天」）+ 「我」的头像默认取微信里的本人头像

日期：2026-09-30 · 状态：已采纳 · 关联：ADR-0191（脸谱域立项）、ADR-0194（保库记录 = 每人一条）、
ADR-0197（聊天仓唯一写者）、ADR-0212（补充素材）、ADR-0217（录音起点是一等数据）、
ADR-0220（录音段落进仓）、issue 529

## 背景（用户原话）

> 「脸谱详情页的中间的合上这页按钮改成查看聊天（改成更符合的含义），然后打开一个和微信界面一样的
> 聊天排版界面，排版界面复用录音的查看轮次的界面，把这个界面改得更像微信」
>
> 「在脸谱的设置界面增加一个选项，可以让用户上传一张图片当头像，默认使用从微信数据里面扒出来的图片」

开工前逐条澄清（均按推荐项拍板）：

1. 改的是**详情页动作签里那枚**「合上这页」——它与页眉右上角那枚完全重复，而聊天仓里那几万条消息
   在面板上**没有任何入口**（只在画脸谱时被 AI 消费）。页眉那枚继续关页。
2. 「上传头像」指**「我」那一侧的头像**（设置里原有的「我的头像」文本路径行）。
3. 聊天页读**真实聊天仓**：默认最近若干条，往上滚 / 点「更早的消息」继续加载（两万条不整页铺）。

## 决策

### 一、会话流单源：`chat.ts`（规则）+ `render.chatStream`（markup）

「什么算一条消息」「标签怎么剥」「什么时候插时间分隔条」三件事收进 `src/people/chat.ts` 单源；
「头像 + 气泡怎么摆」收进 `render.ts` 的 `chatStream`。两个上屏面共用同一份实现：

- 详情页动作签「查看聊天」→ 册页弹窗 `dialog.kind = 'chat'` → `chatPage`（`subPage` 外壳 + 会话流 + 只读页脚）；
- 补充素材页签「查看轮次」（录音逐轮预览）→ `recTurnsPreview` 把轮次翻译成展示行后走同一个 `chatStream`。

原先那份 `bz-people-supp-turn*` 自绘会话流**整体退役**（类名 → `bz-people-chat-*`），
两处不再各写一份「微信式聊天流」。用户说的「复用录音的查看轮次的界面」在实现上是反过来落地的：
**两边共用一个组件**，录音那侧只剩「轮次 → 展示行」的翻译。

### 二、更像微信的四件事（在共用组件里一次做掉）

1. **时间分隔条**：与上一条间隔 > 5 分钟（或它是第一条）才出一条，形态
   `HH:mm` / `昨天 HH:mm` / `M月D日 HH:mm` / `YYYY年M月D日 HH:mm`——微信同款，规则在 `chatSepOf`（`now` 由调用方给，渲染层不算时间）。
2. **媒体标签成签**：`[图片]` / `[语音 12秒·平静]` / `[表情·名]` 这类前缀剥出来单独成签（带同源词表的 lucide 小图标），
   标签后面的图片描述 / 语音转写作气泡正文。只认已知词表（引用 / 分享 / 链接 / 文件 / 撤回 / 通话 / 表情 / 小程序 / 视频 / 录音 / 语音 / 图片）——
   普通文本里以 `[` 开头的句子（`[他说的] 那句`）不会被吃掉。
3. **群聊才写名字**：除「我」之外有多个发送者时，气泡上方出名字；单聊不写（微信同款）。
   旁音轮（录音里不进仓的那类）**恒写名字**——一条灰气泡总得说清是谁的声音。
4. **微信底栏**：只读说明（`只读 · 来自微信导入的聊天记录 · 共 N 条`）+「回到最新」。

### 三、聊天页分页：往里读 50 条一页，往上长

- 常量 `CHAT_PAGE = 50`：进页只把**最近 50 条**铺出来（两万条整页铺会把开页冻死——issue 519 的同一笔账）。
- 顶上「更早的消息（还有 N 条）」既是按钮也是哨兵：`IntersectionObserver`（`rootMargin: 600px`）进视口自动放一页，
  点它同样放一页（IO 缺席环境的兜底），与留影网格分片同款范式。
- **加载更早是往上长**：重画前记「离底距离」，重画后按同一距离还原（通用 `scrollSnapshot` 记的是 `scrollTop`，
  对往上长内容的场景不够用——聊天页单开一条 `chatAnchorBottom` 通道）；进页 / 点「回到最新」则贴底。

### 四、「我」的头像：设置里上传，默认取微信数据里的本人头像

- **工具侧补一次导出**（`tools/obsidian-face/python/bz_sync.py` 的 `write_self_avatar`）：
  sync / export 两轮都把账号自己的头像（微信 `head_image` 库里 `my_wxid` 那条，与联系人头像同一张表）
  按字节比对幂等地落到 `<数据根>/.bz-face/me/avatar.<ext>`。放 `.bz-face/me/` 而不是联系人目录——
  数据源扫描按目录列联系人，落在那儿会被当成一位联系人。
- **插件侧默认值**（`src/people/me-avatar.ts` 单源，三级取值）：
  1. `peopleMyAvatar` 有值 → 库内相对路径原样交给渲染层（走 vault `getResourcePath`），库外绝对路径读字节转 data URL；
  2. 留空 → `<数据根>/.bz-face/me/avatar.<ext>` 读字节转 data URL（与数据源头像同一条通道）；
  3. 都没有 → 空串（渲染层落「首字印」）。
- **设置行改成上传**：`text` 行换成 `custom` 行——预览 + 「上传图片…」+「恢复默认」，来源一句话说清
  （自定义 / 微信里的本人头像 / 还没设置）。上传的图**复制进 vault** 的 `CONFIG/FACES/我/avatar.<ext>`
  （467 后退役的明文头像目录，仍在），键值存**库内相对路径**：换机 / 同步 vault 带得走，两端都加载得了。
  同目录里换过扩展名的旧图先清掉——扩展名探测序会先撞上旧的那张，不清就是「换了图却没生效」。

## 后果

- 聊天仓从「只有 AI 看得见」变成用户看得见的页面；录音「查看轮次」的观感随之一起升级（同一份组件）。
- 会话流加一条新的上屏面只需构造 `ChatLine[]`；微信化的观感改动一处生效两处。
- `CustomRow` 类型放宽为可声明 `name`（`core/settings-schema.ts`）：设置面板早就按 `row.name` 渲染 info 区
  并把行名纳入搜索（`schemaRowCache`），此前只是类型没跟上——脸谱这行要一个能在面板里搜到的行名。
  核心渲染器（原生设置页）仍只渲染插槽，不因它多出标题。
- 本人头像**要跑一次同步（或导入一次）才有**：工具侧此前从未导出过它。没跑过 = 回落首字印，
  设置行如实写着「还没设置——跑一次同步就能拿到微信里的本人头像」。
- `peopleMyAvatar` 键语义不变（仍是「自定义头像」），只是空值不再等于「首字印」，而是「回落微信本人头像」。

## 明确不做

- **不在聊天页渲染图片 / 语音本体**（只出标签 + 描述 / 转写文本）：一场会话动辄上千张图，
  逐张读字节转 data URL 正是 issue 519 记下的开页冻死病根；要看图走补充素材的留影页签（已有网格与大图）。
- **不给聊天页做假输入框**：数据只读，底栏就出只读说明与「回到最新」，不摆一个点了没反应的输入条。
- **不把聊天原文写进人物卡或任何明文文件**：聊天仍只活在保库记录里（ADR-0194）；聊天页读的是解密缓存，
  上锁 / 关面板即清（`clearChatState`）。
