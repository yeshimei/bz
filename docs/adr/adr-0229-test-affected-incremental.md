# ADR-0229 · 增量跑测试：自建依赖索引，不用 vitest 的模块图（选择器 + 结果缓存）

日期：2026-10-01 · 状态：已采纳 · 关联：ADR-0020（样式按域拆分）、ADR-0104（渲染纯层）、
ADR-0122（界面级单源）、ADR-0199（皮肤包）、issue 534

## 背景

用户提出「只跑受影响测试、未变的复用上次成功结果、全量兜底」。本机实测（16 核、
fsModuleCache 热、HEAD f14541fc，全量 **29.2s** / 588 文件 / 8886 例），把 vitest 原生通道
`--changed` / `related` 的三条路都试过了：

| 变更 | 原生命中 | 实际必须跑 |
|---|---|---|
| `src/memo/styles.css`、`src/core/ui/components.css` | **0**（退出码 0） | 该域样式守卫 + 界面级单源守卫 |
| `pnpm-lock.yaml` | **0**（退出码 0） | 全体 |
| 工作区干净（`--changed master`） | **0**（退出码 0） | — |
| `src/memo/data.ts` | 59，墙钟 18.2s | — |

根因**不是配置问题，是口径问题**：`getAffectedModules` 靠 `transformed.deps ∪ dynamicDeps`
建反向边，而本仓 **37 个测试文件没有任何 src import 边** —— 它们用 `readFileSync` 直接读源码
文本断言，守的是跨域不变量（依赖方向 ADR-0002、渲染纯度 ADR-0104、样式单源 ADR-0020/0122、
皮肤包 ADR-0199、打包产物新鲜度）。**模块图里没有 `readFileSync` 这条边**，所以改样式永远选不中
它们 —— 不是「没跑到」，是「命中 0 个还退出码 0」。

另有两条硬伤：`related` 的固定开销实测 **5.4–5.8s**（它要先 transform 全部 588 个 spec），
命中面一大就反超全量（189 文件 23.9s、285 文件 27.1s）；`forceRerunTriggers` 的默认值
在 Windows 下失效（匹配对象是 `path.resolve` 的反斜杠路径，picomatch 实测返回 `false`）。

## 决策

1. **不用 vitest 的 `--changed` / `related` 做增量，也不用它的结果缓存。**
   后者的键是测试路径、变化判定只看**文件 size**（`FilesStatsCache = Pick<Stats,'size'>`），
   没有内容与依赖指纹，只够当 watch 的重跑提示。

2. **自建静态依赖索引**（`scripts/test-affected.mjs`），建三类边，冷建 ~0.4s
   （含 node 启动的整条 `--list` 流程 0.76s；对比原生固定开销 5.4–5.8s）：
   - **import 边**：`from` / `import()` / `require` 的相对路径；
   - **文本边**：字符串字面量里**在仓库里真实存在**的路径 —— 必须抓「藏在变量/helper 里」的形态
     （`repo('src/core/ui/components.css')`），只抓紧贴引号的 `'src/...'` 会漏掉绝大多数守卫；
   - **目录/整树边**：扫树守卫的目录实参（`readdirSync` 上下文里的 `'src'`）→ 该目录下任何
     文件变更都命中。

   实测：**111 个测试有文本边**（281 条文件级 + 58 条目录级），其中 **43 个含整树级**（任何 src
   变更都要跑），其余精确绑定本域。这比「一律常跑 96 个疑似守卫」精确得多，也比「什么守卫都不跑」
   安全得多。

   判定文本边的依据是**路径真实存在**，**不是**「根目录 ∈ {src,tests,scripts}」（初版白名单，
   自审时打回）：`downloads/`、`tools/`、`prototypes/`、`manual/` 在索引根之外，但一样有守卫用
   字面量指着它们；白名单把它们全推给「一律全量」，既不必要又不快（改 `downloads/manifest.json`
   实际只影响 5 个测试，全量要跑 589 个）。代价是要挡住不像路径的字符串，**廉价形状过滤**
   （含 `/` / 带文件后缀 / 是仓库根一级目录名）把 `statSync` 从 **1.66 万次压到 2.8 千次** ——
   不做这层，冷建索引 1.57s，等于把省下来的固定开销又还回去。

3. **三条硬升格 + 一条兜底，宁可全量不许漏测**：
   - 依赖清单 / 测试与构建配置 / `scripts/**` / **`tests/` 下一切非测试文件**（共享夹具是
     开放集合，不逐个列举）→ 全量；
   - `src/core/**` 的 `.ts` → 全量（实测 500/588 个测试依赖 core，增量跑 500 个 ≈ 全量，
     不如直说）；
   - `src/**` 文件新增/删除/改名 → 全量；改动文件**无测试可达** → 全量（可能是注册型入口）；
     `.css` 若**没有任何守卫引用它** → 全量；
   - **索引根之外、且没有任何文本边/目录边盖住它** → 全量（典型：根 `main.js` 构建产物、
     `.gitignore`、新加的顶层目录）；`.md` 例外，仓库里没有任何测试把文档当输入。
     「有没有边」这半句是关键：`src/tests/scripts` 之外的文件**不是天然该全量** —— 有守卫读它
     就精确跑，真·无主才全量。

4. **结果缓存按「内容指纹」算，不按时间戳/大小**：
   `key = TOOL ‖ LOCK ‖ CONFIG ‖ HARNESS ‖ ENV ‖ 依赖闭包内容 hash`。
   只复用 `status = pass`（fail 与靠 retry 救回的 flaky 一律重跑）；**本轮退出码 0 即写回**
   （增量跑也写，非只有全量）；原子写以适配 17 个并发 worktree。
   按文件写回是安全的：某文件的 pass 成立与否只取决于它自己的依赖闭包指纹，
   与同批跑了多少文件无关；未跑到的文件保持原条目不动，增量结论不会把它们伪造成通过。
   依赖闭包**必须用本 ADR 决策 2 的索引**，不能用 vitest 的 transform 图 —— 否则那 37 个
   守卫的依赖永远不在闭包里，缓存会把「样式已改」判成「没变」。
   指纹的 harness 分片里额外混入**本地日期**：用例结果可能与「今天」有关（时间窗口/到期/周界），
   跨日复用一个 pass 是不必冒的风险，代价只是一天一次未命中。

5. **`pnpm test:changed` 从原生命令改指向新脚本**（旧的原生版本改名 `test:changed:vitest`
   留作诊断）。原生命令在本机不仅会「跑 0 个用例报成功」，还因 pnpm shim 路径错乱直接
   `MODULE_NOT_FOUND` —— 一个会报假成功的命令留着比没有更危险。

6. **门的纪律不变：合并前仍跑全量。** 增量只是开发循环的加速器，其结论不是门禁结论。
   选择器在「没得跑」时把三种成因分别说清（工作区无变更 / 命中文件全被缓存复用 /
   变更了但没有测试受影响），**不复刻原生那条含混的静默 0**。

7. **不引入 Turborepo / Nx / Bazel，也不做远程缓存。** 单包无包图，三者的核心价值
   （包图调度、跨包缓存）在本仓没有落点；17 个 worktree 同机且各自 `node_modules`，
   共享缓存目录已够；现在**没有任何 CI 配置**，跨机复用无落点。

## 后果

- 域内改动：`src/memo/styles.css` 23 文件 **11.5s**、`components.css` 28 文件 **11.4s**、
  `src/memo/data.ts` 75 文件 **14.7s**（全量 29.2s，原生 `related` 在这些场景是 0 命中或 18.2s）。
  磁盘无变化时缓存全命中 → **0.82s**。
- 索引根之外的路径按「有守卫读它」精确命中：改 `downloads/manifest.json` 只跑 **5** 个测试
  （白名单版会全量 589）；根 `main.js` 无守卫读它 → 全量兜底；改文档 → 0 个命中但**打出提示**
  （「空命中不等于通过，请加 `--full`」），不静默。
- 跨切面改动（`src/core/**`、锁文件、配置、夹具）自动降级为全量 —— 这是**有意**的：
  它在这些场景本来就没有收益，直说比假装省时间好。
- 代价：新增一条**必须与仓库同步演进**的映射（新写守卫、新样式文件、新夹具目录）。
  兜底是三条硬升格 + 一条「无主即全量」+「无守卫引用的 CSS / 无测试可达的 src 一律全量」——
  漏测的代价被移到「多跑一次全量」，而不是「少跑一次还绿」。回归由
  `tests/scripts/test-affected.test.mjs` 里**拿真实仓库跑**的 7 条断言钉住（改样式必须命中该域
  样式守卫、改界面级单源必须命中滚动条守卫、改锁文件必须全量、改 `downloads/manifest.json`
  必须命中 `skin-pack-catalog` **且不是全量**、改根 `main.js` 必须全量、扫树守卫在任何 src 变更下
  必须入选）。
- **测试自己不能变成假绿源**：选择器的测试文件里不允许出现指向真实仓库的路径字面量
  （夹具用假名，真实路径从 `tests/scripts/affected-repo-paths.ts` 取）。否则那些字面量会被自己
  的索引读成文本边，把「改构建产物 → 全量」这类兜底压掉 —— 这是实测踩到的坑。
- 已知边界：文本边是**正则近似**，比真实解析宽（宁可多跑）。计算型动态 import
  （`import(someVar)`）抓不到 —— 当前全仓 70 处动态 import 全是字面量，属新代码可能引入的
  开放风险，命中它要靠硬升格里的「无测试可达 → 全量」。
- 与提速的关系：本次一并验证了「测试提速还有多少空间」——`afterAll` 排空窗口 60ms→5ms
  **墙钟不变**却立刻爆 4 个 Unhandled Rejection（不是杠杆，别动）；最慢文件的显式 sleep 只占
  其自身耗时 1.5%–26%，其余是 DOM 构造 / 力导向布局 / moment 运算。**剩余提速 ROÏ ≈ 1–2s，
  不值得动 588 个测试文件**；真正的杠杆就是本 ADR 的「少跑文件」。
