# ADR-0016 加密保险箱——平铺点前缀密文布局

状态：已采纳（encrypt 域布局修订，取代 ADR-0015 的存储布局部分）
日期：2026-08

## 背景

ADR-0015 确立的镜像布局为 `<encryptRoot>/附件/<原相对路径>`（镜像目录保留原路径层级），清单为 `<encryptRoot>/safe.enc`，根目录默认 `CONFIG/ENCRYPT`。实际使用暴露两个问题：

1. **误删风险**：密文镜像保留了原路径与扩展名（`.md`/`.png`/`.mp4`），Obsidian 侧栏将其视为可打开的笔记/媒体——用户可能好奇点开或误删，而镜像文件是加密尸体，删除即数据丢失。
2. **可见性**：`CONFIG/ENCRYPT` 目录在 Obsidian 侧栏可见（含空目录误删连带风险）。

用户经 grilling 逐轮拍板：**平铺 + 点前缀隐藏 + 加密二次确认**，彻底消灭侧栏痕迹与误删通道。

## 决策

1. **平铺单目录**：所有密文镜像（正文、附件原始层、附件预览层）直接放 `<encryptRoot>/` 平铺，不再按原路径建层级目录；层间区分全靠清单 ref 映射。
2. **随机名**：每个镜像文件名 `.随机.enc`（点前缀 + .enc 后缀），纯随机、无可辨识信息、不与原路径挂钩；还原/删除完全依赖清单 `path` + `contentRef`/`blobRef`/`previewRef` 映射。
3. **点前缀隐藏（核心）**：镜像文件与清单一律 `.xxx` 命名。Obsidian 对点前缀路径**一律忽略**（不显示在侧栏、不索引、不可点），杜绝误点误删；vault API 仍可直接读写点前缀文件（同 `.obsidian` 机制）。还原写回目标是原**非**点前缀路径，不受影响。
4. **清单改名**：`safe.enc` → `.safe.enc`（点前缀，同样隐藏；插件按硬编码路径读取）。
5. **根目录点前缀**：默认 `CONFIG/ENCRYPT` → `CONFIG/.ENCRYPT`（连空文件夹都不显示，防"误删空目录连带删光数据"）；encryptRoot 仍可配置。
6. **旧布局不兼容**：旧 `附件/<原路径>` 布局与旧清单路径不再读取——旧加密数据的还原能力被放弃（用户明确拍板，ADR 记录不可逆）。旧文件仍留磁盘但不被插件识别。
7. **加密二次确认**：`bz-encrypt-lock` 每次执行先弹确认框（「把当前笔记与 N 个附件加密移入保险箱？」），点确认才开始加密+进度通知；取消则不加密。防"误触命令即移出"。

## 权衡

- **平铺随机名 vs 保留路径层级**：平铺 + 随机牺牲"目录可读性/人工可辨识"，换取最强隐蔽（文件名零信息泄漏）+ 平铺目录单一；原路径信息本就在清单里，还原不受影响。旧布局的"文件名即路径"可读性对用户无价值（密文不可读）。
- **点前缀 vs 仅改扩展名（.enc 可见）**：改扩展名只能让 Obsidian 不当笔记打开（仍可见可点），点前缀使其完全消失——彻底防误删。代价：侧栏看不到任何保险箱痕迹，用户只能靠命令入口访问；插件内部可读不受影响。
- **彻底不兼容 vs 读旧写新**：读旧写新成本低但保留旧镜像目录可见性（与"完全隐藏"目标冲突），且旧布局数据仍可能被误删；用户明确放弃旧数据还原换取干净的隐藏语义。
- **每次确认 vs 首例确认**：加密是**破坏性移出**操作（原路径文件删除），每次确认最稳妥，杜绝误触；代价是每次多点一下。

## 已知限制

- 点前缀文件不参与 Obsidian 元数据缓存/搜索/图谱——本域不需要（密文不可读，还原靠清单），无影响。
- 若用户自行把 encryptRoot 配成非点前缀路径（如外部绝对路径），隐藏语义失效（其自主选择）；默认路径保证隐藏。
- 旧 `附件/<原路径>` 布局与 `safe.enc` 命名彻底废弃，旧数据用户在升级后需重新加密（旧密文文件未被清理，留待用户自行处置）。
